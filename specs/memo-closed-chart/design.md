# 설계: 청구 메모 목록 닫힌 줄에 시술 코드×총투여량과 증상 차트

## 화면 목업 (승인 요청용, 지금 부품·글만. 이름·글은 지어낸 값)
눌러 보는 시안: `docs/mockups/precheck/memo-closed-chart.html`(PC·휴대폰 폭, 줄 열고 닫기). 아래 글 그림은 그 요약이다.

닫힌 줄 — 지금
```
1  11/2 (월) 가상환자M  [메모 바꿈] [점검 경고 있음 · 입력은 돼요]               메모 보기
차트 9004 · 처방 가상신경차단술-후지내측지, 가상리도카인주사_(20mL), 가상재진진찰료, …
┌ 비트에 있는 메모 ─────────┐ ┌ 우리 메모 ─────────────┐
│ ◈MBB C                    │ │ ◈MBB C 4,5,6 Rt  ◈SSNB │
└───────────────────────────┘ └────────────────────────┘
[바꾸지 않기] [메모 고치기]
```
닫힌 줄 — 바뀐 뒤
```
1  11/2 (월) 가상환자M  [메모 바꿈] [점검 경고 있음 · 입력은 돼요]               메모 보기
차트 9004
시술 [LA358 MBB ×2.5] [LA249 SSNB ×1]                    ← 주황 바탕, 짧은 이름 없으면 처방 이름, 모르면 ×?
처방 가상리도카인주사_(20mL), 가상재진진찰료, …           ← 시술은 위로 옮겨 뺌
┌ 비트에 있는 메모 ─────────┐ ┌ 우리 메모 ─────────────┐
│ ◈MBB C                    │ │ ◈MBB C 4,5,6 Rt  ◈SSNB │
└───────────────────────────┘ └────────────────────────┘
┌ 증상 · 차트 원문 5줄 ─────┐                             ← 열린 줄과 같은 칸. PC에서는 왼쪽 반
│ 호소  목 통증             │
│ 호소  오른쪽 어깨까지 당김│
│ 호소  고개 돌릴 때 심함   │
│ 시술  MBB C4,5,6 Rt, SSNB │
│ 계획  1주 뒤 2차 주사.    │
└───────────────────────────┘
[바꾸지 않기] [메모 고치기]
```
- 시술이 없는 사람은 시술 줄 없이 `차트 N` · `처방 …`(각자 한 줄)
- 증상 글이 없는 진료는 증상 칸이 없다
- 열린 줄은 지금 그대로(머리는 `차트 N`뿐, 아래 우리 메모·비트 메모, 증상·처방내역 두 칸)
- 휴대폰 폭에서는 위아래로 쌓인다: 머리 세 줄 → 메모 칸 → 증상 칸

## 구성 요소
- `src/components/claim/rows/MemoRows.tsx`만 고친다. 새 import 없음(지금 `ds`·`isBlankMemo`·타입·`dayLabel`)
  - `Head`: `open`이 아니면 `차트 N` 아래에 `ProcLine`(시술이 있을 때)과 `처방 …`(남는 이름이 있을 때)을 각각 한 줄로 그린다. 처방 이름은 `row.rxNames.filter((name) => !procNames.has(name))`, `procNames = new Set(row.rxRows.filter(proc).map(r => r.name))`
  - `ProcLine({ rows })`: `시술` 글 뒤에 시술마다 `<span class="bg-negative-soft …">코드 짧은이름|이름 ×총투여량|×?</span>`
  - 닫힌 줄 몸통: 지금 그리던 것(나란히 메모·확인 필요의 우리 메모·없음) 뒤에 `ClosedChart`를 더한다. `chartLines`가 있으면 `<div className="grid gap-2 md:grid-cols-2"><ChartLines lines={row.chartLines} /></div>`(열린 줄과 같은 왼쪽 자리), 없으면 아무것도 그리지 않는다. 입력할 사람·빠지는 사람 두 곳에서 같은 부품을 쓴다
  - `ChartLines`·`RxRows`·`Opened`는 그대로다

## 데이터 흐름
바뀌지 않는다. Worker가 보낸 목록 줄(`chartLines`·`rxRows`·`rxNames`) → `MemoRows` props → 그림. 서버·저장소·도우미로 가는 길이 새로 생기지 않는다(화면 파일 하나만 바뀐다)

## 결정과 트레이드오프
- **시술은 머리에, 증상은 칸으로**: 사용자가 고른 '차트 모양'. 메모의 ◈줄과 맞춰 볼 시술 코드·총투여량과 증상을 누르지 않고 본다
- **약제·기타 총투여량은 열어야**: 닫힌 줄이 너무 길어지지 않게. 사용자가 말한 것은 시술 코드의 총투여량이다
- **처방 줄에서 시술 이름을 뺌**: 시술 줄에 코드와 함께 있으니 두 번 쓰지 않는다. 처방 줄 차례는 지금처럼 비트 표 차례(`rxNames`)
- **짧은 이름이 없으면 처방 이름**: 코드만으로는 무엇인지 모를 수 있다
- **증상 칸은 왼쪽 반(PC)**: 줄을 열면 오른쪽에 처방내역이 붙어 자리가 움직이지 않는다
- **목록이 길어진다**: 한 사람에 증상 5~10줄. 사용자가 알고 골랐다(선택지 설명에 적음)

## 위험
- 수백 명 목록에서 그리는 양이 늘어난다. 줄마다 증상 10줄 안팎의 글이라 지금 화면 방식으로 충분하다고 본다. 느리면 다음에 '증상 접기' 단추를 생각한다
- 머리 단추 안 글이 길어져 화면 읽기 프로그램이 읽는 단추 이름이 길어진다(지금 쉼표 처방 줄과 같은 방식)
