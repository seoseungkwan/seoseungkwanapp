# 요구사항: 통계 처방별 추세

> 기능 ID: `treatment-trend` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 지금 통계 탭의 **처방 추세**는 건수가 많은 처방 5가지(재진진찰료·의약품관리료·먹는 약 같은 것)를 보여 준다. 총괄이 보고 싶은 것은 도수치료·체외충격파 같은 **치료 묶음**의 흐름이다
- 처방 추세 자리를 **처방별 추세**로 바꾼다. 줄은 총괄이 만든 묶음이고, 줄마다 건수·지난 기간보다 늘었는지·신환·재진이 바로 보이며, 누르면 날짜별 막대가 열린다
- 묶음은 통계 탭에서 따로 만들고 계정에 저장한다(휴대폰과 PC가 같다). 매출 탭 묶음(`rx_groups`)과 섞이지 않는다
- 묶음별 건수는 불러올 때(비트 PC·파일) 환자 줄로 세어 일 숫자에 함께 저장한다. 저장된 숫자에는 환자가 누구인지가 없어서 나중에 다시 셀 수 없기 때문이다
- 승인 시안: `docs/mockups/treatment-trend/index.html`(2026-11-05 사용자 "좋아"). 시안의 숫자·처방 코드는 지어낸 것이다. 시안의 '정하신 내용'과 '제가 정한 부분'을 모두 지킨다. 앱 규칙 때문에 다르게 정한 곳은 `design.md` '시안과 다른 곳'에 있다

## 이미 정한 것 (다시 묻지 않는다)
사용자 결정(2026-11-05 질문):
1. 줄은 사용자가 만든 **처방 묶음**이다. 묶음은 통계 전용이고 매출 탭의 치료 묶음과 따로 저장한다. 한쪽을 고쳐도 다른 쪽은 그대로다
2. 줄마다 건수, 지난 기간보다의 증감(지금 처방 추세와 같은 규칙·글자: ▲/▼, %, 늘어남/줄어듦, 줄 막대 안 비교 눈금), 신환 건수·신환율, 재진 건수·재진율이 바로 보인다. 줄을 누르면 일·주·달 막대(신환·재진으로 나뉨, 회색 비교 막대)와 숫자 표가 열린다
3. 같은 환자·같은 날·같은 묶음은 1건이다(도수 10분과 20분을 같은 날 받아도 1건). 묶음을 새로 만들거나 처방을 바꾸면, 이미 불러온 기간은 다시 불러와야(비트 PC 또는 파일) 맞게 나온다. 사용자가 받아들였다
4. 처음에는 다섯 묶음(도수치료·체외충격파·C-arm 주사·초음파·냉동치료)이 들어 있다. 맞추는 규칙은 `src/lib/revenue/treatments.ts`의 `SUGGESTED_GROUPS`와 같다. 사용자가 고칠 수 있다
5. 고치기는 칸 안 오른쪽 위 [묶음 고치기]에서 한다(매출 탭 묶음 고치기와 같은 방식)
6. 어느 묶음에도 없는 처방은 보이지 않는다('나머지' 줄 없음)
7. 줄 차례는 사용자가 정한 차례다(▲▼). 건수 차례가 아니다
8. 칸 이름: 처방별 추세 (사용자, 2026-11-05 승인 뒤 바꿈: 처음 이름은 `치료별 추세`)
9. 처방별 신환·재진, 처방 골라 보기는 그대로다

시안에서 Claude가 정하고 사용자가 시안과 함께 승인한 것:
10. 처방 하나는 한 묶음에만 든다. 다른 묶음에 있는 처방을 고르면 그 묶음에서 옮겨 온다
11. 처방을 바꾼 묶음·새 묶음은 다시 불러올 때까지 숫자 대신 "다시 불러오면 보여요"다. 옛 처방으로 센 숫자는 보이지 않는다. 이름·차례만 바꾸면 다시 불러오지 않아도 된다
12. 0건 묶음은 0건으로 남고 비율은 –다. 처방이 없는 묶음은 "넣은 처방이 없어요"다. 이름이 비었거나 겹치면 저장되지 않는다
13. 합계 줄은 없다(한 환자가 같은 날 두 묶음에 들 수 있다)
14. 묶음은 계정에 저장한다. 처방 코드·이름만 있고 환자 정보는 없다
15. 신환 + 재진 < 건수이면 처방 골라 보기처럼 '구분 없음' 칩을 단다. 비율은 소수 첫째 자리까지 버린다
16. 휴대폰은 표를 옆으로 밀지 않고 한 묶음을 여러 줄로 쌓는다
17. 처음 쓸 때는 저장된 숫자에 묶음별 값이 없어서 한 번 다시 불러와야 숫자가 나온다. 화면이 그렇게 말한다

## 요구사항

### REQ-1201: 처방 추세 자리에 처방별 추세
- AC-1201.1: Given 저장된 숫자가 있는 통계 화면, When 섹션을 그리면, Then 차례는 기간 요약 → 환자 수 추이 → 신환 재방문율 → 처방별 추세 → 처방별 신환·재진 → 처방 골라 보기 → 원장님 보고 문장 → 요일별 환자 수이고 h2 `처방 추세`는 어디에도 없다. 새 칸은 h2 `처방별 추세`, 옆 설명 `만들어 둔 묶음마다 건수와 신환·재진 · 같은 날 같은 환자는 1건`, 전체 폭(`col-span-12`)이다. 처방별 신환·재진은 옆 칸이 없어져 `col-span-12`(세로선·왼쪽 여백 없음)이고 내용은 그대로다. 나머지 여섯 칸의 배치 클래스는 그대로다(rx-picker AC-801.1의 차례·배치를 이 AC가 대신한다)
- AC-1201.2: Given 읽는 중, When 기다리는 칸을 그리면, Then 여덟 칸 모두 "불러오는 중"이고 차례·자리가 AC-1201.1과 같다(rx-picker AC-801.2를 이 AC가 대신한다)
- AC-1201.3: Given 저장된 숫자가 하나도 없음(`saved` false), When 새 칸을 그리면, Then `자료 없음 · 불러오면 묶음마다 건수와 신환·재진이 보여요.` 한 줄만 있고 [묶음 고치기]·줄·안내가 없다
- AC-1201.4: Given 저장된 숫자는 있지만 고른 기간에 일 줄이 없음(`hasRows` false), When 새 칸을 그리면, Then 줄·안내 상자 대신 `불러온 숫자에 이 기간 자료가 없어요.`가 있고 [묶음 고치기]는 누를 수 있다(0건으로 거짓말하지 않는다)
- AC-1201.5: Given 시안에서만 쓰는 것(`바뀐 칸` 칩, `시안에서만 보이는 줄`과 두 모습 단추, `지금 화면의 '처방 추세'와 견주기`, `정하신 내용`, `제가 정한 부분`, `예시` 표시), When 실제 화면을 그리면, Then 어느 것도 없다
- AC-1201.6: Given 처방별 신환·재진과 처방 골라 보기, When 이 기능이 끝나면, Then 두 칸의 시험(`RxSplitSection.test.tsx`·`RxPick*.test.tsx`·`RxPickerSection.test.tsx`)이 기대값을 바꾸지 않고 통과한다(바뀌는 것은 `RxPickDetail` 쪽 함수를 불러오는 경로 한 줄뿐이다)
- AC-1201.7: Given 대시보드 기능 목차의 통계 칸(`DASHBOARD_FEATURES`), When 설명 글을 읽으면, Then `환자 수 추이·신환 재방문율·처방별 추세·요일별 환자 수`다. 이름·주소·상태는 그대로다(tab-frame AC-316.3·stats AC-515.2의 `처방 추세` 글자를 이 AC가 대신한다)

### REQ-1202: 통계 묶음 저장 표 (새 migration)
- AC-1202.1: Given 새 파일 `supabase/migrations/20261105000100_stats_rx_groups.sql`, When 인증 migration 뒤에 이 파일만 돌리면(다른 갈래 표가 없는 DB), Then 표 `stats_rx_groups`가 생기고 칸은 `id`·`hospital_id`·`name`·`codes`·`sort_order`·`updated_at` 여섯뿐이다(환자 칸 없음). RLS가 켜져 있다. 다른 migration(통계·매출·처방 골라 보기)이 먼저 있어도 돌고, 그 표·함수(`rx_groups`·`save_rx_groups`·`touch_updated_at`)를 만들거나 바꾸지 않는다. `my_hospital_id()`는 cross-branch C1 글자 그대로다. 파일 머리 주석에 운영자가 붙여 넣는 방법이 있다
- AC-1202.2: Given 로그인 안 한 사용자(anon), When 읽기·넣기·고치기·지우기·`save_stats_rx_groups`를 부르면, Then 모두 권한 없음이다
- AC-1202.3: Given 승인된 병원 A·B, When A가 읽고 저장하면, Then A는 자기 줄만 보고 고치고 지우며 넣은 줄의 `hospital_id`는 A다. B의 줄은 A에게 보이지 않고 A가 지워도 0줄이다. 승인 대기·거절 병원은 아무 줄도 못 보고 못 넣는다
- AC-1202.4: Given 칸 권한, When `hospital_id`·`id`·`updated_at`을 직접 넣거나 고치면, Then 권한 없음이다. 표 권한은 authenticated의 읽기·지우기와 `name`·`codes`·`sort_order` 넣기·고치기뿐이다
- AC-1202.5: Given 칸 제약, When 이름이 빈 글자·31자 이상·앞뒤 빈칸·제어 문자·숫자 6개 이상 이어짐이거나, 코드가 빈 글자·101자 이상·제어 문자·null이거나 1001개 이상이거나, `sort_order`가 0~49 밖이면, Then 거부된다. 시험: 30자 이름, 100자 코드, 빈칸·괄호가 든 코드(`도수(20분)`)는 들어간다
- AC-1202.6: Given 한 병원, When 같은 이름의 묶음을 둘 두면 거부되고(23505), 한 번의 저장 안에서 두 묶음의 이름을 맞바꾸면 된다(끝에 검사). 다른 병원은 같은 이름을 쓸 수 있다
- AC-1202.7: Given 한 병원, When 한 처방 코드가 두 묶음에 있거나(대소문자만 달라도: `eswt1`·`ESWT1`) 한 묶음에 두 번 있으면, Then 저장이 끝날 때 거부된다(23505). 한 번의 저장 안에서 코드를 한 묶음에서 다른 묶음으로 옮기면 된다. 다른 병원은 같은 코드를 쓸 수 있다
- AC-1202.8: Given `save_stats_rx_groups(groups jsonb)`, When 부르면, Then `save_rx_groups`와 같은 규칙이다: id 없는 묶음은 새로 넣고, id 있는 묶음은 그 줄을 고치고, 받은 목록에 없는 내 병원 줄은 지우고, 내 병원 줄을 `sort_order` 차례로 돌려준다. 배열이 아니거나 51개 이상이거나 `codes`가 배열이 아니면 거부한다. 남의 병원 id면 거부한다. 도중에 실패하면 아무것도 바뀌지 않는다. 빈 배열은 내 병원 줄을 모두 지운다
- AC-1202.9: Given 매출 묶음(`rx_groups`)과 통계 묶음이 같은 DB에 있음, When 한쪽을 저장하면, Then 다른 쪽 줄은 그대로다(시험: 매출 migration도 돌린 DB에서 `save_rx_groups` 뒤 `stats_rx_groups` 줄 그대로, `save_stats_rx_groups` 뒤 `rx_groups` 줄 그대로)
- AC-1202.10: Given 시험의 Supabase 흉내, When 새 표·함수를 만들면, Then 흉내가 기본 권한(anon·authenticated 모든 권한)을 진짜로 주고 migration이 거둔 것이 시험으로 보인다(함수: `stats_rx_group_codes_ok`·`stats_rx_groups_touch`·`stats_rx_groups_code_once`·`save_stats_rx_groups`)

### REQ-1203: 묶음 읽기·저장 코드
- AC-1203.1: Given `listStatsRxGroups()`, When 부르면, Then `stats_rx_groups`에서 `id,name,codes,sort_order`를 `sort_order` 차례로 읽어 `RxGroup[]`(`{ id, name, codes, sortOrder }`)로 돌려준다. 줄이 없으면 빈 목록이다
- AC-1203.2: Given `saveStatsRxGroups(after)`, When 부르면, Then RPC `save_stats_rx_groups`에 `{ groups: [{ id, name, codes, sort_order }] }`만 보내고(다른 열쇠·`hospital_id` 없음) 돌려받은 줄을 `RxGroup[]`로 돌려준다
- AC-1203.3: Given 읽기·저장의 오류·예외·배열이 아닌 답, When 부르면, Then `StatsRxGroupStoreError`를 던지고 번호는 읽기 `E-STATS-GROUP-READ-FAILED`, 저장 `E-STATS-GROUP-SAVE-FAILED`뿐이다. 서버 답 내용은 옮기지 않는다. 읽기 실패를 빈 목록으로 돌려주지 않는다(빈 목록이면 화면이 제안 묶음으로 바꿔 버린다)
- AC-1203.4: Given 두 오류 번호, When `errorInfo`로 글을 꺼내면, Then 읽기는 `처방별 추세 묶음을 읽지 못했어요` · `[다시 읽기]를 눌러 주세요. 계속되면 오류 번호를 관리자에게 알려 주세요.`, 저장은 `처방별 추세 묶음을 저장하지 못했어요` · `인터넷 연결을 확인하고 [저장]을 다시 눌러 주세요. 계속되면 화면을 새로 열어 주세요.`다
- AC-1203.5: Given 이 저장 코드의 소스, When 보면, Then 표 이름 `rx_groups`(앞에 `stats_`가 없는 것)와 `save_rx_groups`를 쓰지 않는다(매출 묶음을 건드리지 않는다)

### REQ-1204: 처음 다섯 묶음
- AC-1204.1: Given 저장된 통계 묶음이 하나도 없음, When 묶음을 읽으면, Then 묶음은 `suggestGroups`의 다섯(도수치료·체외충격파·C-arm 주사·초음파·냉동치료, 이 차례)이고 id가 없다(아직 저장 안 함). 처방은 화면의 일 숫자(`input.days`, 고른 기간 + 비교 기간)에 있는 코드 가운데 `SUGGESTED_GROUPS` 규칙에 맞는 것이다(시험: `도수`·`ESWT1`·`eswt7`·`CARM1`·`SONO1`·`CRYO`·`AA254`가 있으면 AA254는 어디에도 없고 체외충격파는 `ESWT1`·`eswt7`). 대소문자만 다른 코드는 한 번만 든다(`codeKey`)
- AC-1204.2: Given 제안 묶음, When 화면을 보기만 하면, Then 저장하지 않는다(`saveStatsRxGroups`를 부르지 않는다)
- AC-1204.3: Given 제안 묶음, When [묶음 고치기]에서 [저장]을 누르거나, 처방이 든 제안 묶음이 하나라도 있는 채로 비트·파일 불러오기를 시작하면, Then 그때의 다섯 묶음을 저장한다. 불러오기 쪽 저장이 실패해도 불러오기는 그 다섯의 처방으로 센다. 처방이 든 제안 묶음이 하나도 없으면 불러오기 때 저장하지 않는다
- AC-1204.4: Given 사용자가 묶음을 모두 지우고 저장함(저장된 줄 0개), When 다음에 묶음을 읽으면, Then 다시 다섯 제안이 보인다(매출 묶음과 같은 규칙)
