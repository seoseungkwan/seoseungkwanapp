# 요구사항: 다른 병원용 접수 현황 — 설정 화면·혼자 설치

> 기능 ID: `reception-other-clinic` · 번호는 5701부터(다른 명세가 쓴 번호 … 56xx와 겹치지 않게).
> 시안 `docs/mockups/reception-other-clinic/index.html`, 결정과 화면 글 목록은 같은 폴더 `notes.md`. **화면 글자는 승인된 시안 notes.md의 '화면에 새로 생기는 글' 목록 그대로다.** 아래 AC는 시험이 보는 글만 따옴표로 옮긴다.
> 바탕: 갈래 `feat-reception-arrange-tune`(2550eb1) 위. 그 밖의 동작은 reception-phone·reception-paper·reception-arrange·reception-memo-papers·reception-pick-lists·reception-arrange-tune 명세 그대로다.
> **[의원 PC]** 가 붙은 AC는 이 서버에서 증명할 수 없고 의원 PC·태블릿에서 사람이 확인한다. 이 서버의 시험은 그 AC의 글자·구성만 본다.

## 배경 / 목표
- 비트(DrBIT)를 쓰는 다른 병원 여러 곳에 접수 현황(`PrecheckReception.exe`)을 무료로 준다. 웹앱·크롬 확장·청구 도우미 없이 접수 현황만 깔고, 그 병원 직원이 혼자 설치한다. 설치 파일(zip)은 사용자가 직접 보내고, 새 판도 zip을 다시 보낸다. 프로그램은 인터넷에 붙지 않는다.
- 병원마다 다른 것(로고·어레인지 탭 쓰기·치료 칸·처방 코드·고르기 목록)을 직원 폰·태블릿의 **설정** 쪽에서 스스로 맞춘다. 잠금은 없다(지금 '목록 고치기'처럼).
- 우리 의원도 같은 판을 쓴다. 새 판으로 바꿔도 우리 화면은 지금과 같다(지금 값이 설정의 처음 값으로 옮겨진다).
- 사용자 결정(2026-11-17 인터뷰·시안 뒤·개선 6개): `~/.claude/state/handoff/reception-other-clinic.md`와 notes.md의 '사용자가 정한 것'·'사용자 결정' 두 묶음. 줄이면: 처음 일곱 칸도 종류·단계를 바꿀 수 있다 · 설정 쪽은 누르면 바로 저장 + [되돌리기] · 칸은 모두 12개까지 · 30일 처방 목록에서 진찰료(AA로 시작)는 숨김 · 넣기 창은 하나는 한 번에 + [같이 고르기] · 넣기 창 [☰ 목록 고치기] · 처방 추천 · 목록에 없는 코드 직접 넣기 · 처음 설정 안내 · 큰 로고 알아서 줄이기.
- 기본값(시안에 없는 글, Claude 결정):
  - 설정 저장 실패 띠 "설정을 저장하지 못했어요", 다른 기기와 부딪힘(409) 띠 "다른 기기에서 설정을 바꿨어요 · 다시 해 주세요"
  - 칸 고치기 [저장] 띠 "{칸} 칸을 저장했어요", 칸 더하기 띠 "{칸} 칸을 더했어요", [이 칸 빼기] 띠 "{칸} 칸을 뺐어요" + [되돌리기]
  - 로고 올리기 실패 띠 "로고를 올리지 못했어요". 새 그림을 올린 뒤의 띠 "로고를 바꿨어요 · 모든 폰·태블릿에 바로 보여요"에는 [되돌리기]가 없다(그림은 하나만 둔다)
  - 설치 창 글은 REQ-5707 AC 그대로

## 요구사항

### REQ-5701: 설정 파일 (도우미)
- AC-5701.1: Given 설정 모양 검사, When 받으면, Then 문서는 `{ rev, logo: { mode, text, ver }, tab, setup: { logo, tab, done }, nextX, cols: [...], picks }`(design.md 1절)이고 하나라도 빠지거나 더 있으면 받지 않는다. rev·ver·nextX는 0 이상 정수, mode는 `pic`·`text`·`none`, text는 null 또는 앞뒤 빈칸을 뺀 1~20글자(제어 글자·짝 없는 대리쌍 없음)이고 mode `text`면 null이 아니다
- AC-5701.2: Given 칸 목록 검사, When 받으면, Then 처음 일곱 칸 `xray·sono·carm·pt·ds·eswt·trac`이 모두 한 번씩 있고(차례는 자유), 더한 칸 열쇠는 `^x[1-9][0-9]?$`이며 nextX보다 작고 겹치지 않는다. 칸은 모두 12개까지, 보이는 칸은 1개 이상이다. 칸마다 name은 앞뒤 빈칸을 뺀 1~10글자·"|"와 제어 글자 없음이고 모든 칸에서 겹치지 않는다. kind는 `rx`(처방 칸)·`mn`(직접 칸), steps는 2·3, show·added는 참·거짓(처음 일곱 칸은 added 거짓, 더한 칸은 참), rule은 `xray` 칸에만 있는 참·거짓이다
- AC-5701.3: Given 칸의 codes, When 검사하면, Then 대문자로 바꾼 코드가 `^[0-9A-Z가-힣_]{1,16}$`이고 한 칸 안에서 겹치지 않으며 칸마다 40개까지다. 같은 코드가 여러 칸에 있어도 된다(사용자 결정 '중복 선택'). 직접 칸의 codes는 남겨 두되 처방 맞춤에 쓰지 않는다
- AC-5701.4: Given picks, When 검사하면, Then 지금 고르기 목록 모양(reception-pick-lists·reception-arrange-tune 규칙)에 `extra`(더한 칸 열쇠 → 이름 0~8개, 이름 규칙은 PT와 같음)가 더해지고, extra의 열쇠는 더한 칸 열쇠와 정확히 같다
- AC-5701.5: Given 설정 파일이 없고 그 PC `data\`에 `reception-lists.dat`·`reception-arrange.dat`·`reception-marks.dat` 가운데 하나라도 있음(지금까지 접수 현황을 쓴 PC = 우리 의원), When 처음 읽으면, Then '우리 의원 처음 값'을 만들어 바로 저장한다: 로고 `pic`(지금 `logo-wordmark.png`를 로고 파일로 옮김)·탭 켜짐·setup 셋 다 참·일곱 칸 이름 X-RAY·SONO·C-ARM·PT·도수·충격파·견인, 종류 xray·sono·carm은 rx·나머지 mn, 단계 sono·carm 3·나머지 2, 모두 보임, xray rule 참, sono codes `SONO1·SONO·EB422·EB466·HA280`, carm codes `CARM1·G0400`, picks는 그 `reception-lists.dat`를 읽은 값(없거나 깨졌으면 지금 기본 목록)에 extra `{}`
- AC-5701.6: Given 설정 파일이 없고 위 세 파일도 없음(새 병원), When 처음 읽으면, Then '새 병원 처음 값'을 만들어 바로 저장한다: 로고 `none`·text null·탭 켜짐·setup 셋 다 거짓·일곱 칸은 AC-5701.5와 같되 sono·carm codes는 비어 있고 picks는 지금 기본 목록 + extra `{}`
- AC-5701.7: Given 설정 저장, When 쓰면, Then `data\reception-settings.dat`(머리 `PRECHECK-STORE-1\n` + DPAPI, 날짜와 상관없음, 64KB까지)에 임시 파일 → 바꾸기로 쓰고 rev를 1 올린다. 읽을 때 깨졌으면 그 파일 이름을 바꿔 두고(지우지 않음) AC-5701.5·5701.6 규칙으로 다시 만들며 기록에 E-STORE-BROKEN 번호만 남긴다
- AC-5701.8: Given 처음 설정 안내, When 설정을 저장하면, Then setup.done은 한 번 참이 되면 다시 거짓이 되지 않는다. 받은 문서의 setup.done이 거짓이어도 저장된 것이 참이면 참으로 둔다

### REQ-5702: 처방 맞춤 (도우미)
- AC-5702.1: Given 설정과 처방 코드, When 칸을 정하면, Then 처방 하나는 보이는 rx 칸 가운데 codes에 그 코드(앞뒤 공백 뺀 대문자)가 있는 칸 **모두**에 든다. xray 칸이 rx이고 rule이 참이면 `^G[1-8][0-9]{3}([0-9]{3})?$` 코드도 xray에 든다. mn 칸·숨긴 칸에는 들지 않는다
- AC-5702.2: Given 우리 의원 처음 값, When 지금 `ArrangeMap` 시험의 코드 예(SONO1·SONO·EB422·EB466·HA280·CARM1·G0400·G7101·G0400이 X-RAY에 들지 않음 등)를 맞추면, Then 지금과 같은 칸이 나온다
- AC-5702.3: Given 한 내원의 오늘 처방 여럿이 같은 칸에 듦, When 칸 하나로 모으면, Then 지금처럼 칸은 하나이고 처방 시각은 가장 이른 것이다(AC-3301.3 그대로, 칸이 여럿이어도 칸마다)

### REQ-5703: 어레인지 판과 쓰기 (도우미)
- AC-5703.1: Given `GET /api/board`, When 답하면, Then 맨 위에 `cfg` = `{ logo: { mode, text, ver }, tab, guide, cols: [{ k, name, kind, steps, added, empty }] }`가 늘 있다. cols는 보이는 칸만 설정 차례대로, empty는 rx 칸인데 codes가 비고 (xray면 rule도 거짓)일 때 참, guide는 setup.done의 반대다. tab이 거짓이면 `arrange`·`picks`를 쓰지 않는다
- AC-5703.2: Given 어레인지 줄, When 칸을 만들면, Then `cells`의 열쇠는 cfg.cols의 k 그대로(더한 칸 포함)이고 숨긴 칸·지운 칸 열쇠는 없다. 단계 2 칸은 todo → done, 단계 3 칸은 todo → ready → done이다(지금 SONO·C-ARM만 3단계이던 것을 칸 설정으로). 순서 번호(ord)는 단계 3인 처방 칸(종류 rx)마다 있다(사용자 결정 2026-11-17 "3단계 처방 칸이면 번호"). 우리 의원 처음 값에서는 sono·carm만 그 칸이라 지금과 같다
- AC-5703.3: Given `POST /api/arrange`, When col이 보이는 칸 열쇠가 아니거나 단계 2 칸에 set v=ready면, Then 400이다. step·set·remove·part·away·ptf·end의 나머지 규칙은 지금 그대로다
- AC-5703.4: Given 직접 넣기 `add`, When 칸이 pt·ds·trac·더한 칸이면, Then v는 그 칸 목록 이름을 "|"로 이은 1~8개(겹침 없음, 목록 차례로)다. 더한 칸의 목록이 비었으면 v는 ""만 받는다(칸 글 없이 '준비'). eswt는 타수 0개 이상과 부위 수 1개 이상을 "|"로 이은 것(타수 먼저, 각각 목록 차례로), carm은 시술 1개 이상을 "|"로 이은 v와 약재 0개 이상의 t(고른 시술이 모두 약재 없음이면 t 없음), sono는 지금 규칙(1~6줄 + 같이 하는 것)이다. xray는 지금처럼 "X-ray 찍기". 어긋나면 400이다
- AC-5703.5: Given 칸 표시 파일, When 읽으면, Then 칸 열쇠는 `^[a-z][a-z0-9]{0,7}$`면 받는다(모르는 열쇠는 판에 쓰지 않고 파일에는 둔다). 칸 글(det)은 "|"로 나눈 1~16조각, 조각마다 1~21글자·제어 글자 없음이면 받는다(지금 "3000타 2부위" 같은 옛 글도 읽힌다). C-ARM part는 1~12줄이다
- AC-5703.6: Given 판 `picks`, When 쓰면, Then 지금 모양에 `extra`(보이는 더한 칸만)가 더해진다

### REQ-5704: 설정 길 (도우미)
- AC-5704.1: Given `GET /api/settings`, When 부르면, Then 200 + 설정 문서 전체(AC-5701.1 모양)다. 쓰기 검사(ClientGuard)는 지금 읽기 길과 같다
- AC-5704.2: Given `POST /api/settings` 몸 = 설정 문서, When 받으면, Then 쓰기 검사가 틀리면 403, 32768바이트를 넘으면 413, 모양이 틀리거나 바꿀 수 없는 것을 바꾸면 400(nextX 줄이기·더한 칸 열쇠 번호가 nextX 이상·logo.ver 바꾸기·mode `pic`인데 로고 파일 없음. 뺀 칸을 [되돌리기]로 같은 열쇠로 되살리는 것은 된다), rev가 저장된 rev와 다르면 409, 맞으면 저장(rev+1)하고 204다
- AC-5704.3: Given 저장 뒤, When 어느 기기든 `GET /api/board`, Then 다음 읽기부터 새 cfg·picks·칸이 나온다(설정은 비트 읽기 캐시와 따로, 읽을 때마다 지금 설정을 쓴다)
- AC-5704.4: Given `POST /api/lists`, When 부르면, Then 404다(목록은 설정 문서의 picks로 옮김). `reception-lists.dat`는 새 판이 더는 쓰지 않고 지우지도 않는다

### REQ-5705: 지난 30일 처방 목록 (도우미)
- AC-5705.1: Given `GET /api/codes`, When 부르면, Then 등록 확인을 지나 비트를 읽기 전용으로 읽어 지난 30일(@from = 오늘−30일, @to = 내일) 이 병원 외래 접수 처방 줄의 코드마다 `{ c, n, v }`(코드 대문자, 코드 사전 이름 또는 null, 내원 수)를 내원 수 많은 순으로 200개까지 준다. 코드가 `AA`로 시작하면 빼고 센다(진찰료, 사용자 결정)
- AC-5705.2: Given `GET /api/code/{코드}`, When 코드가 `^[0-9A-Za-z가-힣_]{1,16}$`(퍼센트 풀기 뒤)면, Then 200 `{ c, n }`(사전 이름 또는 null), 아니면 비트를 읽지 않고 404다
- AC-5705.3: Given 두 길, When 답을 만들면, Then 이름은 40글자에서 자르고 제어 글자는 뺀다. 환자·내원·차트 번호, 날짜, 메모·증상 글은 답에도 기록에도 없다. 비트 읽기 실패·8초 넘음은 503, 기록은 오류 번호만이다
- AC-5705.4: Given 새 문장 `ReceptionSql.RecentCodes`·`CodeName`, When 도우미 SQL 허용 검사(`Sql.IsAllowed`)를 지나면, Then 받고, 다른 틀은 지금처럼 받지 않는다
- AC-5705.5: [의원 PC] Given 다른 병원(또는 우리 의원) 총괄 PC, When 설정 → 처방 칸 [고치기] → [넣을 처방]을 열면, Then 그 병원의 진짜 처방 코드·이름·내원 수가 진찰료 없이 보인다

### REQ-5706: 병원 로고 (도우미)
- AC-5706.1: Given `POST /api/logo`, When 받으면, Then 쓰기 검사가 틀리면 403, 2097152바이트를 넘으면 413, Content-Type이 `image/png`·`image/jpeg`가 아니거나 그 형식의 첫 바이트(PNG 서명 · JPEG FF D8 FF)가 아니거나 그림 크기(PNG IHDR · JPEG SOF0~SOF3)가 가로 1~1200·세로 1~300이 아니면 400이다. 맞으면 `data\reception-logo.dat`(머리 + DPAPI, 형식 한 바이트 + 그림)에 쓰고, 설정 logo.mode = `pic`·logo.ver +1·setup.logo = 참·rev +1로 저장하고 204다
- AC-5706.2: Given `GET /api/logo`, When 부르면, Then 로고 파일이 있으면 200 + 그 형식(Content-Type `image/png`·`image/jpeg`)과 그림, 없으면 404다. 보안 머리 다섯 개는 다른 답과 같다
- AC-5706.3: Given 화면 파일 내주기, When `.jpg`·`.jpeg`를 보면, Then 지금처럼 내주지 않는다(로고는 /api/logo로만). CSP 글은 한 글자도 바뀌지 않는다(`img-src 'self' data:`)
- AC-5706.4: [의원 PC] Given 폰으로 찍은 큰 간판 사진(수 MB), When 설정에서 [로고 그림]으로 고르면, Then 줄어든 그림이 모든 폰·태블릿 화면 맨 위에 보인다
