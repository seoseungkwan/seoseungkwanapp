# 요구사항: 통계 파일의 구분 줄·꾸민 합계 표시 줄 건너뛰기

> 기능 ID: `stats-file-rows` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 실제 비트 '환자별 소모 통계' 엑셀 파일을 통계 탭에 올리면 "일부 기록을 확인하지 못해 저장하지 않았어요 / 확인하지 못한 줄 3건"으로 저장이 거절된다
- 파일에 환자 기록이 아닌 구분 줄이 있어서다. 머리줄 바로 아래에 처방코드 칸이 `◀ 과 목 ▶`, 처방명칭 칸이 진료실 이름, 처방일자·차트번호가 빈 줄이 있다
- 파서가 이 줄을 필수값 오류(`invalidRows`)로 세고, `analyzeFiles`는 오류 줄이 하나라도 있으면 묶음 전체를 `incomplete`로 두어 저장을 막는다
- 이 줄을 합계 줄·반복 머리줄처럼 건너뛴다. stats-core AC-004.2의 좁은 예외이고, 그 밖의 오류 줄 규칙은 그대로다
- 구분 줄을 고친 뒤 실제 파일을 다시 올리니 3건이 2건으로 줄었다. 값을 출력하지 않은 세기 점검 결과: 구분 줄 1개, 오류 줄 2개이고, 오류 줄 2개는 파일의 마지막 두 줄이다
- 그 두 줄은 처방일자·차트번호가 비었고, 처방코드 칸이 공백을 빼야 합계·소계·총계가 보이는 표시다(`[ 소 계 ]`는 지어낸 예다). 처방명칭·유형과 숫자 칸이 차 있기도 하다
- 원인: 파서의 합계 줄 조건이 처방코드를 공백을 빼지 않고 검사한다(`hasSummaryLabel`은 공백을 뺀다). 그래서 오류 줄로 떨어진다
- 그 조건을 넓히면 날짜만 빠진 환자 기록까지 조용히 빠져 저장될 수 있다. 문제가 있는 진짜 기록은 계속 저장을 막아야 하므로, 기존 조건은 두고 좁은 조건을 따로 더한다

## 요구사항

### REQ-901: 과목 구분 줄은 환자 기록이 아니므로 건너뛴다
- AC-901.1: Given 처방일자·차트번호가 비었고(공백만 있어도 빈 칸) 처방코드에서 공백과 ◀ ▶를 뺀 글자가 정확히 `과목`인 줄(`◀ 과 목 ▶`, `◀과목▶`, `◀ 과목 ▶`, 전각·줄바꿈 공백, 화살표 없는 `과목`), When 읽으면, Then 환자 줄에 넣지 않고 `skippedSummaryRows`로 세며 `invalidRows`는 늘지 않는다. 처방명칭 칸 값은 조건이 아니다
- AC-901.2: Given 구분 줄 3개(하나는 머리줄 바로 아래)와 정상 줄만 있는 CSV·xlsx·속이 HTML인 `.xls` 파일, When `analyzeFiles`로 읽으면, Then 묶음은 `valid`, `skippedInvalidRows`는 0이고, 집계는 구분 줄이 없는 같은 파일과 같다
- AC-901.3: Given 구분 줄 모양이지만 차트번호나 처방일자(못 읽는 날짜 포함)가 있는 줄, When 읽으면, Then 건너뛰지 않는다. 처방일자나 차트번호 중 빠진 것이 있거나 날짜를 못 읽으면 `invalidRows`로 세고, 둘 다 읽히면 지금처럼 환자 줄이 된다
- AC-901.4: Given 처방코드에서 공백과 ◀ ▶를 뺀 글자가 `과목`이 아닌 줄(`과목코드`, `◀ 과 목 ▶ 가짜진료실`, 빈 칸), 처방명칭 칸 등 다른 칸에만 `과목`이 있는 줄, When 읽으면, Then 건너뛰지 않고 필수값이 빠졌으면 `invalidRows`로 센다
- AC-901.5: Given 구분 줄과 진짜 오류 줄(차트번호 빈 줄, 못 읽는 날짜 줄)이 함께 있는 파일, When `analyzeFiles`로 읽으면, Then 묶음은 `incomplete`이고 `skippedInvalidRows`는 구분 줄을 뺀 진짜 오류 줄 수다
- AC-901.6: Given 구분 줄의 허용 칸에 주민번호 모양, When 읽으면, Then 건너뛰기 전에 잡아 파일 전체가 `E-PARSE-RRN`이다
- AC-901.7: Given 구분 줄만 있고 환자 줄이 없는 파일, When 읽으면, Then 지금처럼 `E-PARSE-EMPTY`다

### REQ-902: 꾸민 합계 표시만 있는 줄은 환자 기록이 아니므로 건너뛴다
- AC-902.1: Given 처방일자·차트번호가 비었고(공백만 있어도 빈 칸) 처방코드에서 한글이 아닌 글자를 모두 뺀 글자가 정확히 `소계`·`합계`·`총계`인 줄(`[ 소 계 ]`, `< 합 계 >`, `소 계`, `◀ 총 계 ▶`, `A1 소 계`, 전각·줄바꿈 공백), When 읽으면, Then 환자 줄에 넣지 않고 `skippedSummaryRows`로 세며 `invalidRows`는 늘지 않는다
- AC-902.2: Given 그 줄의 처방명칭·유형·주소 같은 다른 허용 칸이나 읽지 않는 숫자 칸에 값이 있는 줄, 칸 순서가 달라 처방코드 앞 칸에 값이 있는 줄, When 읽으면, Then 결과는 같다
- AC-902.3: Given 그 처방코드 중 붙여 쓴 합계 글자가 없는 것(붙여 쓴 것은 AC-902.8)인데 차트번호나 처방일자(못 읽는 날짜 포함)가 있는 줄, When 읽으면, Then 건너뛰지 않는다. 처방일자나 차트번호 중 빠진 것이 있거나 날짜를 못 읽으면 `invalidRows`로 세고, 둘 다 읽히면 지금처럼 환자 줄이 된다
- AC-902.4: Given 처방일자·차트번호가 빈 줄 중 처방코드에서 한글이 아닌 글자를 뺀 글자가 그 세 낱말이 아닌 줄(`복합 계열`, `합 계 정산`, `소 개`, `[ 합 격 ]`, `소 계 합 계`, `소ㄱ계`), 처방코드는 다른 값이고 처방명칭 칸에만 `소 계`가 있는 줄, 처방일자만 비고 차트번호가 찬 `복합 계열`·`합 계 정산` 줄, When 읽으면, Then 다른 칸에 무엇이 있든 건너뛰지 않고 `invalidRows`로 센다
- AC-902.5: Given 구분 줄 1개, 파일 끝의 꾸민 합계 표시 줄 2개(유형·숫자 칸이 차 있고 한 줄은 처방명칭도 찬 줄), 정상 줄이 있는 CSV·xlsx·속이 HTML인 `.xls` 파일, When `analyzeFiles`로 읽으면, Then 묶음은 `valid`, `skippedInvalidRows`는 0이고, 집계는 환자 줄이 같은 파일과 같다
- AC-902.6: Given 같은 파일에 진짜 오류 줄(차트번호 빈 줄, 못 읽는 날짜 줄)이 함께 있는 파일, When `analyzeFiles`로 읽으면, Then 묶음은 `incomplete`이고 `skippedInvalidRows`는 진짜 오류 줄 수다
- AC-902.7: Given 꾸민 합계 표시 줄의 허용 칸에 주민번호 모양, When 읽으면, Then 건너뛰기 전에 잡아 파일 전체가 `E-PARSE-RRN`이다
- AC-902.8: Given 처방일자가 비었고, 처방코드가 허용 칸 중 처음으로 값이 있는 칸이며, 처방코드에 붙여 쓴 합계 글자가 있는 줄(`소계`, `[소계]`, `복합계열`, `합계 정산`. 차트번호가 찬 줄 포함), When 읽으면, Then 이번 변경 전과 똑같이 기존 합계 줄 조건으로 건너뛴다. 기존 조건은 고치지 않는다

## 범위 밖
- 화면 문구, 저장 규칙, 묶음 품질 계산은 바꾸지 않는다
- 진짜 오류 줄의 규칙은 풀지 않는다(차트번호 빈 줄, 못 읽는 날짜 줄은 계속 저장을 막는다)
- stats-core 명세 문서는 고치지 않는다(사용자가 승인한 기록을 다시 받아야 해서). 이 명세가 그 예외를 적는다
- 진료실 이름을 읽거나 저장하거나 집계에 쓰지 않는다
- 기존 합계 줄 조건, `SUMMARY_LABEL`, `hasSummaryLabel`은 바꾸지 않는다. 파일의 몇 번째 줄인지는 보지 않는다
- 가짜 파일 생성기(`fixtures/`)는 고치지 않는다. 시험 안에서 기존 `buildFakeBitTable` 표에 줄을 끼우고, `toCsvBytes`·SheetJS·직접 쓴 HTML로 파일 모양을 만든다
