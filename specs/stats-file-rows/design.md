# 설계: 통계 파일의 구분 줄·꾸민 합계 표시 줄 건너뛰기

## 개요
- `parseBitGrid`의 줄 읽기에 건너뛰는 조건 하나를 더한다. 주민번호 검사, 합계 줄, 반복 머리줄 검사 다음이고 필수값 검사 앞이다
- 세 조건을 모두 볼 때만 건너뛴다: 처방일자 빈 칸, 차트번호 빈 칸, 처방코드가 구분 표시
- 기존 합계 줄 조건은 그대로 두고, 구분 줄 검사와 같은 자리에 좁은 조건을 더한다(REQ-902). 처방일자·차트번호가 모두 빈 칸이고 처방코드에서 한글이 아닌 글자를 뺀 글자가 정확히 소계·합계·총계일 때만 건너뛴다

## 구성 요소 / 인터페이스
- `src/lib/parsers/bit/parseBit.ts`
  - `isSectionDividerCode(code: string): boolean` (내보내지 않음): `code.replace(/[\s◀▶]/g, '') === '과목'`
  - `isDecoratedSummaryCode(code: string): boolean` (내보내지 않음): `/^(?:합계|소계|총계)$/.test(code.replace(/\P{Script=Hangul}/gu, ''))`
  - `parseBitGrid` 안: `if (dateText === '' && chart === '' && (isSectionDividerCode(code) || isDecoratedSummaryCode(code))) { skippedSummaryRows++; continue }`. 기존 합계 줄 조건과 `hasSummaryLabel`은 바꾸지 않는다
- `src/types/consumption.ts`: `skippedSummaryRows`의 설명 주석에 과목 구분 줄을 더한다. 타입은 그대로다
- 결과 모양, `FileReport`, `analyzeFiles`는 바꾸지 않는다

## 데이터 흐름
- 파일 → `readGrid` → `parseBitGrid` → (구분 줄·꾸민 합계 표시 줄은 세고 버림) → `analyzeFiles` → 묶음 품질. 구분 줄의 칸 값은 결과 어디에도 들어가지 않는다

## 결정과 트레이드오프
- 새 명세로 둔다. stats-core를 고치면 2026-10-28 사용자 승인 기록을 통째로 다시 받아야 하고 수정 범위도 넓어진다
- `skippedSummaryRows`에 함께 센다. 새 칸을 만들면 결과 모양과 시험이 늘어나는데, 이 수는 화면에 쓰이지 않는다
- 처방명칭(진료실 이름)은 조건에 넣지 않는다. 진료실 이름 목록은 병원마다 달라 고정할 수 없고, 처방일자·차트번호가 모두 빈 줄은 어차피 환자 기록으로 쓸 수 없다
- 공백은 `\s`로 넓게 본다(엑셀 칸의 전각·줄바꿈 공백). 화살표는 ◀ ▶ 두 글자만 뺀다. 다른 화살표 글자는 아직 본 적이 없어 넓히지 않는다
- 화살표 없는 `과목`도 조건에 맞는다(사용자 요청 규칙 그대로). 처방일자·차트번호가 모두 비어 환자 기록일 수 없으므로 진짜 기록을 놓치지 않는다
- 건너뛰는 줄이라 다른 칸의 값은 보지 않는다. 주민번호 검사는 이 조건보다 앞이라 그대로 파일 전체를 막는다
- 기존 합계 줄 조건을 넓히지 않는다. 그 조건에는 차트번호 검사가 없고 처방코드가 첫 칸이면 앞쪽 칸 조건도 아무것도 거르지 못한다. 공백을 빼고 검사하면 `복합 계열`처럼 공백을 빼야 합계를 품는 코드의, 날짜만 빠진 환자 기록까지 조용히 빠져 묶음이 `valid`로 저장된다
- 좁은 조건은 코드 전체가 낱말과 같아야 한다. `복합 계열`, `합 계 정산`은 맞지 않아 계속 오류 줄이다. 처방일자·차트번호가 모두 비어야 하므로, 둘 중 하나라도 있는 줄은 환자 기록일 수 있어 건너뛰지 않는다
- 한글 판단은 `\p{Script=Hangul}`로 한다. 자모까지 한글로 남으므로 `소ㄱ계`는 맞지 않는다. 한글이 아닌 글자는 모두 빼므로 `A1 소 계` 같은 코드는 맞는다. 처방일자·차트번호가 모두 비어 환자 기록으로 쓸 수 없는 줄이라 받아들인다
- 앞쪽 칸 조건을 쓰지 않으므로 칸 순서와 상관없다. 파일 끝 줄인지도 보지 않는다
- 환자 자료 구역 규칙 안에 있다: 네트워크·console·저장소를 쓰지 않는다. 시험 값은 모두 지어낸 값이다

## 위험 / 미해결 질문
- 값을 출력하지 않은 세기 점검으로 거절된 3건의 정체는 나왔다(구분 줄 1개, 합계 표시 줄 2개). 새 규칙이 먹히는 전제는 그 두 줄의 처방코드가 한글만 남겼을 때 정확히 세 낱말 중 하나라는 것이고, 실제 파일 점검에서 맞다고 나왔다. 전제가 틀렸다면 그 줄 수만큼 계속 거절된다. 고친 뒤 실제 파일로 다시 확인해야 끝난다
- 기존 조건에 남은 틈(이번 변경이 만들지 않았고 고치지도 않는다, 이번 고침으로 달라지는 것이 없다): 처방일자가 빈 줄에서 아래 줄은 차트번호가 있어도 합계 줄로 건너뛴다. 그런 줄은 저장을 막지 않고 조용히 빠져 묶음이 `valid`로 저장될 수 있고, `skippedSummaryRows`는 화면에 쓰이지 않아 알아챌 길이 없다
  - 처방코드가 허용 칸 중 처음으로 값이 있는 칸이고 붙여 쓴 합계 글자를 품은 줄(`소계`, `[소계]`, `복합계열`, `합계 정산`). AC-902.8로 드러내 둔다
  - 처방코드가 비었고 처음으로 값이 있는 칸의 공백을 빼면 합계 글자가 나오는 줄(처방명칭이 `복합 계열`인 줄처럼 띄어 쓴 것 포함)
- 처방코드 칸이 위 모양이 아닌 구분 줄(예: 진료실 이름이 처방코드 칸에 있는 줄)은 건너뛰지 않고 지금처럼 오류 줄로 센다
