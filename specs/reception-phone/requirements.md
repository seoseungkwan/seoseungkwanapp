# 요구사항: 접수 현황 폰 화면

> 기능 ID: `reception-phone` · 형식: 요구사항은 `### REQ-1401: 제목`, 수용 기준은 `- AC-1401.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.
> 번호는 1401부터다. 다른 명세가 쓴 번호(… bit-read-speed 1001, claim-guard 1101~, treatment-trend 1201~, fu-rate 1301~)와 시험 이름이 겹치지 않게 한다.
> **[의원 PC]** 가 붙은 AC는 이 서버에서 증명할 수 없고 의원 PC·직원 휴대폰에서 사람이 확인한다(design.md '의원 PC에서만 확인하는 것'). 이 서버의 시험은 그 AC의 글자·구성만 본다.

## 배경 / 목표
- 사용자 결정(2026-11-05 질문 정리, 메모 `reception-phone`): 직원이 **직원 전용 와이파이**에서 휴대폰으로 비트 접수 현황(진료대기·진료보류·수납대기·수납완료)을 본다. 휴대폰 전용이고 웹사이트에 새 탭은 없다.
- 화면은 **총괄 PC의 도우미가 직접 내준다**. 웹사이트 서버(Vercel·Supabase)를 거치지 않고 환자 자료를 서버에 저장하지 않는다. "환자 자료는 우리 서버에 저장하지 않는다"는 그대로다. 환자 자료가 그 PC에서 같은 의원 와이파이의 직원 휴대폰까지는 간다(사용자 결정, ADR-027). 휴대폰에는 남기지 않는다.
- **잠금 없음**(사용자 결정): 직원 와이파이의 휴대폰이면 누구나 연다. 그래도 사설 주소(의원 안)에서 온 요청만 받는다.
- **보기만 한다.** 비트에 쓰지 않는다. 예외 하나: 진료보류 환자의 **'X-ray 완료' 표시**(엑스레이 찍음). 비트가 아니라 총괄 PC에 둔다.
- 시안(사용자 승인 2026-11-05 "시안좋아", 뒤에 바뀐 것 포함): `docs/mockups/reception-phone/` — `Main.dc.html`(목록), `Detail.dc.html`(지난 진료 전부·증상), `Offline.dc.html`(연결 끊김). 의원 상표(양지바른정형외과 로고)로 다시 그린 시안 v12와 `Tablet.dc.html`(태블릿 두 칸)도 사용자가 승인했다(2026-11-05 "굿"). 주소 보내기 화면(`/link`, QR 없음: 처음 열기는 카카오톡 링크로만, 사용자 결정 2026-11-05)은 따로 시안을 그리지 않고 이 상표 모양(로고·노랑 채움·짙은 글자·쉬운 한국어)으로 design.md 8절의 글대로 만든다(사용자가 사소한 결정을 맡김, 2026-11-05). 만든 뒤 화면 캡처를 사용자에게 보인다.
- 모르는 값(비트 상태 코드·접수 메모·이름·생년·성별 칸·증상 원천)은 추측하지 않는다. 먼저 의원 PC에서 확인 명령을 돌려 답을 받고(REQ-1401), 그 답으로 한 곳(`ReceptionMap`)을 채운다(REQ-1410).
- 도우미 새 버전은 다른 창의 속도 고침(`bit-read-speed`)이 들어간 뒤에만 낸다(사용자 결정). 이 명세는 만들기까지이고 릴리스는 하지 않는다(REQ-1412).

## 요구사항

### REQ-1401: 의원 PC 확인 명령 (모르는 값을 찾는다)
- AC-1401.1: Given 푼 zip 폴더의 `reception-check.cmd`, When 누르면, Then 설치 없이 `app\PrecheckHelper.exe --reception-check`가 콘솔로 켜진다. 인자가 정확히 그 하나이고 표준 입력이 콘솔일 때만 확인 모드다. 크롬이 켜는 모양(origin 인자·`--parent-window=`)·다른 대소문자·둘째 인자에서는 지금의 메시지 통로가 그대로 돈다
- AC-1401.2: Given 확인 모드, When 상태 코드 단계를 돌리면, Then 오늘 외래 접수를 (`OcmComStt`, `OcmRsuYon`) 짝마다 건수와 접수 시각(시:분) 목록으로 콘솔에만 보이고, 짝마다 "1 진료대기 2 진료보류 3 수납대기 4 끝남 5 접수 취소 6 모름" 가운데 사람이 고른 번호를 받는다. 보고서에는 짝·건수·고른 답만 적고 시각은 적지 않는다
- AC-1401.3: Given 확인 모드, When 칸 단계를 돌리면, Then `OcmInf`·`PbsInf`·`OrcInf`·`OdrInf`의 칸 이름·형식·길이와, 이름이 `OcmNum`으로 끝나는 칸을 가진 표(내원에 붙은 표)의 이름이 보고서에 적힌다. 자료 값은 적지 않는다
- AC-1401.4: Given 비트 로그인 창에서 로그인, When 증상 찾기 단계를 돌리면, Then 비트 화면 83(증상)을 최근 진료일 하루(어제부터 7일 전까지 줄이 있는 첫날) 읽고, 내원에 붙은 표의 글자 칸마다 같은 내원번호의 화면 증상 글과 견준 수(견준 내원 수·똑같음·한쪽이 다른 쪽을 품음·내원 하나의 최대 줄 수)를 적는다. 화면 83의 칸 제목도 적는다. 로그인을 취소하면 이 단계와 이름 찾기는 "건너뜀"이다
- AC-1401.5: Given 같은 화면 83 줄, When 이름 찾기 단계를 돌리면, Then `PbsInf`·`OcmInf`의 글자 칸마다 같은 차트번호의 화면 환자명과 똑같은 수를 적는다
- AC-1401.6: Given 접수 메모 단계, When 사람이 비트 접수 화면에서 본 메모 글 두 글자 이상을 치면(엔터만 치면 건너뜀), Then 오늘 접수에 붙은 글자 칸마다 그 글을 품은 줄 수를 적는다. 친 글은 보고서·콘솔 기록·로그 어디에도 남지 않는다
- AC-1401.7: Given 모양 단계, When 오늘 접수 환자의 `PbsInf` 줄(300줄까지)과 오늘 `OcmInf`·`OrcInf` 줄을 보면, Then 칸마다 빈 값 아님 %, 길이 범위, 8자리 날짜 모양 %, 6자리 날짜 모양 %, 13자리 숫자 모양 %, 값이 4가지 이하이고 모두 두 글자 이하일 때만 그 값 목록을 적는다
- AC-1401.8: Given 빠르기 단계, When 이 명세의 비트 문장(REQ-1403)을 오늘 날짜와 오늘 환자 한 명으로 한 번씩 돌리면, Then 문장 이름마다 걸린 ms·줄 수, 오늘 상태별로 처방 줄이 있는 접수 수, 옛 자료 따로 있음(`StatsSql.HistoryGuardSql`의 0·1)이 적힌다
- AC-1401.9: Given 칸 이름 대신 쓰는 글자(표·칸 이름), When 찾기 문장을 만들면, Then 같은 실행에서 `INFORMATION_SCHEMA`로 읽은 `dbo` 표·칸 이름이고 `^[A-Za-z][A-Za-z0-9_]{0,63}$` 모양일 때만 `[ ]`로 감싸 정해 둔 틀 세 가지에 넣는다. 틀 밖 글자·모양 다른 이름은 DB에 닿기 전에 막힌다. 이 틀은 확인 모드 세션만 받고, 도우미의 허용 목록(`Sql.IsAllowed`)은 받지 않는다
- AC-1401.10: Given 모든 칸이 센티널(한글 이름·숫자 차트번호·영문 이름 모양·전화 모양)인 가짜 DB와 가짜 화면 83, 센티널을 친 메모 글, When 확인을 끝까지 돌리면, Then 보고서와 콘솔 기록에 센티널이 하나도 없다. 오류는 형 이름·오류 번호·SQL 오류 번호로만 적는다
- AC-1401.11: Given 단계마다 시간 제한(문장 30초, 전체 15분), When 넘거나 실패하면, Then 그 항목을 "실패(번호)"로 적고 다음 단계로 간다. 보고서는 줄을 쓸 때마다 디스크에 남고, 끝나면 경로를 콘솔에 쓰고 메모장으로 연다. 파일 이름은 `reception-check-yyyyMMdd-HHmmss.txt`이고 푼 폴더(못 쓰면 임시 폴더)에 둔다
- AC-1401.12: Given 확인 모드의 DB 세션, When 글자를 살피면, Then 접속은 지금의 읽기 전용 접속(`ReadOnlyConnection`)이고 되돌리는 트랜잭션 안에서만 읽으며 `Commit`이 없다
- AC-1401.13: [의원 PC] Given 의원 PC에서 푼 zip, When 사용자가 진료 시간에 확인을 돌리면, Then 보고서가 만들어지고 사용자가 그 글을 채팅에 붙일 수 있다(환자 정보 없음)

### REQ-1402: 접수 현황 자료 만들기 (비트 줄 → 화면 줄)
- AC-1402.1: Given 상태 코드 표(`ReceptionMap`), When 오늘 접수 줄을 나누면, Then 표에 있는 코드만 진료대기·진료보류·수납대기·끝남으로 가고, 표에 없는 코드·접수 취소로 정한 줄은 어느 칸에도 나오지 않으며 그 건수만 따로 센다
- AC-1402.2: Given 나눈 줄, When 목록을 만들면, Then 진료 순서는 진료대기 + 진료보류를 함께 접수 시각 빠른 순(같으면 내원번호 순)으로 놓고 1부터 순서 번호와 상태 이름을 붙인다. 진료대기·진료보류·수납대기는 접수 시각 빠른 순이고, 끝남은 접수 시각 늦은 순(시안 "최근 순")이다. 칸마다 건수를 낸다
- AC-1402.3: Given 지금 시각과 접수 시각, When 기다린 글을 만들면, Then 분 = 지난 분(버림, 최소 1)이고 진료대기 "N분째 대기"·"H시간 M분째 대기"(M이 0이면 "H시간째 대기"), 진료보류 "보류 N분째"·"보류 H시간 M분째", 수납대기 "수납 N분째"이다. 끝남은 수납 시각을 알면 "HH:MM 수납", 모르면 "수납완료"이다
- AC-1402.4: Given 진료대기·진료보류 줄, When 기다린 분이 60 이상이면, Then 그 줄만 오래 기다림 표시(`long: true`, 주황)다. 59분까지·수납대기·끝남은 표시하지 않는다
- AC-1402.5: Given 생년월일·성별·이 병원의 지난 완료 내원 수, When 정보 글을 만들면, Then "54세 · 여 · 재진" 모양이다. 나이는 오늘 기준 만 나이, 지난 완료 내원이 없으면 신환이다. 모르는 값은 빼고 나머지만 " · "로 잇는다
- AC-1402.6: Given 오늘 처방 코드와 지난 완료 내원의 처방, When 처방 글을 만들면, Then 오늘 처방이 있으면 이름표 "오늘"과 오늘 처방, 없고 지난 내원이 있으면 "지난번"과 가장 최근 지난 내원의 처방(그 내원에 처방이 없으면 "지난번 처방이 없어요"), 지난 내원도 없으면 "처방"과 "첫 방문이라 지난 처방이 없어요"다. 처방은 "이름(코드)"를 코드 순으로 " · "로 잇고 이름을 모르면 코드만 쓴다
- AC-1402.7: Given 이름·접수 메모를 아직 못 읽는 상태(칸이 채워지기 전), When 줄을 만들면, Then 그 칸만 비우고 줄은 그대로 만든다(지어낸 값 없음)
- AC-1402.8: Given 진료보류 줄, When 엑스레이 칸을 만들면, Then X-ray 완료 표시가 있으면 `{at: "HH:MM"}`, 없으면 `{at: null}`이다. 다른 상태 줄에는 이 칸이 없다
- AC-1402.9: Given 만든 자료, When 휴대폰에 줄 모양을 보면, Then 줄마다 화면용 열쇠(그날 무작위 16자리 16진수)가 있고 내원번호·비트 상태 코드·생년월일 원값은 없다. 같은 내원은 그날 같은 열쇠이고 날이 바뀌면 새 열쇠다

### REQ-1403: 비트 읽기 (읽기 전용, 여럿이 봐도 한 번만)
- AC-1403.1: Given 이 기능의 비트 문장(`ReceptionSql`), When 살피면, Then 모두 매개변수를 받는 SELECT 상수 하나씩이고 `Sql.IsAllowed`가 받으며, 정해 둔 매개변수 표와 함께만 `ReadOnlyGuard`를 지난다. 등록 병원 범위(`DepMst.DepHspNum=@hospital`) 조건이 있다. 확인 결과로 채우는 칸(REQ-1410) 말고는 지금 이 저장소에 이미 쓰인 칸만 읽는다
- AC-1403.2: Given 휴대폰 요청, When 접수 현황을 달라고 하면, Then 마지막으로 읽은 자료가 8초 안이면 비트를 다시 읽지 않고 그것을 준다. 여러 요청이 한꺼번에 와도 비트 읽기는 한 번만 돈다
- AC-1403.3: Given 휴대폰 요청이 하나도 없는 동안, When 시간이 지나면, Then 비트를 읽지 않는다
- AC-1403.4: Given 한 번 읽기가 3초보다 오래 걸림, When 다음 읽기를 정하면, Then 그 걸린 시간의 3배(60초까지)가 지나기 전에는 다시 읽지 않는다. 읽기 한 번의 시간 제한은 8초다
- AC-1403.5: Given 등록 없음·병원 다름·DB 연결 실패·읽기 실패·시간 지남, When 요청이 오면, Then 자료 대신 "볼 수 없음" 답(HTTP 503, 환자 자료 없음)을 주고 실패 뒤 10초 안에는 다시 읽지 않는다
- AC-1403.6: Given 날이 바뀜, When 다음에 읽으면, Then 새 날의 접수만 읽고 화면용 열쇠·내원 연결표를 새로 만든다
- AC-1403.8: Given 새로 고침 요청(`GET /api/board?fresh=1`, 화면의 [새로 고침] 단추), When 받으면, Then 8초 묶음(AC-1403.2)을 건너뛰고 바로 비트를 읽는다. 다만 (가) 이미 읽는 중이면 그 읽기를 함께 기다리고, (나) 마지막 읽기가 끝난 지 2초 안이면 그 결과를 주며, (다) 3초 넘게 걸린 읽기 뒤의 쉼(AC-1403.4)과 실패 뒤 10초(AC-1403.5)는 그대로 지켜 그동안은 `fresh` 없는 요청과 같은 답을 준다. 여러 폰이 한꺼번에 눌러도 비트 읽기는 한 번에 하나다
- AC-1403.7: Given 처방 이름, When 처방 코드에 이름을 붙이면, Then 하루 한 번 읽은 이름표(`SeeMst`, 코드마다 적용일이 가장 늦은 이름 — `RevenueSql`과 같은 규칙)를 쓴다

### REQ-1404: 지난 진료 전부 (상세)

- AC-1410.3: Given 채운 칸 이름, When 문장(`ReceptionSql`의 칸 문장)을 만들면, Then 상수이고 허용 목록에 있으며, 주민번호 모양 칸에서 생년·성별을 얻을 때는 앞 7글자(`LEFT(…,7)`)만 읽는다
- AC-1410.4: Given 증상 원천, When 확인 보고서에 같은 내원번호의 화면 83 증상과 똑같은 칸이 있으면, Then 그 칸을 내원번호로 읽는 상수 문장을 쓴다. 그런 칸이 없으면 이 TASK는 멈추고 화면 83 길(design.md '증상 원천')로 명세를 바꿔 다시 승인받는다
- AC-1410.5: [의원 PC] Given 채운 도우미를 의원 PC에서 돌림, When 휴대폰으로 보면, Then 비트 접수 화면과 칸별 건수·순서·이름·메모가 같다(사용자가 같음/다름만 알려 준다)

### REQ-1411: 늘 켜 두기와 처음 열기
- AC-1411.1: Given 새 프로그램 `PrecheckReception.exe`(창 없는 윈도우 프로그램, x86, .NET Framework 4.8), When 켜면, Then 이 PC 사용자당 하나만 돈다(이름 붙은 뮤텍스). 이미 돌고 있으면 새것은 바로 끝난다
- AC-1411.2: Given 윈도우 로그인, When 사용자가 로그인하면, Then 사용자 레지스트리 시작 항목(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`)이 `PrecheckReception.exe`를 켜고 47200번 문에서 기다린다. 비트 DB가 아직 답하지 않으면 휴대폰에는 "볼 수 없음"이고 DB가 답하면 저절로 자료가 나온다(비트 프로그램 로그인 여부는 보지 않는다)
- AC-1411.3: Given 바탕 화면의 "접수 현황 주소" 바로 가기, When 누르면, Then 돌고 있지 않으면 켜고, 이 PC 브라우저로 `http://127.0.0.1:47200/link`를 연다
- AC-1411.4: Given `/link`(주소 보내기 화면, QR 없음), When 그리면, Then 이 PC의 사설 IPv4 주소마다 큰 글자의 전체 주소 링크 `http://{주소}:47200`(카카오톡이 누르는 링크로 바꾸게)와 [주소 복사] 단추(누르면 `navigator.clipboard`로 복사, 안 되면 주소 글을 골라 둔다), 쉬운 순서 넷("1. 직원 단톡방에 붙여 넣어 보내요" · "2. 직원은 병원 와이파이에서 주소를 눌러요" · "3. 카톡 안에서 열리면 오른쪽 위 메뉴 → '다른 브라우저로 열기'" · "4. 홈 화면에 추가해요"), 안내 "이 주소는 병원 와이파이에서만 열려요. 밖에서는 열리지 않아 환자 정보가 보이지 않아요"가 design.md 8절의 글과 상표 모양대로 나온다. 사설 주소가 없으면 "이 PC가 의원 와이파이에 연결되어 있지 않아요" 모양의 안내다
- AC-1411.5: Given 문 47200을 다른 프로그램이 씀, When 켜면, Then 오류 번호를 기록하고 끝난다(다른 문으로 바꾸지 않는다: 휴대폰 홈 화면 주소가 바뀌기 때문)
- AC-1411.6: [의원 PC] Given 처음 켬, When 윈도우 방화벽 창이 뜨면, Then 사용자가 "개인 네트워크"에 [허용]을 눌러 휴대폰에서 열린다. 네트워크가 "공용"이면 "개인"으로 바꾼 뒤 열린다
- AC-1411.7: [의원 PC] Given PC를 껐다 켜고 로그인, When 직원 휴대폰 홈 화면 아이콘을 누르면, Then 따로 누르지 않아도 접수 현황이 나온다

### REQ-1412: 설치·내보내기와 릴리스 조건
- AC-1412.1: Given `install.ps1`, When 설치하면, Then 관리자 권한 없이 돌던 `PrecheckReception`도 먼저 끄고 덮어쓴 뒤, 시작 항목과 바탕 화면 바로 가기를 만들고 켠다. `uninstall.ps1`은 그 둘을 지우고 끈다. 크롬 등록과 `data\`는 지금처럼 다룬다
- AC-1412.2: Given `helper.yml`의 zip 단계, When 묶으면, Then `app\`에 `PrecheckReception.exe`·`PrecheckReception.exe.config`가 들고, 푼 폴더에 `reception-check.cmd`·`reception-check.ps1`이 든다. 시험·빌드 단계와 태그 규칙은 그대로다
- AC-1412.3: Given 이 명세의 변경, When 도우미 버전(`Directory.Build.props`)·`src/lib/bridge/versions.ts`·`commands.json`을 보면, Then 바뀌지 않았다. 버전 올리기와 `helper-v*` 태그는 `bit-read-speed`가 main에 들어간 뒤 사용자 말에 따라 부모 세션이 한다
- AC-1412.4: Given `helper/install/README.md`, When 읽으면, Then 쉬운 말로 접수 현황 켜기·끄기, 방화벽 창에서 누를 것, 공유기에서 이 PC 주소 고정(DHCP 예약), 휴대폰 첫 열기(바탕 화면 "접수 현황 주소" → [주소 복사] → 직원 단톡방에 보내기 → 병원 와이파이에서 주소 누르기 → 카톡 안이면 '다른 브라우저로 열기' → 홈 화면에 추가), 아이폰은 처음 한 번 화면을 눌러야 소리가 난다는 것, 잠금이 없어 직원 와이파이 비밀번호를 손님에게 알리면 안 된다는 것이 있다
- AC-1412.5: Given `Precheck.Reception.csproj`와 `Precheck.Helper.csproj`, When 이 서버에서 `dotnet build -c Release`로 빌드하면(`buildDotnet`), Then 둘 다 net48·x86으로 컴파일된다(실행은 의원 PC에서만 증명된다)

### REQ-1413: 환자 자료는 의원 안에서만

## 범위 밖
- 비트에 쓰기(엑스레이 표시도 비트에는 쓰지 않는다), 접수·호출·순서 바꾸기
