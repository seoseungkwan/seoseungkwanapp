# 요구사항: 통계 비트 불러올 기간 고르기 (최근 1년·2년·2020년부터 전부, 나눠 읽기)

> 기능 ID: `stats-load-range` · 형식: 요구사항은 `### REQ-3301: 제목`, 수용 기준은 `- AC-3301.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.
> 예시의 오늘은 `2026-11-09`(월)이고 '오늘 진료 끝'은 꺼져 있다(끝난 마지막 날 = 어제 11월 8일). 화면 시험은 그 파일의 오늘로 같은 규칙의 값을 쓴다.

## 배경 / 목표
- 2026-11-09 사용자 제보: 통계에서 긴 기간을 골라 보니 석 달 치만 보였다
- 까닭: [비트에서 불러오기](`StatsScreen.tsx`의 `loadFromBit`)는 지금 고른 기간의 `range.load`만 읽는다. 처음 값 '최근 30일'의 `range.load`는 비교 기간 첫날이 든 달 1일 ~ 오늘(`view.ts` `statsRange`)이라 오늘은 2026-09-01 ~ 11-09, 석 달이다. 저장은 달·날마다 덮어쓰기(upsert, `lib/storage/stats.ts`)라 한 번 저장한 달은 남는다
- 지금 있는 문제(같이 고쳐진다): `range.load`가 800일을 넘으면(2025년 8월 이전 달, 2025년 이전 해, 긴 직접 날짜) 도우미가 기간 한도(`commands.json` stats.rows `maxDays` 800)로 요청을 거절해 'E-HELPER-BAD-MESSAGE'(도우미가 요청을 읽지 못했어요)로 끝난다. 이 기능은 '지금 보는 기간'도 같은 나누기를 쓰므로 그 경우도 나눠 읽게 된다
- 목표: 비트 칸에서 불러올 기간을 고르고(지금 보는 기간 · 최근 1년 · 최근 2년 · 2020년부터 전부), 한 번에 못 읽는 길이는 2년씩 나눠 새것부터 읽어 저장한다
- 승인 시안: `docs/mockups/stats-load-range/index.html`(클릭 목업, 사진 `1-view.png`·`2-all.png`·`3-working.png`·`4-stopped.png`). 시안의 글이 승인된 글이다

## 이미 정한 것 (다시 묻지 않는다)
1. (사용자, 시안) 비트 칸 [비트에서 불러오기] 위에 '불러올 기간' + 묶음 단추 [지금 보는 기간 | 최근 1년 | 최근 2년 | 2020년부터 전부]. 단추 아래 안내 줄은 읽을 날짜(첫날 – 끝날)와 걸리는 때를 말한다
2. (사용자, 시안) 지금 보는 기간 = 지금 동작 그대로(`range.load`). 최근 1년·2년·전부 = `range.load`와 그 기간을 합친 것(지금 보는 기간은 늘 읽힌다). 1년 = 11달 전 달 1일부터, 2년 = 23달 전 달 1일부터, 전부 = 2020-01-01(`FIRST_DAY`)부터
3. (사용자, 시안) 한 번에 못 읽으면 나눠 새것부터 읽고 '읽는 중이에요 (2/4 · 2022년 12월 – 2024년 11월)'과 '다 끝날 때까지 이 창을 닫지 마세요.'를 보인다. 다 되면 '…을 저장했어요.', 중간에 멈추면 저장된 조각은 남고 '4번 가운데 2번째까지 저장하고 멈췄어요.' + 저장된·남은 달 + 오류 번호 + [이어서 불러오기](남은 조각만 읽음)
4. (메인 세션이 정함) 화면을 열 때마다 처음 값은 '지금 보는 기간'이고 고른 것을 기억하지 않는다
5. (지켜야 하는 한도) 한 번 읽기는 800일 이하(도우미 stats.rows `maxDays`), 덮은 기간 줄도 800일 이하(DB 제약, stats AC 506.3). 조각은 달 1일에 시작해 달 말일에 끝난다(가장 새 조각만 오늘에 끝남): 달 줄은 달마다 덮어쓰므로 달을 반으로 자른 조각이 그 달을 덜 된 숫자로 덮으면 안 된다. 한 조각은 24달(731일 이하). '오늘 진료 끝'은 오늘이 든 조각에만 쓴다. 일은 한 번에 하나(`runJob`)이고 읽는 동안 불러올 기간 단추는 막힌다
6. (이 명세에서 Claude가 정함, 승인 때 함께 본다 — design.md '결정') 이웃 조각 쪽으로 한 달씩 더 읽고 저장 전에 뺀다 / 합친 기간이 800일 이하면 지금처럼 한 번에 읽는다 / 보고 문장은 첫 조각, 처방별 신환·재진·세 칸은 지금 보는 기간을 담는 조각의 답을 쓴다 / 확인 필요(incomplete)인 조각은 실패처럼 멈춘다 / 첫 조각에서 멈추면 지금과 똑같다 / 저장한 끝날 글은 해를 넘으면 양 끝에 해를 붙인다(시안의 '2020년 1월 1일 – 11월 8일' → '2020년 1월 1일 – 2026년 11월 8일')

## 요구사항

### REQ-3301: 불러올 기간 고르기 (비트 칸)
- AC-3301.1: Given 비트 PC 연결 상태가 ready, When 비트 칸을 그리면, Then [비트에서 불러오기] 위 한 줄(`basis-full`)에 굵은 '불러올 기간' 글과 `role="group"`·`aria-label="불러올 기간"` 묶음이 있고, 단추는 차례로 [지금 보는 기간][최근 1년][최근 2년][2020년부터 전부]이다(`ds.segment.group`·`button`·`on`/`off`, 768px 미만은 두 칸씩 두 줄 `max-md:grid-cols-2`). 화면을 열 때마다 [지금 보는 기간]만 `aria-pressed="true"`이고, 다른 단추를 누르면 그것만 눌린다. 고른 것은 브라우저 저장소·서버에 쓰지 않는다
- AC-3301.2: Given 일이 있음(비트 불러오기·파일 읽기·다시 저장), When 그리면, Then 네 단추는 `disabled`이고 눌러도 고른 것이 바뀌지 않는다. 일이 끝나면 다시 누를 수 있고 고른 것은 그대로다. [비트에서 불러오기]를 누르면 `onLoad(오늘 진료 끝, 고른 것)`이다(고른 것은 'view'·'1y'·'2y'·'all')
- AC-3301.3: Given 최근 30일(`range.load` 2026-09-01 ~ 11-09), When 단추 아래 안내 줄('오늘 진료 끝' 안내 위, `basis-full text-small text-ink-2`)을 그리면, Then 고른 것마다 이 글이다: 지금 보는 기간 '지금 보는 기간(최근 30일)과 비교할 지난 30일이 든 9월 1일 – 11월 9일을 읽어요. 빨리 끝나요.' · 최근 1년 '2025년 12월 1일 – 2026년 11월 9일(1년)을 읽어요. 30초쯤 걸려요.' · 최근 2년 '2024년 12월 1일 – 2026년 11월 9일(2년)을 읽어요. 1분쯤 걸려요.' · 2020년부터 전부 '2020년 1월 1일 – 2026년 11월 9일을 2년씩 4번에 나눠 읽어요. 4분쯤 걸려요. 한 번 저장한 달은 남으니 처음 한 번만 하면 돼요.'
- AC-3301.4: Given 안내 글 규칙(`loadHint`), When 다른 기간을 보면, Then (가) 날짜 글은 읽을 전체 기간(whole)을 비교 글처럼 쓴다: 해가 같으면 해 없이, 해를 넘으면 양 끝에 해(`spanLabel(whole, false)`). (나) 지금 보는 기간은 '지금 보는 기간({range.name})과 비교할 {이름들}{이/가} 든 {날짜 글}'이고, 이름들은 `previous.name`과 `lastYear.name`(있으면)을 '·'로 이으며 끝 글자에 받침이 있으면 '이', 없으면 '가'다. 예: 2026년 10월 일별 → '지금 보는 기간(2026년 10월)과 비교할 9월·작년 10월이 든 2025년 10월 1일 – 2026년 11월 9일을 읽어요. 1분쯤 걸려요.', 직접 날짜 2026-10-03 ~ 11-01 → '…비교할 바로 전 30일·작년 같은 날짜가 든 2025년 10월 1일 – 2026년 11월 9일을 읽어요. 1분쯤 걸려요.' (다) 최근 1년·2년의 '(1년)'·'(2년)'은 whole 첫날이 그 단추의 첫날과 같을 때만 붙는다: 최근 12개월 + 최근 1년 → '2024년 12월 1일 – 2026년 11월 9일을 읽어요. 1분쯤 걸려요.' (라) 조각이 둘 이상이면 '…을 읽어요.' 대신 '…을 2년씩 {N}번에 나눠 읽어요.'다: 2025년(월별) + 지금 보는 기간 → '지금 보는 기간(2025년)과 비교할 2024년이 든 2024년 1월 1일 – 2026년 11월 9일을 2년씩 2번에 나눠 읽어요. 2분쯤 걸려요.' (마) 걸리는 때는 조각이 둘 이상이면 '{N}분쯤 걸려요.', 하나면 읽을 날 수가 100일 이하 '빨리 끝나요.', 400일 이하 '30초쯤 걸려요.', 그 위 '1분쯤 걸려요.'다. '한 번 저장한 달은 남으니 처음 한 번만 하면 돼요.'는 2020년부터 전부일 때만 끝에 붙는다

### REQ-3302: 나눠 읽기 계획 (순수 함수 `planLoad`·`partSave`)
- AC-3302.1: Given 지금 보는 기간의 `range`와 고른 것, When `planLoad(today, range, span)`, Then whole = { from: min(`range.load.from`, 단추 첫날), to: 오늘 }이다. 단추 첫날은 지금 보는 기간 = 없음(whole = `range.load`), 최근 1년 = 오늘이 든 달의 11달 전 달 1일, 최근 2년 = 23달 전 달 1일, 전부 = 2020-01-01. 예(최근 30일): 2026-09-01 / 2025-12-01 / 2024-12-01 / 2020-01-01. 최근 12개월(load 2024-12-01) + 최근 1년 → 2024-12-01. 2020년 월별(load 2019-01-01) + 전부 → 2019-01-01
- AC-3302.2: Given whole이 800일(`MAX_READ_DAYS`) 이하, When 계획하면, Then 조각은 하나이고 그 조각의 save = read = whole, keepAt = 0이다. 예: 최근 2년 709일 → 하나, 2025년 9월 일별(load 2024-09-01 ~ 2026-11-09, 800일) → 하나, 2025년 8월 일별(load 2024-08-01, 831일) → 둘
- AC-3302.3: Given whole이 800일을 넘음, When 계획하면, Then 조각은 오늘이 든 달부터 거꾸로 24달씩 자른 것이고 차례는 새것부터다. 각 조각의 save는 달 1일에 시작해 달 말일에 끝나고(가장 새 조각만 오늘에 끝남, 가장 옛 조각은 whole 첫날에 시작), save를 이으면 whole과 빈틈·겹침 없이 같다. 예(최근 30일 + 전부): [2024-12-01 ~ 2026-11-09] [2022-12-01 ~ 2024-11-30] [2020-12-01 ~ 2022-11-30] [2020-01-01 ~ 2020-11-30]
- AC-3302.4: Given 조각이 둘 이상, When 계획하면, Then 각 read는 save에 이웃 조각이 있는 쪽으로 한 달씩 더한 것이다(앞쪽: 바로 앞 달 1일부터, 뒤쪽: 바로 다음 달 말일까지. 가장 새 조각의 끝은 오늘, 가장 옛 조각은 앞쪽을 더하지 않는다). 예: [2024-11-01 ~ 2026-11-09] [2022-11-01 ~ 2024-12-31] [2020-11-01 ~ 2022-12-31] [2020-01-01 ~ 2020-12-31]. 오늘이 2026-01-01 ~ 2032-12-31의 어느 날이든, 네 단추 어느 것이든, `range.load` 첫날이 그 달 1일·2020-01-01·2015-01-01 어느 것이든 모든 read는 800일 이하, 모든 save는 731일 이하다
- AC-3302.5: Given 계획, When keepAt을 정하면, Then keepAt = read가 { `range.current.from`, min(`range.current.to`, 오늘) }을 다 담는 가장 새 조각의 차례이고, 없으면 0이다. 예: 최근 30일 + 전부 → 0, 2025년(월별) + 지금 보는 기간 → 0(첫 read 2024-11-01 ~), 2024년(월별) + 지금 보는 기간 → 1(둘째 read 2023-01-01 ~ 2024-12-31), 직접 날짜 2024-06-01 ~ 2025-03-31(주별) + 지금 보는 기간 → 0(어느 read도 다 담지 못함)
- AC-3302.6: Given Worker 답(`StatsLoaded`)과 조각, When `partSave(view, part)`, Then months는 달이 save 안(save 첫 달 ~ 끝 달)인 줄만, days는 날이 save 안인 줄만, sections는 배열이면 달이 save 안인 것만(null이면 null, 열쇠가 없으면 열쇠 없음), covered = `view.covered`와 save가 겹치는 구간(겹치지 않거나 `view.covered`가 null이면 null), source 'bit'이다. 조각이 하나(save = read)면 months·days·covered·sections가 Worker 답 그대로다

### REQ-3303: 차례대로 읽고 저장하기 (통계 화면)
- AC-3303.1: Given 지금 보는 기간(처음 값)이고 조각이 하나, When [비트에서 불러오기]를 누르면, Then 지금과 같다: stats.rows 요청은 하나 { from: `range.load.from`, to: 오늘 }, Worker load 메시지에 keep 칸이 없고 closeToday는 누른 값이며, 보고 문장·처방별 신환·재진·세 칸·저장 값(months·days·covered·sections)·확인 카드가 지금과 같다. 끝난 뒤 '…을 저장했어요.' 상자는 없다(지금처럼 출처 줄 '· 방금')
- AC-3303.2: Given 조각 N개(N ≥ 2), When 누르면, Then 조각을 새것부터 하나씩 읽는다: k번째 stats.rows 요청은 k번째 조각의 read이고, k−1번째 조각의 저장이 끝난 뒤에야 보낸다. Worker load 메시지의 closeToday는 첫 조각만 누른 값이고 나머지는 false, keep은 keepAt 조각만 칸이 없고 나머지는 false다. 조각마다 저장(`saveStats`)을 `partSave` 값으로 한 번씩 부른다(덮은 기간도 조각마다 하나). 처방별 추세 묶음은 누를 때 한 번 읽어 모든 조각에 같이 쓴다
- AC-3303.3: Given 조각 N ≥ 2, When 읽으면, Then 보고 문장(오늘·어제·이번 달·지난달 숫자)은 첫 조각 답으로 정하고, 처방별 신환·재진과 세 칸(환자 구성·시간대별 접수·원장님별)은 keepAt 조각을 읽은 뒤 한 번 묻는다. 예: 최근 30일 + 전부 → 넷을 다 읽은 뒤에도 처방별 신환·재진은 최근 30일 숫자다. 2024년(월별) + 지금 보는 기간 → 둘째 조각을 읽은 뒤 처방별 신환·재진이 2024년 숫자다(지금은 도우미가 거절하던 경우)
- AC-3303.4: Given 조각 N ≥ 2를 읽는 중, When 그리면, Then 띠 아래 읽는 중 줄은 '비트 PC에서 읽는 중이에요 ({k}/{N} · {k번째 save 달 글}). 다 끝날 때까지 이 창을 닫지 마세요.'다. 달 글은 '2022년 12월 – 2024년 11월'처럼 양 끝 해·달이고 한 달이면 '2020년 1월'이다. N = 1이면 지금 글 '비트 PC에서 읽는 중이에요. 기간이 길면 1분쯤 걸려요.'다. 다 끝날 때까지 일은 하나('bit')라 [비트에서 불러오기]('불러오는 중')·[파일 고르기]·불러올 기간 단추·[다시 저장]이 막힌다
