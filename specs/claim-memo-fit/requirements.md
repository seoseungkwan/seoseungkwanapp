# 요구사항: 메모 확인 한눈에 보기

> 기능 ID: `claim-memo-fit` · 형식: 요구사항은 `### REQ-4801: 제목`, 수용 기준은 `- AC-4801.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다. 시험 자료의 이름·글은 지어낸 값이다.

## 배경 / 목표
- 2026-11-16 사용자: 청구 3단계 '메모 확인'에서 오른쪽 상세의 증상·처방내역을 보려면 사람마다 내려야 해서 불편하다. "이거까지 한번에 보고싶어"(증상 8줄 + 처방 11줄)
- 사용자 화면은 가로 1440 창, 두 칸 높이 약 533px. 지금은 오른쪽 상세(머리 → 단추 줄 → 우리 메모 | 비트 메모 → 증상 | 처방)가 한 덩어리로 내려간다(memo-split AC-3105)
- 시안 `docs/mockups/claim-memo-fit/index.html`(?s=new)을 사용자가 고쳐 가며 2026-11-16 "승인해"로 승인했다. 결정 과정은 `docs/mockups/claim-memo-fit/notes.md`

## 이미 정한 것 (다시 묻지 않는다)
1. 바뀌는 것은 lg(1024px) 이상 PC 화면이다. lg 미만(폰·좁은 창)의 배치는 지금 그대로다. 예외: 기본 안내 글 없애기(REQ-4804)와 짧은 이름 한 번만(REQ-4805)은 모든 폭에 적용된다
2. 메모 확인~입력 결과(메모 칸이 그려지는 동안)에는 앱 틀의 1280 폭 제한을 풀어 창 너비를 다 쓴다. 위쪽 띠·탭 줄·본문 셋이 같이 넓어진다(세 감싸개가 같은 폭이라는 AC-218.1 규칙은 그대로). 다른 탭·청구 1~2단계는 그대로
3. 환자 목록: 표시('! 메모 바꿈' 등)를 줄 오른쪽 끝에서 차트번호 바로 뒤로 붙인다(사용자 "왼쪽으로만 밀어"). 목록 폭 360 → 272px
4. 오른쪽 상세: 머리는 한 줄, 그 아래 세 칸 — ① 복사(완료)·단추·우리 메모·비트 메모 ② 증상 · 차트 원문 ③ 처방내역. 증상과 처방은 같은 폭(사용자 "증상을 오른쪽으로 좀 더 키워도 돼")
5. 우리 메모·비트 메모는 크게, 같은 크기(사용자 "크기 좀 키워줘", "칸 똑같이")
6. 증상은 자르지 않는다(사용자 "증상은 다 보이게"). 처방명은 길면 끝을 '…'로 자른다(사용자 "처방내역은 옆에 조금 잘려도 되니까")
7. 복사 단추 밑 기본 안내 글('누르면 우리 메모가 복사되고 완료로 바뀌어요. 그다음 비트 메모 칸에 붙여 넣으세요.')은 없앤다(사용자 "이것도 없애서"). 다른 상태 줄(복사함·복사 못 함·완료한 환자 등)은 그대로 같은 자리에 나온다
8. 도우미·확장·Worker·저장은 바꾸지 않는다. 글자·순서·단추와 움직임(복사(완료)·↑↓·C·메모 고치기)도 그대로

## 요구사항

### REQ-4801: 메모 칸이 그려지는 동안 창 너비를 다 쓴다
- AC-4801.1: Given 메모 칸(`MemoPanel`)이 그려짐, When 그 바깥 틀을 보면, Then 메모 칸 뿌리에 `data-wide-page` 표시가 있다
- AC-4801.2: Given 앱 틀(`AppShell`·`TabBar`), When 그리면, Then 뿌리에 이름 붙은 묶음 `group/app`이 있고 `max-w-7xl`을 가진 감싸개 넷(위쪽 띠 안쪽·탭 띠 안 줄·탭 줄·본문 안쪽)에 모두 `lg:group-has-[[data-wide-page]]/app:max-w-none`가 있다(그 밖의 class는 그대로: `max-w-7xl`·좌우 24px 등)
- AC-4801.3: Given 이름 없는 `group` class, When 앱 틀 뿌리를 보면, Then 없다(안쪽 `group-hover` 등이 앱 전체에 걸리지 않게)

### REQ-4802: 환자 목록을 좁히고 표시를 왼쪽으로
- AC-4802.1: Given lg 이상, When 두 칸을 그리면, Then 두 칸 class는 `lg:grid-cols-[272px_minmax(0,1fr)]`이다(예전 `lg:grid-cols-[360px_minmax(0,1fr)]` 없음). 나머지 높이·스크롤 규칙(AC-3101.1)은 그대로
- AC-4802.2: Given 목록 줄, When 그리면, Then 이름·날짜·차트 묶음은 lg 이상에서 남은 폭을 채우지 않고(`lg:flex-none`), 표시 묶음은 그 바로 뒤에 왼쪽 정렬로 붙는다(`lg:justify-start`). lg 미만은 지금처럼 이름 묶음이 남은 폭을 채우고 표시는 오른쪽 끝이다
- AC-4802.3: Given 목록 위 [전체·미완료·완료] 단추, When lg 이상에서 그리면, Then 단추 안쪽 여백이 좁아져(`lg:px-2`) 272px 목록 한 줄에 '보기'와 함께 들어간다

### REQ-4803: 오른쪽 상세 — 머리 한 줄, 아래 세 칸
- AC-4803.1: Given lg 이상, When 상세 머리를 그리면, Then 이름·표시·진료일|차트·안내(그 묶음 까닭·점검 경고)가 한 줄에 이어지고, '{묶음 이름} {n} / {N}'과 [↑ 앞 사람][↓ 다음 사람]·키보드 안내는 같은 줄 오른쪽에 있다(왼쪽 묶음 `lg:contents`, 위치 글 `lg:order-2 lg:ml-auto`, 단추 묶음 `lg:order-3 lg:flex-row`). lg 미만 배치는 지금 그대로다(안내 글만 머리 왼쪽 묶음 안 진료일 줄 아래로 들어간다)
- AC-4803.2: Given lg 이상, When 머리 아래를 그리면, Then 세 칸 격자(`lg:grid-cols-[clamp(13.75rem,30%,18.75rem)_minmax(0,1fr)_minmax(0,1fr)]`, 남은 높이를 채움)이고 차례는 ① 단추 상자·우리 메모·비트 메모 ② 증상 · 차트 원문 ③ 처방내역이다. 세 칸은 각자 스크롤된다
- AC-4803.3: Given lg 이상 ① 칸, When 그리면, Then 단추 상자 아래 우리 메모 칸과 비트 메모 카드가 남은 높이를 똑같이 나누고(둘 다 `lg:flex-1`, 가장 작게 `lg:min-h-24`) 넘치면 칸 안에서 스크롤된다. 우리 메모의 알림 글(빠진 문장·저장 안 됨·지난 입력)은 우리 메모 칸 바로 아래에 온다
- AC-4803.4: Given lg 이상 ① 칸 단추 상자, When 그리면, Then 복사(완료) 단추가 한 줄을 다 쓰고 그 아래 줄에 [완료 풀기]·[메모 고치기]·[바꾸지 않기]·[이 메모로 바꾸기]·[다시 하기] 가운데 보이는 것들이 나란히 나눠 선다
- AC-4803.5: Given lg 이상 증상 표, When 글이 길면, Then 자르지 않고 다음 줄로 넘긴다(말줄임 없음). 표가 칸보다 길면 표 칸 안에서 스크롤된다
- AC-4803.6: Given lg 이상 처방 표, When 처방명이 길면, Then 처방명은 한 줄로 끝이 '…'로 잘리고(`lg:truncate`) 마우스를 올리면 전체 이름(`title`)이 뜬다. 짧은 이름은 잘리지 않고 늘 보인다. 표가 길면 표 칸 안에서 스크롤되고 표 머리(종류·코드·처방명·총투여량·급여)는 위에 붙어 있다(`lg:sticky lg:top-0`)
- AC-4803.7: Given 메모 칸 오른쪽 상세 칸(`고른 환자 메모`), When lg 이상, Then 세로 flex(`lg:flex lg:flex-col`)이고 상세는 그 높이를 채운다(`lg:flex-1 lg:min-h-0`). 넘치면 예전처럼 상세 칸이 스크롤된다(`overflow-y-auto` 그대로)

### REQ-4804: 기본 안내 글 없애기
- AC-4804.1: Given 상태가 `ready`(memoSplit.copyStatus의 기본), When 상세를 그리면, Then 단추 상자에 상태 줄이 없다('누르면 우리 메모가 복사되고…' 글 없음). 이 AC는 memo-split AC-3103.7을 대신한다
- AC-4804.2: Given 상태가 `ready`가 아님(editing·locked·stuck·failed·failedAgain·reopened·mark·none·copied·done), When 그리면, Then 상태 줄은 지금 글·색·기호 그대로다

### REQ-4805: 처방의 짧은 이름이 처방명과 같으면 한 번만
- AC-4805.1: Given 처방 줄의 짧은 이름이 처방명과 같음(앞뒤 빈칸 빼고 견줌), When 처방 표를 그리면, Then 짧은 이름을 쓰지 않는다. 다르면 지금처럼 처방명 뒤에 쓴다

### REQ-4806: 지금 것은 그대로
- AC-4806.1: Given 이 기능 뒤, When 지금 시험을 돌리면, Then 기대값을 바꾸지 않고 통과한다. 예외(이 기능이 대신함): memo-split AC-3101.1의 왼쪽 360px 기대값(→ AC-4802.1), AC-3103.7과 `ready` 글을 기대하는 메모 칸 시험(→ AC-4804.1), AC-3105 상세 머리·두 칸·표 줄 class 기대값 가운데 이 명세가 바꾸는 것
- AC-4806.2: Given 이 기능 뒤, When `src/guardrails.test.ts`·lint·tsc·build를 돌리면, Then 통과한다(환자 줄 폴더 `components/claim/rows`는 네트워크·저장소·console을 쓰지 않는다)
