# 요구사항: 메모 입력 현황에서 날짜를 직접 완료로 바꾸기

> 기능 ID: `claim-day-done` · 형식: 요구사항은 `### REQ-2801: 제목`, 수용 기준은 `- AC-2801.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.
> 시험 자료의 날짜·숫자는 모두 지어낸 값이다. 환자 자료는 이 기능에 오지도 가지도 않는다.

## 배경 / 목표
- 2026-11-08 사용자(의원 총괄)가 휴대폰으로 청구 탭의 '메모 입력 현황'(밖에서 보는 건수, `src/components/claim/OutsideCounts.tsx`, precheck AC-019.5)을 보고 "이거 내가 완료로 바꿀 수 있게 해 주고 저장도 할 수 있게 해 줘"라고 했다
- 까닭(사용자 확인): 9월 28일 '진행중 32/53'처럼 숫자로는 남아 있지만, 나머지 환자는 메모가 필요 없어 실제로는 끝난 날이 많다. 지금은 '끝난 날'을 숫자(메모 필요 = 입력함)로만 정해서 이런 날이 목록에 계속 남고 'N일 남음'이 부풀어 있다
- 목표: 그런 날을 사람이 골라 '완료'로 저장한다. 저장한 날은 목록과 'N일 남음'에서 빠지고, 잘못 저장하면 되돌린다. 비트 PC 청구 화면도 그 날을 끝난 날로 본다

## 이미 정한 것 (다시 묻지 않는다)
1. 완료로 바꾼 날은 목록에서 빠지고 'N일 남음'도 그만큼 준다(사용자 "줄이자")
2. 목록 맨 아래에 "완료로 바꾼 날"을 접어 두고, 펼치면 [되돌리기]가 있다(사용자 "ㅇㅇ")
3. 저장 방식은 시안 B: 날짜마다 체크 칸, 여러 날을 고른 뒤 [완료로 저장]을 눌러야 저장된다(사용자 "B", `docs/mockups/claim-day-done/index.html`)
4. 아래는 Claude가 정하고 사용자에게 알린 것(2026-11-08, 사용자 "시작해"):
   - 날짜별 숫자(입력/필요)는 비트에서 올라온 그대로 둔다. 완료 표시만 따로 저장한다
   - 비트 PC 청구 화면에서도 그 날은 끝난 날이다. 체크 칸·저장 단추는 밖에서 보는 화면에만 둔다
   - 완료로 바꾼 날은 비트에서 숫자가 다시 올라와도 되돌리기 전까지 완료로 남는다
   - 되돌리기는 하나씩이고 따로 저장을 누르지 않는다(누르면 바로 저장)
   - 완료 표시를 둘 자리(서버 표)를 새로 만든다. 운영자가 Supabase SQL Editor에 마이그레이션 파일을 한 번 붙여 넣어 실행한다

## 요구사항

### REQ-2801: 날짜를 골라 [완료로 저장]
- AC-2801.1: Given 밖에서 보는 화면에 남은 날 줄들(메모 필요 > 입력함, 완료 표시 없음), When 그리면, Then 줄마다 날짜 앞에 체크 칸이 하나 있고 이름은 `{M/D (요일)} 고르기`다(예: '9/28 (월) 고르기'). 표 위 고르기 줄에 '완료로 바꿀 날을 골라 주세요'와 막힌(disabled) [완료로 저장]이 있다. 390px 폭에서도 체크 칸과 단추가 보인다(지금처럼 휴대폰 폭에서는 '입력/필요'를 한 칸에)
- AC-2801.2: Given 고르기 줄, When 체크 칸을 하나씩 켜고 끄면, Then 고른 날 수가 바로 '{N}일 골랐어요'로 보이고 N ≥ 1이면 [완료로 저장]이 풀리고 0이면 다시 막히며 글도 처음 글로 돌아간다
- AC-2801.3: Given 두 날을 고름, When [완료로 저장]을 누르면, Then 서버 요청은 완료 표시 표(`claim_day_closes`) 하나에 한 번이고 줄마다 칸은 `visit_date` 하나뿐이다(고른 두 날짜, 같은 날 두 번 없음). 답을 기다리는 동안 단추는 '저장 중…'으로 막히고 모든 체크 칸이 막힌다
- AC-2801.4: Given AC-2801.3의 저장이 성공, When 답이 오면, Then 그 두 날은 위 목록에서 빠지고 'N일 남음'이 2 줄며 "완료로 바꾼 날"의 수가 2 는다. 고른 것은 비워지고 고르기 줄은 '2일을 완료로 바꿨어요'와 [되돌리기]가 된다. 이 [되돌리기]를 누르면 방금 저장한 두 날을 함께 되돌린다(REQ-2802와 같은 지우기). 다시 체크 칸을 켜면 이 알림은 사라지고 AC-2801.2의 글로 돌아간다
- AC-2801.5: Given 저장이 실패(서버 오류, 연결 끊김, 표가 아직 없음), When 답이 오면, Then 목록·고른 것·'N일 남음'은 그대로이고 패널 안에 오류 안내(`E-DAYCLOSE-FAILED`, `lib/errors.ts` 문구)가 보이며 [완료로 저장]을 다시 누를 수 있다. 원래 오류 글은 화면에 옮기지 않는다
- AC-2801.6: Given 다른 창에서 이미 완료로 저장된 날, When 같은 날을 다시 저장하면, Then 실패하지 않고 그 날의 완료 표시는 한 줄이며 처음 저장한 시각이 남는다
- AC-2801.7: Given 남은 날이 하나도 없음(지금의 '남은 메모가 없어요'), When 그리면, Then 고르기 줄은 없고 "완료로 바꾼 날"은 그대로 있다

### REQ-2802: 완료로 바꾼 날 보기·되돌리기
- AC-2802.1: Given 완료 표시가 있는 날들, When 그리면, Then 패널 맨 아래에 접힌 '완료로 바꾼 날 {N}'이 있다(N = 읽은 완료 표시 수, 없으면 0). 펼치면 '숫자는 비트에서 올라온 그대로예요. [되돌리기]를 누르면 위 목록으로 돌아가요.'와 줄들이 최근 날짜부터 있다. 줄은 날짜, '완료로 바꿈 · {바꾼 시각}'(지금의 '{시각}에 바뀜'과 같은 시각 글), 건수 줄이 있으면 '입력함 / 메모 필요', '완료' 칩(`ds.chip.positive`), [되돌리기]다. 0이면 '아직 없어요'
- AC-2802.2: Given 펼친 칸의 한 줄, When [되돌리기]를 누르면, Then 서버 요청은 `claim_day_closes`에서 그 날짜 하나를 지우는 것 하나다. 성공하면 그 날은 아래 칸에서 빠지고, 그 날에 남은 메모가 있으면(메모 필요 > 입력함) 위 목록의 날짜 차례 자리로 돌아가며 'N일 남음'이 1 는다. 답을 기다리는 동안 그 줄의 [되돌리기]는 막힌다
- AC-2802.3: Given [되돌리기]가 실패, When 답이 오면, Then 그 줄은 아래 칸에 그대로이고 AC-2801.5와 같은 오류 안내가 보인다
- AC-2802.4: Given 완료 표시가 있지만 남은 메모가 없는 날(뒤에 비트에서 다 입력됨) 또는 읽은 건수에 없는 날, When 그리면, Then 아래 칸에 날짜·바꾼 시각·칩·[되돌리기]만 있고 숫자 칸은 비어 있다. 되돌려도 위 목록에는 생기지 않는다

### REQ-2803: 숫자·'마지막으로 바뀐 시각'은 그대로
- AC-2803.1: Given 완료 저장·되돌리기, When 서버 요청을 보면, Then 건수 표(`claim_day_counts`·`claim_month_counts`·`contact_counts`)에는 쓰지 않는다
- AC-2803.2: Given 완료 표시가 건수 표보다 늦게 생김, When 그리면, Then '마지막으로 바뀐 시각 … · 비트 PC에서 올라옴'은 지금처럼 건수 표 세 개의 시각만으로 정한다(완료 표시 시각을 섞지 않는다)
- AC-2803.3: Given 남은 메모가 있는 날 5개 가운데 2개에 완료 표시, When 그리면, Then 'N일 남음'은 3이고 위 목록은 그 3일이다. 완료 표시 읽기가 실패하면 지금처럼 패널 대신 `E-COUNTS-FAILED`, 표가 아직 없으면 완료 표시 없음으로 본다(지금 화면과 같다)

### REQ-2804: 비트 PC 청구 화면도 끝난 날로 본다
- AC-2804.1: Given 날짜 목록(`buildDateList`)에 완료 표시 날짜, When 줄을 만들면, Then 그 날은 남은 메모·진료 수와 상관없이 `done: true`이고 끝난 날 묶음(최근 날부터)에 들며 상태는 '완료'다. 완료 표시 없는 날은 지금 규칙 그대로다
- AC-2804.2: Given 완료 표시 날이 가장 오래된 '남은 일 있는 날', When `listRange`를 구하면, Then 그 날은 남은 일 있는 날로 치지 않는다(목록 시작을 그 날까지 늘리지 않는다)
- AC-2804.3: Given 완료 표시 날, When [입력 안 된 날짜 모두]·처음 기간을 정하면(`unfinishedPeriod`·`defaultPeriod`), Then 그 날은 들지 않는다
- AC-2804.4: Given 비트 PC 청구 화면, When 날짜 목록을 읽거나 새로 읽으면(`loadDates`·`refreshDates`), Then 건수와 같은 400일 범위의 완료 표시를 함께 읽어 `buildDateList`·`listRange`에 넘긴다. 처음 읽기(`loadDates`)에서 완료 표시 읽기만 실패하면 읽은 건수는 그대로 쓰고 완료 표시는 없음으로 보며, 건수 읽기 실패 때와 같은 표시(`countsFailed: true`)를 낸다. 새로 읽기(`refreshDates`)에서 실패하면 지금처럼 보던 목록을 둔다. 표가 아직 없으면 완료 표시 없음이고 실패가 아니다
- AC-2804.5: Given 비트 PC 청구 화면, When 그리면, Then 날짜 목록에 체크 칸·[완료로 저장]·[되돌리기]가 없다(바꾸는 곳은 밖에서 보는 화면 하나)

### REQ-2805: 서버 자리와 권한(완료 표시 표)
- AC-2805.1: Given 마이그레이션 `supabase/migrations/20261108000000_claim_day_closes.sql`, When 실제 Postgres(PGlite)에서 앞 마이그레이션 뒤에 돌리면, Then 표 `public.claim_day_closes`가 있고 칸은 `hospital_id`(uuid, 기본 `my_hospital_id()`, 병원 지우면 함께 지움)·`visit_date`(date)·`closed_at`(timestamptz, 기본 now())뿐이며 (hospital_id, visit_date)는 하나뿐이다. 글자 칸이 없다
- AC-2805.2: Given 로그인 안 한 사용자(anon), When 읽기·넣기·지우기를 하면, Then 모두 막힌다
- AC-2805.3: Given 승인된 병원 A의 사용자, When 읽기·넣기·지우기를 하면, Then 자기 병원 줄만 보이고 넣고 지운다. 병원 B의 줄은 보이지 않고 지워지지 않는다. 승인 안 된 사용자는 아무 줄도 넣지 못한다
- AC-2805.4: Given 넣기, When `hospital_id`나 `closed_at`을 보내거나 고치기(update)를 하면, Then 권한이 없어 막힌다(넣기는 `visit_date` 칸만, 고치기 권한 없음)
- AC-2805.5: Given 이미 있는 (병원, 날짜), When `on conflict do nothing`으로 다시 넣으면, Then 오류 없이 줄 하나와 처음 `closed_at`이 남는다(AC-2801.6의 DB 쪽)
- AC-2805.6: Given 같은 병원·날짜의 건수 줄, When 건수 표에 다시 올리면(upsert) 또는 건수 줄이 없으면, Then 완료 표시 줄은 그대로다(두 표는 서로 묶이지 않는다)
- AC-2805.7: Given 이 마이그레이션, When 두 번 돌리면, Then 오류 없이 같은 상태다

### REQ-2806: 울타리와 지금 시험
- AC-2806.1: Given 완료 저장·되돌리기·읽기, When 보내는 값을 보면, Then 날짜(`YYYY-MM-DD`)뿐이다. 날짜 모양이 아닌 값이 하나라도 있으면 아무것도 보내지 않고 `E-DAYCLOSE-FAILED`로 던진다. 받은 원래 오류 글은 옮기지 않는다
- AC-2806.2: Given 이 기능 뒤, When `src/guardrails.test.ts`·`npm run lint`·`npx tsc --noEmit`을 돌리면, Then 통과한다. 새 코드는 환자 자료 구역(`lib/precheck`·`workers`·`components/claim/rows` 등)을 고치지 않는다
- AC-2806.3: Given 지금 시험, When 이 기능 뒤에 돌리면, Then 기대값을 바꾸지 않고 통과한다. 예외는 `OutsideCounts.test.tsx`의 가짜 서버가 새 표를 알게 하는 것과, 거기서 새 표 읽기만큼 늘어난 읽기 수·체크 칸만큼 늘어난 표 칸 기대값, `ClaimScreen.test.tsx`의 가짜 서버가 새 표를 알게 하는 것뿐이다

## 범위 밖
- 비트 PC 청구 화면에서 완료로 고르기·되돌리기

- 완료 표시 바뀜을 다른 창에 바로 알리기(지금처럼 창 초점이 오면 다시 읽는다)
- 도우미·확장·명령 표 바꾸기
