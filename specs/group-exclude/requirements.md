# 요구사항: 처방별 추세 묶음 빼는 처방·조건·총환자 대비

> 기능 ID: `group-exclude` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 총괄은 "기본 PT만 받은 환자"가 얼마나 되는지 보고 싶다. 예: MM010·MM015를 받았지만 그날 충격파(ESWT7 등)·도수는 받지 않은 환자
- 지금 처방별 추세(specs/treatment-trend)의 묶음은 "넣는 처방 중 하나라도 받으면 1건"뿐이다. 여기에 세 가지를 더한다
  1. **빼는 처방**: 그날 이 중 하나라도 받은 환자는 그날 그 묶음에서 뺀다
  2. **처방마다 조건**: 넣는 처방마다 "이 처방과 같은 날 받으면 이 처방으로는 세지 않는다"를 정한다
  3. **총환자 대비 %·추세선**: 줄마다 총환자 대비 %, 열린 그래프에 추세선과 [총환자 대비 %] 꺾은선
- 셈은 지금처럼 불러올 때 Worker 안에서 환자·날마다 한다. 저장되는 것은 묶음 열쇠별 숫자뿐이다
- 승인 시안: `docs/mockups/group-exclude/index.html`, 결정 메모 `docs/mockups/group-exclude/notes.md` (2026-11-12 "클리어하고 이어서하자"). 시안의 숫자·처방 이름은 지어낸 것이다. 앱 규칙 때문에 다르게 정한 곳은 `design.md` '시안과 다른 곳'에 있다

## 이미 정한 것 (다시 묻지 않는다)
사용자 결정(2026-11-12, notes.md에 말 그대로):
1. 넣는 처방과 빼는 처방을 모두 여러 개 고른다. 어떤 처방이든 빼는 처방이 될 수 있다
2. 하루 기준: 같은 환자·같은 날·같은 묶음 = 1건
3. 그래프·추세선, 주·월·년별 %. % = 그 기간 총환자 대비. 1년 = 최근 12개월
4. 기본 PT는 미리 만들어 두지 않는다. 사용자가 이름·넣는 처방·빼는 처방을 정한다
5. 넣는 처방마다 [조건 더하기]. 예: MM080은 MM020·MM030·TENS와 같은 날 받으면 MM080으로는 안 센다. 그날 MM010 같은 다른 넣는 처방을 받았으면 그것으로 1건

시안에서 Claude가 정하고 사용자가 시안과 함께 승인한 것(notes.md '시안이 정한 부분'):
6. 자리는 처방별 추세 묶음이다. 처방 골라 보기는 그대로
7. 셈: 그날 (가) 넣는 처방 가운데 '그 처방의 조건 처방을 그날 하나도 안 받은' 처방이 하나 이상 있고 (나) 빼는 처방을 하나도 안 받았으면 1건
8. 총환자 = 그 기간 날마다 온 환자 수의 합(통계 '환자 수'와 같은 셈). 총환자 대비 = 묶음 건수 ÷ 총환자. 모든 묶음 줄에 보인다
9. 그래프 칸: 7·30일 일, 90일 주, 12개월 달(지금 처방별 추세와 같다). 열린 칸 단추 [건수]·[총환자 대비 %]. 둘 다 점선 추세선(최소제곱). 쉬는 날(총환자 0)은 추세선에서 뺀다. 추세를 글로도 쓴다
10. 빼는 처방·조건 처방은 다른 묶음의 넣는 처방이어도 된다. "처방 하나는 한 묶음에만"은 넣는 처방에만 쓴다. 한 묶음 안에서 같은 처방이 넣는 처방이면서 빼는 처방일 수는 없다
11. 빼는 처방 고르기의 '묶음째 고르기': 다른 묶음 이름을 누르면 그때의 처방을 복사해 넣는다(나중에 그 묶음을 고쳐도 따라 바뀌지 않는다)
12. 처방 옆 [빼기] 단추는 [지우기]로 바꾼다
13. 만들거나 바꾼 뒤 보고 싶은 기간을 한 번 다시 불러와야 숫자가 나온다

이 명세에서 Claude가 정한 것(시안에 없음, design.md에 까닭):
14. 빼는 처방·조건이 없는 묶음의 열쇠는 지금과 글자까지 같다. 그래서 지금 묶음은 다시 불러오지 않아도 그대로 보인다
15. 추세선은 총환자 0인 칸과 일부 기간 칸(빗금: 기간 끝에 걸린 주, 끝나지 않은 달·오늘)을 빼고 긋는다. 두 그래프 모양 모두 같다
16. 고른 그래프 모양([건수]·[총환자 대비 %])은 화면을 연 동안만 기억한다(줄을 닫았다 열어도 그대로, 새로 열면 [건수])
17. 넣는 처방을 지우면(또는 다른 묶음으로 옮기면) 그 처방의 조건도 같이 없어진다

## 요구사항

### REQ-3701: 통계 묶음 표에 빼는 처방·조건 칸 (DB)
- AC-3701.1: Given 새 migration `supabase/migrations/20261112000000_stats_rx_groups_exclude.sql`을 treatment-trend 묶음 표 위에 붙임, When 표를 보면, Then `stats_rx_groups`에 `out_codes text[] not null default '{}'`와 `cond jsonb not null default '[]'` 칸이 있고, 이미 있던 줄은 두 칸이 빈 값이다(옛 줄이 그대로 읽힌다)
- AC-3701.2: Given 승인된 병원 사용자, When `out_codes`·`cond`를 넣거나 고치면, Then 된다. `anon`은 칸을 읽지도 쓰지도 못하고, 다른 병원 줄은 RLS로 보이지 않는다(treatment-trend 권한 그대로)
- AC-3701.3: Given 한 줄, When `out_codes`에 (가) 그 줄 `codes`와 대소문자 무시로 같은 코드 (나) 대소문자 무시로 겹친 코드 (다) 빈 글자·101자·제어 문자·null (라) 1001개를 넣으면, Then 각각 CHECK 오류로 저장되지 않는다
- AC-3701.4: Given 한 줄, When `cond`가 (가) 배열이 아님 (나) 칸이 `code`·`unless` 둘이 아닌 항목 (다) `code`가 그 줄 `codes`에 없음(대소문자 무시) (라) 같은 `code` 항목 둘(대소문자 무시) (마) `unless`가 빈 배열·1001개·글자가 아닌 값·`code` 자신·안에서 겹침(대소문자 무시) (바) 코드 글자 규칙(1~100자, 제어 문자 없음) 위반 (사) 항목 1001개이면, Then 각각 CHECK 오류로 저장되지 않는다. `unless`의 코드는 다른 묶음의 넣는 처방·같은 묶음의 다른 넣는 처방·빼는 처방이어도 된다
- AC-3701.5: Given 저장 함수 `save_stats_rx_groups(groups jsonb)`, When 항목마다 `out_codes`(배열)와 `cond`(배열)를 실어 부르면, Then 새 줄·고친 줄에 그대로 들어가고 돌려준 줄에 두 칸이 있다. 열쇠가 없는 항목(옛 앱)은 새 줄이면 빈 값, 고친 줄이면 그 칸을 지금 값 그대로 둔다(옛 탭에서 저장해도 빼는 처방·조건이 지워지지 않는다). 둘 중 하나가 배열이 아니면 `bad groups`로 아무것도 바뀌지 않는다
- AC-3701.6: Given 이 migration, When 넣는 처방 겹침 검사(`stats_rx_groups_code_once`)를 보면, Then 그대로 `codes`만 본다: 다른 묶음의 넣는 처방을 `out_codes`·`cond`에 넣어도 저장된다
- AC-3701.7: Given 새 함수(칸 검사), When 권한을 보면, Then `public`·`anon`은 부르지 못하고 `authenticated`만 부른다. migration은 다른 갈래 함수(`touch_updated_at` 등)를 만들거나 부르지 않는다
- AC-3701.8: Given `docs/ARCHITECTURE.md`의 `stats_rx_groups` 줄, When 읽으면, Then 칸 목록에 `out_codes`·`cond`가 있고 이 명세를 가리킨다

### REQ-3702: 묶음 모양과 읽기·저장 코드
- AC-3702.1: Given `src/types/rxGroups.ts`, When 타입을 보면, Then `RxCond = { code: string; unless: string[] }`와 `StatsRxGroup = RxGroup & { out?: string[]; cond?: RxCond[] }`가 있고 매출 묶음 `RxGroup`은 그대로다. 칸이 없으면 빈 것으로 본다(`groupOut`·`groupCond`가 빈 배열을 돌려준다)
- AC-3702.2: Given 읽기 `listStatsRxGroups`, When 부르면, Then `select('id,name,codes,out_codes,cond,sort_order')`이고 줄마다 `StatsRxGroup`(`out` = `out_codes`, `cond` = `cond`)을 돌려준다. 두 칸이 null이면 빈 배열로 읽는다
- AC-3702.3: Given 저장 `saveStatsRxGroups(after)`, When 부르면, Then 항목마다 `{ id, name, codes, out_codes, cond, sort_order }` 여섯 칸만 새 객체로 보낸다(`cond` 항목도 `{ code, unless }`만). 실패는 지금처럼 번호 하나다
- AC-3702.4: Given AI 리포트 묶음 이름 읽기(`app/api/ai/store.ts` `loadReportMonths`), When `stats_rx_groups`를 읽으면, Then `select('name, codes, out_codes, cond, sort_order')`이고 열쇠는 `groupKey(codes, { out, cond })`다. `out_codes`가 글자 배열이 아니거나 `cond`가 `{ code: 글자, unless: 글자 배열 }` 배열이 아니면 지금처럼 모양 오류다(ai-report-stats AC-2002.1의 select 글자를 이 AC가 대신한다)

### REQ-3703: 불러올 때 빼는 처방·조건으로 세기
- AC-3703.1: Given 묶음 {넣는 MM010·MM015, 빼는 ESWT7}, When 한 환자가 같은 날 MM010과 ESWT7을 받으면, Then 그날 그 묶음 줄이 없다(0건). 다른 날 MM010만 받은 날은 1건이다(월요일 기본 PT만, 목요일 충격파까지 → 월요일만)
- AC-3703.2: Given 같은 묶음, When 같은 날 MM010과 MM015를 받으면, Then 1건이다(지금 규칙 그대로)
- AC-3703.3: Given 묶음 {넣는 MM010·MM080, 조건 MM080 ← MM020·MM030·TENS}, When 같은 날 (가) MM080 + MM020 (나) MM080 + MM020 + MM010 (다) MM080 + MS1(조건 밖) (라) MM080만 받으면, Then (가) 0건 (나) 1건 (다) 1건 (라) 1건이다
- AC-3703.4: Given 조건과 빼는 처방이 같이 있는 묶음, When 그날 넣는 처방이 조건을 지나도 빼는 처방을 하나 받으면, Then 0건이다
- AC-3703.5: Given 빼는 처방·조건 코드, When 처방 줄 코드와 대소문자만 다르면, Then 같은 코드로 본다(넣는 처방과 같은 규칙)
- AC-3703.6: Given 입원 줄(`outpatient === false`), When 세면, Then 넣는 처방·빼는 처방·조건 모두 그 줄을 보지 않는다(지금 규칙 그대로)
- AC-3703.7: Given 빼는 처방·조건이 없는 묶음, When 세면, Then 일·주·달 칸의 `groups` 숫자(`patients`·`newPatients`·`returning`·`followup`)가 이 기능 전과 같다. 한 코드가 여러 묶음에 들어간 정의도 지금처럼 각 묶음에서 센다(stats-core AC-006.3 그대로)
- AC-3703.8: Given 주·달 칸, When 한 환자가 그 주에 센 날이 이틀이면, Then 그 칸 `patients`는 1명, F/U 칸은 2회다(뺀 날은 날 수에 들지 않는다)
- AC-3703.9: Given 신환·재진, When 센 날의 환자를 나누면, Then 지금처럼 그 칸의 환자 표시(`visit`)로 나눈다
- AC-3703.10: Given 10만 줄, 묶음 50개(그중 빼는 처방·조건 있는 묶음 10개), When `aggregate`를 부르면, Then 1초 안에 끝난다(지금 시험과 같은 재기)

### REQ-3704: 묶음 열쇠에 빼는 처방·조건
- AC-3704.1: Given `groupKey(codes)`와 `groupKey(codes, { out: [], cond: [] })`, When 견주면, Then 같고 treatment-trend AC-1206.1의 고정 값 그대로다
- AC-3704.2: Given 같은 넣는 처방, When 빼는 처방이 있거나 조건이 있으면, Then 열쇠가 달라진다. 빼는 처방 차례·대소문자·겹침, 조건 항목 차례·`unless` 차례·대소문자는 열쇠를 바꾸지 않는다
- AC-3704.3: Given 조건 항목이 넣는 처방에 없는 코드이거나 `unless`가 빈 배열, When 열쇠를 만들면, Then 그 항목은 없는 것으로 본다
- AC-3704.4: Given 열쇠, When 모양을 보면, Then `t` + 소문자 16진수 16자리(`GROUP_KEY`)이고 고정 값 시험이 있다(빼는 처방 하나 든 묶음 하나, 조건 하나 든 묶음 하나)
- AC-3704.5: Given `groupDefs(groups)`, When 부르면, Then 처방 든 묶음마다 `{ id, codes }`를 내고, 빼는 처방이 있으면 `out`, 조건이 있으면 `cond`(열쇠와 같은 규칙으로 걸러 낸 항목)를 더 싣는다. 둘 다 없으면 지금 모양 그대로다
- AC-3704.6: Given `treatmentRows`, When 묶음의 빼는 처방·조건을 바꿈, Then 그 묶음은 다시 불러올 때까지 `다시 불러오면 보여요`다. 이름·차례만 바꾸면 바로 보인다(treatment-trend 결정 11 그대로)

### REQ-3706: 총환자와 총환자 대비 (숫자)
- AC-3706.1: Given 고른 기간의 저장된 일 줄, When `periodPatients(days, range)`를 부르면, Then 날마다 `totals.patients`를 더한 값과 `totals.patients` > 0인 날 수(진료한 날)를 돌려준다. 같은 날이 둘이면 뒤의 줄을 쓴다(`rowsIn` 규칙)
- AC-3706.2: Given 묶음 건수와 총환자, When 총환자 대비 글을 만들면, Then `rateText(건수, 총환자)`(소수 첫째 자리까지 버림, 총환자 0이면 `–`)다

## 범위 밖
- 처방 골라 보기·처방별 신환·재진·원장님 보고 문장·요일별 환자 수·대시보드는 바꾸지 않는다
- 증감(지난 기간보다)을 총환자 대비 %p로 견주는 것. 증감은 지금처럼 건수끼리다
- 묶음째 고르기를 '묶음과 이어 두기'(그 묶음을 고치면 따라 바뀜)로 하는 것. 그때의 처방을 복사만 한다
- 빼는 처방에 조건을 다는 것, 조건을 "같은 날 받아야 센다"(반대 뜻)로 하는 것
- 기본 PT 묶음을 미리 만들어 두거나 제안 다섯에 넣는 것
- 매출 탭 묶음(`rx_groups`)에 빼는 처방을 넣는 것
- 환자 명단 '장기 미방문'의 마지막 진료 묶음 거르기(`LapsedTool.tsx`·`workers/patients/handler.ts`)는 통계 묶음의 넣는 처방만 쓴다. 빼는 처방·조건은 거기에 쓰지 않는다
- 그래프 모양을 브라우저나 서버에 저장해 다음에 열 때 기억하는 것
- 저장된 옛 날의 숫자를 다시 계산하는 것(다시 불러와야 한다)
