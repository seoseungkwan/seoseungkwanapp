# 요구사항: 청구 메모 목록에 증상·처방내역(총투여량)을 한 줄씩

> 기능 ID: `memo-chart-lines` · 형식: 요구사항은 `### REQ-2601: 제목`, 수용 기준은 `- AC-2601.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.
> 사용자: "계획은 최소화, 검토는 마지막 한 번, 병렬로 할 수 있는 건 병렬로". 이름·글은 모두 지어낸 값이다.

## 배경 / 목표
- 2026-11-07 사용자: "우리 청구메모 이거 증상도 나오게 해줘, 내가 확인이 안 되네" · "증상이랑 처방내역 이것도 한 줄씩 보여주고 총투여량도 보여야 해" · 원래 쓰던 도구(증상·차트 원문 / 처방내역 칸) 사진을 보여 줌
- 지금 청구 화면 메모 목록(입력할 사람·빠지는 사람, `rows/MemoRows.tsx`)은 줄 머리에 `차트 N · 처방 a, b, c`(이름만, 쉼표로 이어 붙임)만 있다. 증상 글과 총투여량은 보이지 않아 메모가 맞는지 비트를 따로 열어 봐야 한다
- 자료는 이미 브라우저 Worker 안에 있다: 증상 줄(`Visit.lines`, 83 표), 처방 줄(`Visit.rx`의 코드·이름·급여·`qty`, 47 표). `qty`는 도우미가 47 표의 총투여량 칸(없으면 투여량 → 수량)에서 읽은 값이다(`helper GridRows.QuantityColumn`). 증상 줄 종류는 메모 분석이 이미 나눈다(`memo/engine.ts analyze`의 `k`)
- 도우미·확장·명령은 바꾸지 않는다. 새 도우미 배포가 없다

## 요구사항

### REQ-2601: Worker가 목록 줄에 증상 줄과 처방내역을 싣는다
- AC-2601.1: Given 증상 줄이 L1…Ln인 진료와 그 달 메모 분석, When 메모 화면 보기를 만들면, Then 그 사람의 목록 줄(`TargetRow`) `chartLines`는 L1…Ln을 같은 차례로 담고 줄마다 `kind`는 메모 분석이 본 종류(`subj`·`exam`·`dx`·`img`·`proc`·`rx`·`plan`)다. 글은 자르거나 고치지 않은 원문(`Visit.lines`)이다
- AC-2601.2: Given 처방 줄이 여럿인 진료(같은 이름 두 줄 포함), When 보기를 만들면, Then `rxRows`는 그 진료의 처방 줄을 하나도 빼거나 합치지 않고 담는다. 차례는 시술(코드 사전 `k`가 `proc`) → 약제(`drug`) → 기타이고, 같은 종류 안에서는 비트 47 표 차례다. 줄마다 `{ kind, code, name, short, qty, benefit }`이고 `short`는 코드 사전의 짧은 이름(없으면 빈 글)이다
- AC-2601.3: Given 총투여량을 읽지 못한 처방 줄(`qty: null`), When 보기를 만들면, Then 그 줄의 `qty`는 `null` 그대로다(0으로 바꾸지 않는다)

### REQ-2602: 줄을 열면 증상·처방내역이 한 줄씩 보인다
- AC-2602.1: Given 열린 줄(메모 보기), When 그리면, Then 우리 메모·비트 메모 칸 아래에 '증상 · 차트 원문 N줄' 칸이 있고 증상이 한 줄에 하나씩, 앞에 이름표(호소·검사·진단·영상·시술·처치·계획)와 함께 보인다. 종류가 없는 줄은 이름표 없이 글만 보인다
- AC-2602.2: Given 열린 줄, When 그리면, Then '처방내역 N줄 · 시술 M' 칸이 있고 처방이 한 줄에 하나씩 `종류(시술·약제·기타) · 코드 · 이름 짧은이름 · ×총투여량 · 급여/비급여`로 보인다. 총투여량을 모르면 `×?`다. 칸 아래에 '×숫자는 총투여량이에요.'가 있다. 처방이 없으면 '처방내역이 없어요.'다
- AC-2602.3: Given 열린 줄, When 그리면, Then 줄 머리 둘째 줄은 `차트 N`뿐이다(쉼표 처방 줄은 아래 처방내역으로 옮김). 닫힌 줄의 머리는 지금 그대로다
- AC-2602.4: Given 닫힌 줄(입력할 사람·빠지는 사람 모든 묶음), When 그리면, Then 증상·처방내역 칸은 없고 지금 보이던 칸(나란히 메모·확인 필요의 우리 메모)은 그대로다
- AC-2602.5: Given 닫힌 줄, When [메모 고치기]를 누르면, Then 고치는 칸이 열리면서 그 줄도 함께 열려 증상·처방내역이 보인다. 이미 열린 줄은 열린 채다

### REQ-2603: 보내는 것·울타리·지금 시험은 그대로
- AC-2603.1: Given 증상·처방내역이 실린 목록 줄, When [비트에 입력] 묶음과 저장을 보내면, Then `bit.input` 줄의 칸은 지금 칸(`visitKey`·`chart`·`name`·`date`·`memo`·`replaces`·`checkedByHand`)뿐이고 `chartLines`·`rxRows`나 증상·처방 글이 없다. `store.save`는 `month`·`drafts`·`done`뿐이다. 날짜별 건수 올리기도 지금 모양 그대로다
- AC-2603.2: Given `components/claim/rows/MemoRows.tsx`, When 고친 코드를 보면, Then 증상·처방은 props로만 받고 새 import가 없다. `src/guardrails.test.ts`와 `npm run lint`가 그대로 통과한다
- AC-2603.3: Given 지금 시험, When 이 기능 뒤에 돌리면, Then 기대값을 바꾸지 않고 통과한다. 목록 줄을 만드는 시험 자료에 새 칸(`chartLines`·`rxRows`)을 더하는 것만 허용한다
