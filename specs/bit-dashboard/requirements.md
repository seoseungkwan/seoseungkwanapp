# 요구사항: 비트 연결하면 대시보드 숫자 자동 채움

> 기능 ID: `bit-dashboard` · 형식: 요구사항은 `### REQ-601: 제목`, 수용 기준은 `- AC-601.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다. 번호를 600부터 쓰는 것은 다른 명세(stats-core·precheck REQ-001~, tab-frame 300번대, ui-90 400번대, stats 500번대)의 시험 이름과 섞이지 않게 하려는 것이다.

## 배경 / 목표
- 사용자 요청(2026-11-01): "비트 PC 연결 시작을 누르면 자동으로 나오게". 지금 대시보드 자료 자리(`dashboardSummarySource`)는 늘 '자료 없음'이라 연결해도 숫자가 안 나온다.
- 목표: 비트 PC에서 연결이 끝나면 대시보드가 비트에서 읽은 숫자로 저절로 채워진다. 다음부터는 대시보드를 열기만 해도 채워진다.
- 사용자 요청(2026-11-01): "오늘만 나오잖아 날짜 선택할 수 있게 해". 읽어 온 100일 안에서 날짜를 골라 그날 숫자를 본다.
- 사용자 결정(2026-11-01): "비트 읽는 부분은 통계 탭 것을 같이 써". 도우미의 `stats.rows`와 통계 Worker(`specs/stats` REQ-503·505)를 그대로 쓰고, 이 기능에서 도우미 SQL과 Worker 계산을 새로 만들지 않는다.
- 사용자 결정(2026-11-01): "항상 내원환자는 접수기준이야". 처방 줄이 없는 접수도 환자로 센다. 통계도 같은 기준으로 바꾼다. 세는 곳의 변경은 `specs/stats`에서 하고, 이 기능은 그 결과를 확인한다.
- 시안: `docs/mockups/bit-dashboard/` (2026-11-01 사용자 승인. 날짜 고르기는 사용자 요청으로 더했다).
- 환자 정보는 그 PC 밖으로 나가지 않는다. 대시보드가 자동으로 읽은 숫자는 서버로 보내지 않는다.

## 요구사항

### REQ-601: 대시보드가 저절로 채워진다
- AC-601.1: Given 연결·등록을 마친 비트 PC, When `/dashboard`를 열면, Then 아무것도 누르지 않아도 `stats.rows`(오늘 100일 전 ~ 오늘)를 통계 Worker로 읽고, 끝나면 연결 뒤 모양(보고 문장, 오늘 숫자, 기간별 흐름)을 Worker가 준 일 숫자로 그린다
- AC-601.2: Given 저장 숫자 없이 처음 읽는 중, When 그리면, Then 큰 문장 자리에 "비트에서 오늘 숫자를 읽고 있어요"와 "최근 100일 자료를 읽어요. 길면 3분쯤 걸려요. 다 읽을 때까지 이 화면을 열어 두세요."가 나오고, 오늘 하루 분석의 칩과 숫자 칸은 지어낸 값 없이 "읽는 중"이다. 기간별 흐름 자리에는 "읽기가 끝나면 생기는 것 4가지"가 나온다
- AC-601.3: Given 읽기 끝, When 그리면, Then 보고 문장 아래에 "오늘 오후 3:42에 읽었어요" 모양의 읽은 시각과 [다시 읽기]가 있다. 누르면 이전 숫자를 둔 채 다시 읽고, 그동안 단추는 "다시 읽는 중"으로 막힌다
- AC-601.4: Given 저장 숫자 없이 읽기 실패(`E-STATS-HISTORY`·`E-STATS-TOO-BIG`·`E-BIT-READ-FAILED`·등록 관련 번호 포함), When 그리면, Then 큰 문장 자리에 `lib/errors.ts` 문구·번호와 [다시 확인]·[연결 확인]이 나오고 숫자를 지어내지 않는다. 오늘 하루 분석의 칩은 "읽지 못함", 숫자 칸은 "읽지 못했어요"다
- AC-601.5: Given 숫자가 있는 상태에서 다시 읽기 실패, When 그리면, Then 이전 숫자와 읽은 시각을 그대로 두고 그 아래 오류 상자에 문구·번호, "아래 숫자는 오후 3:42에 읽은 그대로예요.", [다시 확인]·[연결 확인]을 보인다. 이때 [다시 읽기]는 없다
- AC-601.6: Given 확장 없는 곳(휴대폰·다른 PC), 또는 도우미 없음·버전 안 맞음·등록 안 됨, When `/dashboard`를 열면, Then `stats.rows`를 부르지 않는다. 저장 숫자가 없으면 지금의 연결 전 모양 그대로다
- AC-601.7: Given 다른 창이 통로를 쓰는 중(`busy`), When `/dashboard`를 열면, Then `E-BIT-IN-USE` 문구("다른 창이 비트 자료를 쓰고 있어요")·번호와 [다시 확인]이 나온다. 칩은 "기다리는 중", 숫자 칸은 "아직 못 읽었어요"다. 청구 화면의 `E-BRIDGE-BUSY` 문구는 그대로다
- AC-601.8: Given 읽기 성공·실패 어느 쪽이든, When 끝나면, Then 통로를 닫고 Worker를 끝낸다. 다른 창의 청구·통계 화면을 막지 않는다
- AC-601.9: Given 자동 읽기 전 과정, When 살펴보면, Then 서버로 가는 요청(`fetch`)이 하나도 없고, 화면 상태에 일 숫자 말고 진료 줄·보고 금액을 담지 않는다
- AC-601.10: Given 3분 안에 답이 끝나지 않을 때, When 기다리면, Then `E-BIT-READ-FAILED`로 끝내고 통로를 닫는다
- AC-601.11: Given 읽기는 성공했지만 일 숫자가 빈 배열, When 그리면, Then 연결 전 모양으로 돌아가지 않고 보고 문장 자리에 "오늘 받은 진료 자료가 아직 없어요", 숫자 칸에 "자료 없음"이 나온다
- AC-601.12: Given Worker 답의 품질이 `incomplete`(`days: null`), When 그리면, Then 숫자를 보여 주지 않고 `E-BIT-DATA-UNSURE` 문구·번호로 AC-601.4·AC-601.5처럼 그린다
- AC-601.13: Given 처음 자료로 받은 저장 숫자(`{ kind: 'data', days }`), When 비트 PC에서 열면, Then 그 숫자를 먼저 그리고 읽는 동안 그대로 둔 채 "다시 읽는 중"이다. 읽기가 끝나면 비트 숫자로 바꾸고, 실패하면 저장 숫자를 둔 채 AC-601.5의 오류 상자를 보인다. 비트 PC가 아니면 저장 숫자만 그린다
- AC-601.14: Given 통계의 저장 숫자 읽기(`specs/stats` REQ-516 `LiveDashboard`)가 합쳐진 뒤, When `/dashboard`를 열면, Then 그 파일이 읽은 값이 처음 자료로 `BitDashboard`에 간다. 저장 숫자를 읽는 코드를 두 벌 두지 않는다

### REQ-602: 내원환자는 접수 기준이다
- AC-602.1: Given 처방 줄이 없는 접수 환자가 든 가짜 도우미 답, When 통계 Worker를 거쳐 대시보드 숫자를 만들면, Then 그 환자가 그날 환자 수와 신환 또는 재진에 들어가고 처방 목록에는 빈 코드가 나오지 않는다
- AC-602.2: Given 같은 날 두 번 접수한 환자, When 숫자를 만들면, Then 그날 환자 수에 1명으로 센다

### REQ-603: 연결이 끝나면 대시보드로 돌아온다
- AC-603.1: Given 대시보드 연결 전 화면, When [비트 PC 연결 시작](위 단추·휴대폰 아래 단추)을 보면, Then 주소는 `/claim/setup?next=dashboard`다
- AC-603.2: Given `next=dashboard`로 연 비트 PC 연결 화면, When 5단계가 모두 됨이 되면, Then "5단계를 모두 마쳤어요. 대시보드로 돌아가요."를 1.5초 보인 뒤 누르지 않아도 `/dashboard`로 돌아간다
- AC-603.3: Given `next` 없이 또는 다른 값으로 연 비트 PC 연결 화면, When 5단계가 모두 됨이어도, Then 그 자리에 머문다(열린 리디렉트 금지. 받는 값은 `dashboard` 하나다)

### REQ-604: 새 도우미 버전
- AC-604.1: Given 이 기능의 도우미, When 버전을 보면, Then `Directory.Build.props`·`LATEST_HELPER`·`MIN_HELPER`가 모두 `0.2.0`이다
- AC-604.2: Given 옛 도우미(0.1.x)가 깔린 PC, When 웹이 hello하면, Then `update-helper`로 도우미 업데이트 안내가 나오고 `stats.rows`를 부르지 않는다
- AC-604.3: Given 도우미 업데이트 안내, When 보면, Then `E-HELPER-OLD`는 "대시보드 숫자와 청구 화면을 쓸 수 없어요"를 말하고, 오류 상자 안에 [새 도우미 내려받기] → zip을 풀어 `install.cmd` 실행 → [다시 확인] 순서가 있다

### REQ-605: 날짜를 골라 그날 숫자를 본다
- AC-605.1: Given 숫자를 읽은 대시보드(다시 읽는 중·다시 읽기 실패 포함), When 날짜 줄을 보면, Then [이전 날]·날짜 고르기 칸·[다음 날]이 있고 처음 고른 날은 오늘이다. 오늘이 아닐 때만 [오늘로]가 보인다
- AC-605.2: Given 지난 날짜를 고름, When 보고 문장을 그리면, Then "{M}월 {D}일 환자 N명이 왔습니다."로 시작하고 "오늘" 글자가 없다. 다음은 "신환 a명, 재진 b명입니다."이고, 7일 전 자료가 있으면 "지난주 X요일보다 …"가 붙는다. [복사]는 이 문장을 복사한다
- AC-605.3: Given 지난 날짜를 고름, When 숫자 줄을 그리면, Then 제목은 "{M}월 {D}일 하루 분석", 첫 칸 이름은 "환자 수"이고 넷째 칸은 그날과 7일 전을 견준 값이다. 7일 전 자료가 없으면 "지난주 자료가 없어요"다
- AC-605.4: Given 자료가 없는 지난 날짜(휴진일 등), When 그리면, Then "이 날은 진료 자료가 없어요" · "진료가 없었거나 비트에 접수 기록이 없는 날이에요."가 나오고 숫자 칸은 "자료 없음", [복사]는 막힌다
- AC-605.5: Given 고를 수 있는 범위, When 보면, Then 오늘부터 100일 전까지다. 오늘에서는 [다음 날], 100일 전에서는 [이전 날]이 막히고, 범위 밖 날짜를 넣으면 고른 날이 바뀌지 않는다
- AC-605.6: Given 날짜를 바꿈, When 살펴보면, Then `stats.rows`를 다시 부르지 않고 기간별 흐름은 그대로다. [다시 읽기] 뒤에도 고른 날이 유지되고, 대시보드를 새로 열면 오늘이다
- AC-605.7: Given 연결 전·저장 숫자 없이 처음 읽는 중·처음 읽기 실패, When 그리면, Then 날짜 줄은 지금처럼 오늘 글자뿐이고 날짜 고르기가 없다

## 범위 밖
- 도우미 SQL·`stats.rows` 답 모양·통계 Worker 계산의 변경. 접수 기준으로 세는 수정을 포함해 `specs/stats`에서 한다
- 자동으로 읽은 숫자의 서버 저장. 폰 숫자는 통계 탭에서 [비트에서 불러오기]로 저장한 시점까지다
- 저장 숫자 읽기(`specs/stats` REQ-516)와 통계 탭(`/stats`) 화면, 파일 끌어다 놓기 화면
- 100일보다 옛날 날짜 고르기, 기간별 흐름의 날짜 직접 지정
- 매출·접수 피크·장기 미방문 등 다른 항목. 1차 확인 뒤 사용자가 고른다
- 열어 둔 화면의 자동 새로 읽기(지금은 열 때 + [다시 읽기])
- 확장·도우미 설치 자동화. 웹사이트가 PC에 프로그램을 설치하는 길은 브라우저가 막는다. 처음 한 번의 설치 안내는 지금 화면 그대로 쓴다
