# 요구사항: 비트 연결하면 대시보드 숫자 자동 채움

> 기능 ID: `bit-dashboard` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 사용자 요청(2026-11-01): "비트 PC 연결 시작을 누르면 자동으로 나오게". 양지바른·메디코어 1.25.0 통계 대시보드가 비트를 읽던 방식을 참고한다.
- 지금은 도우미가 `hello`·`bit.check`·`bit.register`만 처리하고, 대시보드 자료 자리(`dashboardSummarySource`)는 늘 '자료 없음'이다. 그래서 연결해도 숫자가 안 나온다.
- 목표: 비트 PC에서 연결이 끝나면 대시보드가 비트에서 읽은 숫자로 저절로 채워진다. 다음부터는 대시보드를 열기만 해도 채워진다.
- 사용자 요청(2026-11-01): "오늘만 나오잖아 날짜 선택할 수 있게 해". 읽어 온 100일 안에서 날짜를 골라 그날 숫자를 본다.
- 시안: `docs/mockups/bit-dashboard/` (2026-11-01 사용자 승인. 날짜 고르기는 사용자 요청으로 더했다).
- 환자 정보는 그 PC 밖으로 나가지 않는다. 이 기능은 서버로 아무것도 보내지 않는다.

## 요구사항

### REQ-001: 도우미가 통계 줄을 읽는다 (`stats.rows`)
- AC-001.1: Given 등록된 병원과 기간, When `stats.rows {from, to}`, Then 도우미는 조각(`chunk … end`)으로 JSON `{from, to, visits, orders, names, skippedCodes}`를 보낸다. `visits`는 `[환자 번호, 내원일, 첫 내원일]`, `orders`는 `[환자 번호, 내원일, 처방코드]`, `names`는 그 기간에 나온 처방코드의 이름이다
- AC-001.2: Given `stats.rows` 답, When 내용을 보면, Then 환자 번호는 그 답 안에서만 쓰는 1부터의 숫자이고 차트번호 글자가 어디에도 없다. SQL은 이름·주소·전화·주민번호 칸을 읽지 않는다
- AC-001.3: Given 등록이 없거나 비트가 등록한 병원과 다를 때, When `stats.rows`, Then `E-BIT-NOT-REGISTERED`·`E-BIT-HOSPITAL-MISMATCH`로 끝나고 줄을 읽지 않는다. 비트 로그인 창과 PC 확인 창은 뜨지 않는다
- AC-001.4: Given 새 SQL 상수, When 시험하면, Then 모두 `Sql` 허용 목록에 있고 매개변수를 받는 SELECT이며 `original-sql/`의 사본과 공백만 다르다. 원본을 고친 곳은 사본 첫 줄에 적는다
- AC-001.5: Given 신환을 확정할 수 없는 비트(이관 자료 있음·차트번호 없는 내원·중복 내원·첫 내원을 못 찾은 환자·형식이 어긋난 날짜·첫 내원일이 내원일보다 늦음·실환자 수가 줄 수와 다름), When `stats.rows`, Then `E-BIT-DATA-UNSURE`만 보내고 조각을 보내지 않는다
- AC-001.6: Given 조회 기간 안에 등록 기관기호와 다른 기관기호가 있거나 기관기호가 없을 때, When `stats.rows`, Then `E-BIT-HOSPITAL-MISMATCH`만 보내고 조각을 보내지 않는다
- AC-001.7: Given 내원 줄과 처방 줄이 합쳐 30만 줄을 넘을 때, When `stats.rows`, Then `E-BIT-TOO-MANY`만 보내고 조각을 보내지 않는다
- AC-001.8: Given 어느 SQL이든 실패, When `stats.rows`, Then `E-BIT-READ-FAILED`만 보내고 조각을 보내지 않는다. 기록·오류에 값이 남지 않는다
- AC-001.9: Given 형식에 맞지 않는 처방코드 줄(원본 `ValidCode` 기준), When `stats.rows`, Then 그 줄은 처방에서 빼고 `skippedCodes`에 건수만 더한다. 내원 수는 그대로다

### REQ-002: Worker가 날짜별 숫자로 바꾼다
- AC-002.1: Given 조각과 `end {count, bytes, sha256}`, When 합치면, Then 순서·개수·바이트·해시가 모두 맞을 때만 계산한다. 하나라도 틀리면 `failed`(`E-ANALYZE-FAILED`)다
- AC-002.2: Given 내원은 있고 처방 줄이 없는 환자, When 계산하면, Then 그날 환자 수에는 들어가고 처방 목록에는 빈 코드가 나오지 않는다
- AC-002.3: Given 첫 내원일이 내원일과 같은 환자, When 계산하면, Then 그날 신환이고 아니면 재진이다(`unknown` 0). 오늘은 `partial: true`, 어제까지는 `partial: false`다
- AC-002.4: Given 모든 내원에 처방이 있는 같은 가짜 자료, When 파일 길(`parseBitFile` → `aggregate`)과 이 길로 각각 계산하면, Then 날짜별 `totals`·`rx`의 코드와 환자 수·`revisit`이 같다
- AC-002.5: Given 계산 끝, When Worker가 화면에 보내면, Then `validateDayPayload`를 통과한 `DayPayload[]`와 오류 번호뿐이다. 환자 번호와 줄이 없다
- AC-002.6: Given 모양이 어긋난 JSON이나 계산 중 예외, When 처리하면, Then 내용 없이 `E-ANALYZE-FAILED`만 보낸다
- AC-002.7: Given `names`에 없는 처방코드, When 계산하면, Then 이름 자리에 처방코드를 쓴다

### REQ-003: 대시보드가 저절로 채워진다
- AC-003.1: Given 연결·등록을 마친 비트 PC, When `/dashboard`를 열면, Then 아무것도 누르지 않아도 `stats.rows`(오늘 100일 전 ~ 오늘)를 부르고, 끝나면 연결 뒤 모양(보고 문장, 오늘 숫자, 기간별 흐름)을 그 숫자로 그린다
- AC-003.2: Given 처음 읽는 중, When 그리면, Then 큰 문장 자리에 "비트에서 오늘 숫자를 읽고 있어요"와 "최근 100일 자료를 읽어요. 길면 3분쯤 걸려요. 다 읽을 때까지 이 화면을 열어 두세요."가 나오고, 오늘 하루 분석의 칩과 숫자 칸은 지어낸 값 없이 "읽는 중"이다. 기간별 흐름 자리에는 "읽기가 끝나면 생기는 것 4가지"가 나온다
- AC-003.3: Given 읽기 끝, When 그리면, Then 보고 문장 아래에 "오늘 오후 3:42에 읽었어요" 모양의 읽은 시각과 [다시 읽기]가 있다. 누르면 이전 숫자를 둔 채 다시 읽고, 그동안 단추는 "다시 읽는 중"으로 막힌다
- AC-003.4: Given 읽기 실패(처음), When 그리면, Then 큰 문장 자리에 `lib/errors.ts` 문구·번호와 [다시 확인]·[연결 확인]이 나오고 숫자를 지어내지 않는다. 오늘 하루 분석의 칩은 "읽지 못함", 숫자 칸은 "읽지 못했어요"다
- AC-003.5: Given 숫자가 있는 상태에서 다시 읽기 실패, When 그리면, Then 이전 숫자와 읽은 시각을 그대로 두고 그 아래 오류 상자에 문구·번호, "아래 숫자는 오후 3:42에 읽은 그대로예요.", [다시 확인]·[연결 확인]을 보인다. 이때 [다시 읽기]는 없다
- AC-003.6: Given 확장 없는 곳(휴대폰·다른 PC), 또는 도우미 없음·버전 안 맞음·등록 안 됨, When `/dashboard`를 열면, Then 지금의 연결 전 모양 그대로이고 `stats.rows`를 부르지 않는다
- AC-003.7: Given 다른 창이 통로를 쓰는 중(`busy`), When `/dashboard`를 열면, Then `E-BIT-IN-USE` 문구("다른 창이 비트 자료를 쓰고 있어요")·번호와 [다시 확인]이 나온다. 칩은 "기다리는 중", 숫자 칸은 "아직 못 읽었어요"다. 청구 화면의 `E-BRIDGE-BUSY` 문구는 그대로다
- AC-003.8: Given 읽기 성공·실패 어느 쪽이든, When 끝나면, Then 통로를 닫고 Worker를 끝낸다. 다른 창의 청구 화면을 막지 않는다
- AC-003.9: Given 비트 읽기 전 과정, When 살펴보면, Then 서버로 가는 요청(`fetch`)이 하나도 없다
- AC-003.10: Given 3분 안에 답이 끝나지 않을 때, When 기다리면, Then `E-BIT-READ-FAILED`로 끝내고 통로를 닫는다
- AC-003.11: Given 읽기는 성공했지만 자료가 하나도 없음(`days` 빈 배열), When 그리면, Then 연결 전 모양으로 돌아가지 않고 보고 문장 자리에 "오늘 받은 진료 자료가 아직 없어요", 숫자 칸에 "자료 없음"이 나온다

### REQ-004: 연결이 끝나면 대시보드로 돌아온다
- AC-004.1: Given 대시보드 연결 전 화면, When [비트 PC 연결 시작](위 단추·휴대폰 아래 단추)을 보면, Then 주소는 `/claim/setup?next=dashboard`다
- AC-004.2: Given `next=dashboard`로 연 비트 PC 연결 화면, When 5단계가 모두 됨이 되면, Then "5단계를 모두 마쳤어요. 대시보드로 돌아가요."를 1.5초 보인 뒤 누르지 않아도 `/dashboard`로 돌아간다
- AC-004.3: Given `next` 없이 또는 다른 값으로 연 비트 PC 연결 화면, When 5단계가 모두 됨이어도, Then 그 자리에 머문다(열린 리디렉트 금지. 받는 값은 `dashboard` 하나다)

### REQ-005: 새 도우미 버전
- AC-005.1: Given 이 기능의 도우미, When 버전을 보면, Then `Directory.Build.props`·`LATEST_HELPER`·`MIN_HELPER`가 모두 `0.2.0`이다
- AC-005.2: Given 옛 도우미(0.1.x)가 깔린 PC, When 웹이 hello하면, Then `update-helper`로 도우미 업데이트 안내가 나오고 `stats.rows`를 부르지 않는다
- AC-005.3: Given 도우미 업데이트 안내, When 보면, Then `E-HELPER-OLD`는 "대시보드 숫자와 청구 화면을 쓸 수 없어요"를 말하고, 오류 상자 안에 [새 도우미 내려받기] → zip을 풀어 `install.cmd` 실행 → [다시 확인] 순서가 있다

### REQ-006: 날짜를 골라 그날 숫자를 본다
- AC-006.1: Given 숫자를 읽은 대시보드(다시 읽는 중·다시 읽기 실패 포함), When 날짜 줄을 보면, Then [이전 날]·날짜 고르기 칸·[다음 날]이 있고 처음 고른 날은 오늘이다. 오늘이 아닐 때만 [오늘로]가 보인다
- AC-006.2: Given 지난 날짜를 고름, When 보고 문장을 그리면, Then "{M}월 {D}일 환자 N명이 왔습니다."로 시작하고 "오늘" 글자가 없다. 다음은 "신환 a명, 재진 b명입니다."이고, 7일 전 자료가 있으면 "지난주 X요일보다 …"가 붙는다. [복사]는 이 문장을 복사한다
- AC-006.3: Given 지난 날짜를 고름, When 숫자 줄을 그리면, Then 제목은 "{M}월 {D}일 하루 분석", 첫 칸 이름은 "환자 수"이고 넷째 칸은 그날과 7일 전을 견준 값이다. 7일 전 자료가 없으면 "지난주 자료가 없어요"다
- AC-006.4: Given 자료가 없는 지난 날짜(휴진일 등), When 그리면, Then "이 날은 진료 자료가 없어요" · "진료가 없었거나 비트에 접수 기록이 없는 날이에요."가 나오고 숫자 칸은 "자료 없음", [복사]는 막힌다
- AC-006.5: Given 고를 수 있는 범위, When 보면, Then 오늘부터 100일 전까지다. 오늘에서는 [다음 날], 100일 전에서는 [이전 날]이 막히고, 범위 밖 날짜를 넣으면 고른 날이 바뀌지 않는다
- AC-006.6: Given 날짜를 바꿈, When 살펴보면, Then `stats.rows`를 다시 부르지 않고 기간별 흐름은 그대로다. [다시 읽기] 뒤에도 고른 날이 유지되고, 대시보드를 새로 열면 오늘이다
- AC-006.7: Given 연결 전·처음 읽는 중·처음 읽기 실패, When 그리면, Then 날짜 줄은 지금처럼 오늘 글자뿐이고 날짜 고르기가 없다

## 범위 밖
- 서버 저장(숫자 표·RLS). 그래서 집·휴대폰에서는 아직 숫자가 안 보이고 AI 리포트도 아직 자료가 없다. 사용자가 나중에 폰에서도 보기를 원하므로 다음 기능으로 한다
- 100일보다 옛날 날짜 고르기, 기간별 흐름의 날짜 직접 지정
- 매출·접수 피크·장기 미방문 등 다른 항목. 1차 확인 뒤 사용자가 고른다
- 통계 탭(`/stats`) 화면, 파일 끌어다 놓기 화면
- 열어 둔 화면의 자동 새로 읽기(지금은 열 때 + [다시 읽기])
- 확장·도우미 설치 자동화. 웹사이트가 PC에 프로그램을 설치하는 길은 브라우저가 막는다. 처음 한 번의 설치 안내는 지금 화면 그대로 쓴다
- 금액·소모량, 처방 추세, 일일 운영 숫자(`specs/precheck` REQ-027의 나머지). `specs/precheck`는 승인본이라 고치지 않는다. Phase 6을 할 때 이 기능의 `stats.rows` 위에 더하도록 그쪽 명세를 바꾼다
- 처방 유형(`rxType`) 칸. 대시보드가 쓰지 않아 비워 둔다
