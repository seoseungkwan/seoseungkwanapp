# 요구사항: 청구메모 설정 확장

> 기능 ID: `memo-settings` · 형식: `### REQ-n: 제목` + `- AC-n.m: Given/When/Then`. 시험 이름에 AC ID를 넣는다.
> 근거: `docs/handoff-memo-settings.md`(2026-11-08 인터뷰, 사용자 확정). 이 명세의 REQ-3002는 `specs/precheck` AC-014.10을 대신한다(그 파일은 승인을 지키려고 고치지 않는다).

## 배경 / 목표
- 시술이 2개 이상인 날 약이 늘 `[약 확인]`이 되고, IA 부위·아라간+트리암 날에 고장이 있다.
- 메모 엔진은 고정 코드 42개만 알고, 엔진이 쓰는 문구·표기 칸 상당수가 설정 화면에 없다.
- 비트에서 처방된 코드를 설정 화면에서 직접 정하고, 메모 줄 순서·표기·문구를 고치고, 저장 전에 시험·비교할 수 있게 한다.

## 정한 것 (Claude 판단, 사용자에게 알림)
- 처방코드 목록은 **통계에 저장된 날별 처방**(서버 `DayPayload.rx`: 코드·이름·종류)에서 모은다. 도우미 새 판이 필요 없다. 한 번도 처방되지 않은 비트 코드는 목록에 없다.
- `[코드 확인]`은 그날 메모에 시술 줄이 있을 때만, 급여 줄만 본다(약 규칙 AC-014.14와 같은 생각). 첫 정리를 쉽게 '새 코드 한꺼번에 제외' 단추를 둔다.
- 새 설정 칸은 원본 칸(TPL·CODEMAP)에 넣지 않고 따로 `memoRules`에 둔다(원본과 같은 검사 결과를 지키려고, `procedureDrugs`와 같은 방식).

## 요구사항

### REQ-3001: 메모 엔진 고장 2개
- AC-3001.1: Given 우리 병원 설정(`ourClinicPhrases()`)과 처방 KK090×1·A21, When 차트가 `Rt ankle IA triam` · `Lt hip IA triam` · `Rt elbow 관절강내 주사 triam` · `Rt wrist IA triam`인 진료의 메모를 만들면, Then IA 줄이 `◈IA injection of - ankle(triam)`처럼 그 부위 영어 이름을 쓰고 `[부위 확인]`이 없다. 무릎·어깨 IA는 지금과 같다(골든)
- AC-3001.2: Given 차트 `Rt knee 아라간 2차` / `Lt knee IA triam`, 처방 KK090×2·A49·A21, When 메모를 만들면, Then 연골주사 줄(`◈우측 슬관절 강내 연골주사 2회차`)과 트리암이 든 일반 IA 줄(`◈IA injection of - knee(triam)`)이 함께 있다
- AC-3001.3: Given 연골주사 날에 넣기인 일반 약(트리암·덱사)이 있는데 차트에 아라간이 아닌 IA 줄이 없음, When 메모를 만들면, Then `[약 확인: 트리암]`을 남긴다. 넣기인 약이 표시 없이 사라지는 날은 없다

### REQ-3002: 시술 2개 이상인 날의 약 (AC-014.10을 대신함)
- AC-3002.1: Given 시술 종류가 2개 이상이고 그 약이 '넣기'인 시술이 딱 하나이며 나머지 시술은 모두 '빼기', When 메모를 만들면, Then 그 약을 그 시술 줄의 고른 자리(시술 뒤·끝맺음 뒤·따로 한 줄)에 넣고 `[약 확인]`이 없다. 예: 처방 KK090·LA358·A21, 차트 `MBB L4,5 both` / `Rt knee IA triam` → IA 줄 `…knee(triam)`, MBB 줄에는 약이 없다
- AC-3002.2: Given '넣기'인 시술이 2곳 이상이거나 정하지 않은 시술이 하나라도 있음, When 메모를 만들면, Then 지금처럼 `[약 확인: 약 이름]`이다. 모두 '빼기'면 뺀다
- AC-3002.3: Given 넣기 시술이 하나인데 그 시술 줄이 메모에 없음(예: 무릎 세트 날 IA 줄 생략), When 메모를 만들면, Then `[약 확인: 약 이름]`을 남긴다
- AC-3002.4: Given 연골주사약이 KK090에서만 넣기이고 다른 시술은 빼기, When 시술 2개 이상인 날의 메모를 만들면, Then 연골주사 줄을 쓴다(원본과 같음)
- AC-3002.5: Given 설정 `memoRules.singleOwnerDrug`가 `false`, When 메모를 만들면, Then 옛 규칙(AC-014.10) 그대로다. 칸이 없으면 켜진 것이다
- AC-3002.6: Given 설정 화면 '시술별 약', When 열면, Then 안내 글이 새 규칙을 말하고 켜고 끄는 칸이 있다

### REQ-3003: 고르는 칸 두 개 (처음 값 = 지금 동작)
- AC-3003.1: Given `memoRules.iaSide`가 없거나 거짓, When IA·건초내주사 줄을 만들면, Then 지금과 같다(좌우 없음, 골든). 참이면 `◈IA injection of - Rt knee(triam)`·`◈Rt thumb 건초내주사 시행(triam)`처럼 차트 좌우를 부위 앞에 쓴다
- AC-3003.2: Given 무릎 세트 날(LA274·LA272 + KK090, `kneeSetSkipIa` 켬)에 IA 넣기 약이 있음, When `memoRules.kneeSetIaWithDrug`가 없거나 거짓이면, Then 지금과 같다(IA 줄 생략, `[약 확인]`). 참이면 IA 줄을 그 약과 함께 쓴다. 약이 없으면 참이어도 생략한다

### REQ-3004: 처방코드 사전과 `[코드 확인]`
- AC-3004.1: Given 그날 메모에 시술 줄이 있고 급여 처방 중 사전(CODEMAP)에 없고 지운 코드(CODEMAP_DEL)도 아닌 코드가 있음, When 메모를 만들면, Then 그 코드마다 한 번 `[코드 확인: 처방 이름]`을 확인 표시 자리(`[약 확인]` 옆)에 남기고 `unfinished`가 참이다. 시술 줄이 없는 날·비급여 줄·사전에 있는 코드는 표시가 없다
- AC-3004.2: Given 통계 날별 처방(`DayPayload.rx`)과 오늘, When 코드 목록을 만들면, Then 최근 3개월(오늘 포함 92일)에 처방된 코드와 사전에 있는 코드만 보이고 '전체 보기'면 읽은 전체 기간의 코드가 나온다. 줄마다 코드·비트 이름·종류·마지막 처방일·'새 코드'(사전에도 지운 목록에도 없음) 표시가 있고, 새 코드가 먼저, 다음은 코드 순이다
- AC-3004.3: Given 설정 '처방코드' 묶음, When 코드 하나를 고치면, Then 메모 이름(n)·구분(시술 proc·약 drug·문구 note·검사 lab·제외 skip)·코드별 메모 문구(memo)·부위(자동 null 또는 12개 부위)·줄 순서를 정할 수 있고 저장하면 `CODEMAP[코드]`와 `memoRules.order`에 들어간다. 찾기 칸은 코드·이름으로 거른다
- AC-3004.4: Given 새 코드가 보이는 목록, When '새 코드 모두 제외'를 누르면, Then 보이는 새 코드가 모두 `{n: 비트 이름, k: 'skip', rg: null}`로 초안에 들어간다(저장 전까지 메모는 그대로)
- AC-3004.5: Given 통계를 못 읽음, When 처방코드 묶음을 열면, Then 사전의 코드만 보이고 '통계를 읽지 못했어요 · 다시 읽기' 안내가 있다

### REQ-3005: 메모 줄 순서
- AC-3005.1: Given `memoRules.order`가 없음, When 메모를 만들면, Then 지금과 같다(차트 순서, 골든)
- AC-3005.2: Given 순서 번호가 있는 코드(예: KK090=1), When 그 코드의 줄이 있는 메모를 만들면, Then 번호가 있는 코드의 줄이 번호 작은 차례로 먼저 오고, 번호 없는 줄은 그 뒤에 원래 차례로 온다. 확인 표시·사유 문장은 늘 맨 끝이다

### REQ-3006: 설정 값 모양과 검사
- AC-3006.1: Given `memoRules`(`singleOwnerDrug`·`iaSide`·`kneeSetIaWithDrug` 참거짓, `order` 코드→1~999 정수), When `validatePhrases`, Then 맞으면 지나고 틀리면 `memoRules.…` 경로로 오류를 낸다. `memoRules`가 없어도 지난다. 원본 칸 검사 결과는 그대로다(골든 phrases-engine)
- AC-3006.2: Given 두 설정 값, When `diffPhrases`, Then `memoRules` 칸과 코드 칸(`CODEMAP.<코드>.<칸>`)도 쉬운 이름표로 전·후를 낸다

### REQ-3007: 설정 화면
- AC-3007.1: Given 병원 문구 칸, When 열면, Then 묶음 단추 [기본 · 시술별 문구와 약 · 처방코드 · 표기 규칙 · 사유 문장 · 메모 시험]으로 나뉘고 저장 단추는 묶음과 상관없이 아래에 하나다
- AC-3007.2: Given '표기 규칙' 묶음, When 고치면, Then 좌우 기본 표기(sideMode)·앞 좌우 적용(sideSpread)·코드별 좌우(sideByCode)·부위 영어 표기 12칸(siteNames)·표기 바꾸기(rename)·경추 CPB 따로(splitCpb)·요추 SNB 따로(splitSnb)·시술 줄 나누기(splitEach)·무릎 세트 IA 생략(kneeSetSkipIa)·IA·건초내주사 좌우 넣기(iaSide)·무릎 세트 약 있으면 IA 줄 쓰기(kneeSetIaWithDrug)를 고칠 수 있다
- AC-3007.3: Given '시술별 문구와 약' 묶음, When 고치면, Then 지금 칸에 더해 시술 이름별 문구(byProc: 이름 더하기·지우기)·부위별 문구(byRegion 12칸)·고정 멘트(fixedPhrases: 단추 이름·글·켜기, 30개까지)를 고칠 수 있다
- AC-3007.4: Given '메모 시험' 묶음, When 차트 글(여러 줄)과 처방(`코드 수량` 한 줄에 하나, 수량 없으면 1)을 넣고 [메모 만들기]를 누르면, Then 지금 초안 설정으로 만든 메모가 보인다. 처음 값은 지금의 가짜 진료(`LBP` / `MBB L4,5 both`, `LA358 2`)다. 이 글은 저장하지 않는다
- AC-3007.5: Given 고친 칸이 있음, When [저장]을 누르면, Then 바로 쓰지 않고 바뀐 칸의 이름·전·후 표를 보여 주고 [이대로 저장]을 눌러야 저장한다. 바뀐 칸이 없으면 '바뀐 것이 없어요'다
- AC-3007.6: Given 저장, When 그사이 다른 PC가 다른 칸을 고쳤음, Then 내가 고친 칸(TPL·시술별 약·코드·지운 코드·memoRules)만 얹어 남의 값을 덮지 않는다(지금 `withPhraseChanges`와 같은 생각)

### REQ-3008: 문구 칸의 {항목} 넣기와 순서 바꾸기 (2026-11-08 사용자 "{ㅇㅇ} 이거 순서도 내가 정할 수 있게해", "{}이거 내가 커스텀해서 넣을 수 있는거", "메디코어에 그런기능 있을거야")
- 메디코어 참고: 고정 멘트 편집 `renderFixedPhrases`(mx999_v22 11422줄), 칸마다 '자동 채움 넣기' 단추 `tokenRow`(10940줄, 커서 자리에 넣음)
- AC-3008.1: Given 틀 글을 쓰는 문구 칸(시술 문구·시술 이름별·부위별·사유·코드별 메모 문구), When 열면, Then 칸 아래에 '자동 채움 넣기' 단추로 그 칸에서 쓸 수 있는 {항목}과 병원이 만든 고정 멘트 {단추 이름}이 보이고, 누르면 글쓰기 표시가 있는 자리(없으면 글 끝)에 넣는다. 단추 목록은 `validatePhrases`가 그 칸에 허용하는 항목과 같다(`allowedTokens(경로, 설정)`). 고정 멘트를 더하거나 이름을 바꾸면 모든 칸의 단추가 바로 바뀐다
- AC-3008.2: Given 칸 글이 조각(낱말·{항목})으로 보임, When {항목} 조각의 ◀·▶를 누르면, Then 그 항목이 바로 앞·뒤 조각(빈칸 말고)과 자리를 바꾸고 빈칸은 제자리에 둔다. 예: `IA injection of - {부위}{약제}`에서 {약제} ◀ → `IA injection of - {약제}{부위}`. ×를 누르면 그 항목만 지운다. 맨 앞·맨 뒤에서는 그쪽 단추가 꺼진다
- AC-3008.3: Given 칸 글, When 고치면, Then 칸 아래에 보기 값(좌우 Rt · 부위 knee · 약제 (triam) · 시술 MBB L4,5 · 회차 2 · 레벨 4,5)으로 채운 한 줄이 바로 보인다(엔진 `fill`)

## 범위 밖
- 설정 이력, 설정 파일 주고받기(사용자가 고르지 않음)
- 비트에서 한 번도 처방되지 않은 코드 불러오기(도우미 새 명령·새 판이 필요)

- 도우미·확장·DB 마이그레이션 변경
