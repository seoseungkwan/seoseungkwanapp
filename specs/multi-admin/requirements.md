# 요구사항: 관리자 여럿 — 가입 승인 화면에서 관리자 정하기·빼기 · 주 관리자 · 관리자만 보는 탭

> 기능 ID: `multi-admin` · 형식: `### REQ-7701: 제목` 아래 `- AC-7701.1: Given/When/Then`. 시험 이름에 AC ID를 넣는다.
> 번호: REQ-7701~7707(77xx는 저장소 모든 갈래의 specs에서 안 쓴 묶음, 2026-11-22 git grep으로 확인).
> **MVP 모드**(사용자 규칙: 계획 최소 · Phase별 · 같은 Phase는 병렬 · 검토는 마지막 한 번). SQL 파일 하나(새 공용 표 `tab_access` 하나 · `admins` 칸 `is_owner` 하나 · DB 함수 셋) · 서버 읽기 하나(인증 예외 넓힘, ADR-042) · 새 패키지 없음 · 도우미·확장 새 판 없음.
> **시안**(둘 다 2026-11-22 사용자 승인 "이대로 만들기", 커밋 e9c87ca3, PC 1440·1024만): `docs/mockups/multi-admin/index.html`(가입 승인, 상태 `?s=list|other|add|remove|done|removed|error`) · `docs/mockups/multi-admin/settings.html`(설정 새 칸, 상태 `?s=owner|saved|error`) · `notes.md`. 화면 글자는 2026-11-22 공통 안내의 글을 한 글자도 바꾸지 않고 옮긴 아래 '화면 글자'(시안 `notes.md` '쓴 화면 글자'와 같음)다. 자리·모양은 시안 `notes.md` '모양 결정'·'칸 폭'·'설정 새 칸'이 기준이고, 명세와 시안이 다르면 시안이 이긴다.

## 배경 / 목표
- 지금은 가입 승인(`/admin`)을 운영자 한 사람만 한다. `admins` 표는 SQL 편집기로만 넣는다(`supabase/first-admin.sql`).
- 관리자가 가입 승인 화면 '승인' 탭에서 다른 원장 계정을 관리자로 정하거나 뺄 수 있게 한다. 정한 사람은 지금 관리자와 같은 일을 한다.
- (추가 요청) 원장님(운영자) 계정을 **주 관리자**로 표시해 아무도 빼지 못하게 하고, 주 관리자가 설정에서 고른 탭은 관리자 계정에만 보이게 한다. 사용자: "관리자 계정만 볼 수 있는 탭 목록을 만들고, 지금 있는 탭도 몇 개는 관리자만 보게. 그 목록은 나만 정하게."

## 이미 정한 것 (사용자 2026-11-22, 다시 묻지 않는다)
1. 새 관리자 = 이미 가입해 **승인된 병원**(`hospitals.status = 'approved'`)의 **주인**(`owner_id`) 계정. 승인만 하는 따로 계정·데스크 계정은 아니다. 문지기(`lib/auth/gate.ts`)는 바꾸지 않는다.
2. 고르는 곳: `/admin`의 '승인' 탭 줄마다 단추.
3. 정하기·빼기는 관리자 누구나 한다.
4. 권한은 지금 관리자와 똑같다. `admins` 표에 그 사람 줄을 넣는다(역할 칸을 만들지 않는다) → 가입 승인·거절·되돌리기, 설치 파일 올리기, 고시 모으기 기록 보기가 저절로 따라온다.
5. 자기 자신은 빼지 못한다(내 줄에는 단추가 없다) → 관리자가 0명이 되지 않는다. DB 함수도 자기 자신을 바꾸려 하면 거부한다(Claude 기본값, 사용자에게 알림).
6. PC 화면만. 폰 전용 모양(`max-md:` 새 줄)을 새로 만들지 않는다. 시안 사진도 1440·1024만.
7. (추가) **주 관리자** = 원장님(운영자) 계정 하나. DB에 표시한다(`admins.is_owner`, 참인 줄은 하나만). 마이그레이션이 지금 운영자 계정을 주 관리자로 정한다 — `first-admin.sql`처럼 "구글 계정 · 이메일 앞부분에 `e2e-` 없음 · `admins`에 있음"이 정확히 하나일 때만, 아니면 아무것도 안 바꾸고 알기 쉬운 오류로 멈춘다(두 번 돌려도 같음).
8. (추가) 주 관리자는 **아무도 관리자에서 못 뺀다**(`set_admin`이 거부, 화면에 단추 없음).
9. (추가) **관리자만 보는 탭**: 탭마다 '관리자만' 켜고 끄기. 켜진 탭은 관리자가 아닌 원장 계정(다른 병원 포함)·데스크 계정에서 메뉴(탭 띠·[더보기])에서 사라지고, 주소로 들어와도 말 없이 `/dashboard`로 돌려보낸다. 관리자에게는 그대로 보인다. 자료 권한(RLS)은 바꾸지 않는다(보이기 문제, ADR-042).
10. (추가) 목록은 설정 탭(`/settings`) 안 새 칸에서 정한다. 그 칸은 **주 관리자에게만** 보인다. 고치기도 DB 함수가 주 관리자만 허락한다(42501).
11. (추가) **앞으로 새로 만드는 탭은 처음엔 관리자만**: DB에 줄이 없는 탭 = 관리자만. 마이그레이션이 지금 있는 탭(12개)을 모두 '모두에게'로 넣어 둔다(지금 보이는 그대로 — 시안에서 켜져 있는 AI 리포트·직원·재고는 보기용 예시). 표는 병원과 상관없는 공용 표 하나(ADR-037 같은 예외), 로그인한 사람 모두 읽기, 쓰기는 함수로만.
12. (추가) 목록에 넣지 않는 탭(늘 보임): 대시보드·설정. 가입 승인(`/admin`)은 원래 관리자만이라 목록 밖.
13. (시안이 공통 안내보다 앞섬, 사용자 승인) 켜고 끄기 모양 = 지금 설정 화면의 체크 상자 `ds.checkbox`(설정 화면에 미끄럼 스위치는 없다). 저장 = 상병 연결표(`DxLinks`)와 같은 방식. 실패 번호 = 지금의 `E-SETTINGS-FAILED`(새 번호 `E-TAB-ACCESS`는 만들지 않는다). 칸 자리 = 설정 맨 아래(데스크 계정 다음). 탭 목록 = `menu.ts` `MENU` 차례에서 대시보드·설정을 뺀 12개.

## 화면 글자 (`{ }`는 바뀌는 값, `[ ]`는 단추)
- 화면 위 안내(INTRO) 전체(지금 두 문장 끝에 한 문장을 더함): `승인하면 그 계정은 바로 대시보드를 쓸 수 있어요. 거절한 신청은 거절 탭에서 되돌릴 수 있어요. 승인 탭에서 관리자를 정하거나 뺄 수 있어요.`
- '승인' 탭 줄
  - 관리자인 줄(내 줄 포함): 의원 이름 옆 작은 표 `관리자`. 주 관리자 줄은 그 대신 `주 관리자`
  - 관리자가 아닌 줄의 동작 칸: [`관리자로 정하기`]
  - 다른 관리자 줄의 동작 칸: [`관리자 빼기`]
  - 주 관리자 줄의 동작 칸: 비움(아무도 뺄 수 없다)
  - 내 줄(내가 주인인 병원)의 동작 칸: 단추 없이 흐린 글자 `내 계정`(주 관리자 자신이 볼 때 자기 줄도 이것)
- 정하기 확인 창: 제목 `이 계정을 관리자로 정할까요?` · 신청 내용 칸(의원 이름 / `{신청자} · {이메일}`, 거절 창과 같음) · 본문 `관리자는 가입 승인·거절, 설치 파일 올리기, 관리자 정하기·빼기를 할 수 있어요.` · [`취소`] [`관리자로 정하기`]
- 빼기 확인 창: 제목 `관리자에서 뺄까요?` · 신청 내용 칸(같음) · 본문 `빼도 이 계정은 지금처럼 대시보드를 써요. 가입 승인 화면만 열 수 없어요.` · [`취소`] [`빼기`]
- 끝 알림(지금 완료 줄 자리·모양 그대로): `{의원 이름} 계정을 관리자로 정했어요.` / `{의원 이름} 계정을 관리자에서 뺐어요.`
- 실패 카드(지금 상태 바꾸기 실패 카드와 같은 자리·모양, `ErrorCard`): 번호 `E-ADMIN-ROLE` · 무엇이 `관리자를 정하거나 빼지 못했어요` · 어떻게 고치나 `인터넷 연결을 확인하고 다시 눌러 주세요. 계속되면 오류 번호와 함께 문의해 주세요.` (번호만 공통 안내에 있고 글은 시안 `notes.md`가 정함)
- 설정 새 칸(주 관리자에게만)
  - 제목 `관리자만 보는 탭`
  - 설명 `켜 둔 탭은 관리자 계정에만 보여요. 다른 원장 계정과 데스크 계정에서는 메뉴에서 사라지고, 주소로 들어와도 대시보드로 돌아가요. 새로 생긴 탭은 처음에 켜져 있어요.`
  - 줄마다 체크 상자 + 탭 이름, 12줄 이 차례: `통계` · `청구` · `고시·공지` · `환자` · `업무일지` · `수납일지` · `예약` · `AI 리포트` · `서식` · `직원` · `재고` · `주소록` (글자는 `menu.ts`의 탭 이름 그대로)
  - [`저장`] — 실패한 뒤에는 [`다시 저장`] · 저장 알림 `저장했어요.` · 실패 카드 `E-SETTINGS-FAILED`(지금 글 그대로: `설정을 불러오거나 저장하지 못했어요` / `저장하던 중이었다면 고친 값은 화면에 그대로 있어요. 인터넷 연결을 확인하고 단추를 다시 눌러 주세요. 계속되면 오류 번호와 함께 문의해 주세요.`)
  - 목록 읽기 실패: 같은 카드 + [`다시 불러오기`](다른 설정 칸과 같은 글자)
- 막힌 주소로 들어오면: 글 없음(말 없이 `/dashboard`로)

## 요구사항

### REQ-7701: 관리자 DB 함수 둘 (`supabase/migrations/20261122000000_multi_admin.sql`)
- AC-7701.1: Given 앞 migration `20261028000000_auth.sql` 다음에 이 파일을 두 번 돌림, When 끝나면, Then 오류가 없고 `public.set_admin(p_hospital_id uuid, p_admin boolean) returns void`와 `public.admin_hospitals() returns table (hospital_id uuid, is_me boolean, is_owner boolean)`이 plpgsql·`security definer`·`set search_path = ''`로 있다. 두 함수 모두 `public`·`anon`은 실행할 수 없고 `authenticated`만 실행한다. `admins` 정책은 '내 관리자 줄 읽기' 하나, `authenticated`의 `admins` 표 권한은 `select` 하나 그대로이고, 어느 사용자도 `admins`에서 남의 줄을 읽거나 넣거나 고치거나 지울 수 없다. `hospitals` 표·정책·권한은 그대로다
- AC-7701.2: Given 주 관리자 A(승인된 병원 HA의 주인)·승인된 병원 HB의 주인 B(관리자 아님)·승인된 병원 HD의 주인 D(관리자)·대기 병원 HC·거절 병원 HR(주인이 관리자여도)·병원 줄 없는 관리자 E, When A가 `admin_hospitals()`를 부르면, Then 주인이 관리자인 승인된 병원만 `(HA, true, true)`·`(HD, false, false)` 두 줄이다(D가 부르면 `(HA, false, true)`·`(HD, true, false)`). 관리자가 아닌 사용자(B·대기 병원 주인·병원 줄 없는 사용자)가 부르면 42501, anon은 권한 오류(42501)다
- AC-7701.3: Given 관리자 A, When `set_admin(HB, true)`를 부르면, Then `admins`에 B 줄(`is_owner` 거짓)이 생기고, 한 번 더 불러도 오류 없이 한 줄이다. `set_admin(HB, false)`면 B 줄이 없어지고, 한 번 더 불러도(이미 없음) 오류가 없다. 어느 경우에도 `hospitals` 줄(상태·검토 날짜)과 다른 사람의 `admins` 줄은 그대로다
- AC-7701.4: Given 거부할 부르기, When `set_admin`을 부르면, Then 오류이고 `admins`는 그대로다: 관리자가 아닌 사용자(승인된 원장·대기 병원 주인·병원 줄 없는 사용자) → 42501(인자가 틀려도 이것이 먼저), anon → 권한 오류(42501), 관리자가 자기 병원으로 `true`·`false`(A의 HA, D의 HD) → 22023, 다른 관리자 D가 주 관리자 병원 HA로 `true`·`false` → 22023, 대기·거절 병원·없는 병원 id·`null` 병원 id·`null` 참거짓 → 22023
- AC-7701.5: Given A가 B를 관리자로 정함, When B로 들어가면, Then B는 모든 병원 줄을 읽고, `set_hospital_status`로 대기 줄을 승인하고, `admin_hospitals()`와 다른 병원으로 `set_admin`을 부를 수 있다(자기 병원 HB와 주 관리자 병원 HA는 22023). 그 뒤 A가 B를 빼면 B는 다시 내 병원 줄만 읽고 `set_hospital_status`·`admin_hospitals`·`set_admin`이 42501이다. 이 읽기·부르기 어디에서도 무한 되부름 오류(42P17)가 나지 않는다

### REQ-7702: 관리자 브라우저 함수 (`src/lib/auth/admin.ts`) · 오류 번호
- AC-7702.1: Given 가짜 Supabase, When `listAdminHospitals()`를 부르면, Then `rpc('admin_hospitals')`를 인자 없이 한 번만 부르고, 답 줄마다 `{ hospitalId, mine, owner }`(`hospital_id` 글자, `is_me`·`is_owner` 참거짓)를 받은 차례로 돌려준다. 답이 오류이거나, 목록이 아니거나, 줄 모양이 하나라도 틀리거나, 부르기·클라이언트 만들기가 던지면 `AdminError`이고 메시지에 원래 오류 글이 없다(원래 오류는 `cause`에만)
- AC-7702.2: Given 가짜 Supabase, When `setAdmin(id, true)`·`setAdmin(id, false)`를 부르면, Then 각각 `rpc('set_admin', { p_hospital_id: id, p_admin: true|false })`만 한 번 부르고 표(`from`)를 쓰지 않는다. 오류·던짐이면 `AdminError`(원래 글은 `cause`에만)이고 저절로 다시 부르지 않는다. `listApplications`·`setHospitalStatus`는 그대로다
- AC-7702.3: Given 오류 번호 표, When `errorInfo('E-ADMIN-ROLE')`를 부르면, Then what `관리자를 정하거나 빼지 못했어요`, fix `인터넷 연결을 확인하고 다시 눌러 주세요. 계속되면 오류 번호와 함께 문의해 주세요.`이고 `ErrorCode`에 든다. 다른 번호와 그 글은 그대로다

### REQ-7703: '승인' 탭 줄 (`/admin` 가입 승인 화면)
