# 요구사항: 통계 처방 골라 보기

> 기능 ID: `rx-picker` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 사용자 요청: "내가 처방코드 골라서 그 처방 얼마나 나왔는지 볼 수 있게 하자, 신환률이랑 재진률도". 많이 나온 차례 몇 개만 보여 주는 목록은 사용자가 뺐다
- 지금 통계 탭은 많이 낸 처방 5가지(처방 추세)와 비트로 불러온 뒤에만 보이는 표(처방별 신환·재진)뿐이다. 내가 보고 싶은 처방을 골라 볼 길이 없다
- 통계 탭에 새 칸 **처방 골라 보기**를 더한다. 저장된 날 숫자로 돌아가서 휴대폰에서도 된다. 도우미·확장은 바꾸지 않는다
- 승인 시안: `docs/mockups/rx-picker/index.html`(claude.ai artifact `KPKHAx1vzx19Pjox4XcYxx`와 같은 파일, 2026-11-03 사용자 "처방고르기 좋아"). 시안의 숫자는 지어낸 것이다. 시안 끝 '제가 정한 부분'도 모두 지킨다. 앱 규칙 때문에 다르게 정한 곳은 `design.md` '시안과 다른 곳'에 있다

## 이미 정한 것 (다시 묻지 않는다)
1. 비율의 밑수는 건수다. 신환율 = 신환 ÷ 건수, 재진율 = 재진 ÷ 건수. 뜻을 표 가까이에 적는다. 근거: 2026-11-03 사용자가 시안을 승인했고 건수 기준을 안내받았으며 이의를 말하지 않았다. plan.md·PRD의 처방별 비율 줄과 다르므로 이 칸에 한정한 줄을 두 문서에 더한다(REQ-815)
2. `30 초진`은 재진으로 센다(REQ-813, 따로 뺄 수 있는 TASK). `진찰료산정안함`은 구분 없음 그대로다. 이미 저장한 날은 그 파일을 다시 넣어야 바뀐다
3. 고른 처방은 계정에 저장해 휴대폰과 컴퓨터에서 같이 본다. 환자 자료 구역에는 브라우저 저장소를 쓰지 않고, 이 기능은 어디에도 브라우저 저장소를 쓰지 않는다
4. 웹만 고친다. 도우미·확장·`MIN_HELPER`·윈도우 빌드는 그대로다

## 요구사항

### REQ-801: 통계 탭의 새 칸
- AC-801.1: Given 저장된 숫자가 있는 통계 화면, When 섹션을 그리면, Then 차례는 기간 요약 → 환자 수 추이 → 신환 재방문율 → 처방 추세 → 처방별 신환·재진 → 처방 골라 보기 → 원장님 보고 문장 → 요일별 환자 수이고, 새 칸은 h2 `처방 골라 보기`, 옆 설명 `고른 처방만 건수와 신환율·재진율을 봐요`, 전체 폭(`col-span-12`)이다. 다른 일곱 칸의 배치 클래스는 그대로다(specs/stats AC-513.1의 차례를 이 AC가 대신한다)
- AC-801.2: Given 읽는 중, When 기다리는 칸을 그리면, Then 여덟 칸 모두 "불러오는 중"이고 새 칸의 차례·자리(`col-span-12`)가 AC-801.1과 같다(specs/stats AC-514.1·514.10의 일곱 칸을 이 AC가 대신한다)
- AC-801.3: Given 저장된 숫자가 하나도 없음(`saved` false), When 새 칸을 그리면, Then `자료 없음 · 불러오면 처방을 골라 볼 수 있어요.` 한 줄만 있고 찾기 칸·칩·표가 없다
- AC-801.4: Given 시안에서만 쓰는 것(`새 칸` 칩, `시안에서만 보이는 줄`, `제가 정한 부분`, `예시` 표시), When 실제 화면을 그리면, Then 어느 것도 없다

### REQ-802: 처방 찾기 칸
- AC-802.1: Given 새 칸, When 그리면, Then 칸 이름 `처방 찾기`, 안내 글 `이름이나 코드를 적어 주세요`, 아래 도움말 `불러온 숫자에 있는 처방만 찾아요. 고른 처방은 다음에도 남아요.`가 있고 `ds.input`을 쓰며 넓은 화면에서 폭은 480px까지다
- AC-802.2: Given 글자를 적지 않음, When 칸을 누르거나 초점이 오면, Then 목록이 바로 열리고 전체 처방이 이름 가나다 차례(`localeCompare(…, 'ko')`, 같으면 코드 차례)로 나온다. 줄마다 이름, 코드(caption muted), 이 기간 건수(`n건`, 세 자리 쉼표, 표의 건수와 같은 셈), 고른 처방이면 `고름`이다
- AC-802.3: Given 칸에 글자를 적으면, When 목록을 그리면, Then 앞뒤 빈칸을 뺀 글자가 이름이나 코드에 들어 있는 줄만 나온다(영문 대소문자 가리지 않음). 시험: 이름 일부, 코드 일부, 소문자로 적은 코드
- AC-802.4: Given 맞는 줄이 없음, When 목록을 그리면, Then `“적은 글자”에 맞는 처방이 없어요. 불러온 숫자에 있는 처방만 찾을 수 있어요.`가 나온다
- AC-802.5: Given 고른 기간에는 없지만 저장된 날 숫자(오늘 기준 최근 12개월 + 작년 범위, `statsRange(today, '12m')`의 `previous.from` ~ `current.to`)에 있는 처방, When 목록을 열면, Then 그 처방도 나오고 이 기간 건수는 `0건`이다. 이름은 가장 최근 날의 이름이다. 넓은 범위를 읽는 일은 처음 열 때 한 번뿐이고, 열기 전에는 읽지 않는다(시험: 열기 전 `readDays` 호출 수가 페이지 읽기 그대로, 열면 넓은 범위 한 번 더, 닫았다 다시 열어도 더 부르지 않음)
- AC-802.6: Given 넓은 범위를 읽는 중, When 목록을 그리면, Then 지금 화면에 있는 날 숫자의 처방과 고른 처방이 먼저 나오고 아래에 `처방 목록을 더 읽는 중이에요`가 있다. 읽기에 실패하면 같은 줄들과 `전체 처방 목록을 읽지 못해 지금 보는 기간의 처방만 보여요.`, [다시 읽기]가 있고 누르면 다시 읽는다. 실패해도 표·칩은 그대로다
- AC-802.7: Given 파일이나 비트로 새 숫자를 저장함(`useStatsData`의 `revision`이 바뀜), When 목록이 이미 읽혔으면, Then 넓은 범위를 다음에 열 때 다시 읽는다(열려 있으면 바로). 페이지 안 날 숫자에 있는 처방은 그 전에도 나온다. 넓은 읽기의 답이 오기 전에 `revision`이 바뀌면 늦게 온 그 답은 버린다(시험: 첫 답을 잡아 둔 채 `revision`을 바꾸고 새 답이 온 뒤 첫 답을 풀어도 목록이 새 답 그대로)
- AC-802.8: Given 열린 목록, When 고르지 않은 줄을 누르면, Then 표 끝에 더해지고 글자가 지워지며 목록은 열린 채이고 초점은 칸에 있다. 고른 줄을 다시 누르면 빠진다(같은 방식). 고르는 개수에 한도가 없다(시험: 250개). 어느 길로 빠지든(목록·칩·[모두 지우기]) 그 처방의 그래프 열림과 모양은 잊는다. 다시 고르면 닫힌 채다
- AC-802.9: Given 초점이 칸에 있음, When ↓↑를 누르면 줄이 옮겨 가고(닫혀 있으면 먼저 열림) `aria-activedescendant`가 그 줄을 가리키며 목록이 그 줄이 보이게 밀리고(`scrollIntoView({ block: 'nearest' })`), Enter는 옮겨 간 줄(없으면 첫 줄)을 고르거나 빼고, Esc는 목록을 닫는다. 한글 조합 중(`isComposing`)의 Enter는 아무것도 고르지 않는다
- AC-802.10: Given 열린 목록, When [닫기]나 칸 밖을 누르면, Then 닫힌다. 목록을 누르는 동안 초점이 칸을 떠나지 않는다. 목록은 칸 바로 아래 떠 있는 층(`absolute`, `rounded-float`, `shadow-float`)이라 아래 내용을 밀지 않고 줄 부분은 264px(`max-h-66`)에서 세로로 밀린다. 칸은 `role="combobox"`·`aria-expanded`·`aria-controls`·`aria-autocomplete="list"`, 목록은 `role="listbox"`·`aria-multiselectable`·`aria-label="찾은 처방"`, 줄은 `role="option"`·`aria-selected`다. 줄 높이와 [닫기]는 44px 이상이다
- AC-802.11: Given 저장 검사(`validateRxPick`, AC-811.1)에 걸리는 처방 줄, When 목록을 만들면, Then 그 줄은 목록에 없다(고를 수 없어 저장 실패가 생기지 않는다)
- AC-802.12: Given 코드를 대문자로 바꿔 견주는 규칙(`codeKey`), When 목록을 만들고 그리면, Then 대소문자만 다른 코드는 한 줄이고(가장 최근 날의 글자·이름) 저장된 고른 처방 `abc`가 있으면 목록 줄 `ABC`는 `고름`·`aria-selected` true다. 그 줄을 누르면 더하지 않고 뺀다(저장된 코드로 지운다, AC-812.7). 찾기 글자도 대소문자를 가리지 않는다(AC-802.3)

### REQ-803: 고른 처방 칩과 빈 안내
- AC-803.1: Given 고른 처방이 있음, When 그리면, Then 찾기 칸 아래에 고른 차례대로 칩(이름 + 빼기 단추, `aria-label` `<이름> 빼기`. 칩 이름은 그 처방 표 줄의 이름과 같다, AC-804.5)과 [모두 지우기] 글자 단추가 있다. 칩과 빼기 단추는 32px, 휴대폰은 44px이다
- AC-803.2: Given 칩, When 빼기를 누르면, Then 칩과 표 줄이 사라지고 초점은 찾기 칸에 오며 목록은 닫혀 있다. 그 처방을 다시 고르면 맨 뒤에 붙고 그래프는 닫힌 채다
- AC-803.3: Given 고른 처방이 있음, When [모두 지우기]를 누르면, Then 다시 묻지 않고 모두 빠지며 빈 안내가 나온다. 다시 고르면 그래프는 닫힌 채다
- AC-803.4: Given 고른 처방이 없음, When 그리면, Then 칩·표·[표 복사] 없이 `아직 고른 처방이 없어요`와 `위 칸에 이름이나 코드를 적어 찾아보세요. 여러 개를 고를 수 있어요.`가 있다
- AC-803.5: Given 처방 이름이 빈 글자이거나 코드와 같음, When 칩·표 줄·목록 줄을 그리면, Then 코드 하나만 보이고 빼기 단추 이름도 그 코드다

### REQ-804: 표의 숫자
- AC-804.1: Given 고른 처방 목록과 저장된 날 숫자, When `rxPickRows(input, picks)`를 부르면, Then 줄은 고른 차례 그대로다(많은 차례로 다시 줄 세우지 않는다). 고른 처방이 없으면 빈 목록이고 `buildTrend`를 부르지 않는다
- AC-804.2: Given 그 처방의 기간 안 날 줄, When 세면, Then 건수·신환·재진은 처방 추세(`rxList`)와 같은 셈이다: 덮은 기간 안 날의 `patients`·`newPatients`·`returning` 합이고, 덮은 기간 밖 날은 더하지 않는다. 코드는 대소문자를 가리지 않는다
- AC-804.3: Given 건수·신환·재진, When 구분 없음을 내면, Then 구분 없음 = 건수 − 신환 − 재진이다. 저장 모양에는 칸을 더하지 않는다
- AC-804.4: Given 건수가 0보다 큼, When 비율 글자를 내면, Then `formatRate`로 소수 첫째 자리까지 버린 글자 + `%`이고 밑수는 건수다. 시험: 건수 3·신환 1·재진 2 → `33.3%`·`66.6%`(반올림하지 않는다). 건수 0이면 두 비율 모두 `–`다
- AC-804.5: Given 고른 처방이 이 기간에 0건(저장된 줄 없음 포함), When 줄을 만들면, Then 줄을 지우지 않고 건수 `0건`, 신환·재진 `0건`, 비율 `–`, 빈 띠로 남긴다. 이름은 이 기간 가장 최근 날의 이름, 이 기간 줄이 없으면 저장해 둔 이름이다. 시험: 비교 기간 5건 → `5건 (−100.0%)` ▼, 비교 기간 0건 → `변화 없음`
- AC-804.6: Given 7·30·90일, When 증감과 지난 기간 건수를 내면, Then 두 기간 모두 덮이고 끝난 날끼리의 짝만 쓴다(`rxRow`의 `comparable`, 표시 칸과 상관없이 날끼리). 지난 기간 칸은 `comparable.previous`이고 증감은 `compareNumbers(comparable.current, comparable.previous)`다. 건수는 기간 전체다. 시험: 지난 기간에 덮이지 않은 날이 있으면 건수 − 지난 기간 건수 ≠ 증감 크기
- AC-804.7: Given 최근 12개월, When 증감과 지난 기간 건수를 내면, Then 두 기간 모두 끝난 달끼리만 견주고(처방 추세와 같은 규칙) 건수는 덜 끝난 달을 포함한 기간 전체다. 시험: 오늘 2026-11-13이면 11달을 견주고 건수에는 11월이 들어 건수 − 지난 기간 건수 ≠ 증감 크기
- AC-804.8: Given 견줄 짝이 하나도 없음, When 줄을 만들면, Then 지난 기간 칸은 `–`이고 증감은 `비교할 수 없음`이다
- AC-804.9: Given 고른 처방이 둘 이상, When 합계를 내면, Then 건수·신환·재진·구분 없음은 줄의 합이고 비율은 합계 건수를 밑수로 다시 낸다. 지난 기간 건수는 Σ`comparable.previous`이고 증감은 `compareNumbers(Σcomparable.current, Σcomparable.previous)`다(합계 건수로 내지 않는다). 견줄 짝이 없으면 AC-804.8과 같다. 시험: 오늘 2026-11-13 최근 12개월에 두 처방 모두 11월 건수가 있으면 합계 증감은 끝난 11달의 합끼리이고 합계 건수 − 합계 지난 기간 건수 ≠ 증감 크기. 고른 처방이 하나면 합계가 없다
- AC-804.10: Given 고른 처방 201개 이상(시험: 250개), When `rxPickRows`를 부르면, Then 오류 없이 250줄이 고른 차례다(`buildTrend` 200개 한도는 나눠 부른다)
- AC-804.11: Given 처방이 고른 대로 있지만 고른 기간에 저장된 날 줄이 하나도 없음(`hasRows` false), When 새 칸을 그리면, Then 칩은 남고 표·[표 복사] 대신 `불러온 숫자에 이 기간 자료가 없어요.`가 나온다(0건으로 거짓말하지 않는다)
- AC-804.12: Given 고른 코드와 날 줄 코드의 대소문자가 다름(`abc`·`ABC`), When `rxPickRows`를 부르면, Then 건수가 맞게 든다. 입력에 대소문자만 다른 코드가 둘 있어도 처음 것 한 줄로 모으고 0건 줄을 만들지 않는다(`buildTrend`의 `distinctCodes`가 뒤 코드의 점을 만들지 않으므로 부르기 전에 합친다)
