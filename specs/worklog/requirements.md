# 요구사항: 업무일지

> 기능 ID: `worklog` · 주소 `/worklog` · 탭 이름 **업무일지** · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC는 시험 하나 이상으로 검증하고, 시험 이름에 AC ID를 넣는다. REQ 번호 = TASK 번호다. 문서 TASK(TASK-1)·E2E TASK(TASK-13·TASK-18)·의원 PC 확인 TASK(TASK-19)는 단위 시험 대신 리뷰·실제 Supabase 확인·사용자 확인으로 본다(tasks.md).
> 번호 규칙: 지운 AC 번호는 다른 뜻으로 다시 쓰지 않는다. 2026-11-01 변경에서 REQ-002의 다섯째 번호(숫자 읽기)는 REQ-003으로 옮겼고, REQ-003의 1~5번(옛 이 PC 저장소)은 지웠다. 새 REQ-003은 6번부터 시작한다.

## 배경 / 목표
- 의원이 날마다 쓰는 엑셀 업무일지(하루 한 시트, 인쇄 범위 A1:I23)를 웹으로 옮긴다. `plan.md` §2-7(일일마감)의 첫 양식이다. 탭 틀은 이미 있다(`specs/tab-frame`, 지금 `/worklog`는 '준비 중' 화면)
- 기준 시안: 사용자가 승인한 목업 v2 `docs/mockups/worklog/index.html`(claude.ai artifact `BZ9iGjQ6Wmj5QXy76Z73EU`). **엑셀과 똑같이**(2026-10-29 사용자: "엑셀이랑 완전 똑같이"): 굴림 13pt 굵게, 제목 맑은 고딕 32pt, 연보라 `#CCCCFF`·회색 `#D9D9D9`, 검은 1px 선과 바깥 굵은 선, 엑셀 칸 너비·줄 높이
- 엑셀 계산식(사용자 파일에서 확인, 26개 시트 모두 같음): 환자 합계 `D6 = SUM(C5,C6)`, 수납액 `E15 = SUM(E9:I12)`, 총지불액 `E22 = SUM(E17:G21)`, 합계 `E23 = E15-E22`. 날짜 칸 서식 `yyyy/mm/dd aaa`, 금액 칸 서식 `#,###"원"`
- 2026-11-01 사용자 결정(다시 묻지 않는다)
  - 목업 v2 모양 그대로. 단 **아래 날짜 시트 탭 줄은 뺀다**. 화면은 날짜로 고른 하루 한 장이고(전날·다음 날·날짜 고르기), **오늘 날짜로 열리며**, 날이 바뀌면 그 날짜의 빈 양식이 저절로 나온다("매일 날짜 바껴야해")
  - **자동 저장**: [저장] 단추가 없다. 적으면 저절로 저장되고 저장 중·저장됨이 보인다. 인터넷이 끊기거나 저장에 실패하면 반드시 보이고, 조용히 사라지지 않는다
  - 합계 칸은 엑셀 계산식대로 저절로 계산된다("더하기하는것도 있어")
  - 칸 값은 서버(Supabase)에 저장해 다른 PC·휴대폰에서도 보인다. 업무사항도 서버에 저장한다(아래 grill 결정 1이 처음 결정 "이 PC에만"을 바꿨다)
  - 인쇄: A4 한 장, 결재 칸 포함, 엑셀 모양
  - 처음부터 새로 쓴다. 지난 엑셀 날짜를 가져오지 않는다
- 2026-11-01 사용자 결정 더함("비트 연결하는거 가능하면 불러와줘야해", "비트에서 불러와서 알아서 입력되게"): 비트 PC가 연결돼 있으면 비트 자료로 채울 수 있는 칸을 **저절로** 채운다(단추 없음). 이미 적은 값은 몰래 덮어쓰지 않고 다르다고 보여 주며 한 번 눌러 [비트 숫자로 바꾸기]를 고를 수 있다. 칸은 계속 고칠 수 있고, 비트에서 온 칸은 표시한다. 연결 안 됨·도우미 옛 판·읽기 실패면 지금처럼 손으로 적고 쉬운 안내만 보인다. 지출·업무사항은 손으로만. 숫자만 오고 환자 줄은 도우미 밖으로 나오지 않는다(Phase 4)
  - 자료 길은 새로 만들지 않는다: 매출 갈래(`specs/revenue` 5-2절)의 도우미 명령 `revenue.days` 하나를 쓴다(양지바른 일일보고 기준: 외래환자경영통계, 금액은 수납일(회계일) 기준, 신환·재진은 접수일 기준, 금액을 세지 않은 날은 금액 '확인 필요'이고 금액 칸이 모두 빈칸이다. 환불·예치금뿐 아니라 금액 맞춤 검사에 걸린 날도 그렇고 까닭은 답에 없다). 채우는 칸: 신환·재진·총진료비·조합청구액·현금수납·카드수납·계좌이체·미수입금. 미수발생·지역화폐는 그 계약에 없어 손으로 적는다(계약에 생기면 더한다). Phase 4 첫 step은 `revenue.days`가 main에 들어올 때까지 기다린다
- 2026-11-01 사용자 답: 휴대폰은 **보기만** 한다(목업 v2의 폰 모양, `plan.md` §1). 비고 칸은 서버에 저장한다(환자 이름을 적지 않는다).
- Claude 판단(design.md에 근거): 미래 날짜는 고를 수 없다
- 2026-11-01 사용자 결정(grill, 다시 묻지 않는다). 위 결정과 부딪히면 이것이 이긴다
  1. **업무사항은 서버(`worklog_days`의 `memo` 칸)에 저장한다.** 모든 PC가 같은 글을 보고, 어느 PC에서든 인쇄되고, 휴대폰에서도 보인다(보기만, 승인된 로그인). 사용자는 환자 이름·차트번호를 적지 않는다. 흐린 안내는 "환자 이름·차트번호는 적지 않아요". AI로 보내지 않는다
  2. **숫자 칸(수입·지출 금액, 신환·재진)에 글자도 적을 수 있다.** 숫자만 또는 "12,000원"은 더한다. 글 안에 숫자가 하나면 그 숫자를 더한다('12,000 별도' = 12,000). 숫자가 없으면 더하지 않고 표시도 없다('별도 보고'). 숫자가 둘 이상이면('2건 12,000') 더하지 않고 칸에 "합계에서 빠졌어요"를 표시한다(짐작하지 않는다). 쉼표는 한 숫자에 속한다. 업무사항과 비고는 더하지도 표시하지도 않는다
  3. **새 칸은 없고 양식은 엑셀 그대로다.** 수입·지출 항목 이름 전부를 그날에 한해 고칠 수 있고, 다음 날은 기본 이름으로 시작한다. 비트 자동 채우기는 이름이 아니라 칸 위치를 따른다
  4. **두 PC가 같은 날을 고치면 바뀐 칸만 저장한다.** 다른 칸은 둘 다 남고, 같은 칸은 나중 저장이 이긴다
  5. **지난 날은 승인된 계정이 언제든 고칠 수 있다.** 잠금이 없고, 고친 사람·시각을 남기지 않는다
- 유지하는 기본값(Claude 판단, 사용자에게 알림): 전날·다음 날은 일요일·휴일을 포함해 모든 날짜를 지나고 빈 양식이며 적기 전에는 저장하지 않는다. 막는 모양을 업무일지에 한해 넓힌다(업무사항·비고·숫자 칸 글자·항목 이름 모두): 전화·주민번호·메일 모양 글자가 있는 칸은 그 칸만 서버로 보내지 않고 빨갛게 보인다
- 화면 AC는 내용(보이는 것·단추·상태)만 정한다. 배치·글자는 기준 시안과 design.md '목업과 다른 점'을, 양식 밖 모양은 `docs/UI_GUIDE.md`(`ds`·토큰·앱 틀)를 따른다

## 요구사항

### REQ-001: 결정과 규칙 문서 (Phase 1 · Step 0 · docs)
- AC-001.1: Given `docs/ADR.md`, When 업무일지 ADR을 읽으면, Then 2026-11-01 사용자 결정 다섯 가지가 이유·트레이드오프와 함께 있다: ① 업무사항은 서버(`worklog_days`의 `memo` 칸)에 저장한다(남는 위험: 환자 이름은 자동으로 못 막는다. 안내 글과 모양 막기로 줄이고, AI로 보내지 않는다. CLAUDE.md CRITICAL '서버·Claude API에는 집계 숫자만 간다'의 업무일지 예외다: 사람이 손으로 적는 일지 글이고 비트 환자 자료가 아니다) ② 서버 칸은 적으면 자동 저장한다(저장 단추 없음. 입력값 임시 저장이 아니라 바로 DB 저장이고, 못 하면 값을 화면에 둔 채 알린다) ③ 업무일지 양식 칸은 엑셀 서식 예외다(굴림·맑은 고딕 시스템 글꼴, 700 굵기, 엑셀 색 토큰 넷, CSS Module 한 파일) ④ 숫자 칸은 친 글자를 저장한다(금액 정수 규칙의 업무일지 예외. 합계는 그대로 원 단위 정수다) ⑤ 바뀐 칸만 저장한다(다른 칸은 둘 다 남고 같은 칸은 나중 저장이 이긴다)
- AC-001.2: Given `docs/ARCHITECTURE.md`, When 읽으면, Then 디렉토리 구조에 `components/worklog/`·`lib/worklog/`·`lib/storage/worklogDays.ts`가, DB 표에 `daily_reports`(미정) 대신 `worklog_days`(칸 요약)가, 데이터 흐름에 [업무일지] 줄이 있다. 상태 관리 절에 업무일지 예외 줄은 없다(업무일지는 브라우저 저장소를 쓰지 않는다)
- AC-001.3: Given `docs/UI_GUIDE.md`, When 읽으면, Then '업무일지 양식(엑셀 예외)' 절이 예외 범위(양식 칸 안만)·토큰 이름·글꼴·칸 높이(pt)·인쇄·휴대폰(업무사항도 보인다)·막힌 칸 빨강·"합계에서 빠졌어요" 표시를 적고, '하지 마라' 표의 두 번째 글꼴·700 굵기·토큰 밖 색 줄에 "업무일지 양식 칸은 예외(아래 절)"가 붙는다

### REQ-002: 합계·칸 글자·날짜 규칙 (Phase 1 · Step 1 · calc-format)
- AC-002.1: Given 신환·재진의 읽은 숫자(없으면 0), When 환자 합계를 구하면, Then 신환 + 재진이다(엑셀 `D6 = SUM(C5,C6)`)
- AC-002.2: Given 수입 칸 여덟 개의 읽은 숫자, When 수납액을 구하면, Then 현금수납 + 카드수납 + 계좌이체 + 지역화폐뿐이다(엑셀 `E15 = SUM(E9:I12)`). 총진료비·조합청구액·미수발생·미수입금은 더하지 않는다
- AC-002.3: Given 지출 네 줄(현금·카드·환불·free)의 읽은 숫자, When 총지불액을 구하면, Then 네 금액의 합이다(엑셀 `E22 = SUM(E17:G21)`)
- AC-002.4: Given 수납액·총지불액, When 합계를 구하면, Then 수납액 − 총지불액이고 음수도 그대로다(엑셀 `E23 = E15-E22`). 모든 값은 원 단위 정수다
- AC-002.6: Given 숫자, When 칸 글자로 보이면, Then 금액은 엑셀 `#,###"원"` 모양이다: 입력 칸은 값이 없거나 0이면 빈 글자, 있으면 "1,234,500원"이고, 초점이 있는 동안은 "1,234,500"(원 없음)이다. 자동 칸(수납액·총지불액·합계)은 0이면 "원", 음수면 "-12,000원"이다. 인원 칸은 "86"처럼 숫자만, 환자 합계 칸은 0도 "0"이다
- AC-002.7: Given 날짜 '2026-10-28', When 날짜 칸 글자로 보이면, Then "2026/10/28 수"다(엑셀 `yyyy/mm/dd aaa`, 한국 요일 한 글자)
- AC-002.8: Given 고른 날짜와 오늘(한국 날짜), When 이동을 구하면, Then 전날은 하루 앞이고, 다음 날은 오늘을 넘지 않는다(오늘이면 없음). 일요일·휴일도 건너뛰지 않고 모든 날짜를 지난다. 날짜 모양이 아니거나 오늘보다 뒤인 날짜는 오늘로 바꾼다
- AC-002.9: Given 화면이 열린 채 한국 날짜가 바뀜, When 다음에 볼 날짜를 구하면, Then 옛 오늘을 보고 있었으면 새 오늘이고, 지난 날을 보고 있었으면 그대로다
- AC-002.10: Given 업무일지 칸 글자(업무사항·비고·숫자 칸 글자·항목 이름), When 개인정보 모양을 검사하면, Then 전화번호(`010-0000-1234`·`01000001234`·`010-00001234`·`0200001234`·`(02)000-1234`·`+82 10-0000-1234`)·주민번호(`900101-1234567`·`900101 1234567`·붙여 쓴 13자리)·메일 모양이면 문제로 본다. 금액 같은 보통 숫자("1234567"·"12,000"·"2건 12,000"·"00012")와 보통 글자는 문제가 아니다. 넓힌 모양은 업무일지에만 쓰고 `lib/payload/validate.ts`는 고치지 않는다 전각 숫자·전각 붙임표·긴 줄표(`－`·`—`·`–`·`―`·`‐`·`‑`·`−`·`ㅡ`)로 적어도 같은 모양으로 본다.

### REQ-003: 칸 글자 읽기 (Phase 1 · Step 2 · cell-text)
- AC-003.6: Given 숫자만이거나 쉼표·"원"이 붙은 글자, When 읽으면, Then 그 숫자다: "1,234,500원" → 1234500, "00012" → 12(앞의 0을 지운다). 빈 글자·공백뿐이면 '없음'이다
- AC-003.7: Given 글 안에 숫자가 하나인 글자, When 읽으면, Then 그 숫자다: '12,000 별도' → 12000, 쉼표는 한 숫자에 속한다, 끝에 붙임표 등이 붙어도('12,000-') 숫자 하나다
- AC-003.8: Given 숫자가 없는 글자('별도 보고'), When 읽으면, Then '없음'이다(더하지 않고 표시도 없다)
- AC-003.9: Given 숫자가 둘 이상인 글자('2건 12,000'·'12 000'·'10/28'), When 읽으면, Then '합계 제외'다
- AC-003.10: Given 짐작해야 읽을 수 있는 숫자, When 읽으면, Then '합계 제외'다: 소수점('12.5'·'.5'), 빼기 표시('-5,000'·'- 5,000'·'△5,000'·'(5,000)'·'ㅡ5,000'), 전각 숫자('１２,０００'), 3자리 묶음이 아닌 쉼표('120,00'·'3,4건'·'12,000,'), 숫자 바로 뒤 십·백·천·만·억·조('12만원'·'12 만원'·'3백원'·'3십만원'), 인원 5자리·금액 12자리를 넘는 숫자(앞의 0은 세지 않는다). 앞자리만 잘라 읽지 않는다
- AC-003.11: Given 개인정보 모양(REQ-002의 모양 검사)에 걸리는 글자, When 읽으면, Then '합계 제외'다(저장되지 않는 값이 합계에 들어가지 않는다)

- AC-017.7: Given 비트 표시가 저장된 날, When 비트를 읽지 않는 화면(폰·연결 안 된 PC)에서 비트 칸 밖 칸을 고치거나 앱 안 이동 뒤 저장되면, Then 비트 칸 목록이 바뀌지 않았으므로 `bit_fields` 칸을 보내지 않아 표시가 지워지지 않는다. 목록은 바뀌었을 때만 보낸다
- AC-017.8: Given 비트 답, When 그날 첫 읽기가 끝나기 전이면, Then 읽기가 끝난 뒤에 합친다. 불러오기에 실패한 날은 합치지 않고(저장하지 않는다), 고른 날짜와 다른 옛 날짜 답은 버린다(서버에 있는 값을 모른 채 비트 숫자로 덮지 않는다)

### REQ-018: 실제 Supabase 비트 칸 확인 (Phase 5 · Step 0 · bit-e2e)
- AC-018.1: Given 사용자가 `20261101000110_worklog_bit_fields.sql`을 실제 Supabase에 붙여 넣음, When 시험 코드가 승인 시험 계정의 클라이언트(RLS 아래)로 시험 날짜 줄에 `bit_fields`를 넣고, 화면(비트 PC 없음)에서 그 날의 다른 칸을 고쳐 자동 저장한 뒤 다시 읽으면, Then 고친 값이 저장되고 `bit_fields`는 그대로다. 화면에는 그 칸들의 비트 표시가 보인다
- AC-018.2: Given 칸에 막는 모양을 적음, When 그동안 보낸 모든 요청과 다시 읽은 줄을 보면, Then 그 값이 없다(cross-branch C7)

### REQ-019: 의원 PC 확인 (Phase 5 · Step 1 · clinic-check)
- AC-019.1: Given Phase 4가 사용자 지시로 배포되어 의원 PC 업무일지 화면이 비트 숫자를 채움, When 총괄이 지난 날 사흘(금액이 채워진 날 둘 + 금액이 '확인 필요'로 빈칸인 날 하나, 그런 날이 있으면)을 업무일지 화면·그날 엑셀 업무일지·비트 '외래환자경영통계'로 칸마다 견주면, Then `docs/worklog/bit-check.md`에 칸마다 "같음 / 다름(어떻게) / 비트에 없음"이 적힌다(숫자는 적지 않는다): 날짜별 신환·재진, 수납 나눔(현금·카드·계좌·미수입금 — 매출 갈래가 넘긴 확인), 총진료비, 조합청구액, 그리고 미수발생·지역화폐가 비트에 따로 있는지
- AC-019.2: Given 확인 결과, When design.md 20-2절 표와 다르면, Then 명세를 고쳐 다시 승인받고(채우는 칸 목록), 매출 계약 쪽 문제(수납 나눔·신환·재진 기준, 금액이 날마다 빈칸)는 매출 갈래에 알린다
