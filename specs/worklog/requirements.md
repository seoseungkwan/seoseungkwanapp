# 요구사항: 업무일지

> 기능 ID: `worklog` · 주소 `/worklog` · 탭 이름 **업무일지** · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC는 시험 하나 이상으로 검증하고, 시험 이름에 AC ID를 넣는다. REQ 번호 = TASK 번호다. 문서 TASK(TASK-1)와 E2E TASK(TASK-13)는 시험 대신 리뷰·실제 Supabase 확인으로 본다(tasks.md).

## 배경 / 목표
- 의원이 날마다 쓰는 엑셀 업무일지(하루 한 시트, 인쇄 범위 A1:I23)를 웹으로 옮긴다. `plan.md` §2-7(일일마감)의 첫 양식이다. 탭 틀은 이미 있다(`specs/tab-frame`, 지금 `/worklog`는 '준비 중' 화면)
- 기준 시안: 사용자가 승인한 목업 v2 `docs/mockups/worklog/index.html`(claude.ai artifact `BZ9iGjQ6Wmj5QXy76Z73EU`). **엑셀과 똑같이**(2026-10-29 사용자: "엑셀이랑 완전 똑같이"): 굴림 13pt 굵게, 제목 맑은 고딕 32pt, 연보라 `#CCCCFF`·회색 `#D9D9D9`, 검은 1px 선과 바깥 굵은 선, 엑셀 칸 너비·줄 높이
- 엑셀 계산식(사용자 파일에서 확인, 26개 시트 모두 같음): 환자 합계 `D6 = SUM(C5,C6)`, 수납액 `E15 = SUM(E9:I12)`, 총지불액 `E22 = SUM(E17:G21)`, 합계 `E23 = E15-E22`. 날짜 칸 서식 `yyyy/mm/dd aaa`, 금액 칸 서식 `#,###"원"`
- 2026-11-01 사용자 결정(다시 묻지 않는다)
  - 목업 v2 모양 그대로. 단 **아래 날짜 시트 탭 줄은 뺀다**. 화면은 날짜로 고른 하루 한 장이고(전날·다음 날·날짜 고르기), **오늘 날짜로 열리며**, 날이 바뀌면 그 날짜의 빈 양식이 저절로 나온다("매일 날짜 바껴야해")
  - **자동 저장**: [저장] 단추가 없다. 적으면 저절로 저장되고 저장 중·저장됨이 보인다. 인터넷이 끊기거나 저장에 실패하면 반드시 보이고, 조용히 사라지지 않는다
  - 합계 칸은 엑셀 계산식대로 저절로 계산된다("더하기하는것도 있어")
  - **업무사항 칸은 이 PC에만 저장한다**(서버로 보내지 않는다). 나머지(숫자, 지출 비고)는 서버(Supabase)에 저장해 다른 PC·휴대폰에서도 보인다
  - 인쇄: A4 한 장, 결재 칸 포함, 엑셀 모양
  - 처음부터 새로 쓴다. 지난 엑셀 날짜를 가져오지 않는다
- 2026-11-01 사용자 결정 더함("비트 연결하는거 가능하면 불러와줘야해", "비트에서 불러와서 알아서 입력되게"): 비트 PC가 연결돼 있으면 비트 자료로 채울 수 있는 칸(환자현황 신환·재진, 수입 총진료비·조합청구액·현금수납·카드수납·계좌이체·미수발생·미수입금, 지역화폐는 비트에 있을 때만)을 **저절로** 채운다(단추 없음). 이미 적은 값은 몰래 덮어쓰지 않고 다르다고 보여 주며 한 번 눌러 [비트 숫자로 바꾸기]를 고를 수 있다. 칸은 계속 고칠 수 있고, 비트에서 온 칸은 표시한다. 연결 안 됨·도우미 옛 판·읽기 실패면 지금처럼 손으로 적고 쉬운 안내만 보인다. 지출·업무사항은 손으로만. 숫자만 오고 환자 줄은 도우미 밖으로 나오지 않는다(Phase 4)
  - 자료 길은 새로 만들지 않는다: 금액은 매출 갈래(`specs/revenue`)의 도우미 명령 `revenue.days`(양지바른 일일보고 기준: 외래환자경영통계, 수납일(회계일) 기준, 환불·예치금 있는 날은 '확인 필요')를 쓰고, 신환·재진은 그 명령에 없으므로 통계 갈래(`specs/stats`)의 길(`stats.rows` → Worker → 날짜별 저장 숫자)을 쓴다. Phase 4 첫 step은 그 명령이 main에 들어올 때까지 기다린다
- Claude 판단(design.md에 근거): 휴대폰은 목업 v2의 폰 모양(같은 양식을 화면 폭에 맞춤)으로 **보기만** 한다(`plan.md` §1 "폰은 보기만"). 비고 칸에 전화번호·주민번호·메일 모양 글자가 있으면 서버로 보내지 않는다(CLAUDE.md 개인정보 규칙). 미래 날짜는 고를 수 없다
- 화면 AC는 내용(보이는 것·단추·상태)만 정한다. 배치·글자는 기준 시안과 design.md '목업과 다른 점'을, 양식 밖 모양은 `docs/UI_GUIDE.md`(`ds`·토큰·앱 틀)를 따른다

## 요구사항

### REQ-001: 결정과 규칙 문서 (Phase 1 · Step 0 · docs)
- AC-001.1: Given `docs/ADR.md`, When 업무일지 ADR을 읽으면, Then 2026-11-01 사용자 결정 세 가지가 이유·트레이드오프와 함께 있다: ① 업무사항은 그 PC 브라우저 저장소(localStorage)에만 두고 서버·백업·AI로 보내지 않는다(ARCHITECTURE '브라우저 저장소에는 폴더 핸들만'의 예외) ② 서버 칸은 적으면 자동 저장한다(저장 단추 없음. 입력값 임시 저장이 아니라 바로 DB 저장이고, 못 하면 값을 화면에 둔 채 알린다) ③ 업무일지 양식 칸은 엑셀 서식 예외다(굴림·맑은 고딕 시스템 글꼴, 700 굵기, 엑셀 색 토큰 넷, CSS Module 한 파일)
- AC-001.2: Given `docs/ARCHITECTURE.md`, When 읽으면, Then 디렉토리 구조에 `components/worklog/`·`lib/worklog/`·`lib/storage/worklogDays.ts`가, DB 표에 `daily_reports`(미정) 대신 `worklog_days`(칸 요약)가, 데이터 흐름에 [업무일지] 줄이, 상태 관리에 업무사항 예외 한 줄이 있다
- AC-001.3: Given `docs/UI_GUIDE.md`, When 읽으면, Then '업무일지 양식(엑셀 예외)' 절이 예외 범위(양식 칸 안만)·토큰 이름·글꼴·칸 높이(pt)·인쇄·휴대폰을 적고, '하지 마라' 표의 두 번째 글꼴·700 굵기·토큰 밖 색 줄에 "업무일지 양식 칸은 예외(아래 절)"가 붙는다

### REQ-002: 합계·칸 글자·날짜 규칙 (Phase 1 · Step 1 · calc-format)
- AC-002.1: Given 신환·재진 값(빈 칸은 0), When 환자 합계를 구하면, Then 신환 + 재진이다(엑셀 `D6 = SUM(C5,C6)`)
- AC-002.2: Given 수입 칸 여덟 개, When 수납액을 구하면, Then 현금수납 + 카드수납 + 계좌이체 + 지역화폐뿐이다(엑셀 `E15 = SUM(E9:I12)`). 총진료비·조합청구액·미수발생·미수입금은 더하지 않는다
- AC-002.3: Given 지출 네 줄(현금·카드·환불·free), When 총지불액을 구하면, Then 네 금액의 합이다(엑셀 `E22 = SUM(E17:G21)`)
- AC-002.4: Given 수납액·총지불액, When 합계를 구하면, Then 수납액 − 총지불액이고 음수도 그대로다(엑셀 `E23 = E15-E22`). 모든 값은 원 단위 정수다
- AC-002.5: Given 칸에 친 글자, When 숫자로 읽으면, Then 숫자가 아닌 글자(쉼표·"원"·빈칸·붙임표)는 버리고 앞의 0을 지운다. 빈 글자는 빈 값(null)이다. 인원 칸은 앞에서 5자리, 금액 칸은 앞에서 12자리까지만 받는다
- AC-002.6: Given 숫자, When 칸 글자로 보이면, Then 금액은 엑셀 `#,###"원"` 모양이다: 입력 칸은 값이 없거나 0이면 빈 글자, 있으면 "1,234,500원"이고, 초점이 있는 동안은 "1,234,500"(원 없음)이다. 자동 칸(수납액·총지불액·합계)은 0이면 "원", 음수면 "-12,000원"이다. 인원 칸은 "86"처럼 숫자만, 환자 합계 칸은 0도 "0"이다
- AC-002.7: Given 날짜 '2026-10-28', When 날짜 칸 글자로 보이면, Then "2026/10/28 수"다(엑셀 `yyyy/mm/dd aaa`, 한국 요일 한 글자)
- AC-002.8: Given 고른 날짜와 오늘(한국 날짜), When 이동을 구하면, Then 전날은 하루 앞이고, 다음 날은 오늘을 넘지 않는다(오늘이면 없음). 날짜 모양이 아니거나 오늘보다 뒤인 날짜는 오늘로 바꾼다
- AC-002.9: Given 화면이 열린 채 한국 날짜가 바뀜, When 다음에 볼 날짜를 구하면, Then 옛 오늘을 보고 있었으면 새 오늘이고, 지난 날을 보고 있었으면 그대로다
- AC-002.10: Given 비고 글자, When 개인정보 모양을 검사하면, Then 전화번호·주민번호(붙임표 있음·붙여 쓴 13자리)·메일 모양이면 문제로 본다. 금액 같은 보통 숫자("1234567"·"12,000")와 보통 글자는 문제가 아니다

### REQ-003: 업무사항 이 PC 저장소 (Phase 1 · Step 2 · memo-store)
- AC-003.1: Given 병원 id·날짜·글, When 쓰고 다시 읽으면, Then 같은 글이 나온다. 열쇠는 `worklog:memo:v1:<병원 id>:<YYYY-MM-DD>`이고 다른 병원·다른 날짜의 글과 섞이지 않는다
- AC-003.2: Given 빈 글, When 쓰면, Then 그 열쇠를 지운다. Given 적은 적 없는 날, When 읽으면, Then 빈 글이다
- AC-003.3: Given 2,000자를 넘는 글, When 쓰면, Then 앞 2,000자만 둔다
- AC-003.4: Given 브라우저 저장소를 쓸 수 없음(꺼짐·가득 참·예외), When 읽거나 쓰면, Then 던지지 않고 실패(`ok: false`)를 돌려준다
- AC-003.5: Given 저장소 파일 소스, When 읽어 보면, Then supabase·`fetch`·`@/lib/storage`·`sessionStorage`를 쓰지 않는다(업무사항이 서버로 갈 길이 없다)

### REQ-004: 서버 표 `worklog_days` (Phase 1 · Step 3 · db-table)
- AC-004.1: Given migration `supabase/migrations/20261101000000_worklog.sql`, When 실행하면, Then 표 `worklog_days`의 칸은 정해 둔 목록과 정확히 같다: `hospital_id`·`work_date`(합쳐서 기본 열쇠), 인원 2칸, 수입 8칸, 지출 금액 4칸, 비고 5칸, `updated_at`. 업무사항 칸은 없다
- AC-004.2: Given RLS, When 로그인 안 한 사용자(anon)가 읽거나 쓰면, Then 모두 거부된다
- AC-004.3: Given 승인된 병원 사용자, When 내 병원 줄을 넣고·읽고·`insert … on conflict (hospital_id, work_date) do update`로 고치면, Then 된다
- AC-004.4: Given 다른 병원 줄, When 읽거나 그 병원 id로 넣거나 내 줄을 그 병원으로 옮기면, Then 보이지 않거나 거부된다
- AC-004.5: Given 승인 대기·거절 병원 사용자, When 읽거나 쓰면, Then 아무 줄도 보이지 않고 쓰기는 거부된다
- AC-004.6: Given 값 제약, When 음수·인원 99,999 초과·금액 999,999,999,999 초과·빈 글자 비고·100자 넘는 비고를 넣으면, Then 거부된다. 빈 칸(null)은 된다
- AC-004.7: Given 권한, When 줄을 지우거나 `updated_at`을 직접 넣으려 하면, Then 거부된다. 줄을 고치면 `updated_at`이 새 시각으로 바뀐다

### REQ-005: 하루 읽기·저장 (Phase 1 · Step 4 · day-storage)
- AC-005.1: Given 병원 id·날짜, When 하루를 읽으면, Then 정해 둔 칸만 골라 그 병원·그 날짜 줄을 읽고 화면 모양(camelCase)으로 바꾼다. 줄이 없으면 null이다
- AC-005.2: Given 화면 값, When 하루를 저장하면, Then `onConflict: 'hospital_id,work_date'` upsert 한 번이고, 보내는 칸은 `hospital_id`·`work_date`와 서버 칸 19개뿐이다. 빈 비고는 null로 보낸다. 업무사항은 받는 모양에도 보내는 칸에도 없다
- AC-005.3: Given 비고에 개인정보 모양(AC-002.10), When 저장하면, Then 네트워크를 부르지 않고 `private` 오류(어느 칸인지)를 낸다
- AC-005.4: Given 브라우저가 오프라인이거나 응답 status가 0(연결 실패), When 읽거나 저장하면, Then `offline` 오류다. 그 밖의 오류는 `failed`다. 오류에는 종류와 칸 이름만 있고 Supabase 오류 문구·값은 담지 않는다

### REQ-006: 자동 저장 제어 (Phase 2 · Step 0 · autosave)
- AC-006.1: Given 그날 값이 바뀜, When 마지막 바뀜 뒤 800ms 동안 더 바뀌지 않으면, Then 그날 최신 값으로 한 번 저장한다
- AC-006.2: Given 저장 중에 같은 날 값이 또 바뀜, When 그 저장이 끝나면, Then 최신 값으로 한 번 더 저장한다. 같은 날 저장은 동시에 둘이 돌지 않는다
- AC-006.3: Given 저장 성공, When 상태를 보면, Then `saved`와 저장한 시각이다
- AC-006.4: Given `failed` 오류, When 저장이 실패하면, Then 2초·5초·15초 뒤 다시 해 보고, 그래도 안 되면 `failed`로 멈춘다. `retry()`는 바로 다시 저장한다
- AC-006.5: Given `offline` 오류, When 저장이 실패하면, Then `offline`이고 15초마다 다시 해 본다. `online()`을 부르면 바로 저장한다
- AC-006.6: Given `private` 오류, When 저장이 실패하면, Then `blocked`(칸 이름 포함)이고 그날 값이 다시 바뀔 때까지 다시 해 보지 않는다
- AC-006.7: Given 기다리는 저장, When `flush()`를 부르면, Then 기다리지 않고 바로 저장을 시작한다
- AC-006.8: Given 날짜 여러 개, When 상태를 보면, Then 날짜마다 따로 저장하고, 전체 상태는 가장 나쁜 것이다(`failed` > `blocked` > `offline` > `saving` > `saved` > `idle`). 저장 안 된 값이 하나라도 있으면 `hasUnsaved()`가 참이다
- AC-006.9: Given `dispose()`, When 부르면, Then 남은 타이머가 모두 멈춘다

### REQ-007: 엑셀 서식 예외 규칙 (Phase 2 · Step 1 · sheet-style)
- AC-007.1: Given `src/app/globals.css` `:root`, When 토큰을 보면, Then 엑셀 색 넷 `--xl-ink: #000000`·`--xl-lav: #CCCCFF`·`--xl-gray: #D9D9D9`·`--xl-focus: #107C41`이 한 번씩 있고, 토큰 시험 표에 들어 있다. `@theme inline`은 이 넷을 가리키지 않는다(Tailwind 색 클래스가 생기지 않는다)
