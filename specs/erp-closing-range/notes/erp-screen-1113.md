## 3. 저장 단추 (확실)
- 업무일지 1 '전체 저장'·'중간저장'(181529~181585줄): 확인 창 없음. 누르면 둘 다 막히고 누른 단추 글자가 '저장 중...'. 성공 쪽지 `.toast.toast-success .toast-message` — 전체 저장 '저장되었습니다.', 중간저장 '중간저장했습니다(작성중)'/'(확정 상태 유지)'. 실패 `.toast-error`(서버 글 또는 '저장 중 오류가 발생했습니다.'). 쪽지는 3초 뒤 사라짐(12689·12717줄)
- 화면 쪽 검사 둘뿐: '날짜를 선택해 주세요.', '이 날짜의 업무일지를 불러오지 못했습니다...'. 음수·필수 칸 검사 없음(서버는 모름)
- **업무일지 1 저장 카드는 1 탭일 때만 있다**(182159줄 `ie === "w1" && !f &&`)
- 업무일지 2 '일일 상세 저장'·'중간저장'(179382~179451줄): 확인 창 없음, 저장 중 세 단추 막힘. 두 단추는 같은 요청(쪽지만 다름), 상태는 안 보냄. 성공하면 '저장되었습니다.' 뒤 1을 입력 유지한 채 다시 불러오고(182240줄 `onSaved: () => { ve(!1), Ae(j, { keepEdits: !0 }) }`) 2도 서버 값으로 다시 그림
- **두 저장 모두 '저장되었습니다.'** → 1 저장 → 끝 확인 → 2 저장 → 다시 불러오기 끝까지 하나씩
- 1 저장은 2 칸을 지우거나 다시 그리지 않음. 같이 쓰는 칸은 '특이사항' 하나
- '초기화' = 직접 만든 확인 창 `.dialog-overlay .dialog-box[role=dialog]`('확인'·'취소'), '마감일지 삭제' = window.confirm

## 실제 화면에서 볼 것 (사용자와 확인 때)
1. value 설정 + input 이벤트로 날짜가 바뀌는지·달력 창이 안 열리는지, replaceState + popstate도 되는지
2. 날짜를 바꾼 뒤 '로딩 중...'이 나왔다 사라지는 순서와 2 저장 줄이 나오는 때
3. 두 저장 쪽지 글자·시간, 실패 때 서버 글, 숨은 2 탭에서 '일일 상세 저장' click()
4. 이 병원 진료실 수(0이면 2 저장 불가), 이 계정 권한(원무 오늘만인지), 확정한 날에 전체 저장해도 확정이 남는지
5. 2만 저장했을 때 마감일지가 작성중으로 생기는지, 음수·빈 칸을 서버가 거절하는지, autoKept 안내가 뜨는지
6. 로그인 유지 시간(긴 기간), 도는 중 새 판 안내 창
