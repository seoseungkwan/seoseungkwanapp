# 요구사항: 비트 PC 청구 화면에서 고른 기간의 날짜를 완료로 저장

> 기능 ID: `claim-day-done-pc` · 형식: 요구사항은 `### REQ-2901: 제목`, 수용 기준은 `- AC-2901.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다. 시험 자료의 날짜·숫자는 지어낸 값이다.

## 배경 / 목표
- 2026-11-08 `claim-day-done`(운영 배포 b0c72cc)은 완료로 바꾸는 곳을 밖에서 보는 화면(휴대폰·집 PC) 하나로 두었다(AC-2804.5). 사용자가 비트 PC 청구 화면을 원격으로 보다가 "완료 표시 어딨어"라고 했고, 비트 PC 화면에도 넣기로 했다(사용자 "ㅇㅇ")
- 시안 두 가지(가: 줄 끝 [완료로] / 나: 체크 칸으로 고른 기간을 한꺼번에) 가운데 사용자가 **나**를 골랐다(`docs/mockups/claim-day-done-pc/index.html`)
- 저장 자리(`claim_day_closes`)·저장소 함수(`closeDays`·`reopenDays`·`readClosedDays`)·'완료 표시 날 = 끝난 날' 규칙은 `claim-day-done` 그대로 쓴다. 서버·SQL 바꿈 없음

## 이미 정한 것 (다시 묻지 않는다)
1. 비트 PC 날짜 목록의 지금 체크 칸(불러올 기간 고르기)으로 고른 기간 안의 '아직 입력 안 된 날'을 [고른 날 완료로 저장]으로 한꺼번에 완료로 바꾼다(사용자 "나")
2. 아래는 Claude가 정한 것(시안 설명으로 보임): 완료로 바꾼 줄은 '입력이 끝난 날짜'로 내려가고, 그 줄에 '완료로 바꿈 · 시각'과 [되돌리기]가 있다. 저장 뒤 알림 줄에 '{N}일을 완료로 바꿨어요'와 [되돌리기](방금 바꾼 날 모두). 묻는 창은 없다(되돌리기가 있다)
3. 이 기능은 `claim-day-done` AC-2804.5('비트 PC 화면에는 [완료로 저장]·[되돌리기]가 없다')를 대신한다. 밖에서 보는 화면은 바꾸지 않는다

## 요구사항

### REQ-2901: 고른 기간의 날짜를 한꺼번에 완료로
- AC-2901.1: Given 비트 PC 날짜 목록이 그려짐(`dates.kind === 'ready'`), When 그리면, Then 표 위(머리 줄 아래)에 고르기 줄이 있고 '고른 기간에서 아직 입력 안 된 날 {N}일'과 [고른 날 완료로 저장]이 있다. N은 고른 기간(`inPeriod`) 안에서 `done`이 아닌 줄 수다. N = 0이면 단추가 막힌다(disabled)
- AC-2901.2: Given 체크 칸으로 기간을 바꿈, When 다시 그리면, Then N이 바로 바뀐다(체크 칸은 지금처럼 기간 고르기 그대로다)
- AC-2901.3: Given N = 3, When [고른 날 완료로 저장]을 누르면, Then 서버 요청은 `claim_day_closes` 한 번이고 줄마다 칸은 `visit_date` 하나, 날짜는 그 3일뿐이다(끝난 날·기간 밖 날 없음). 답을 기다리는 동안 단추는 '저장 중…'으로 막힌다
- AC-2901.4: Given AC-2901.3이 성공, When 답이 오면, Then 날짜 목록을 다시 읽어 그 3일이 '입력이 끝난 날짜'로 내려가고 '아직 입력 안 된 날짜 {n}일'이 3 준다. 고르기 줄은 '3일을 완료로 바꿨어요'와 [되돌리기]가 된다. 이 [되돌리기]는 방금 바꾼 3일을 지우는 요청 하나다. 기간을 바꾸면 알림은 사라지고 AC-2901.1의 글로 돌아간다
- AC-2901.5: Given 저장·되돌리기가 실패(서버 오류·연결 끊김·표 없음), When 답이 오면, Then 목록·기간은 그대로이고 고르기 줄 아래에 `E-DAYCLOSE-FAILED` 안내(`ErrorCard`)가 보이며 다시 누를 수 있다. 다음 저장·되돌리기를 시작하면 안내는 사라진다
- AC-2901.6: Given 자료 불러오는 중이거나 비트 입력 중(지금 화면이 목록을 새로 묻지 않는 때), When 그리면, Then [고른 날 완료로 저장]과 [되돌리기]가 막힌다

### REQ-2902: 완료로 바꾼 줄 보기·되돌리기
- AC-2902.1: Given 완료 표시가 있는 날(`claim_day_closes`), When 목록을 그리면, Then 그 줄은 '입력이 끝난 날짜'에 있고 상태 '완료', 안내 칸은 '완료로 바꿈 · {바꾼 시각}'(지금 '{시각}에 바뀜'과 같은 시각 글), 줄 끝에 [되돌리기](이름 '{M/D (요일)} 되돌리기')가 있다. 숫자(진료·메모 필요·입력함)는 그대로다. 숫자로 끝난 날(완료 표시 없음)에는 [되돌리기]가 없다
- AC-2902.2: Given 그 줄의 [되돌리기], When 누르면, Then 서버 요청은 `claim_day_closes`에서 그 날짜 하나를 지우는 것이고, 성공하면 목록을 다시 읽어 그 날이 '아직 입력 안 된 날짜'로 돌아간다(남은 메모가 있을 때). 기다리는 동안 그 단추는 막힌다
- AC-2902.3: Given '입력이 끝난 날짜'가 많아 접혀 있음([끝난 날짜 더 보기]), When 그리면, Then 지금 규칙 그대로다(완료 표시 날도 같은 묶음·같은 차례)

### REQ-2903: 지금 것은 그대로
- AC-2903.1: Given 완료 저장·되돌리기, When 서버 요청을 보면, Then 건수 표(`claim_day_counts` 등)에는 쓰지 않고, 보내는 값은 날짜뿐이다
- AC-2903.2: Given 이 기능 뒤, When 지금 시험을 돌리면, Then 기대값을 바꾸지 않고 통과한다. 예외: `ClaimScreen.test.tsx`의 AC-2804.5 시험은 이 기능이 대신하므로 이름과 기대값을 AC-2903.2로 바꾼다(비트 PC 화면에 '휴대폰용' 체크 칸 이름 '… 고르기'·'완료로 바꾼 날' 접는 칸이 없다는 것만 남긴다), 가짜 서버가 `claim_day_closes` 쓰기를 알게 하는 것
- AC-2903.3: Given 밖에서 보는 화면(`OutsideCounts`), When 이 기능 뒤, Then 바뀌지 않는다(파일을 고치지 않는다). `src/guardrails.test.ts`·lint·tsc가 통과한다

## 범위 밖

- 기간 고르기 규칙(35일 한도·[입력 안 된 날짜 모두] 등) 바꾸기
- 밖에서 보는 화면, 서버 표·권한, 도우미·확장
