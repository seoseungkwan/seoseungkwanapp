# 요구사항: 환자 탭: F/U 명단 읽는 기간을 120일에서 30일로

> 기능 ID: `patients-fu-30days` · 형식: 요구사항은 `### REQ-001: 제목`, 수용 기준은 `- AC-001.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.

## 배경 / 목표
- 지금 F/U 명단은 오늘까지 120일을 31일 조각 넷으로 비트에서 읽는다(`specs/patients` AC-604.2, `src/workers/patients/plan.ts` `FOLLOWUP_DAYS = 120`)
- 사용자 결정(2026-11-07): "환자 탭 FU 명단은 30일로 하자. 정기 주사 제외하고"
- 목표: F/U 명단만 오늘 포함 30일을 읽는다. 30일은 조각 한도(31일) 안이라 비트에 한 번만 묻는다. 정기 주사 명단은 그대로다
- 이 명세는 `specs/patients` AC-604.2의 F/U 기간(120일·조각 넷)만 바꾼다. 그 명세 파일은 고치지 않는다(승인본)
- 요구사항 번호는 다른 창과 겹치지 않게 24xx를 쓴다(2026-11-06 tjtmd-61 창과 나눔)

## 요구사항

### REQ-2401: F/U 명단은 오늘 포함 30일만 한 번에 읽는다
- AC-2401.1: Given 아무 오늘(월초·월말·윤년 2월 29일·연말·연초), When `followupPlan(today)`, Then 조각은 하나이고 `{ from: today − 29일, to: today }`다(오늘 포함 30일, 빈틈·겹침 없음). `FOLLOWUP_DAYS`는 30이다
- AC-2401.2: Given 정기 주사 기록이 없거나 있는 날, When `recallPlan`, Then 지금과 같은 달 조각이다(F/U 기간을 바꿔도 정기 주사 읽기는 바뀌지 않는다)
- AC-2401.3: Given 오늘 포함 30일 조각 하나로 된 가짜 도우미 F/U 답, When Worker가 plan → stored → piece → build를 거치면, Then plan 답의 F/U 조각은 그 하나뿐이고, F/U 보기 모양의 읽은 기간(`read`)이 `{ today − 29일, today }`이며, 지금 사례(같은 환자의 마지막 내원만 봄 · 지난 예정 · 날짜 미정 · 조건부 · 전화 없음)가 그대로 나온다

### REQ-2402: 읽는 중 안내가 30일을 말한다
- AC-2402.1: Given F/U 명단을 읽는 중, When 환자 탭이 안내를 보이면, Then "최근 30일을 읽어요. 다 읽을 때까지 이 창을 열어 두세요."를 보이고 '120일'·'네 번' 글자는 없다

## 범위 밖
- 정기 주사 명단(읽는 달·규칙·36개월 쌓기)
- 메모에 적은 날짜를 진료일부터 120일 안만 날짜로 보는 규칙(`lib/patients/followup.ts` `writtenDate`, AC-602.1). 원본 옮김이라 그대로 둔다
- 도우미(`helper/`)·통로(`lib/bridge`)·확장. 웹이 묻는 기간만 바뀐다
- 기간을 화면에서 고르게 하기
- E2E(`e2e/patients`)는 고치지 않는다(가짜 조각 파일을 따라가므로 같이 맞춰진다)
