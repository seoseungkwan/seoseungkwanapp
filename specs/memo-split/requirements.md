# 요구사항: 비트에 입력 — 환자별 두 칸 보기와 복사(완료)

> 기능 ID: `memo-split` · 형식: 요구사항은 `### REQ-3101: 제목`, 수용 기준은 `- AC-3101.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다. 시험 자료의 이름·차트·글은 지어낸 값이다.

## 배경 / 목표
- 2026-11-08 사용자가 청구 '비트에 입력' 화면을 메디코어처럼 바꾸자고 했다: 지금은 입력할 사람·빠지는 사람 목록(줄을 열고 닫음)과 그 아래 메모 표가 길게 이어져 한참 스크롤해야 한다
- 왼쪽에 환자 목록(따로 스크롤), 오른쪽에 고른 한 사람의 메모·차트·처방을 보이고 ↑↓로 옮긴다. C 키나 초록 [복사(완료)]로 우리 메모를 복사하고 그 환자를 완료로 바꾼다. 사람이 비트 메모 칸에 붙여 넣는다
- 목업: `docs/mockups/memo-split/index.html`(시안 4, 사용자와 네 번 다듬음). 실제 화면은 앱 토큰·`ds.*` 부품으로 같은 모양을 만든다

## 이미 정한 것 (다시 묻지 않는다)
1. 두 칸 보기. 왼쪽 줄에는 환자 정보만(번호·이름·진료일·차트번호·상태 표). 이름 밑 차트 원문·고른 처방, 설정 '목록에 보이기' 칸은 하지 않는다(사용자)
2. C 키 또는 초록 단추 = 우리 메모 복사 + 그 환자 완료. 확인 창 없음. 복사에 성공했을 때만 완료. 옮기기만으로는 완료되지 않는다. 잘못 누르면 [완료 풀기](사용자)
3. 초록 단추 이름은 **복사(완료)**, 완료한 뒤에는 **다시 복사**(사용자)
4. 우리 메모·비트 메모 두 칸은 같은 크기로 나란히, 복사 단추와 [완료 풀기]는 두 칸 위(사용자)
5. 처방코드별에서 코드 단추를 고르면 그 처방이 있는 환자만 나온다(지금 기능 그대로). 왼쪽 위 [전체 · 미완료 · 완료]로 골라 본다(사용자)
6. 색: 흰 바탕·옅은 회색 구획 / 파랑 = 고른 환자·지금 위치 / 초록 = 완료 단추·완료 / 주황 = 확인 필요 / 복사 실패 = 기존 오류색. 색만으로 알리지 않고 늘 글자(✓ 완료, ! 확인 필요, ✕ 복사 못 함)를 같이 쓴다(사용자)
7. 아래는 Claude가 정했고 목업에 보였다: 알림은 떠 사라지는 알림 대신 초록 단추 밑 상태 줄 한 곳 / 처음 보기는 [전체] / 미완료 보기에서 방금 완료한 사람은 다른 사람으로 옮길 때까지 남는다 / 확인 표시가 남았거나 빈 메모는 복사를 막는다 / 메모를 고치면 완료가 풀린다(지금 규칙 AC-2202.1 그대로) / 입력 방식은 두 칸 위 한 줄 / 자동 입력 단추는 흰 단추이고 완료한 사람을 뺀 수다

## 요구사항

### REQ-3101: 두 칸 보기 — 왼쪽 환자 목록
- AC-3101.1: Given 메모 보기가 왔고 입력 단계가 '고르기'(`pick`), When 그리면, Then 메모 칸은 위 도구 줄과 그 아래 두 칸이다. 왼쪽은 '환자 목록'(`aria-label`), 오른쪽은 '고른 환자 메모'다. 1024px 이상에서는 나란히(왼쪽 360px 안팎), 그보다 좁으면 위아래다. 두 칸은 각자 스크롤되고 높이는 화면 높이에 맞춰 정해져 페이지가 목록 길이만큼 늘지 않는다
- AC-3101.2: Given 고른 조건의 환자(`targets`의 입력할 사람 + 빠지는 사람 묶음), When 왼쪽을 그리면, Then 묶음 차례는 입력할 사람 → 확인 필요 → 다른 메모 있음 → 직접 입력 → 지난번 건너뜀 → 비트 메모를 읽지 못함 → 이미 입력됨 → 메모 없음이고, 묶음마다 머리(이름 · 'n명', 보기로 걸러지면 'n / 전체명')가 목록을 내려도 위에 붙어 있다. 사람이 없는 묶음은 없다
- AC-3101.3: Given 목록 한 줄, When 그리면, Then 줄은 단추 하나이고 번호(입력할 사람 묶음에서만 1부터)·이름·진료일(`M/D (요일)`)·차트번호·상태 표만 있다. 차트 원문·처방 이름·메모 글은 없다. 상태 표는 복사 실패면 '✕ 복사 못 함', 완료면 '✓ 완료', 확인 표시가 남았으면 '! 확인 필요', 입력할 사람 가운데 메모 바꿈이면 '! 메모 바꿈', 새 메모면 '새 메모'다(뒤 셋은 하나만)
- AC-3101.4: Given 고른 환자, When 그리면, Then 그 줄은 파란 바탕·왼쪽 굵은 파란 선·이름 굵게이고 `aria-current="true"`다. 다른 줄은 `"false"`다. 고른 줄이 목록 밖에 있으면 보이게 목록을 움직인다
- AC-3101.5: Given 목록 위 [전체 n · 미완료 n · 완료 n](눌린 것 `aria-pressed`), When 화면을 처음 열면, Then [전체]가 눌려 있다. 미완료·완료를 누르면 그 줄만 남고 맨 위 사람이 골라진다. 수는 지금 고른 조건 안의 사람 수다
- AC-3101.6: Given [미완료] 보기에서 고른 사람을 완료함, When 다시 그리면, Then 그 사람은 다른 사람으로 옮길 때까지 목록에 남는다. 옮긴 뒤에는 빠진다
- AC-3101.7: Given 보일 사람이 없음, When 그리면, Then 왼쪽에 까닭 글이 있다: 조건 안내(`targets.problem`)가 있으면 그 글, 보기가 미완료면 '모두 완료했어요.', 완료면 '완료한 환자가 없어요.', 그 밖은 '이 조건에 맞는 진료가 없어요.'. 오른쪽은 '목록에 보여 줄 환자가 없어요.'다
- AC-3101.8: Given 고른 조건·보기가 바뀌어 새 목록이 옴, When 고른 사람이 새 목록에 있으면, Then 그 사람을 그대로 고른다. 없으면 맨 위 사람을 고른다. 메모 보기를 다시 받아도(저장 뒤 등) 고른 사람·목록 스크롤은 그대로다

### REQ-3102: 사람 옮기기
- AC-3102.1: Given 목록의 줄, When 누르면, Then 그 사람이 골라지고 오른쪽 상세가 그 사람으로 바뀌며 맨 위로 간다
- AC-3102.2: Given 오른쪽 위 [↑ 앞 사람]·[↓ 다음 사람], When 누르면, Then 지금 보이는 목록 차례로 앞·뒤 사람으로 옮긴다. 맨 앞이면 [↑ 앞 사람], 맨 뒤면 [↓ 다음 사람]이 막힌다
- AC-3102.3: Given 고르기 단계, When ↑·↓ 키를 누르면, Then AC-3102.2와 같고 페이지는 스크롤되지 않는다(`preventDefault`)
- AC-3102.4: Given 초점이 글 칸(`textarea`)·글자 칸(`input`, 동그라미 단추 제외)·고르는 칸(`select`)에 있거나, Ctrl·Alt·⌘를 함께 누르거나, 확인 표시 알림 창이 떠 있거나, 입력 중·확인 기다리는 중·결과 화면이면, When ↑·↓·C를 누르면, Then 옮기지도 복사하지도 않는다(그 칸의 보통 동작 그대로). 입력 방식 동그라미에 초점이 있어도 ↑↓는 환자를 옮기고 방식은 바뀌지 않는다
- AC-3102.5: Given 화면을 연 뒤 사람이 처음으로 줄을 누르거나 옮김, When 그때, Then 비트 메모를 한 번 저절로 읽는다(지금 AC-018.27의 '처음 열 때'를 '처음 고를 때'로). 화면을 열 때 맨 위 사람이 저절로 골라지는 것으로는 읽지 않는다. 입력 중이면 읽지 않고, 두 번째부터는 읽지 않으며, 실패해도 저절로 다시 읽지 않는다

### REQ-3103: 복사(완료)
- AC-3103.1: Given 고른 사람에게 우리 메모 글이 있고(`hasMemo`이고 빈 메모가 아님) 확인 표시가 없음(`unfinished` 거짓), When 초록 [C 복사(완료)]를 누르거나 C 키를 누르면(한글 자판이어도 같은 자리 키, 눌러 둔 채 반복은 무시), Then 확인 창 없이 그 사람의 우리 메모(고치던 글이 있으면 그 글)가 클립보드에 들어간다
- AC-3103.2: Given AC-3103.1의 복사가 성공, When 답이 오면, Then Worker에 `memoCopied`(그 내원번호와 복사한 글)를 보내고 메모 보기를 다시 받는다. 그 사람은 '✓ 완료'이고, 단추는 [C 다시 복사]가 되며 옆에 [완료 풀기]가 생긴다. 상태 줄은 '✓ 복사했고 완료했어요. 비트 메모 칸에 붙여 넣으세요.'다
- AC-3103.3: Given 복사가 실패(클립보드가 거절·없음, 예비 방법도 실패), When 답이 오면, Then Worker에 아무것도 보내지 않고 완료로 바뀌지 않는다. 그 사람 줄에 '✕ 복사 못 함'이 남고, 상태 줄은 오류색으로 '✕ 복사하지 못했어요. 완료로 바뀌지 않았어요. 다시 눌러 주세요.'(`role="alert"`)다. 이미 완료였던 사람이면 '✕ 다시 복사하지 못했어요. 완료는 그대로예요. 다시 눌러 주세요.'다. 그 사람 복사가 성공하면 '✕ 복사 못 함'이 지워진다
- AC-3103.4: Given 복사가 오래 걸림, When 기다리는 동안, Then 단추는 '복사 중…'으로 막히고 C도 무시된다. 그사이 다른 사람으로 옮겨도 결과(완료·실패)는 누른 사람에게 붙는다
- AC-3103.5: Given 확인 표시가 남은 사람, When 그리면, Then 초록 단추가 막히고 상태 줄은 주황으로 '! 확인 표시가 남아 있어 복사할 수 없어요. [메모 고치기]로 표시를 지운 뒤 눌러 주세요.'다. 우리 메모가 없는 사람은 단추가 막히고 '우리 메모가 없어 복사할 게 없어요.'다. 둘 다 C를 눌러도 아무 일이 없다
- AC-3103.6: Given 입력 중·확인 기다리는 중이거나 저장이 막혀 있음(`storeStuck`), When 그리면, Then 초록 단추·[완료 풀기]가 막히고 C도 무시된다. 상태 줄은 '입력 중에는 복사할 수 없어요.' 또는 '저장이 막혀 있는 동안에는 복사할 수 없어요.'다
- AC-3103.7: Given 상태 줄, When 다른 사람으로 옮기면, Then 앞 사람의 잠깐 글('복사했고 완료했어요'·'완료가 풀렸어요')은 지우고 새 사람의 상태를 보인다. 복사 실패는 그 사람에게 남는다. 다른 경우의 상태 줄: 완료면 '✓ 완료한 환자예요. 다시 복사해도 완료는 그대로예요.', 아니면 '누르면 우리 메모가 복사되고 완료로 바뀌어요. 그다음 비트 메모 칸에 붙여 넣으세요.'
- AC-3103.8: Given 고른 사람의 메모를 고치는 중, When 그리면, Then 초록 단추는 막히고 상태 줄은 '우리 메모를 고치는 중이에요. 칸 밖을 누르면 반영돼요.'다

### REQ-3104: 완료 저장·풀기 (Worker)
- AC-3104.1: Given `memoCopied`(내원번호·글), When 그 진료의 지금 우리 메모가 그 글과 같고 빈 메모·확인 표시가 아니며 아직 완료가 아니면, Then 자동 입력이 '완료'로 끝난 사람과 같게 완료로 둔다: 완료 표시를 더하고 완료 풀림을 지우며, 그 달 칸 `done`에 그 글을 두고 그 달을 store.save로 보낸다. 같지 않으면 아무것도 바꾸지 않는다. 이미 완료면 바꾸지 않고 보내지 않는다(다시 복사)
- AC-3104.2: Given `memoUndone`(내원번호), When 그 사람이 완료 표시로 완료(비트 메모가 우리 메모와 같아서가 아님)면, Then 지금 '고쳐서 완료를 푼 것'(AC-2202.1)과 같게 푼다: 완료 표시를 지우고 그 달 칸 `done`에 false를 두어 store.save로 보낸다. 아니면 아무것도 하지 않는다
- AC-3104.3: Given 화면, When 완료가 비트 메모와 같아서인 사람(비교 '같음')을 그리면, Then [완료 풀기]가 없다(풀어도 다시 완료이므로)
- AC-3104.4: Given 복사로 이 불러오기 안에서 새로 완료한 사람, When 메모 보기를 다시 만들면, Then 그 사람은 완료 전과 같은 묶음·같은 차례에 있고 줄에 완료(`done: true`)가 있다. 이미 완료였던 사람을 다시 복사한 것은 해당하지 않는다. 새 [자료 불러오기]가 시작되면 이 기억은 지워진다
- AC-3104.5: Given 완료인 사람(복사로 완료 포함), When [비트에 입력]을 누르면, Then 묶음에 들지 않는다. 단추의 수 N과 '그중 ✓ 완료' 수는 입력할 사람 묶음의 완료를 빼고·세고, '다른 메모 n명은 우리 메모로 바뀌고' 수도 완료를 뺀다. 입력할 사람이 모두 완료면 0명 안내는 '…입력할 환자가 없습니다. (완료한 환자와 메모가 없는 환자는 뺍니다)'다
- AC-3104.6: Given 완료인 사람의 메모를 고침, When 칸 밖을 누르면, Then 지금처럼 완료가 풀리고(AC-2202.1), 그 사람의 상태 줄은 주황으로 '! 메모를 고쳐서 완료가 풀렸어요. 고친 메모를 다시 복사(완료)해 주세요.'다. '복사했어요' 글은 지운다

### REQ-3105: 오른쪽 — 고른 환자 상세
- AC-3105.1: Given 고른 사람, When 오른쪽을 그리면, Then 맨 위에 '{묶음 이름} {i} / {n}'(파랑), 이름(크게)과 상태 표(AC-3101.3과 같은 것), '진료일 {M/D (요일)} | 차트 {번호}'가 있고, 오른쪽에 [↑ 앞 사람]·[↓ 다음 사람]과 '키보드 ↑ ↓'가 있다. 입력할 사람 묶음이 아니면 그 묶음의 까닭 글(지금 `LEFT_GROUPS`의 글)이 머리 아래 있고, 직접 입력이면 '같은 날 진료 n건' 또는 '지난 입력 때 PC가 찾아냈어요.', 점검 경고가 있으면 '점검 경고 있음 · 입력은 돼요'가 있다
- AC-3105.2: Given 고른 사람, When 그리면, Then 그 아래 단추 줄(옅은 회색 칸)에 초록 복사 단추(`<kbd>C</kbd>`와 함께), 완료면 [완료 풀기], 오른쪽에 [메모 고치기](우리 메모 글이 있을 때), [바꾸지 않기](입력할 사람 가운데 메모 바꿈), [이 메모로 바꾸기](다른 메모 있음 묶음), [다시 하기 (n명)](지난번 건너뜀 묶음)가 있고, 단추 줄 맨 아래가 상태 줄이다. 각 단추의 동작·막힘은 지금 그대로다
- AC-3105.3: Given 고른 사람, When 그리면, Then 단추 줄 아래에 같은 크기 두 칸이 나란히 있다: 왼쪽 '우리 메모'(글, 없으면 '우리 메모가 없어요.'), 오른쪽 비트 메모 칸(지금 `BitMemoCard` 내용 그대로). 우리 메모 칸 아래에 빠진 문장이 있으면 '빠진 문장: …', 저장되지 않은 고친 글이면(저장이 막혔거나 저장 실패일 때) '저장 안 됨', 완료가 아니고 지난 입력 기록이 있으면 '지난 입력: {확인 필요·건너뜀·직접 확인·쓰다 멈춤}'이 있다
- AC-3105.4: Given [메모 고치기], When 누르면, Then 우리 메모 칸이 그 자리에서 고치는 칸(파란 테두리, `aria-label="{이름} 우리 메모 고치기"`, 초점)이 된다. 칸 밖을 누르면 지금처럼 반영되고(같은 글이면 보내지 않음) 칸 밖을 누른 그 클릭(다른 사람 줄·다음 사람)도 먹힌다. 입력 중에는 읽기 전용이다
- AC-3105.5: Given 고른 사람, When 그리면, Then 그 아래 '증상 · 차트 원문 {n}줄' 표(종류 이름표 | 원문, 바탕색 없음, 시술 줄의 이름표는 굵게)와 '처방내역 {n}줄 · 시술 {n}' 표(종류 · 코드 · 처방명(짧은 이름) · 총투여량 '×n'(못 읽으면 '×?') · 급여/비급여)가 2 : 3 너비로 나란히 있다. 줄 차례는 지금 그대로다(처방은 시술 → 약제 → 기타)
- AC-3105.6: Given 다른 화면의 [메모 확인에서 고치기]로 온 사람(`focusKey`), When 메모 칸을 열면, Then 그 사람이 골라지고 고치는 칸이 열려 있다
