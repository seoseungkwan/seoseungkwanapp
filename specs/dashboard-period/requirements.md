# 요구사항: 대시보드 기간 고르기 (기간별 흐름에 일별·주별·월별 + 달·해 고르기 + 직접 날짜)

> 기능 ID: `dashboard-period` · 형식: 요구사항은 `### REQ-1801: 제목`, 수용 기준은 `- AC-1801.1: Given/When/Then`.
> 각 AC 는 테스트 하나 이상으로 검증되어야 하며, 테스트 이름에 AC ID 를 넣는다.
> 사용자: "계획은 최소화해" — 짧게 쓴다. 시험의 오늘은 `2026-11-06`(금), 어제는 `2026-11-05`, 손에 든 숫자의 첫날(오늘 − 100)은 `2026-07-29`다.

## 배경 / 목표
- 2026-11-06 사용자 승인(대화): 고르기 모양은 통계 탭과 같게, 자리는 빠른 단추와 같은 줄, 처방 상위 날짜 줄은 설명 바로 아래. 이 PC에는 승인 기록 훅이 없어 `approval.json`은 없다
- 대시보드 '기간별 흐름'은 지금 [최근 7일][최근 30일][최근 90일]뿐이다. 총괄은 통계 탭처럼 딱 정한 달·해를 보고, "내가 원하는 기간도 볼 수 있게" 하고 싶다
- 고르기 부품은 통계 탭 것(`stats-period`의 `PeriodPicker`·`periodPick`, 승인 시안 `BEpX6zDbmmBmvBhZqCKmno`)을 그대로 쓴다. 처방 상위 날짜 줄은 사용자 승인 시안("설명 바로 아래")이다
- 서버 표·API·마이그레이션을 더하지 않는다. 저장된 일 숫자 읽기(`readDays`)만 쓴다
- `specs/bit-dashboard` 범위 밖의 '100일보다 옛날 날짜 고르기, 기간별 흐름의 날짜 직접 지정'은 기간별 흐름에 한해 이 명세가 맡는다. 하루 날짜 고르기(bit-dashboard REQ-605, 오늘 ~ 100일 전)는 그대로다
- 구현은 `feat-stats-period`를 이 브랜치에 합친 뒤에 시작한다(tasks.md '먼저 할 일')

## 이미 정한 것 (다시 묻지 않는다)
1. 빠른 단추 셋은 그대로이고 지금과 똑같이 셈한다(오늘 − N ~ 어제). 옆에 통계 탭과 같은 고르기: [일별][주별][월별] + `◀ 2026년 10월 ▶`(월별은 `◀ 2026년 ▶`) + [직접 날짜]. 한도·규칙도 통계 탭과 같다(2020-01-01부터, 직접 날짜 일별 92일까지, 한 번에 5년까지, 한 주는 월–일, 잘린 주·끝나지 않은 달은 '일부 기간')
2. 그래프 넷(환자 수 추이·신환 재방문율·요일별 환자 수·처방 상위)이 고른 기간을 따른다
3. 처방 상위 설명 바로 아래 한 줄 `{기간 글} · 자료 있는 N일`
4. 고른 것은 저장하지 않는다. 처음은 최근 30일. 원장님 보고 문장·오늘 하루 분석·하루 날짜 고르기는 그대로
5. 바로 전·작년 비교는 대시보드에 더하지 않는다

## 요구사항

### REQ-1801: 기간 고르기 자리와 처음 모양
- AC-1801.1: Given 대시보드를 처음 엶, When 기간별 흐름을 그리면, Then [최근 30일]만 눌려 있고(aria-pressed) 고르기의 [일별][주별][월별]·[직접 날짜]는 안 눌려 있으며 기간 글·그래프 넷은 지금과 같다. 고른 것은 브라우저 저장소·주소·서버에 쓰지 않아 새로 열면 늘 최근 30일이다
- AC-1801.2: Given 그래프가 그려진 기간별 흐름(저장 숫자·비트 숫자, 읽었는데 자료 없는 빈 틀 포함), When 그리면, Then 머리 줄(h2·기간 글·빠른 단추)의 빠른 단추 바로 오른쪽, 같은 줄에 통계 탭의 `PeriodPicker`가 있다(통계 탭처럼. 폭이 모자라면 고르기 묶음이 통째로 다음 줄로 가고 묶음 안에서는 꺾이지 않는다). [일별]을 누르면 2026년 10월 일별이 되고 빠른 단추는 모두 안 눌림이며, 그 뒤 [최근 7일]을 누르면 고르기가 풀리고 [최근 7일]만 눌린다. 연결 전·처음 읽는 중·처음 읽기 실패('…생기는 것 4가지' 목록)에는 고르기가 없고 빠른 단추만 지금처럼 있다
- AC-1801.3: Given 손에 든 숫자, When 끝난 마지막 날을 정하면, Then 오늘 줄이 있고 `partial: false`면 오늘(2026-11-06), 아니면 어제(2026-11-05)이고 이 날을 `PeriodPicker`의 `lastDay`로 넘긴다. 그래서 ▶·[직접 날짜] 판의 `max`·'어제(11월 5일)까지만 고를 수 있어요.' 글이 통계 탭과 같다
- AC-1801.4: Given 고른 기간, When 머리 줄 기간 글을 그리면, Then 오늘과 같은 해는 해 없이('10월 1일 – 31일', '9월 3일 – 10월 2일'), 다른 해는 앞에 해('2025년 10월 1일 – 31일'), 해를 넘으면 양 끝에 해('2025년 12월 20일 – 2026년 1월 10일')다. 끝나지 않은 달·해는 뒤에 ' (어제까지)'(끝난 날이 오늘이면 ' (오늘까지)')가 붙는다('11월 1일 – 5일 (어제까지)', 2026년 → '1월 1일 – 11월 5일 (어제까지)'). 직접 날짜에는 붙지 않는다. 빠른 단추일 때 글은 지금과 한 글자도 같다('10월 7일 – 11월 5일')
- AC-1801.5: Given 폭 768px 미만, When 그리면, Then 빠른 단추는 지금처럼 다음 줄 전체 폭 세 칸이고, 고르기는 통계 탭처럼 한 줄씩 전체 폭·누름 칸 44px이며 [직접 날짜] 판은 단추 바로 아래 문서 흐름 안이다. 768px 이상에서 고르기 줄은 오른쪽에 붙고 판은 단추 아래 뜬 판이다. 390·1440px 어느 쪽도 쪽이 옆으로 밀리지 않는다

### REQ-1802: 그래프 넷이 고른 기간을 따름
- AC-1802.1: Given 2026년 10월 일별, When 환자 수 추이를 그리면, Then 설명은 '신환·재진, 하루씩'이고 자료 있는 날마다 한 칸이다(줄 없는 날은 칸이 없다, 지금 대시보드와 같다). 아래 날짜 글자는 기간이 31일 이하면 첫날부터 7일마다, 넘으면 21일마다다. 칸이 7개를 넘으면 막대 위 합계가 없다(`dense`). 기간 안 줄이 없으면 지금 빈 틀 + '자료 없음'이고 눈금은 일별일 때만 있다
- AC-1802.2: Given 2026년 10월 주별, When 그리면, Then 설명 '신환·재진, 한 주씩', 칸은 월–일 주를 기간으로 자른 다섯(10-01~10-04 · 10-05~10-11 · … · 10-26~10-31)이고 잘린 첫·끝 주는 '일부 기간'이다. 해 2026년은 '신환·재진, 한 달씩'·1월~12월이고 11월은 '일부 기간', 12월은 달 글자만 있는 빈 칸이다. 값은 칸 안 자료 있는 날의 합이고, partial 줄이 든 칸도 '일부 기간', 줄이 하나도 없는 주·달은 막대 자리에 '–'다(0이 아니다). '일부 기간' 칸이 있으면 범례에 '일부 기간'이 더해진다
- AC-1802.3: Given 고른 기간, When 신환 재방문율을 그리면, Then 7·14·30일 줄 모두 고른 기간의 날로 센다(30일 줄을 앞 기간으로 옮기지 않는다). 그 값이 아직 없는(null) 날은 빼고, 모두 없으면 '집계 중', 기간에 줄이 없으면 '자료 없음'이다. 뺀 날이 있는 비율 줄 아래에는 '온 뒤 {7|14|30}일이 안 된 날의 신환은 빼고 셌어요'가 붙는다. '온 뒤 30일이 지난 가장 최근 신환' 글은 최근 30일에만 있다(지금 그대로)
- AC-1802.4: Given 고른 기간, When 요일별 환자 수·처방 상위를 그리면, Then 고른 기간 안 날만 센다. 요일 평균·묶음 합 규칙과 '자료 없음'·'다시 불러와야 숫자가 나와요'·묶음 글·링크는 지금 그대로다
- AC-1802.5: Given 빠른 단추, When 그래프 넷을 그리면, Then 지금 대시보드 시험(`src/components/dashboard/**`)이 기대값을 바꾸지 않고 통과한다

### REQ-1803: 처방 상위 날짜 줄
- AC-1803.1: Given 최근 30일, 기간 안 자료 있는 날 26일, When 처방 상위를 그리면, Then 설명 "통계 탭에서 묶은 치료 중 많이 한 순서예요" 바로 아래 한 줄이 '10월 7일 – 11월 5일 (어제까지) · 자료 있는 26일'이다. 최근 7일·90일도 끝에 ' (어제까지)'가 붙은 같은 모양이다
- AC-1803.2: Given 2026년 10월(자료 있는 날 26일), When 그리면, Then '10월 1일 – 31일 · 자료 있는 26일'이고, 끝나지 않은 11월(1–5일 가운데 4일)은 '11월 1일 – 5일 (어제까지) · 자료 있는 4일'이다. 앞의 기간 글은 머리 줄 기간 글과 같다
- AC-1803.3: Given 날짜 줄, When N을 세면, Then N은 기간 안 일 줄이 있는 날 수(같은 날 두 줄은 하루)이고 `groupRank`가 센 날과 같다. 기간 안 줄이 없으면 날짜 줄은 '{기간 글}'뿐이고 가운데는 지금처럼 '자료 없음'이다. 묶음을 읽지 못함·묶음 없음·다시 불러와야 함에도 날짜 줄은 같은 규칙이고 가운데 글·링크는 지금 그대로다. 옛 기간을 읽는 중·읽기 실패에는 '{기간 글}'뿐이다

### REQ-1804: 옛 기간 읽기
- AC-1804.1: Given 고른 기간의 첫날이 손에 든 숫자의 첫날(2026-07-29)과 같거나 뒤(2026년 8월·10월, 그 안의 직접 날짜, 빠른 단추 셋), When 그리면, Then 새로 읽지 않고 손에 든 숫자(저장 숫자, 비트 PC면 비트 숫자)로 그린다
- AC-1804.2: Given 첫날이 그보다 앞(2026년 7월·2025년), When 고르면, Then 저장 숫자를 고른 기간으로 한 번 읽는다(`readDays`, 10초 한도). 읽는 동안 그래프 넷은 빈 틀 가운데 '읽는 중'이고 숫자를 지어내지 않는다. 다 읽으면 읽은 줄에 손에 든 숫자를 얹어(같은 날은 손에 든 것) 그린다. 같은 기간에서 단위만 바꾸면(일별 → 주별) 다시 읽지 않고, 읽는 중에 다른 것을 고르면 앞 답은 버린다
- AC-1804.3: Given 그 읽기가 실패하거나 10초 안에 끝나지 않음, When 그리면, Then 고르기 아래에 오류 카드(`E-STATS-READ-FAILED`, 새 번호 없음)와 [이 기간 다시 읽기]가 있고 그래프 넷은 '자료 없음' 빈 틀이다(손에 든 일부 날만으로 그리지 않는다). 다시 읽는 동안 단추는 '다시 읽는 중'으로 막히고, 성공하면 카드가 없어진다. 읽었는데 줄이 없으면 카드 없이 '자료 없음'이다
- AC-1804.4: Given 비트 PC, When 기간을 고르면, Then 비트 읽기(`stats.rows`, 오늘 − 100 ~ 오늘)는 지금처럼 열 때와 [다시 읽기]에만 하고 고르기로는 하지 않는다. 옛 기간 읽기는 저장 숫자를 받아 오기만 하고 아무것도 보내지 않는다. 새 표·RPC·API 경로가 없다

### REQ-1805: 그대로인 것과 불러오기 고리
- AC-1805.1: Given 고른 기간, When 대시보드를 보면, Then 원장님 보고 문장·오늘 하루 분석·하루 날짜 고르기는 고르기 전과 같다(고른 기간을 쓰지 않는다)
- AC-1805.2: Given `components/dashboard/summary/*`(시험 밖), When 불러오는 곳을 보면, Then `view.ts`는 `components/stats`를 부르지 않는다(통계 `view.ts`가 이 파일을 불러 고리가 생긴다). 통계 쪽을 부르는 곳은 `flow.ts`(`periodPick`·`view`)와 `DashboardAnalysis.tsx`(`PeriodPicker`) 둘뿐이고, 대시보드 불러오기 허락 목록에는 그 줄과 `ErrorCard`·새 파일 둘(`flow`·`usePeriodDays`)만 더한다. 통계 탭 파일은 고치지 않는다

## 범위 밖
- 바로 전·작년 비교, 고른 기간 보고 문장(통계 탭에만 있다)
- 고른 기간 기억하기(다시 열면 늘 최근 30일)
- 하루 날짜 고르기를 100일보다 옛날로 넓히기
- 비트 읽기 범위 넓히기(비트 PC도 옛 기간은 저장 숫자로 본다)
- 휴진한 날과 저장하지 않은 날 가르기(대시보드는 덮은 기간을 읽지 않는다. 통계 탭이 한다)
- 연결 전 안내 글('기간 단추로 7일·30일·90일을 바꿔 볼 수 있어요') 바꾸기
- 새 서버 표·API·마이그레이션, 옛 기간 읽기의 10초 한도 늘리기
