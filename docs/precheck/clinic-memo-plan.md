# 병원마다 맞추는 청구메모·문자 문구 계획

> 2026-10-31 총괄과 질문·답으로 정한 내용이다. 아직 명세 전이고, 사전점검 3단계(`precheck-3-memo`) 명세를 고칠 때 넣는다. 화면은 클릭 목업 승인 뒤에 만든다.
> 바탕: 원본 양지바른 사전점검(`seoseungkwan/shared` `YangjiBareun_사전점검/`)의 문구 설정(`tools/claim_hospital_settings.js`, `assets/mx999_v22.html`의 `TPL`·`CODEMAP`)과 변경 기록(`README.txt`).

## 1. 무엇을 바꾸나

- 지금 메모 방식과 기본값은 우리 병원 하나에 맞춰져 있다. 이것을 **병원마다** 자기 방식으로 쓰게 한다(직원마다가 아니다. 한 병원은 계정 하나).
- 범위: 청구메모 + 문자 문구. 삭감 예방 점검 규칙과 추천 상병은 지금 계획 그대로다.
- 진료 프로그램은 비트만 생각한다. 다른 프로그램은 나중에 정한다.

## 2. 가입 질문

- 새 병원은 가입 뒤 질문에 답해서 자기 설정을 만든다. **우리 병원도 똑같이 질문부터** 한다(지금 설정을 그대로 옮기지 않는다).
- 순서: 먼저 둘 중 하나로 답을 미리 채운다 → 그다음 질문을 하나씩 확인한다.
  - **예전 메모 붙여 넣기**: 그 병원이 쓴 메모 몇 줄을 붙여 넣으면 좌우·레벨·모양을 읽어 답을 채운다. 브라우저 안에서만 읽고, AI에 보내지 않고, 저장하지 않는다. 모양이 섞인 항목(예: Rt와 우측)은 채우지 않고 질문에서 고르게 한다.
  - **예시 고르기**: 가짜 진료 3건(신경차단술·관절 주사·연골주사)을 모양 4가지로 보여 주고 가장 비슷한 것을 고른다. 글 시안은 `clinic-memo-samples.md`(2026-11-01). 고르면 메모 모양만 채우고, 시술별로 넣을 약은 약 질문에서 따로 묻는다.
- 질문은 묶음마다 쪽을 나누고 남은 양을 보인다. 보기를 고를 때마다 아래 예시 메모가 바로 바뀐다. 중간에 나가도 이어서 한다.
- 건너뛸 수 있고, 설정 화면에서 언제든 다시 할 수 있다. 다시 하면 바뀔 것을 보여 주고 확인받는다. **건너뛴 병원은 질문을 마칠 때까지 메모를 만들지 않는다**('처음 질문을 먼저 해 주세요').

## 4. 기호

- 쓸 수 있는 자리 네 곳, 자리마다 쓸지와 무엇을 쓸지 병원이 고른다: **줄 맨 앞**(◈ MBB …), **구분**(레벨·시술·약 사이), **묶음**(약을 감싸는 ( ) [ ] < >), **줄 끝·메모 끝**.
- 등록: 자주 쓰는 기호(◈ ◆ ▶ → - · * ※ □ …)를 누르거나 직접 적는다. 청구 파일에 못 들어가는 글자는 막고 이유를 알려 준다.
- 줄 앞 기호는 시술 종류마다 다르게 정할 수 있다(기본은 모두 같음. 예: 신경차단술 ◈, 관절 주사 ▶, 사유 ※).

## 5. 차트 줄임말 바꾸기

- 원본이 이미 아는 바꾸기(예: `Cmbb 456 → MBB C 4,5,6`, `Lmbb 45s1 → MBB L4,5,S1`)는 기본으로 두고, 병원이 '이 말 → 이렇게'를 더한다.
- 바꾸기는 **원장님마다** 따로 둘 수 있다(비트 담당 의사로 구분 — 비트에서 담당 의사를 읽을 수 있는지 만들 때 확인). 메모 모양은 병원 하나다.
- 차트에서 못 읽은 말은 그 메모에 [확인] 표시를 남기고, 그 자리에서 뜻을 정한다.

## 6. 조건 조각 (새 사유·새 전용 규칙)

- 조각을 골라 '그리고 / 또는'으로 잇는다.
- 조각: 같은 날 [처방]과 [처방]이 같이 있음, [처방]을 [며칠] 안에 다시 함, [처방] 양이 [얼마] 이상, 차트에 [낱말]이 있음, [부위]·[좌우](예: 무릎일 때, both일 때, 부위가 2곳 이상).
- 보험 종류·초진/재진·회차·상병 조각은 넣지 않는다.

## 7. 확인과 쓰면서 바뀌는 것

- 질문을 마치면 두 번 확인한다: ① 가짜 진료로 만든 메모(틀린 줄을 누르면 그 질문으로 돌아감) ② 비트 연결 뒤 지난 몇 주 진료로 만든 메모와 그 병원이 실제로 쓴 메모를 나란히 비교하고, 다른 곳만 보여 설정을 고치도록 추천(그 PC에서만).
- 같은 모양의 고침이 3번 이상 되풀이되면 '앞으로 이렇게 쓸까요?'를 묻고, 예를 누르면 설정을 바꾼다.
- **앱에서 자유롭게 고친다(2026-11-01 총괄 요구).** 가입 보기로 채운 값, 시술별 약과 자리, 문구 글자를 모두 나중에 설정 화면에서 고칠 수 있다. 가입 보기 글과 안내 문구도 코드를 고치지 않고 총괄이 앱 안에서 고친다. `clinic-memo-samples.md`의 글은 최종본이 아니라 처음 넣는 기본값이다.
- 설정을 바꾸면 **다음에 만드는 메모부터** 바뀐다. 이미 만든 메모는 그대로다. 여기서 '이미 만든 메모'는 사람이 고쳤거나 완료한 메모다(도우미에 저장되는 것). 손대지 않은 자동 메모는 저장하지 않으므로 새 설정으로 다시 만든다(원본 `protectWork`와 같다).
- 설정을 저장할 때마다 날짜와 바뀐 칸을 기록하고, 예전 설정으로 되돌릴 수 있다(최근 30번).
- 설정 옮기기: 병원이 직접 파일로 내보내기·가져오기(바뀔 것 확인, 처방은 보험 코드로 맞춤) + 부탁하면 운영자가 관리자 화면에서 옮겨 준다.
- 메모가 청구 파일 글자 수 한도를 넘으면: 문구를 적을 때 미리 알리고, 넘은 메모는 비트에 자동으로 넣지 않고 [길이 확인]으로 남긴다(총괄이 고르지 않아 Claude가 정함).

## 8. 만드는 때와 확인 방법

- 사전점검 **3단계를 만들 때 처음부터** 병원별로 함께 만든다(3단계 명세를 고친다).
- 원본과 같은지: 우리 병원이 가입 질문에 답해 나온 설정으로 만든 메모가 원본 메모와 같은지 골든 시험으로 확인한다. 약은 일부러 다르다. 원본은 병원 전체에서 주사약으로 표시한 약을 그날 메모에 묶어 넣고, 시술이 2종 이상인 날은 비운 뒤 검토로 돌린다(`ambiguousDrug`). 정하지 않은 약은 메모에 표시하지 않는다. 새 방식은 §3 약과 §9를 따른다. 이 차이는 골든 파일의 `knownDiffs`에 적는다.
- 설정은 환자 정보가 아니므로 지금처럼 서버 설정 표(병원마다 한 줄, RLS)에 둔다. 붙여 넣은 메모·차트·비교는 PC 밖으로 나가지 않는다.
- 화면(가입 질문·설정·비교)은 클릭 목업을 먼저 승인받는다.

## 9. 메디코어·양지바른에서 참고한 것 (2026-11-01 조사)

바탕: `seoseungkwan/shared`의 `YangjiBareun_사전점검/`(`2a1069b`)와 `MediCore_사전점검/`. 코드를 읽어 확인했고 프로그램을 실행하지는 않았다. 시험 본문과 큰 파일(`mx999_v22.html`)은 낱말로 찾은 곳만 봤다.

**같은 날 시술이 2개 이상이고 약이 있을 때 (Claude가 제안, 2026-11-01 총괄 승인):**

- 원본은 어느 시술에 쓴 약인지 처방만으로 알 수 없다고 보고 약을 메모에서 비운 뒤 검토로 돌린다(`ambiguousDrug`, 시험 `test_multiple_procedure_drug_link_is_held_and_not_misattributed`).
- 새 방식: 그날 시술 중 그 약을 '넣기'로 정한 시술이 하나뿐이면 병원 설정을 따라 그 시술에 넣는다. 둘 이상이거나 아직 정하지 않은 시술이 있으면 넣지 않고 `[약 확인: 약 이름]`을 남긴다. 모두 '빼기'면 뺀다.
- 위험: 병원 설정과 실제로 쓴 시술이 다른 날에는 메모가 틀린다. 설정 화면에서 이 점을 알린다.
- 확인 표시가 남은 메모는 비트에 자동으로 넣지 않는다(원본 `unresolved`와 같다).

**가져올 것:**

- 고치기 흐름: 초안 → 검사 → 전후 미리 보기 → 바뀐 칸 확인 → 저장. 기본값·예전 설정·가져오기·추천도 모두 초안으로만 들어온다.
- 칸마다 쓸 수 있는 낱말 목록과 검사(`tokens`, `validate`). 미리 보기는 실제 메모를 만드는 함수로 한다.
- 사람이 만진 것 지키기: 고쳤거나 완료한 메모 고정(`protectWork`), 처방 코드의 정체가 같을 때만 설정 유지(`sameSource`), 옛 기본값과 글자까지 같을 때만 새 기본값으로 교체(`applyCfg`).
- 메모 비교 추천: 일정 비율을 넘을 때만 정해진 값을 추천하고, 섞이면 '섞여 있음'으로 둔다. 자동 적용은 없다(`samStyle`, `samRecommend`). 계산은 환자 자료 구역 안에서만 한다.

**가져오지 않을 것:**

- 문구 칸이 겹치는 구조(`byProc`·`byRegion`·Central/Peripheral·전용 문구·코드별 메모·한 줄 틀). 쓰는 사람이 우선순위를 머리로 풀어야 한다.
- 모든 칸에 같은 낱말을 주고 값이 없으면 빈칸으로 두는 방식. 잘못 넣어도 오류 없이 사라진다.
- 약 역할 체크와 이름 일부 일치 판정(`injectionDrug`, `drugNames`). 시술별 약 고르기로 바꾼다.
- 완성된 글을 정규식으로 다시 고치는 방식(`styleSides`, `oneLineMemo`). 좌우가 두 번 붙는 문제가 있었다. 값을 갖고 조립한다.
- 코드 수천 개를 넘기며 고치는 화면, JSON 붙여 넣기 칸, PC 저장과 원장님 잠금(RLS로 대신한다).

**원본에 없어 새로 만드는 것:** 시술과 약의 짝, 약마다 자리, 메모 안 `[약 확인]`, 가입 보기 글을 앱에서 고치기, 청구 파일 글자 검사, 되풀이 고침 제안. 원본에서 찾은 글자 수 한도는 메모 20,000자뿐이라, 청구 파일의 실제 한도는 만들 때 따로 확인한다.

**지킬 것:** 자유 글 칸의 값은 서버 설정으로 간다. 실제 메모 글이나 환자 정보를 설정 칸으로 옮기는 길을 만들지 않는다(원본의 '자주 나오는 문장' 복사 같은 길).
