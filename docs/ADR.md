# Architecture Decision Records

> 2026-10-28에 정한 것. 근거는 `plan.md` 절 번호. 부딪히면 plan.md가 이긴다.

## 철학
- 혼자 쓰는 MVP다. 오버엔지니어링 하지 않는다. 다른 병원·직원용 장치는 지금 만들지 않고, 모든 표에 `hospital_id`만 둔다 (§0)
- 파일럿(`seoseungkwan/tonggye-bunseok`) 코드와 규칙을 그대로 쓴다. 새로 만드는 것은 새 기능에 꼭 필요한 것만
- 환자 개인정보는 의원 PC 밖으로 나가지 않는다. 이것은 줄이는 대상이 아니다
- 같은 효과면 코드 대신 DB 제약. 자동 계산보다 직접 입력 + 조정 칸. 드문 경우는 공통 안내로 묶는다
- 2차로 미룬 것(§10)은 다시 넣지 않는다

---

### ADR-001: Next.js 15 (파일럿과 같은 버전)
**결정**: Next.js 15.5 App Router · React 19.1 · TypeScript strict · Vitest (§5)
**이유**: 파일럿 코드와 시험을 경로 그대로 옮기려고
**트레이드오프**: 최신 버전 대신 파일럿 버전에 묶인다

### ADR-002: 파일럿 코드·규칙 이식
**결정**: 인증·통계·시험·ESLint 울타리·CSP·오류 카드 방식을 파일럿에서 옮긴다. 옮긴 시험은 v2로 바뀌는 모양 때문에 기대값이 달라지는 것만 고친다 (§0, §5, §9-1, specs/stats-core/design.md)
**이유**: 이미 쓰던 코드다. 새로 만들 것을 줄인다
**트레이드오프**: 파일럿의 폴더 이름과 흐름을 그대로 따른다

### ADR-003: 환자 파일은 브라우저 Web Worker에서만 계산
**결정**: 통계·매출 파일은 Worker 안에서 읽고 센다. `lib/parsers`·`lib/analytics`·`lib/payload`·`workers`는 환자 자료 구역이고, ESLint가 네트워크·저장소·console을 막는다. 서버에는 집계만 저장한다 (§2-2, §2-4, §4, §5)
**이유**: 환자 개인정보는 "절대 올리면 안 돼"(사용자)
**트레이드오프**: 서버에서 다시 계산할 수 없다. 그룹을 바꾸면 이전 달은 파일을 다시 넣어야 반영된다 (§7)

### ADR-004: 서버 코드는 AI 경로 하나, 나머지는 RLS
**결정**: 서버 경로는 `app/api/ai/`뿐. 나머지는 브라우저 + Supabase RLS. 가입 승인은 DB 함수 하나가 한다. service role 키는 두지 않는다 (§0, §5)
**예외 (2026-10-28 사용자 결정)**: 인증은 파일럿처럼 서버에서 돈다 — 로그인 콜백 `/auth/callback`, `middleware.ts`(세션 갱신·로그인 여부), 페이지 그리기 전 상태 확인(`lib/auth/*.server.ts`). 세션과 `hospitals`·`admins`의 내 줄만 읽고, 쓰기는 하지 않는다 (specs/auth/design.md)
**이유**: 서버 코드를 줄인다. 같은 효과면 DB 제약을 쓴다
**트레이드오프**: 권한은 RLS와 DB 함수가 유일한 방어선이다. 그래서 시험으로 증명한다

### ADR-005: Supabase 새 프로젝트(서울), 무료 플랜 + JSON 백업
**결정**: 무료 플랜을 쓴다. 설정 화면 [백업 내려받기]가 내 병원의 모든 표를 브라우저에서 읽어 JSON 파일 하나로 내려받는다. [급여 확정] 뒤 "백업을 받아 두세요" 한 줄 (§5)
**이유**: 사용자 결정. 무료 플랜에 없는 자동 백업을 손으로 받는 백업이 대신한다
**트레이드오프**: 되살리기 화면이 없다(필요하면 SQL). 1주일 안 쓰면 일시정지된다(데이터는 남음). 개발용 DB 분리도 없다 — E2E는 가짜 병원 계정 (§10)

### ADR-006: 구글 OAuth + 관리자 승인 가입
**결정**: 구글 로그인만 쓴다(OAuth는 새로 만든다). 처음 들어오면 가입 신청 → 앱 안 관리자 화면에서 승인·거절. 거절은 되돌릴 수 있다. 계정 1개 = 병원 1개 (§2-1)
**이유**: 지금은 혼자 쓰지만 나중에 다른 병원을 받을 수 있게
**트레이드오프**: 직원·원장 계정과 역할은 없다 (§10)

### ADR-007: AI 분석은 서버가 DB에서 읽은 집계만 보낸다
**결정**: 승인 확인 → DB에서 집계 읽기 → `validate.ts` 검사 → Claude 호출 → `ai_usage` 기록. 키는 서버 환경 변수 `ANTHROPIC_API_KEY`에만. 채팅 기록은 저장하지 않는다 (§2-3, §6-2)
**이유**: 브라우저가 보낸 숫자를 쓰지 않아 개인정보가 섞일 길을 막는다. 인건비는 총액만 보낸다
**트레이드오프**: 새로 고침하면 채팅이 사라진다. 사용자별 호출 제한 대신 Anthropic 콘솔 월 한도를 쓴다. 모델은 미정 — 구현 때 비용을 보고 정함

### ADR-008: 반올림하지 않는다 — 원 미만은 항목마다 버린다
**결정**: 금액은 원 단위 정수. 항목마다 원 미만을 버리고(129,629.535원 → 129,629원) 합계는 항목 금액의 합이다. %는 소수 둘째 자리까지 (§5)
**이유**: 사용자 결정(반올림 안 함). 명세 줄과 합계가 늘 맞는다
**트레이드오프**: 합계가 버리기 전 값의 합보다 조금(항목마다 1원 미만) 적을 수 있다

### ADR-009: 급여는 세후 지급액까지만, 확정하면 잠근다
**결정**: 세후 지급액 = 기본급 + 인센티브 합 + 고정 수당 + 조정(±). [급여 확정]은 그 달 결과를 저장하고, `final`인 달은 RLS가 수정을 막는다. 규칙 이력은 만들지 않는다 (§2-6, §6-3)
**이유**: 세전 역산·4대보험·원천세는 세무사가 한다. 확정 잠금이 규칙 이력을 대신한다
**트레이드오프**: 일할 계산·공제는 조정 칸에 직접 넣는다. 변경 기록·규칙 적용 시작 월이 없다 (§10)

### ADR-010: 매출 파일은 브라우저 폴더 연결로 읽는다
**결정**: 크롬·엣지에서 [비트 폴더 연결]을 한 번 한다. 폴더 핸들만 브라우저 저장소(`lib/folder/`)에 둔다. 읽기 전용, 정해진 파일 이름만 연다. 안 되면 끌어다 놓기 (§2-4, §5, §6-5)
**이유**: 원본은 PC 밖으로 나가지 않고, 연결해 두면 최신 파일을 바로 읽는다
**트레이드오프**: 크롬·엣지에서만 된다. 권한이 풀리면 다시 열어야 한다(`E-FOLDER-PERMISSION`)

### ADR-011: 월간 PDF는 브라우저 인쇄로
**결정**: 월말보고 + 통계 그래프 + AI 분석을 한 화면에 모으고 [인쇄 → PDF로 저장]을 쓴다. 인쇄용 CSS만 둔다 (§2-9)
**이유**: 서버에서 PDF를 만들지 않는다(서버 경로는 AI 하나)
**트레이드오프**: 보고서를 저장하지 않는다. 열 때마다 새로 만든다

### ADR-012: 랜딩 이미지는 히글스필드로 만들고 `public/`에 둔다
**결정**: 기능 소개 이미지 6장(`public/landing/`). 생성 전 크레딧 견적을 먼저 보인다. 히어로는 영상이 아니라 코드 차트다(2026-10-28 사용자가 바꿈, 만든 영상은 저장소 밖 보관). CSP에는 `media-src 'self'`만 더한다(§6-1). 모션 줄이기 설정이면 차트·애니메이션이 멈춘다 (§2-10)
**이유**: 다른 병원 유치용이라 제대로 만든다. 우리 쪽에 두면 CSP를 `'self'`로 둘 수 있다
**트레이드오프**: 상업적으로 써도 되는지 요금제 약관을 확인해야 한다 (§6-6)

### ADR-013: Vercel 배포, VPS 없음
**결정**: Vercel에 배포한다. VPS는 쓰지 않는다 (§5)
**이유**: 사용자 결정. 서버 코드가 AI 경로 하나뿐이다
**트레이드오프**: 무료 플랜은 비상업 용도만 → 다른 병원을 받기 시작하면 Pro (§10). 서버가 UTC라 날짜는 `dates.ts`로 한국 날짜를 쓴다

### ADR-014: 스타일링은 CSS Modules
**결정**: 화면마다 `*.module.css`를 두고, 색·글꼴 값은 `src/app/globals.css` 변수 한 곳에 둔다. 글꼴은 `next/font/google`로 빌드 때 받아 우리 쪽에서 낸다 (2026-10-28 사용자 결정)
**이유**: Next 기본 기능이라 새 패키지가 없다. 승인된 목업의 inline 값을 그대로 옮기기 쉽다. 글꼴을 우리 쪽에서 내면 CSP에 Google을 열지 않아도 된다
**트레이드오프**: 유틸리티 클래스(Tailwind)보다 화면을 새로 만들 때 손이 더 간다. 애니메이션 keyframes는 CSS Module마다 따로 둔다(이름이 모듈 안으로 갇힌다)
