# Architecture Decision Records

> 2026-10-28에 정한 것(ADR-016·020~022는 2026-10-30 청구 사전점검). 근거는 `plan.md` 절 번호. 부딪히면 plan.md가 이긴다.

## 철학
- 혼자 쓰는 MVP다. 오버엔지니어링 하지 않는다. 다른 병원·직원용 장치는 지금 만들지 않고, 모든 표에 `hospital_id`만 둔다 (§0)
- 파일럿(`seoseungkwan/tonggye-bunseok`) 코드와 규칙을 그대로 쓴다. 새로 만드는 것은 새 기능에 꼭 필요한 것만
- 환자 개인정보는 의원 PC 밖으로 나가지 않는다. 이것은 줄이는 대상이 아니다
- 같은 효과면 코드 대신 DB 제약. 자동 계산보다 직접 입력 + 조정 칸. 드문 경우는 공통 안내로 묶는다
- 2차로 미룬 것(§10)은 다시 넣지 않는다. 사용자가 다시 꺼낸 것만 넣는다(ADR-022)

### ADR-001: Next.js 15 (파일럿과 같은 버전)
**결정**: Next.js 15.5 App Router · React 19.1 · TypeScript strict · Vitest (§5)
**이유**: 파일럿 코드와 시험을 경로 그대로 옮기려고
**트레이드오프**: 최신 버전 대신 파일럿 버전에 묶인다

### ADR-002: 파일럿 코드·규칙 이식
**결정**: 인증·통계·시험·ESLint 울타리·CSP·오류 카드 방식을 파일럿에서 옮긴다. 옮긴 시험은 v2로 바뀌는 모양 때문에 기대값이 달라지는 것만 고친다 (§0, §5, §9-1, specs/stats-core/design.md)
**이유**: 이미 쓰던 코드다. 새로 만들 것을 줄인다
**트레이드오프**: 파일럿의 폴더 이름과 흐름을 그대로 따른다

### ADR-003: 환자 파일은 브라우저 Web Worker에서만 계산
**결정**: 통계·매출 파일은 Worker 안에서 읽고 센다. `lib/parsers`·`lib/analytics`·`lib/payload`·`workers`는 환자 자료 구역이고, ESLint가 네트워크·저장소·console을 막는다. 서버에는 집계만 저장한다 (§2-2, §2-4, §4, §5)
**이유**: 환자 개인정보는 "절대 올리면 안 돼"(사용자)
**트레이드오프**: 서버에서 다시 계산할 수 없다. 그룹을 바꾸면 이전 달은 파일을 다시 넣어야 반영된다 (§7)

### ADR-004: 서버 코드는 AI 경로 하나, 나머지는 RLS
**결정**: 서버 경로는 `app/api/ai/`뿐. 나머지는 브라우저 + Supabase RLS. 가입 승인은 DB 함수 하나가 한다. service role 키는 두지 않는다 (§0, §5)
**예외 (2026-10-28 사용자 결정)**: 인증은 파일럿처럼 서버에서 돈다 — 로그인 콜백 `/auth/callback`, `middleware.ts`(세션 갱신·로그인 여부), 페이지 그리기 전 상태 확인(`lib/auth/*.server.ts`). 세션과 `hospitals`·`admins`의 내 줄만 읽고, 쓰기는 하지 않는다 (specs/auth/design.md)
**이유**: 서버 코드를 줄인다. 같은 효과면 DB 제약을 쓴다
**트레이드오프**: 권한은 RLS와 DB 함수가 유일한 방어선이다. 그래서 시험으로 증명한다

### ADR-005: Supabase 새 프로젝트(서울), 무료 플랜 + JSON 백업
**결정**: 무료 플랜을 쓴다. 설정 화면 [백업 내려받기]가 내 병원의 모든 표를 브라우저에서 읽어 JSON 파일 하나로 내려받는다. [급여 확정] 뒤 "백업을 받아 두세요" 한 줄 (§5)
**이유**: 사용자 결정. 무료 플랜에 없는 자동 백업을 손으로 받는 백업이 대신한다
**트레이드오프**: 되살리기 화면이 없다(필요하면 SQL). 1주일 안 쓰면 일시정지된다(데이터는 남음). 개발용 DB 분리도 없다 — E2E는 가짜 병원 계정 (§10)

### ADR-006: 구글 OAuth + 관리자 승인 가입
**결정**: 구글 로그인만 쓴다(OAuth는 새로 만든다). 처음 들어오면 가입 신청 → 앱 안 관리자 화면에서 승인·거절. 거절은 되돌릴 수 있다. 계정 1개 = 병원 1개 (§2-1)
**이유**: 지금은 혼자 쓰지만 나중에 다른 병원을 받을 수 있게
**트레이드오프**: 직원·원장 계정과 역할은 없다 (§10)
**상태**: 앱 화면은 그대로 구글뿐이다. E2E 시험 계정 때문에 Supabase Email 제공자를 켠다 — ADR-017(2026-10-29)

### ADR-007: AI 분석은 서버가 DB에서 읽은 집계만 보낸다
**결정**: 승인 확인 → DB에서 집계 읽기 → `validate.ts` 검사 → Claude 호출 → `ai_usage` 기록. 키는 서버 환경 변수 `ANTHROPIC_API_KEY`에만. 채팅 기록은 저장하지 않는다 (§2-3, §6-2)
**이유**: 브라우저가 보낸 숫자를 쓰지 않아 개인정보가 섞일 길을 막는다. 인건비는 총액만 보낸다
**트레이드오프**: 새로 고침하면 채팅이 사라진다. 사용자별 호출 제한 대신 Anthropic 콘솔 월 한도를 쓴다. 모델은 미정 — 구현 때 비용을 보고 정함
**상태**(2026-11-01): 모델·저장: ADR-024 (모델은 Claude Opus 5.5, AI 리포트는 달마다 저장한다. 채팅 기록은 그대로 저장하지 않는다)

### ADR-008: 반올림하지 않는다 — 원 미만은 항목마다 버린다
**결정**: 금액은 원 단위 정수. 항목마다 원 미만을 버리고(129,629.535원 → 129,629원) 합계는 항목 금액의 합이다. %는 소수 둘째 자리까지 (§5)
**이유**: 사용자 결정(반올림 안 함). 명세 줄과 합계가 늘 맞는다
**트레이드오프**: 합계가 버리기 전 값의 합보다 조금(항목마다 1원 미만) 적을 수 있다

### ADR-009: 급여는 세후 지급액까지만, 확정하면 잠근다
**결정**: 세후 지급액 = 기본급 + 인센티브 합 + 고정 수당 + 조정(±). [급여 확정]은 그 달 결과를 저장하고, `final`인 달은 RLS가 수정을 막는다. 규칙 이력은 만들지 않는다 (§2-6, §6-3)
**이유**: 세전 역산·4대보험·원천세는 세무사가 한다. 확정 잠금이 규칙 이력을 대신한다
**트레이드오프**: 일할 계산·공제는 조정 칸에 직접 넣는다. 변경 기록·규칙 적용 시작 월이 없다 (§10)

### ADR-010: 매출 파일은 브라우저 폴더 연결로 읽는다
**결정**: 크롬·엣지에서 [비트 폴더 연결]을 한 번 한다. 폴더 핸들만 브라우저 저장소(`lib/folder/`)에 둔다. 읽기 전용, 정해진 파일 이름만 연다. 안 되면 끌어다 놓기 (§2-4, §5, §6-5)
**이유**: 원본은 PC 밖으로 나가지 않고, 연결해 두면 최신 파일을 바로 읽는다
**트레이드오프**: 크롬·엣지에서만 된다. 권한이 풀리면 다시 열어야 한다(`E-FOLDER-PERMISSION`)

### ADR-011: 월간 PDF는 브라우저 인쇄로
**결정**: 월말보고 + 통계 그래프 + AI 분석을 한 화면에 모으고 [인쇄 → PDF로 저장]을 쓴다. 인쇄용 CSS만 둔다 (§2-9)
**이유**: 서버에서 PDF를 만들지 않는다(서버 경로는 AI 하나)
**트레이드오프**: 보고서를 저장하지 않는다. 열 때마다 새로 만든다

### ADR-012: 랜딩 이미지는 히글스필드로 만들고 `public/`에 둔다
**상태**: 2026-10-30 ADR-018이 대체한다. 랜딩 그림을 모두 뺐다(`public/landing/` 지움). 승인했던 그림은 `docs/mockups/landing/images/`에 기록으로만 남는다. CSP `media-src 'self'`는 그대로 둔다
**결정**: 기능 소개 이미지 6장(`public/landing/`). 생성 전 크레딧 견적을 먼저 보인다. 히어로는 영상이 아니라 코드 차트다(2026-10-28 사용자가 바꿈, 만든 영상은 저장소 밖 보관). CSP에는 `media-src 'self'`만 더한다(§6-1). 모션 줄이기 설정이면 차트·애니메이션이 멈춘다 (§2-10)
**이유**: 다른 병원 유치용이라 제대로 만든다. 우리 쪽에 두면 CSP를 `'self'`로 둘 수 있다
**트레이드오프**: 상업적으로 써도 되는지 요금제 약관을 확인해야 한다 (§6-6)

### ADR-013: Vercel 배포, VPS 없음
**결정**: Vercel에 배포한다. VPS는 쓰지 않는다 (§5)
**이유**: 사용자 결정. 서버 코드가 AI 경로 하나뿐이다
**트레이드오프**: 무료 플랜은 비상업 용도만 → 다른 병원을 받기 시작하면 Pro (§10). 서버가 UTC라 날짜는 `dates.ts`로 한국 날짜를 쓴다
**배포 방법**(2026-10-29): Vercel CLI 배포만 한다. 깃 연결을 하지 않고 `vercel.json`의 `git.deploymentEnabled: false`로 깃 자동 배포를 끈다. 운영 배포는 할 때마다 사용자가 OK 한 뒤 Claude가 한다. 함수 지역은 icn1 (specs/auth-live/design.md)

### ADR-014: 스타일링은 CSS Modules
**상태**: 앱 화면은 ADR-015가 대체한다(2026-10-29). 랜딩은 이 결정 그대로다. 2026-10-30 개편(ADR-018) 뒤에도 랜딩은 CSS Modules이고, 변수 값만 앱 토큰과 같아졌다. 글꼴은 IBM Plex Sans KR 하나다
**상태**(2026-10-30): 토큰·글꼴은 ADR-019 / specs/b2b-redesign이 대체한다(토큰은 `globals.css` `:root` 한 곳, 글꼴은 `next/font/local`의 Pretendard). 랜딩이 CSS Modules인 것은 그대로다
**결정**: 화면마다 `*.module.css`를 두고, 색·글꼴 값은 `src/app/globals.css` 변수 한 곳에 둔다. 글꼴은 `next/font/google`로 빌드 때 받아 우리 쪽에서 낸다 (2026-10-28 사용자 결정)
**이유**: Next 기본 기능이라 새 패키지가 없다. 승인된 목업의 inline 값을 그대로 옮기기 쉽다. 글꼴을 우리 쪽에서 내면 CSP에 Google을 열지 않아도 된다
**트레이드오프**: 유틸리티 클래스(Tailwind)보다 화면을 새로 만들 때 손이 더 간다. 애니메이션 keyframes는 CSS Module마다 따로 둔다(이름이 모듈 안으로 갇힌다)

### ADR-015: 앱 화면 스타일링은 Tailwind CSS v4 (ADR-014를 앱 화면에서 대체)
**결정**: 앱 화면(로그인·가입 신청·승인 대기·오류·앱 틀·대시보드·관리자)은 Tailwind CSS v4로 그린다. 패키지는 `tailwindcss`·`@tailwindcss/postcss`·`postcss`(개발 패키지, 버전 고정), 설정은 `postcss.config.mjs` 하나. 색·모서리·글자 크기·그림자 토큰은 `src/app/globals.css`의 `@theme` 한 곳에 두고, Tailwind 기본 색 팔레트는 지워 토큰 색만 쓰게 한다. Preflight(기본 초기화)는 불러오지 않고, 앱 화면 뿌리(`.app-ui`) 안에만 작은 초기화를 둔다. 글꼴은 그대로 `next/font`의 IBM Plex Sans KR. 랜딩은 CSS Modules 그대로 두고 둘이 함께 산다. 화면 확인은 이미 설치된 `dev-browser`로 하고 `@playwright/test`는 넣지 않는다 (docs/UI_GUIDE.md '앱 화면', specs/auth/design.md)
**이유**: 사용자 결정 2026-10-29: 앱 리디자인. 앱이 "AI가 만든 SaaS 템플릿"처럼 보인다며 상용 B2B 수준(토스의 정돈, Linear의 디테일, ERP의 밀도)을 요구했고, 시안 A 배치와 블루 팔레트를 승인하면서 Tailwind를 골랐다. 토큰을 클래스 이름으로 강제하면 화면마다 값이 흩어지지 않는다. 빌드 때 정적 CSS 파일로 나오므로 CSP는 바꾸지 않는다
**트레이드오프**: 개발 패키지 3개가 는다. 스타일링 방식이 둘(랜딩 CSS Modules, 앱 Tailwind)이다. `postcss.config.mjs`가 Next 기본 PostCSS 설정을 대신하므로 랜딩 빌드 결과가 바뀌지 않는지 확인해야 한다. Preflight 없이 쓰므로 앱 화면은 초기화를 `.app-ui` 범위 안에서 직접 준다. 클래스 문자열이 길어진다 → 반복되는 모양은 `src/components/ui/classes.ts`에 모은다
**상태**: E2E는 ADR-017이 바꾼다(2026-10-29). 화면 스크린샷 확인은 이 결정 그대로 `dev-browser`다
**상태**(2026-10-30): 토큰·글꼴 줄은 ADR-019 / specs/b2b-redesign이 대체한다(토큰 값은 `:root` 한 곳, `@theme inline`은 `var()`로만 가리킴, 글꼴은 Pretendard). Tailwind v4·Preflight 없음·`.app-ui` 범위·`classes.ts`는 그대로다

### ADR-016: 청구 사전점검은 크롬 확장 + 네이티브 메시징 도우미(C#/.NET)로 비트와 연결한다
**결정** (2026-10-30 사용자): 청구 사전점검(`docs/precheck/PRD.md`)은 양지바른 없이 우리 앱만으로 돈다. 비트 PC에 두 가지를 설치한다
- **크롬 확장**(`extension/`, Manifest V3, 크롬 웹스토어 **비공개(unlisted)**): 우리 사이트 origin에서 온 메시지만 받아(`externally_connectable`) 도우미에 넘긴다. 권한은 `nativeMessaging` 하나다
- **도우미**(`helper/`, C#/.NET Framework 4.8, 윈도우): 크롬이 필요할 때 켜는 네이티브 메시징 프로그램이다. 하는 일은 비트 DB 읽기(읽기 전용), 요양기관기호 확인, 비트 자동 입력(FlaUI), PC 확인 창, 작업 중 내용 저장(윈도우 계정 암호화 DPAPI)이다. 양지바른 `vendor/drbit_export`·`vendor/secure_bridge`의 C# 코드를 옮긴다
- .NET Framework 4.8을 고른 까닭: 원본이 비트 한 달 자료를 비트 통계 화면 DLL(.NET Framework)을 그대로 불러 읽는다(`NativeReportAdapter`). 같은 방식으로 옮기려면 같은 런타임이 안전하다. 윈도우 10·11에 기본으로 있어 런타임을 따로 깔지 않는다. 플랫폼과 상관없는 부분(메시지 틀·명령 표·저장 형식·입력 규칙)은 netstandard2.0 라이브러리로 떼어 이 서버(리눅스)에서 .NET 10 SDK로 시험한다
- 도우미 exe는 32비트(x86, csproj `PlatformTarget`)로 빌드한다. 비트 DLL이 32비트다(원본 `tools/build_stats.ps1`의 `/platform:x86`). AnyCPU면 64비트 윈도우에서 64비트로 돌아 비트 DLL을 불러오지 못한다 (2026-10-30, `specs/precheck` TASK-33)
- 도우미는 GitHub Actions 윈도우 빌드로 만든다. 서명하지 않으므로 처음 실행할 때 윈도우 경고가 뜬다. 윈도우 전용 부분(비트 DLL·FlaUI·DPAPI·확인 창)은 Actions 윈도우에서 시험하고 의원 PC에서 확인한다
- 입력은 PC 확인 창에서 [확인]을 눌러야 시작한다. 그 창의 '이제부터 묻지 않기'를 켜면 청구 창을 닫을 때까지 창 없이 시작하고, 비트의 다른 메모도 원래 메모를 남기고 바꾼다(2026-11-01 사용자 결정, `specs/precheck` REQ-037). 처음은 꺼져 있고 사이트는 이것을 켤 수 없다. 확인 표시가 남은 메모는 입력하지 않는다. [직접 확인했어요]로 온 사람과 승인 뒤에 바뀐 메모는 켜져 있어도 바꾸지 않는다 **(Claude 판단)**. 체크는 켠 다음 묶음부터 친다 **(승인 목업)**. 비트 화면이 바뀐 것이 보이면 입력을 멈춘다
**버린 대안**:
- PC에 열린 포트(127.0.0.1 웹 서버): 다른 프로그램·사이트도 그 문을 두드릴 수 있어 열쇠값(토큰)을 주고받아야 하고, 크롬 '로컬 네트워크 허용' 창이 뜨며, CSP `connect-src`를 열어야 한다
- 양지바른 다리(이미 있는 `secure_bridge`에 붙기): 양지바른을 켜 두어야 하고 설정을 맞춰야 한다. 사용자가 "양지바른 안켜도", "독립적으로" 쓰기를 원했다
**이유**: 네이티브 메시징은 크롬과 PC 프로그램이 직접 대화하는 공식 통로다. 열린 포트·로컬 네트워크 허용 창·토큰이 없다. 도우미는 우리 확장의 메시지만 받는다(호스트 등록 파일의 `allowed_origins`)
**트레이드오프**: 크롬에서만 된다(엣지는 시험하지 않음). 기술이 셋 는다(확장·C#·윈도우 빌드). 웹스토어 등록(구글 개발자 5달러, 사용자 계정)과 심사가 필요하다. 도우미에서 크롬으로 가는 메시지는 한 번에 1MB까지라 나눠 보낸다. 윈도우 전용 코드(FlaUI·DPAPI·비트 DB 접속)는 이 서버에서 돌려 볼 수 없어 의원 PC 시험이 꼭 필요하다 (`specs/precheck/design.md`)

### ADR-017: E2E는 `@playwright/test` + 실제 Supabase 시험 계정 (ADR-015의 "`@playwright/test`는 넣지 않는다"를 E2E에서 바꿈)
**결정**: E2E는 `@playwright/test` 1.64.1(개발 패키지, 버전 고정, 파일럿과 같은 판)로 `npm run e2e`에서 돌린다. `npm test`(Vitest)와 따로다. 실제 Supabase에 시험 계정 4개(관리자·승인됨·승인 대기·신청 전)를 둔다. 로그인은 시험 코드가 비밀번호로 세션을 받아 `@supabase/ssr`가 만든 세션 쿠키를 그대로 브라우저에 넣는다(앱 코드에는 시험용 길이 없다). trace·영상·스크린샷·HAR은 끄고 보고는 글자(`list`)로만 본다. 비밀번호 로그인 때문에 Supabase Email 제공자를 켠다(새 가입 켬·Confirm email 켬·익명 끔). 앱 화면은 ADR-006대로 구글뿐이다. 승인·거절·되돌리기처럼 상태를 바꾸는 동작은 E2E에서 끝까지 하지 않는다. 구글 로그인은 사용자가 폰으로 운영 주소에서 손으로 확인한다. 화면 스크린샷 확인은 그대로 `dev-browser`다 (specs/auth-live/design.md)
**이유**: 사용자 결정 2026-10-29. 문지기·승인 대기·관리자 화면과 RLS를 실제 DB에서 자동으로 보려면 진짜 세션이 필요하다. 쿠키는 라이브러리가 만든 것을 옮기므로 앱과 모양이 늘 같다. service role 키 없이 공개 열쇠 + 비밀번호 로그인만 쓰므로 E2E가 할 수 있는 일은 그 계정이 RLS로 할 수 있는 일뿐이다. 구글은 자동 브라우저 로그인을 막는다. 상태를 바꾸지 않으므로 몇 번을 돌려도 같다
**트레이드오프**: 개발 패키지가 하나 는다. 실제 네트워크·시험 계정이 있어야 돌아 verify 관문 밖이다 → Phase 끝에 Claude가 돌려 보고한다. 운영 DB에 시험 계정 4개(관리자 하나)가 산다 → 비밀번호 16자 이상, `.env.local`에만. Email 제공자가 켜져 있어 누구나 API로 이메일 가입을 시도할 수 있다 → 낯선 주소는 확인 메일을 끝내지 못하고, 끝내도 승인 전에는 승인 대기 화면이며 RLS로 막힌다. 시작 전 검사가 이 설정을 매번 본다. 승인 성공은 PGlite RLS 시험·화면 시험·폰 확인이 맡는다. 실패는 사진 없이 글자 메시지로만 본다

**상태**(2026-10-30): 색·글꼴·랜딩 짜임·미리보기는 b2b-redesign·ADR-019가 대체한다. 그림 없음·로고 C③은 그대로다

  - 마크는 병원 십자 C③(`docs/mockups/landing-v2/logo-options.html`)이다. 같은 날 처음 정한 "막대 세 개 한 색"을 사용자가 바꿨다
  - 색은 테두리 `#14C8BA`·십자 `#6D5DF5`로 고정이다. 강조색 하나 규칙의 유일한 예외다
  - 빨강은 쓰지 않는다(적십자 표장, 「대한적십자사 조직법」)
- **그대로 두는 것**: CSP와 middleware matcher(쓰지 않는 `landing/` 예외 포함). 승인 기록 `docs/mockups/landing/`도 남긴다

**이유**: 사용자 결정 2026-10-30. 랜딩이 "AI가 만든 템플릿"처럼 보인다며 Linear의 절제와 Stripe의 데이터 중심 화면을 요구했다. 그림을 빼고 실제 제품 화면을 보여 주고, 색은 중립 + 하나로 줄이고, 칸·글자·간격을 한 벌로 맞추라고 했다. 이것은 UI_GUIDE 랜딩 원칙 2("한 가지 색으로 통일하지 않는다", 2026-10-28)를 바꾼다. 앱 토큰을 그대로 쓰면 랜딩에서 로그인·대시보드로 넘어갈 때 모양이 이어진다. CSS Modules를 그대로 두면 Tailwind 쪽 규칙(Preflight 없음, `.app-ui` 범위, 클래스 금지 목록)을 건드리지 않고 시안 CSS를 그대로 옮길 수 있다

- `color-mix()`를 쓴다(Chrome 111·Safari 16.2 이상)
- 그림 생성에 쓴 크레딧은 결과물로 남지 않는다(기록만 남는다)

### ADR-019: 디자인 토큰 한 곳 + Pretendard (ADR-014·015·018의 토큰·글꼴 줄을 바꿈)
**결정**: 토큰 값(색·차트 색·글자 크기/줄 높이/자간·모서리·그림자·틀 폭·글꼴 묶음)은 `src/app/globals.css`의 layer 밖 `:root` 한 곳에 CSS 변수로 둔다. 앱(Tailwind v4)은 `@theme inline`에서 이 변수를 `var()`로만 가리키고(기본 팔레트·모서리·그림자·글자 크기는 `initial`로 지움), 랜딩(CSS Modules)은 같은 변수를 바로 쓴다. 차트·미리보기 부품(`components/charts`·`components/preview`)은 앱 쪽 Tailwind로 만들고 랜딩이 그대로 놓는다. 랜딩 요소 초기화는 `@layer base` 안에 둔다. 글꼴은 Pretendard 1.3.9 정적 subset 세 굵기(400·500·600)를 `next/font/local`로 우리 쪽에서 낸다(`src/app/fonts/`, `OFL.txt` 함께). IBM Plex Sans KR을 뺀다.
**이유**: 사용자 결정 2026-10-30(한 벌의 디자인 규칙, Pretendard). 값이 한 곳이면 랜딩과 앱이 어긋날 수 없다(지금은 `@theme`과 랜딩 `:root`에 두 번 있어 시험으로 묶었다). 정적 subset은 글꼴 저자가 낸 파일 그대로라 OFL의 Reserved Font Name 조건(고친 글꼴은 다른 이름을 써야 함)에 걸리지 않는다. 가변 글꼴 전체(2.0MB)보다 작고, `next/font/local`은 unicode-range 조각(dynamic subset)을 받지 못한다. CSP는 그대로 `font-src 'self'`다.
**트레이드오프**: 글꼴 세 파일 합 804,172바이트(약 785KB)를 첫 방문에 받는다(캐시 뒤에는 없음). `next/font`가 모든 페이지에서 세 파일을 미리 받는다(preload) — 사용자 결정의 글꼴이라 받아들인다. Plex(구글이 나눈 조각)보다 첫 방문이 무겁다 → 810,000바이트 상한을 시험으로 묶는다. subset 밖의 드문 한글 음절은 맑은 고딕·Apple SD Gothic Neo로 보인다. 옮기는 동안 옛 Tailwind 이름 별칭이 잠시 남는다. 스타일링 방식은 여전히 둘(랜딩 CSS Modules, 앱 Tailwind)이지만 같은 토큰을 쓰고 규칙 시험이 둘 다 본다.

### ADR-020: 비트 환자 자료 통로는 확장 → 통로 코드(`lib/bridge`) → Worker, 통로 코드도 환자 자료 구역
**결정**: 도우미가 읽은 비트 자료는 확장을 거쳐 웹의 통로 코드 `src/lib/bridge/`로 오고, 통로 코드는 받은 조각을 풀지 않은 채 바로 Web Worker로 넘긴다. 계산은 Worker와 `src/lib/precheck/`(새 환자 자료 구역)에서 한다
- `lib/bridge`·`lib/precheck`를 환자 자료 구역에 더한다. 기존 울타리(네트워크·console·브라우저 저장소·React/Next/supabase/auth import 금지)를 그대로 걸고, 통로 코드에는 하나를 더 건다: 확장에 말을 거는 곳은 정해 둔 확장 ID 상수 하나뿐이다. `eslint.config.mjs`가 막고 `src/guardrails.test.ts`가 증명한다
- 환자 줄을 그리는 화면 폴더(`components/claim/rows/`·`components/contact/rows/`)도 네트워크·저장소·console·supabase를 못 쓰게 막는다. 화면에는 Worker가 만든 보기 모양만 간다
- 고치던 메모·완료 표시·연락 표시는 도우미가 그 PC에 암호화해 저장한다. 브라우저 저장소에는 두지 않는다
- CSP는 바꾸지 않는다. 네이티브 메시징은 `connect-src`와 상관없다
- 청구 화면에는 오류 수집 도구를 달지 않는다
**이유**: 환자 개인정보는 의원 PC 밖으로 나가지 않는다(plan.md §0 원칙 3). 지금 울타리는 파일에서 온 자료만 막고 있어, 확장에서 온 자료가 지나는 길도 같은 울타리 안에 넣어야 한다
**트레이드오프**: 청구·연락 화면은 일을 하려면 PC 화면에 환자 줄(차트번호·이름, 연락은 전화)을 보여야 한다. 통계처럼 번호로만 바꿔 둘 수 없다. 그래서 그 화면 폴더에도 울타리를 친다. 엑셀 내려받기(규칙별·환자별)는 그 PC에 파일로 남는다

**보충 (환자 탭 `specs/patients`, 2026-11)**: 도우미는 그 PC의 `contact.dat`에 ① 연락 표시(줄 열쇠·연락한 날) ② 정기 주사 기록(차트번호·이름·날짜·처방코드·증상 한 줄·전화, 원본 양지바른과 같은 모양)을 둔다
- DPAPI CurrentUser로 암호화한다
- 기록은 36개월·50,000건까지다(넘으면 오래된 것부터 정리)
- 등록 프로필 ID가 다른 파일은 읽지 않는다
- `.bak`과 깨진 파일은 지우지 않는다: 깨진 파일은 이름만 바꿔 남기고, `.bak`은 다음 저장 때 바로 전 값으로 바뀔 뿐 따로 지우지 않는다
- 서버·브라우저 저장소에는 가지 않는다

**이유**: 36개월을 매번 비트 통계 화면으로 읽으면 느리다
**트레이드오프**: 환자 기록이 그 PC에 암호화돼 남는다

### ADR-021: 청구 기능의 서버 자료는 건수 표와 설정 표뿐, 서버 경로는 늘리지 않는다
**결정**: 서버(Supabase)에는 두 가지만 간다
- **건수 표**(숫자만): 날짜별 메모 입력 현황, 월말 마감 남은 일, 연락 남은 건수. 칸은 날짜·정수·바뀐 시각뿐이고 글자 칸이 없다. DB 제약이 0 이상 정수만 받는다
- **설정 표**: 점검 규칙 켜기·끄기와 등급, 병원 문구, 문자 문구. 설정의 원본은 서버다(휴대폰에서도 바꾼다)
- 모든 표는 RLS를 켜고 기본 권한을 먼저 회수한 뒤 내 병원 줄만 읽고 쓰게 준다. `hospital_id`는 DB 기본값으로만 들어간다
- 새 서버 경로를 만들지 않는다. 서버 코드는 그대로 `app/api/ai/` 하나다 (ADR-004)
**이유**: 집·휴대폰에서 "얼마나 남았나"만 보면 된다(사용자). 환자 정보가 글자로 섞여 들어갈 칸을 만들지 않으면 실수로도 올라갈 수 없다
**트레이드오프**: 집에서는 건수만 보이고 어느 환자인지는 볼 수 없다. 12개월 이력·F/U 명단은 서버에 없으니 비트 PC에서만 그때그때 계산한다. 서버가 잠깐 안 되면 건수는 나중에 다시 올리고, 설정은 마지막으로 받은 것을 쓴다

### ADR-022: plan.md §10의 "청구·삭감 관리"·"청구메모 exe"를 다시 꺼낸다
**결정**: 2026-10-30 사용자가 2차로 미뤘던 두 가지를 양지바른 사전점검 가져오기로 다시 꺼냈다. 범위는 `docs/precheck/PRD.md`, 만드는 법과 순서는 `docs/precheck/plan.md`, 명세는 `specs/precheck/`. "청구메모 exe"는 따로 exe를 만들지 않고 도우미(ADR-016)가 맡는다
**이유**: 사용자가 통계·매출·청구를 우리 앱 하나에서 보고, 양지바른 없이 쓰기를 원했다
**트레이드오프**: §10의 나머지(일정·법정 마감 알림, 구글캘린더·슬랙, 비급여 가격표 등)는 그대로 미룬다. 양지바른의 팀장 도구·구매·운영·지식·원장님 잠금·원격 PC 목록·자리 비움 잠금·비상용 화면은 가져오지 않는다

### ADR-024: AI 월간 리포트는 달마다 저장하고, 근거 숫자는 앱이 채운다 (모델 Claude Opus 5.5)
**결정**: 2026-11-01 사용자 인터뷰로 정했다. AI 분석(ADR-007) 가운데 리포트의 뒷단(화면 뒤에서 도는 부분)을 먼저 만든다. 채팅은 다음 명세다 (`specs/ai-report/`)
- **저장**: 리포트는 병원·달마다 하나 저장한다(`ai_reports`). 다시 분석하면 그 달 리포트를 덮어쓴다(옛 판은 남기지 않는다)
- **지문**: 만들 때 쓴 숫자의 지문(SHA-256, 소문자 16진수 64자)을 함께 저장해, 나중에 숫자가 바뀌었는지 화면이 알 수 있게 한다
- **근거 숫자는 앱이 채운다**: AI는 카드마다 근거로 볼 지표 ID만 고르고, 근거 줄의 숫자는 앱이 그 지표의 진짜 값으로 만든다. AI 문장에는 숫자를 쓰지 않는다. 숫자 규칙을 어긴 카드는 버린다(고쳐 쓰지 않는다). 다만 자료에 있는 이름(처방명·그룹명·동네 이름 가운데 글자와 숫자가 함께 든 것)을 글자 그대로 쓴 숫자는 예외다. 숫자로만 된 이름은 예외가 아니다 **(사용자, 2026-11-01)**
- **모델**: Claude Opus 5.5(`claude-opus-5-5`). 거절되면 서버가 다른 모델로 다시 돌린다(`fallbacks: "default"`)
- **비용**: 거절하고 다른 모델이 대신 답하면 맨 위 사용량은 마지막 시도 몫뿐이다. 비용 기록은 거절한 시도까지 청구된 모든 시도의 토큰(`usage.iterations`의 합)으로 세고, 값은 마지막에 답한 모델 값(표에 없으면 표에서 가장 비싼 값)이다 **(사용자, 2026-11-01)**
- **숫자 읽는 자리**: `loadReportMonths`는 사용자 세션으로 `stats_months`(고른 달·지난달·작년 같은 달)와 `stats_rx_groups`(묶음 이름)를 읽는다(specs/ai-report-stats, 2026-11-06). 앱 경로에는 지어낸 숫자가 없다. 가짜 숫자는 `fixtures/fake-ai/`·시험·`npm run ai:try`에만 있다
- **쓰기**: DB 함수 둘(`save_ai_report`·`add_ai_usage`)로만 쓴다. 함수 안에서 내 병원이 승인됐는지 확인한다. 사용자 세션으로 부르고 service role 키는 두지 않는다. 서버 코드는 그대로 `app/api/ai/` 하나다 (ADR-004)
**이유**: 사용자 결정(2026-11-01). AI가 숫자를 옮겨 적지 않으니 숫자 오기가 없다. 저장해 두면 다시 볼 때 비용·기다림이 없고 월간 PDF에도 쓸 수 있다. 진짜 숫자가 아직 DB에 없어 가짜 숫자로 흐름을 끝까지 만들되, 앱 경로에는 지어낸 숫자를 두지 않는다
**트레이드오프**: AI 문장에 숫자를 못 써서 "크게 늘었습니다"처럼 쓴다. 덮어쓰기라 옛 판은 남지 않는다(필요해지면 이력 표). 사용자 세션으로 쓰는 구조라 마음먹은 사용자는 브라우저에서 같은 함수를 불러 자기 병원 리포트·사용량을 꾸밀 수 있다 — 자기 자료만이고, 화면은 글자로만 그리며, 실제 비용 한도는 Anthropic 콘솔이 지킨다. 다른 모델로 다시 돌린 부름은 그 가격이 표에 없으면 비싸게 센다
**바꾸는 것**: `docs/ARCHITECTURE.md` '상태 관리'의 "월간 보고서는 저장하지 않는다"는 AI 리포트에서만 바뀐다(월간 PDF는 그대로 열 때마다 모으고, 채팅도 저장하지 않는다). ADR-007의 "모델은 미정"은 Claude Opus 5.5로 정해졌다

### ADR-025: 업무일지 — 업무사항 서버 저장, 자동 저장, 엑셀 양식 예외, 칸 글자 저장, 바뀐 칸만 저장
**결정**: 2026-11-01 사용자 결정 다섯이다. 만드는 법은 `specs/worklog/design.md` 5·7·8·9·10·12·16절
- **업무사항은 서버(`worklog_days`의 `memo` 칸)에 저장한다 (사용자).** 모든 PC가 같은 글을 보고 어느 PC에서든 인쇄되고 휴대폰에서도 보인다(보기만, 승인된 로그인). AI로 보내지 않는다. 남는 위험: 환자 이름은 자동으로 못 막는다 → 흐린 안내 글 "환자 이름·차트번호는 적지 않아요"와 모양 막기(전화·주민번호·메일, 모든 입력 칸)로 줄인다. `CLAUDE.md` CRITICAL '서버·Claude API에는 집계 숫자만 간다'의 업무일지 예외다: 사람이 손으로 적는 일지 글이고 비트 환자 자료가 아니다(환자 자료 구역 규칙은 그대로다)
- **서버 칸은 적으면 자동 저장한다 (사용자).** 저장 단추가 없다. 입력을 800ms 묶어 `worklog_days`에 바로 저장하고, 못 하면 값을 화면에 둔 채 알린다. 브라우저 저장소에 임시 사본을 두지 않고, 저장 안 된 값이 있으면 떠나기 확인을 묻는다 **(Claude 판단)**
- **업무일지 양식 칸은 엑셀 서식 예외다 (사용자 결정에서 나온 Claude 판단).** `WorklogSheet` 표 안만 굴림·맑은 고딕(시스템 글꼴, 글꼴 파일 없음), 700 굵기, 엑셀 색 토큰 넷(`--xl-ink`·`--xl-lav`·`--xl-gray`·`--xl-focus`), CSS Module 한 파일(`components/worklog/sheet.module.css`)을 쓴다. 규칙 시험은 지우지 않고 이 예외만 연다
- **숫자 칸은 친 글자를 저장한다 (사용자).** 칸에 글자도 적고, 합계는 짐작하지 않는 규칙으로 읽은 숫자로만 낸다. 금액 정수 규칙(`plan.md` §5, `CLAUDE.md` 금액 줄)의 업무일지 예외이고 합계는 그대로 원 단위 정수다
- **바뀐 칸만 저장한다 (사용자).** 두 PC가 같은 날을 고치면 다른 칸은 둘 다 남고 같은 칸은 나중 저장이 이긴다. 다른 PC 글은 화면이 60초마다·다시 보일 때 다시 읽어 보인다(실시간 연결은 쓰지 않는다)
- `plan.md` §10 '입력값 임시 저장'과의 관계: 서버 칸은 임시 저장이 아니라 바로 저장이다. §10을 다시 꺼낸 것이 아니다
**이유**: 업무일지를 여러 PC에서 쓰고 같은 업무사항을 봐야 한다 **(사용자)**. 사용자는 환자 이름·차트번호를 적지 않는다 **(사용자)**. 올린 옛 엑셀의 업무사항 칸에는 적혀 있었으므로 안내 글이 필요하다 **(Claude 확인)**. 저장 단추 없이 적으면 저절로 저장되기를 바랐다 **(사용자)**. 양식은 "엑셀이랑 완전 똑같이" **(사용자)**. 칸에 글자도 적고 싶다 **(사용자)**
**트레이드오프**: 업무사항에 이름이 적히면 서버에 남는다(자동으로 못 막는다). 같은 칸을 두 PC가 고치면 앞 글이 사라지고 바꾼 기록이 없다(지난 날 잠금·고친 사람·시각 기록도 없다, 사용자 결정. 동시 수정 막기는 §10 2차). 숫자 칸은 DB가 숫자 범위를 지켜 주지 못하고, 다른 명세가 쓰려면 같은 읽기 규칙을 거쳐야 한다. 다른 PC 글이 최대 60초 늦게 보인다. 양식 칸은 Pretendard·400~600 굵기·토큰 규칙의 예외다 → 색 토큰 넷과 CSS Module 한 파일로 가둔다

### ADR-026: 대시보드는 통계의 `stats.rows`로 비트를 바로 읽고, 내원환자는 접수 기준으로 센다
**번호**: `specs/bit-dashboard/design.md`의 'ADR-025'는 이 결정이다. 합칠 때 업무일지 ADR-025와 번호가 겹쳐 026으로 옮겼다
**결정** (2026-11-01, 사용자 요청 "비트 PC 연결 시작을 누르면 자동으로", "비트 읽는 부분은 통계 탭 것을 같이 써", "항상 내원환자는 접수기준이야"): 대시보드는 통계 탭의 도우미 명령 `stats.rows`와 통계 Worker를 함께 쓴다. 양지바른·메디코어 1.25.0 통계 대시보드(`RxVisitSplit`)처럼 등록 병원으로 확인한 읽기 전용 접속에서 정해 둔 SELECT로 읽는다. 내원환자는 처방 유무와 상관없이 접수 기준으로 세고, 신환 기준은 비트 일일보고와 같은 '이 병원 첫 내원일'이다. 명세는 `specs/bit-dashboard/`·`specs/stats/`
**이유**: 비트 통계 화면(47번 표)을 띄우면 비트 로그인 창과 숨은 비트 창이 따라온다. SQL은 첫 등록 뒤 창이 뜨지 않아 "자동으로"가 된다. 같은 일을 하는 명령과 파일을 두 벌 두지 않는다
**트레이드오프**: 진짜 차트번호가 Worker까지 간다(화면·서버로는 가지 않는다, ADR-020 안). `stats.rows`는 금액 보고까지 매번 읽어 대시보드를 열 때 더 느려질 수 있다. 파일 길(비트 `초재진구분` 칸)과 신환 수가 다를 수 있다. 자동으로 읽은 숫자는 서버에 저장하지 않아, 폰 숫자는 통계 탭에서 불러와 저장한 시점까지다
