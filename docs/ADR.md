# Architecture Decision Records

> 2026-10-28에 정한 것(ADR-016·020~022는 2026-10-30 청구 사전점검). 근거는 `plan.md` 절 번호. 부딪히면 plan.md가 이긴다.

## 철학
- 혼자 쓰는 MVP다. 오버엔지니어링 하지 않는다. 다른 병원·직원용 장치는 지금 만들지 않고, 모든 표에 `hospital_id`만 둔다 (§0)
- 파일럿(`seoseungkwan/tonggye-bunseok`) 코드와 규칙을 그대로 쓴다. 새로 만드는 것은 새 기능에 꼭 필요한 것만
- 환자 개인정보는 의원 PC 밖으로 나가지 않는다. 이것은 줄이는 대상이 아니다
- 같은 효과면 코드 대신 DB 제약. 자동 계산보다 직접 입력 + 조정 칸. 드문 경우는 공통 안내로 묶는다
- 2차로 미룬 것(§10)은 다시 넣지 않는다. 사용자가 다시 꺼낸 것만 넣는다(ADR-022)

### ADR-001: Next.js 15 (파일럿과 같은 버전)
**결정**: Next.js 15.5 App Router · React 19.1 · TypeScript strict · Vitest (§5)
**이유**: 파일럿 코드와 시험을 경로 그대로 옮기려고
**트레이드오프**: 최신 버전 대신 파일럿 버전에 묶인다

### ADR-002: 파일럿 코드·규칙 이식
**결정**: 인증·통계·시험·ESLint 울타리·CSP·오류 카드 방식을 파일럿에서 옮긴다. 옮긴 시험은 v2로 바뀌는 모양 때문에 기대값이 달라지는 것만 고친다 (§0, §5, §9-1, specs/stats-core/design.md)
**이유**: 이미 쓰던 코드다. 새로 만들 것을 줄인다
**트레이드오프**: 파일럿의 폴더 이름과 흐름을 그대로 따른다

### ADR-003: 환자 파일은 브라우저 Web Worker에서만 계산
**결정**: 통계·매출 파일은 Worker 안에서 읽고 센다. `lib/parsers`·`lib/analytics`·`lib/payload`·`workers`는 환자 자료 구역이고, ESLint가 네트워크·저장소·console을 막는다. 서버에는 집계만 저장한다 (§2-2, §2-4, §4, §5)
**이유**: 환자 개인정보는 "절대 올리면 안 돼"(사용자)
**트레이드오프**: 서버에서 다시 계산할 수 없다. 그룹을 바꾸면 이전 달은 파일을 다시 넣어야 반영된다 (§7)

### ADR-004: 서버 코드는 AI 경로 하나, 나머지는 RLS
**결정**: 서버 경로는 `app/api/ai/`뿐. 나머지는 브라우저 + Supabase RLS. 가입 승인은 DB 함수 하나가 한다. service role 키는 두지 않는다 (§0, §5)
**예외 (2026-10-28 사용자 결정)**: 인증은 파일럿처럼 서버에서 돈다 — 로그인 콜백 `/auth/callback`, `middleware.ts`(세션 갱신·로그인 여부), 페이지 그리기 전 상태 확인(`lib/auth/*.server.ts`). 세션과 `hospitals`·`admins`의 내 줄만 읽고, 쓰기는 하지 않는다 (specs/auth/design.md)
**이유**: 서버 코드를 줄인다. 같은 효과면 DB 제약을 쓴다
**트레이드오프**: 권한은 RLS와 DB 함수가 유일한 방어선이다. 그래서 시험으로 증명한다

### ADR-005: Supabase 새 프로젝트(서울), 무료 플랜 + JSON 백업
**결정**: 무료 플랜을 쓴다. 설정 화면 [백업 내려받기]가 내 병원의 모든 표를 브라우저에서 읽어 JSON 파일 하나로 내려받는다. [급여 확정] 뒤 "백업을 받아 두세요" 한 줄 (§5)
**이유**: 사용자 결정. 무료 플랜에 없는 자동 백업을 손으로 받는 백업이 대신한다
**트레이드오프**: 되살리기 화면이 없다(필요하면 SQL). 1주일 안 쓰면 일시정지된다(데이터는 남음). 개발용 DB 분리도 없다 — E2E는 가짜 병원 계정 (§10)

### ADR-006: 구글 OAuth + 관리자 승인 가입
**결정**: 구글 로그인만 쓴다(OAuth는 새로 만든다). 처음 들어오면 가입 신청 → 앱 안 관리자 화면에서 승인·거절. 거절은 되돌릴 수 있다. 계정 1개 = 병원 1개 (§2-1)
**이유**: 지금은 혼자 쓰지만 나중에 다른 병원을 받을 수 있게
**트레이드오프**: 직원·원장 계정과 역할은 없다 (§10)
**상태**: 앱 화면은 그대로 구글뿐이다. E2E 시험 계정 때문에 Supabase Email 제공자를 켠다 — ADR-017(2026-10-29)

### ADR-007: AI 분석은 서버가 DB에서 읽은 집계만 보낸다
**결정**: 승인 확인 → DB에서 집계 읽기 → `validate.ts` 검사 → Claude 호출 → `ai_usage` 기록. 키는 서버 환경 변수 `ANTHROPIC_API_KEY`에만. 채팅 기록은 저장하지 않는다 (§2-3, §6-2)
**이유**: 브라우저가 보낸 숫자를 쓰지 않아 개인정보가 섞일 길을 막는다. 인건비는 총액만 보낸다
**트레이드오프**: 새로 고침하면 채팅이 사라진다. 사용자별 호출 제한 대신 Anthropic 콘솔 월 한도를 쓴다. 모델은 미정 — 구현 때 비용을 보고 정함
**상태**(2026-11-01): 모델·저장: ADR-024 (모델은 Claude Opus 5.5, AI 리포트는 달마다 저장한다. 채팅 기록은 그대로 저장하지 않는다)

### ADR-008: 반올림하지 않는다 — 원 미만은 항목마다 버린다
**결정**: 금액은 원 단위 정수. 항목마다 원 미만을 버리고(129,629.535원 → 129,629원) 합계는 항목 금액의 합이다. %는 소수 둘째 자리까지 (§5)
**이유**: 사용자 결정(반올림 안 함). 명세 줄과 합계가 늘 맞는다
**트레이드오프**: 합계가 버리기 전 값의 합보다 조금(항목마다 1원 미만) 적을 수 있다

### ADR-009: 급여는 세후 지급액까지만, 확정하면 잠근다
**결정**: 세후 지급액 = 기본급 + 인센티브 합 + 고정 수당 + 조정(±). [급여 확정]은 그 달 결과를 저장하고, `final`인 달은 RLS가 수정을 막는다. 규칙 이력은 만들지 않는다 (§2-6, §6-3)
**이유**: 세전 역산·4대보험·원천세는 세무사가 한다. 확정 잠금이 규칙 이력을 대신한다
**트레이드오프**: 일할 계산·공제는 조정 칸에 직접 넣는다. 변경 기록·규칙 적용 시작 월이 없다 (§10)

### ADR-010: 매출 파일은 브라우저 폴더 연결로 읽는다
**결정**: 크롬·엣지에서 [비트 폴더 연결]을 한 번 한다. 폴더 핸들만 브라우저 저장소(`lib/folder/`)에 둔다. 읽기 전용, 정해진 파일 이름만 연다. 안 되면 끌어다 놓기 (§2-4, §5, §6-5)
**이유**: 원본은 PC 밖으로 나가지 않고, 연결해 두면 최신 파일을 바로 읽는다
**트레이드오프**: 크롬·엣지에서만 된다. 권한이 풀리면 다시 열어야 한다(`E-FOLDER-PERMISSION`)

### ADR-011: 월간 PDF는 브라우저 인쇄로
**결정**: 월말보고 + 통계 그래프 + AI 분석을 한 화면에 모으고 [인쇄 → PDF로 저장]을 쓴다. 인쇄용 CSS만 둔다 (§2-9)
**이유**: 서버에서 PDF를 만들지 않는다(서버 경로는 AI 하나)
**트레이드오프**: 보고서를 저장하지 않는다. 열 때마다 새로 만든다

### ADR-012: 랜딩 이미지는 히글스필드로 만들고 `public/`에 둔다
**상태**: 2026-10-30 ADR-018이 대체한다. 랜딩 그림을 모두 뺐다(`public/landing/` 지움). 승인했던 그림은 `docs/mockups/landing/images/`에 기록으로만 남는다. CSP `media-src 'self'`는 그대로 둔다
**결정**: 기능 소개 이미지 6장(`public/landing/`). 생성 전 크레딧 견적을 먼저 보인다. 히어로는 영상이 아니라 코드 차트다(2026-10-28 사용자가 바꿈, 만든 영상은 저장소 밖 보관). CSP에는 `media-src 'self'`만 더한다(§6-1). 모션 줄이기 설정이면 차트·애니메이션이 멈춘다 (§2-10)
**이유**: 다른 병원 유치용이라 제대로 만든다. 우리 쪽에 두면 CSP를 `'self'`로 둘 수 있다
**트레이드오프**: 상업적으로 써도 되는지 요금제 약관을 확인해야 한다 (§6-6)

### ADR-013: Vercel 배포, VPS 없음
**결정**: Vercel에 배포한다. VPS는 쓰지 않는다 (§5)
**이유**: 사용자 결정. 서버 코드가 AI 경로 하나뿐이다
**트레이드오프**: 무료 플랜은 비상업 용도만 → 다른 병원을 받기 시작하면 Pro (§10). 서버가 UTC라 날짜는 `dates.ts`로 한국 날짜를 쓴다
**배포 방법**(2026-10-29): Vercel CLI 배포만 한다. 깃 연결을 하지 않고 `vercel.json`의 `git.deploymentEnabled: false`로 깃 자동 배포를 끈다. 운영 배포는 할 때마다 사용자가 OK 한 뒤 Claude가 한다. 함수 지역은 icn1 (specs/auth-live/design.md)

### ADR-014: 스타일링은 CSS Modules
**상태**: 앱 화면은 ADR-015가 대체한다(2026-10-29). 랜딩은 이 결정 그대로다. 2026-10-30 개편(ADR-018) 뒤에도 랜딩은 CSS Modules이고, 변수 값만 앱 토큰과 같아졌다. 글꼴은 IBM Plex Sans KR 하나다
**상태**(2026-10-30): 토큰·글꼴은 ADR-019 / specs/b2b-redesign이 대체한다(토큰은 `globals.css` `:root` 한 곳, 글꼴은 `next/font/local`의 Pretendard). 랜딩이 CSS Modules인 것은 그대로다
**결정**: 화면마다 `*.module.css`를 두고, 색·글꼴 값은 `src/app/globals.css` 변수 한 곳에 둔다. 글꼴은 `next/font/google`로 빌드 때 받아 우리 쪽에서 낸다 (2026-10-28 사용자 결정)
**이유**: Next 기본 기능이라 새 패키지가 없다. 승인된 목업의 inline 값을 그대로 옮기기 쉽다. 글꼴을 우리 쪽에서 내면 CSP에 Google을 열지 않아도 된다
**트레이드오프**: 유틸리티 클래스(Tailwind)보다 화면을 새로 만들 때 손이 더 간다. 애니메이션 keyframes는 CSS Module마다 따로 둔다(이름이 모듈 안으로 갇힌다)

### ADR-015: 앱 화면 스타일링은 Tailwind CSS v4 (ADR-014를 앱 화면에서 대체)
**결정**: 앱 화면(로그인·가입 신청·승인 대기·오류·앱 틀·대시보드·관리자)은 Tailwind CSS v4로 그린다. 패키지는 `tailwindcss`·`@tailwindcss/postcss`·`postcss`(개발 패키지, 버전 고정), 설정은 `postcss.config.mjs` 하나. 색·모서리·글자 크기·그림자 토큰은 `src/app/globals.css`의 `@theme` 한 곳에 두고, Tailwind 기본 색 팔레트는 지워 토큰 색만 쓰게 한다. Preflight(기본 초기화)는 불러오지 않고, 앱 화면 뿌리(`.app-ui`) 안에만 작은 초기화를 둔다. 글꼴은 그대로 `next/font`의 IBM Plex Sans KR. 랜딩은 CSS Modules 그대로 두고 둘이 함께 산다. 화면 확인은 이미 설치된 `dev-browser`로 하고 `@playwright/test`는 넣지 않는다 (docs/UI_GUIDE.md '앱 화면', specs/auth/design.md)
**이유**: 사용자 결정 2026-10-29: 앱 리디자인. 앱이 "AI가 만든 SaaS 템플릿"처럼 보인다며 상용 B2B 수준(토스의 정돈, Linear의 디테일, ERP의 밀도)을 요구했고, 시안 A 배치와 블루 팔레트를 승인하면서 Tailwind를 골랐다. 토큰을 클래스 이름으로 강제하면 화면마다 값이 흩어지지 않는다. 빌드 때 정적 CSS 파일로 나오므로 CSP는 바꾸지 않는다
**트레이드오프**: 개발 패키지 3개가 는다. 스타일링 방식이 둘(랜딩 CSS Modules, 앱 Tailwind)이다. `postcss.config.mjs`가 Next 기본 PostCSS 설정을 대신하므로 랜딩 빌드 결과가 바뀌지 않는지 확인해야 한다. Preflight 없이 쓰므로 앱 화면은 초기화를 `.app-ui` 범위 안에서 직접 준다. 클래스 문자열이 길어진다 → 반복되는 모양은 `src/components/ui/classes.ts`에 모은다
**상태**: E2E는 ADR-017이 바꾼다(2026-10-29). 화면 스크린샷 확인은 이 결정 그대로 `dev-browser`다
**상태**(2026-10-30): 토큰·글꼴 줄은 ADR-019 / specs/b2b-redesign이 대체한다(토큰 값은 `:root` 한 곳, `@theme inline`은 `var()`로만 가리킴, 글꼴은 Pretendard). Tailwind v4·Preflight 없음·`.app-ui` 범위·`classes.ts`는 그대로다

### ADR-016: 청구 사전점검은 크롬 확장 + 네이티브 메시징 도우미(C#/.NET)로 비트와 연결한다
**결정** (2026-10-30 사용자): 청구 사전점검(`docs/precheck/PRD.md`)은 양지바른 없이 우리 앱만으로 돈다. 비트 PC에 두 가지를 설치한다
- **크롬 확장**(`extension/`, Manifest V3, 크롬 웹스토어 **비공개(unlisted)**): 우리 사이트 origin에서 온 메시지만 받아(`externally_connectable`) 도우미에 넘긴다. 권한은 `nativeMessaging` 하나다
- **도우미**(`helper/`, C#/.NET Framework 4.8, 윈도우): 크롬이 필요할 때 켜는 네이티브 메시징 프로그램이다. 하는 일은 비트 DB 읽기(읽기 전용), 요양기관기호 확인, 비트 자동 입력(FlaUI), PC 확인 창, 작업 중 내용 저장(윈도우 계정 암호화 DPAPI)이다. 양지바른 `vendor/drbit_export`·`vendor/secure_bridge`의 C# 코드를 옮긴다
- .NET Framework 4.8을 고른 까닭: 원본이 비트 한 달 자료를 비트 통계 화면 DLL(.NET Framework)을 그대로 불러 읽는다(`NativeReportAdapter`). 같은 방식으로 옮기려면 같은 런타임이 안전하다. 윈도우 10·11에 기본으로 있어 런타임을 따로 깔지 않는다. 플랫폼과 상관없는 부분(메시지 틀·명령 표·저장 형식·입력 규칙)은 netstandard2.0 라이브러리로 떼어 이 서버(리눅스)에서 .NET 10 SDK로 시험한다
- 도우미 exe는 32비트(x86, csproj `PlatformTarget`)로 빌드한다. 비트 DLL이 32비트다(원본 `tools/build_stats.ps1`의 `/platform:x86`). AnyCPU면 64비트 윈도우에서 64비트로 돌아 비트 DLL을 불러오지 못한다 (2026-10-30, `specs/precheck` TASK-33)
- 도우미는 GitHub Actions 윈도우 빌드로 만든다. 서명하지 않으므로 처음 실행할 때 윈도우 경고가 뜬다. 윈도우 전용 부분(비트 DLL·FlaUI·DPAPI·확인 창)은 Actions 윈도우에서 시험하고 의원 PC에서 확인한다
- 입력은 PC 확인 창에서 [확인]을 눌러야 시작한다. 그 창의 '이제부터 묻지 않기'를 켜면 청구 창을 닫을 때까지 창 없이 시작하고, 비트의 다른 메모도 원래 메모를 남기고 바꾼다(2026-11-01 사용자 결정, `specs/precheck` REQ-037). 처음은 꺼져 있고 사이트는 이것을 켤 수 없다. 확인 표시가 남은 메모는 입력하지 않는다. [직접 확인했어요]로 온 사람과 승인 뒤에 바뀐 메모는 켜져 있어도 바꾸지 않는다 **(Claude 판단)**. 체크는 켠 다음 묶음부터 친다 **(승인 목업)**. 비트 화면이 바뀐 것이 보이면 입력을 멈춘다
**버린 대안**:
- PC에 열린 포트(127.0.0.1 웹 서버): 다른 프로그램·사이트도 그 문을 두드릴 수 있어 열쇠값(토큰)을 주고받아야 하고, 크롬 '로컬 네트워크 허용' 창이 뜨며, CSP `connect-src`를 열어야 한다
- 양지바른 다리(이미 있는 `secure_bridge`에 붙기): 양지바른을 켜 두어야 하고 설정을 맞춰야 한다. 사용자가 "양지바른 안켜도", "독립적으로" 쓰기를 원했다
**이유**: 네이티브 메시징은 크롬과 PC 프로그램이 직접 대화하는 공식 통로다. 열린 포트·로컬 네트워크 허용 창·토큰이 없다. 도우미는 우리 확장의 메시지만 받는다(호스트 등록 파일의 `allowed_origins`)
**트레이드오프**: 크롬에서만 된다(엣지는 시험하지 않음). 기술이 셋 는다(확장·C#·윈도우 빌드). 웹스토어 등록(구글 개발자 5달러, 사용자 계정)과 심사가 필요하다. 도우미에서 크롬으로 가는 메시지는 한 번에 1MB까지라 나눠 보낸다. 윈도우 전용 코드(FlaUI·DPAPI·비트 DB 접속)는 이 서버에서 돌려 볼 수 없어 의원 PC 시험이 꼭 필요하다 (`specs/precheck/design.md`)

### ADR-017: E2E는 `@playwright/test` + 실제 Supabase 시험 계정 (ADR-015의 "`@playwright/test`는 넣지 않는다"를 E2E에서 바꿈)
**결정**: E2E는 `@playwright/test` 1.64.1(개발 패키지, 버전 고정, 파일럿과 같은 판)로 `npm run e2e`에서 돌린다. `npm test`(Vitest)와 따로다. 실제 Supabase에 시험 계정 4개(관리자·승인됨·승인 대기·신청 전)를 둔다. 로그인은 시험 코드가 비밀번호로 세션을 받아 `@supabase/ssr`가 만든 세션 쿠키를 그대로 브라우저에 넣는다(앱 코드에는 시험용 길이 없다). trace·영상·스크린샷·HAR은 끄고 보고는 글자(`list`)로만 본다. 비밀번호 로그인 때문에 Supabase Email 제공자를 켠다(새 가입 켬·Confirm email 켬·익명 끔). 앱 화면은 ADR-006대로 구글뿐이다. 승인·거절·되돌리기처럼 상태를 바꾸는 동작은 E2E에서 끝까지 하지 않는다. 구글 로그인은 사용자가 폰으로 운영 주소에서 손으로 확인한다. 화면 스크린샷 확인은 그대로 `dev-browser`다 (specs/auth-live/design.md)
**이유**: 사용자 결정 2026-10-29. 문지기·승인 대기·관리자 화면과 RLS를 실제 DB에서 자동으로 보려면 진짜 세션이 필요하다. 쿠키는 라이브러리가 만든 것을 옮기므로 앱과 모양이 늘 같다. service role 키 없이 공개 열쇠 + 비밀번호 로그인만 쓰므로 E2E가 할 수 있는 일은 그 계정이 RLS로 할 수 있는 일뿐이다. 구글은 자동 브라우저 로그인을 막는다. 상태를 바꾸지 않으므로 몇 번을 돌려도 같다
**트레이드오프**: 개발 패키지가 하나 는다. 실제 네트워크·시험 계정이 있어야 돌아 verify 관문 밖이다 → Phase 끝에 Claude가 돌려 보고한다. 운영 DB에 시험 계정 4개(관리자 하나)가 산다 → 비밀번호 16자 이상, `.env.local`에만. Email 제공자가 켜져 있어 누구나 API로 이메일 가입을 시도할 수 있다 → 낯선 주소는 확인 메일을 끝내지 못하고, 끝내도 승인 전에는 승인 대기 화면이며 RLS로 막힌다. 시작 전 검사가 이 설정을 매번 본다. 승인 성공은 PGlite RLS 시험·화면 시험·폰 확인이 맡는다. 실패는 사진 없이 글자 메시지로만 본다

  - 색은 테두리 `#14C8BA`·십자 `#6D5DF5`로 고정이다. 강조색 하나 규칙의 유일한 예외다
  - 빨강은 쓰지 않는다(적십자 표장, 「대한적십자사 조직법」)

**이유**: 사용자 결정 2026-10-30. 랜딩이 "AI가 만든 템플릿"처럼 보인다며 Linear의 절제와 Stripe의 데이터 중심 화면을 요구했다. 그림을 빼고 실제 제품 화면을 보여 주고, 색은 중립 + 하나로 줄이고, 칸·글자·간격을 한 벌로 맞추라고 했다. 이것은 UI_GUIDE 랜딩 원칙 2("한 가지 색으로 통일하지 않는다", 2026-10-28)를 바꾼다. 앱 토큰을 그대로 쓰면 랜딩에서 로그인·대시보드로 넘어갈 때 모양이 이어진다. CSS Modules를 그대로 두면 Tailwind 쪽 규칙(Preflight 없음, `.app-ui` 범위, 클래스 금지 목록)을 건드리지 않고 시안 CSS를 그대로 옮길 수 있다

- 그림 생성에 쓴 크레딧은 결과물로 남지 않는다(기록만 남는다)

### ADR-019: 디자인 토큰 한 곳 + Pretendard (ADR-014·015·018의 토큰·글꼴 줄을 바꿈)
**결정**: 토큰 값(색·차트 색·글자 크기/줄 높이/자간·모서리·그림자·틀 폭·글꼴 묶음)은 `src/app/globals.css`의 layer 밖 `:root` 한 곳에 CSS 변수로 둔다. 앱(Tailwind v4)은 `@theme inline`에서 이 변수를 `var()`로만 가리키고(기본 팔레트·모서리·그림자·글자 크기는 `initial`로 지움), 랜딩(CSS Modules)은 같은 변수를 바로 쓴다. 차트·미리보기 부품(`components/charts`·`components/preview`)은 앱 쪽 Tailwind로 만들고 랜딩이 그대로 놓는다. 랜딩 요소 초기화는 `@layer base` 안에 둔다. 글꼴은 Pretendard 1.3.9 정적 subset 세 굵기(400·500·600)를 `next/font/local`로 우리 쪽에서 낸다(`src/app/fonts/`, `OFL.txt` 함께). IBM Plex Sans KR을 뺀다.
**이유**: 사용자 결정 2026-10-30(한 벌의 디자인 규칙, Pretendard). 값이 한 곳이면 랜딩과 앱이 어긋날 수 없다(지금은 `@theme`과 랜딩 `:root`에 두 번 있어 시험으로 묶었다). 정적 subset은 글꼴 저자가 낸 파일 그대로라 OFL의 Reserved Font Name 조건(고친 글꼴은 다른 이름을 써야 함)에 걸리지 않는다. 가변 글꼴 전체(2.0MB)보다 작고, `next/font/local`은 unicode-range 조각(dynamic subset)을 받지 못한다. CSP는 그대로 `font-src 'self'`다.
**트레이드오프**: 글꼴 세 파일 합 804,172바이트(약 785KB)를 첫 방문에 받는다(캐시 뒤에는 없음). `next/font`가 모든 페이지에서 세 파일을 미리 받는다(preload) — 사용자 결정의 글꼴이라 받아들인다. Plex(구글이 나눈 조각)보다 첫 방문이 무겁다 → 810,000바이트 상한을 시험으로 묶는다. subset 밖의 드문 한글 음절은 맑은 고딕·Apple SD Gothic Neo로 보인다. 옮기는 동안 옛 Tailwind 이름 별칭이 잠시 남는다. 스타일링 방식은 여전히 둘(랜딩 CSS Modules, 앱 Tailwind)이지만 같은 토큰을 쓰고 규칙 시험이 둘 다 본다.

### ADR-020: 비트 환자 자료 통로는 확장 → 통로 코드(`lib/bridge`) → Worker, 통로 코드도 환자 자료 구역
**결정**: 도우미가 읽은 비트 자료는 확장을 거쳐 웹의 통로 코드 `src/lib/bridge/`로 오고, 통로 코드는 받은 조각을 풀지 않은 채 바로 Web Worker로 넘긴다. 계산은 Worker와 `src/lib/precheck/`(새 환자 자료 구역)에서 한다
- `lib/bridge`·`lib/precheck`를 환자 자료 구역에 더한다. 기존 울타리(네트워크·console·브라우저 저장소·React/Next/supabase/auth import 금지)를 그대로 걸고, 통로 코드에는 하나를 더 건다: 확장에 말을 거는 곳은 정해 둔 확장 ID 상수 하나뿐이다. `eslint.config.mjs`가 막고 `src/guardrails.test.ts`가 증명한다
- 환자 줄을 그리는 화면 폴더(`components/claim/rows/`·`components/contact/rows/`)도 네트워크·저장소·console·supabase를 못 쓰게 막는다. 화면에는 Worker가 만든 보기 모양만 간다
- 고치던 메모·완료 표시·연락 표시는 도우미가 그 PC에 암호화해 저장한다. 브라우저 저장소에는 두지 않는다
- CSP는 바꾸지 않는다. 네이티브 메시징은 `connect-src`와 상관없다
- 청구 화면에는 오류 수집 도구를 달지 않는다
**이유**: 환자 개인정보는 의원 PC 밖으로 나가지 않는다(plan.md §0 원칙 3). 지금 울타리는 파일에서 온 자료만 막고 있어, 확장에서 온 자료가 지나는 길도 같은 울타리 안에 넣어야 한다
**트레이드오프**: 청구·연락 화면은 일을 하려면 PC 화면에 환자 줄(차트번호·이름, 연락은 전화)을 보여야 한다. 통계처럼 번호로만 바꿔 둘 수 없다. 그래서 그 화면 폴더에도 울타리를 친다. 엑셀 내려받기(규칙별·환자별)는 그 PC에 파일로 남는다

**보충 (환자 탭 `specs/patients`, 2026-11)**: 도우미는 그 PC의 `contact.dat`에 ① 연락 표시(줄 열쇠·연락한 날) ② 정기 주사 기록(차트번호·이름·날짜·처방코드·증상 한 줄·전화, 원본 양지바른과 같은 모양)을 둔다
- DPAPI CurrentUser로 암호화한다
- 기록은 36개월·50,000건까지다(넘으면 오래된 것부터 정리)
- 등록 프로필 ID가 다른 파일은 읽지 않는다
- `.bak`과 깨진 파일은 지우지 않는다: 깨진 파일은 이름만 바꿔 남기고, `.bak`은 다음 저장 때 바로 전 값으로 바뀔 뿐 따로 지우지 않는다
- 서버·브라우저 저장소에는 가지 않는다

**이유**: 36개월을 매번 비트 통계 화면으로 읽으면 느리다
**트레이드오프**: 환자 기록이 그 PC에 암호화돼 남는다

### ADR-021: 청구 기능의 서버 자료는 건수 표와 설정 표뿐, 서버 경로는 늘리지 않는다
**결정**: 서버(Supabase)에는 두 가지만 간다
- **건수 표**(숫자만): 날짜별 메모 입력 현황, 월말 마감 남은 일, 연락 남은 건수. 칸은 날짜·정수·바뀐 시각뿐이고 글자 칸이 없다. DB 제약이 0 이상 정수만 받는다
- **설정 표**: 점검 규칙 켜기·끄기와 등급, 병원 문구, 문자 문구. 설정의 원본은 서버다(휴대폰에서도 바꾼다)
- 모든 표는 RLS를 켜고 기본 권한을 먼저 회수한 뒤 내 병원 줄만 읽고 쓰게 준다. `hospital_id`는 DB 기본값으로만 들어간다
- 새 서버 경로를 만들지 않는다. 서버 코드는 그대로 `app/api/ai/` 하나다 (ADR-004)
**이유**: 집·휴대폰에서 "얼마나 남았나"만 보면 된다(사용자). 환자 정보가 글자로 섞여 들어갈 칸을 만들지 않으면 실수로도 올라갈 수 없다
**트레이드오프**: 집에서는 건수만 보이고 어느 환자인지는 볼 수 없다. 12개월 이력·F/U 명단은 서버에 없으니 비트 PC에서만 그때그때 계산한다. 서버가 잠깐 안 되면 건수는 나중에 다시 올리고, 설정은 마지막으로 받은 것을 쓴다

### ADR-022: plan.md §10의 "청구·삭감 관리"·"청구메모 exe"를 다시 꺼낸다
**결정**: 2026-10-30 사용자가 2차로 미뤘던 두 가지를 양지바른 사전점검 가져오기로 다시 꺼냈다. 범위는 `docs/precheck/PRD.md`, 만드는 법과 순서는 `docs/precheck/plan.md`, 명세는 `specs/precheck/`. "청구메모 exe"는 따로 exe를 만들지 않고 도우미(ADR-016)가 맡는다
**이유**: 사용자가 통계·매출·청구를 우리 앱 하나에서 보고, 양지바른 없이 쓰기를 원했다
**트레이드오프**: §10의 나머지(일정·법정 마감 알림, 구글캘린더·슬랙, 비급여 가격표 등)는 그대로 미룬다. 양지바른의 팀장 도구·구매·운영·지식·원장님 잠금·원격 PC 목록·자리 비움 잠금·비상용 화면은 가져오지 않는다

### ADR-024: AI 월간 리포트는 달마다 저장하고, 근거 숫자는 앱이 채운다 (모델 Claude Opus 5.5)
**결정**: 2026-11-01 사용자 인터뷰로 정했다. AI 분석(ADR-007) 가운데 리포트의 뒷단(화면 뒤에서 도는 부분)을 먼저 만든다. 채팅은 다음 명세다 (`specs/ai-report/`)
- **저장**: 리포트는 병원·달마다 하나 저장한다(`ai_reports`). 다시 분석하면 그 달 리포트를 덮어쓴다(옛 판은 남기지 않는다)
- **지문**: 만들 때 쓴 숫자의 지문(SHA-256, 소문자 16진수 64자)을 함께 저장해, 나중에 숫자가 바뀌었는지 화면이 알 수 있게 한다
- **근거 숫자는 앱이 채운다**: AI는 카드마다 근거로 볼 지표 ID만 고르고, 근거 줄의 숫자는 앱이 그 지표의 진짜 값으로 만든다. AI 문장에는 숫자를 쓰지 않는다. 숫자 규칙을 어긴 카드는 버린다(고쳐 쓰지 않는다). 다만 자료에 있는 이름(처방명·그룹명·동네 이름 가운데 글자와 숫자가 함께 든 것)을 글자 그대로 쓴 숫자는 예외다. 숫자로만 된 이름은 예외가 아니다 **(사용자, 2026-11-01)**
- **모델**: Claude Opus 5.5(`claude-opus-5-5`). 거절되면 서버가 다른 모델로 다시 돌린다(`fallbacks: "default"`)
- **비용**: 거절하고 다른 모델이 대신 답하면 맨 위 사용량은 마지막 시도 몫뿐이다. 비용 기록은 거절한 시도까지 청구된 모든 시도의 토큰(`usage.iterations`의 합)으로 세고, 값은 마지막에 답한 모델 값(표에 없으면 표에서 가장 비싼 값)이다 **(사용자, 2026-11-01)**
- **숫자 읽는 자리**: `loadReportMonths`는 사용자 세션으로 `stats_months`(고른 달·지난달·작년 같은 달)와 `stats_rx_groups`(묶음 이름)를 읽는다(specs/ai-report-stats, 2026-11-06). 앱 경로에는 지어낸 숫자가 없다. 가짜 숫자는 `fixtures/fake-ai/`·시험·`npm run ai:try`에만 있다
- **쓰기**: DB 함수 둘(`save_ai_report`·`add_ai_usage`)로만 쓴다. 함수 안에서 내 병원이 승인됐는지 확인한다. 사용자 세션으로 부르고 service role 키는 두지 않는다. 서버 코드는 그대로 `app/api/ai/` 하나다 (ADR-004)
**이유**: 사용자 결정(2026-11-01). AI가 숫자를 옮겨 적지 않으니 숫자 오기가 없다. 저장해 두면 다시 볼 때 비용·기다림이 없고 월간 PDF에도 쓸 수 있다. 진짜 숫자가 아직 DB에 없어 가짜 숫자로 흐름을 끝까지 만들되, 앱 경로에는 지어낸 숫자를 두지 않는다
**트레이드오프**: AI 문장에 숫자를 못 써서 "크게 늘었습니다"처럼 쓴다. 덮어쓰기라 옛 판은 남지 않는다(필요해지면 이력 표). 사용자 세션으로 쓰는 구조라 마음먹은 사용자는 브라우저에서 같은 함수를 불러 자기 병원 리포트·사용량을 꾸밀 수 있다 — 자기 자료만이고, 화면은 글자로만 그리며, 실제 비용 한도는 Anthropic 콘솔이 지킨다. 다른 모델로 다시 돌린 부름은 그 가격이 표에 없으면 비싸게 센다
**바꾸는 것**: `docs/ARCHITECTURE.md` '상태 관리'의 "월간 보고서는 저장하지 않는다"는 AI 리포트에서만 바뀐다(월간 PDF는 그대로 열 때마다 모으고, 채팅도 저장하지 않는다). ADR-007의 "모델은 미정"은 Claude Opus 5.5로 정해졌다

### ADR-025: 업무일지 — 업무사항 서버 저장, 자동 저장, 엑셀 양식 예외, 칸 글자 저장, 바뀐 칸만 저장
**결정**: 2026-11-01 사용자 결정 다섯이다. 만드는 법은 `specs/worklog/design.md` 5·7·8·9·10·12·16절
- **업무사항은 서버(`worklog_days`의 `memo` 칸)에 저장한다 (사용자).** 모든 PC가 같은 글을 보고 어느 PC에서든 인쇄되고 휴대폰에서도 보인다(보기만, 승인된 로그인). AI로 보내지 않는다. 남는 위험: 환자 이름은 자동으로 못 막는다 → 흐린 안내 글 "환자 이름·차트번호는 적지 않아요"와 모양 막기(전화·주민번호·메일, 모든 입력 칸)로 줄인다. `CLAUDE.md` CRITICAL '서버·Claude API에는 집계 숫자만 간다'의 업무일지 예외다: 사람이 손으로 적는 일지 글이고 비트 환자 자료가 아니다(환자 자료 구역 규칙은 그대로다)
- **서버 칸은 적으면 자동 저장한다 (사용자).** 저장 단추가 없다. 입력을 800ms 묶어 `worklog_days`에 바로 저장하고, 못 하면 값을 화면에 둔 채 알린다. 브라우저 저장소에 임시 사본을 두지 않고, 저장 안 된 값이 있으면 떠나기 확인을 묻는다 **(Claude 판단)**
- **업무일지 양식 칸은 엑셀 서식 예외다 (사용자 결정에서 나온 Claude 판단).** `WorklogSheet` 표 안만 굴림·맑은 고딕(시스템 글꼴, 글꼴 파일 없음), 700 굵기, 엑셀 색 토큰 넷(`--xl-ink`·`--xl-lav`·`--xl-gray`·`--xl-focus`), CSS Module 한 파일(`components/worklog/sheet.module.css`)을 쓴다. 규칙 시험은 지우지 않고 이 예외만 연다
- **숫자 칸은 친 글자를 저장한다 (사용자).** 칸에 글자도 적고, 합계는 짐작하지 않는 규칙으로 읽은 숫자로만 낸다. 금액 정수 규칙(`plan.md` §5, `CLAUDE.md` 금액 줄)의 업무일지 예외이고 합계는 그대로 원 단위 정수다
- **바뀐 칸만 저장한다 (사용자).** 두 PC가 같은 날을 고치면 다른 칸은 둘 다 남고 같은 칸은 나중 저장이 이긴다. 다른 PC 글은 화면이 60초마다·다시 보일 때 다시 읽어 보인다(실시간 연결은 쓰지 않는다)
- `plan.md` §10 '입력값 임시 저장'과의 관계: 서버 칸은 임시 저장이 아니라 바로 저장이다. §10을 다시 꺼낸 것이 아니다
**이유**: 업무일지를 여러 PC에서 쓰고 같은 업무사항을 봐야 한다 **(사용자)**. 사용자는 환자 이름·차트번호를 적지 않는다 **(사용자)**. 올린 옛 엑셀의 업무사항 칸에는 적혀 있었으므로 안내 글이 필요하다 **(Claude 확인)**. 저장 단추 없이 적으면 저절로 저장되기를 바랐다 **(사용자)**. 양식은 "엑셀이랑 완전 똑같이" **(사용자)**. 칸에 글자도 적고 싶다 **(사용자)**
**트레이드오프**: 업무사항에 이름이 적히면 서버에 남는다(자동으로 못 막는다). 같은 칸을 두 PC가 고치면 앞 글이 사라지고 바꾼 기록이 없다(지난 날 잠금·고친 사람·시각 기록도 없다, 사용자 결정. 동시 수정 막기는 §10 2차). 숫자 칸은 DB가 숫자 범위를 지켜 주지 못하고, 다른 명세가 쓰려면 같은 읽기 규칙을 거쳐야 한다. 다른 PC 글이 최대 60초 늦게 보인다. 양식 칸은 Pretendard·400~600 굵기·토큰 규칙의 예외다 → 색 토큰 넷과 CSS Module 한 파일로 가둔다

### ADR-026: 대시보드는 통계의 `stats.rows`로 비트를 바로 읽고, 내원환자는 접수 기준으로 센다
**번호**: `specs/bit-dashboard/design.md`의 'ADR-025'는 이 결정이다. 합칠 때 업무일지 ADR-025와 번호가 겹쳐 026으로 옮겼다
**결정** (2026-11-01, 사용자 요청 "비트 PC 연결 시작을 누르면 자동으로", "비트 읽는 부분은 통계 탭 것을 같이 써", "항상 내원환자는 접수기준이야"): 대시보드는 통계 탭의 도우미 명령 `stats.rows`와 통계 Worker를 함께 쓴다. 양지바른·메디코어 1.25.0 통계 대시보드(`RxVisitSplit`)처럼 등록 병원으로 확인한 읽기 전용 접속에서 정해 둔 SELECT로 읽는다. 내원환자는 처방 유무와 상관없이 접수 기준으로 세고, 신환 기준은 비트 일일보고와 같은 '이 병원 첫 내원일'이다. 명세는 `specs/bit-dashboard/`·`specs/stats/`
**이유**: 비트 통계 화면(47번 표)을 띄우면 비트 로그인 창과 숨은 비트 창이 따라온다. SQL은 첫 등록 뒤 창이 뜨지 않아 "자동으로"가 된다. 같은 일을 하는 명령과 파일을 두 벌 두지 않는다
**트레이드오프**: 진짜 차트번호가 Worker까지 간다(화면·서버로는 가지 않는다, ADR-020 안). `stats.rows`는 금액 보고까지 매번 읽어 대시보드를 열 때 더 느려질 수 있다. 파일 길(비트 `초재진구분` 칸)과 신환 수가 다를 수 있다. 자동으로 읽은 숫자는 서버에 저장하지 않아, 폰 숫자는 통계 탭에서 불러와 저장한 시점까지다

### ADR-028: 서식 AI 정리는 적은 글을 보낸다 · 안내문 그림 예외
**결정** (2026-11-10 사용자 결정, `specs/forms`): 서식 탭의 휴진 안내는 사용자가 대충 적은 글을 AI가 날짜 카드로 정리하고, 안내문을 테마 그림으로 그려 인쇄·PDF·그림 파일로 뽑는다. 이것은 "AI에는 서버가 DB에서 읽은 집계만 보낸다"(ADR-007, `CLAUDE.md` 아키텍처 규칙)와 앱 화면의 토큰·굵기 규칙(ADR-019)에 부딪힌다. 그래서 예외 둘을 이 경로와 이 그림 안에만 연다
- **서식 AI 정리는 사용자가 적은 글(500자까지, 개인정보 모양 거부, 저장 안 함)을 Claude로 보낸다 (사용자, 2026-11-10).** 경로는 `app/api/ai/forms` 하나다(서버 코드는 그대로 `app/api/ai/` 안, ADR-004). 보내는 것은 적은 글(앞뒤 공백을 뗀 1자 이상, 500자까지)과 오늘 한국 날짜뿐이다. 승인 확인 뒤 서버가 다시 검사해, 줄바꿈·탭 밖의 제어 문자나 전화번호·주민번호(붙여 쓴 13자리 포함)·메일 주소 모양(`validate.ts`의 `hasPrivateShape`)이 있으면 Claude를 부르지 않는다(`E-FORMS-PRIVATE`, 화면도 보내기 전에 같은 검사를 한다). 적은 글은 `<memo>`로 감싸 자료로만 다루고 그 안의 지시는 따르지 않는다(`<`·`>`는 바꿔 넣어 태그를 닫지 못한다). 생각 깊이(effort)는 low, 모델은 AI 리포트와 같은 Claude Opus 5.5다(ADR-024). 적은 글은 DB·브라우저 저장소에 저장하지 않고 로그에도 남기지 않는다(로그는 오류 번호·경로 한 줄). 저장하는 것은 정리한 카드·안내 달·테마뿐이다(`form_notices`, RLS). 답은 검사한 카드로만 받아 글자로 그린다
- **안내문 그림은 인쇄물이라 테마 색·글꼴 700·900을 그림 안에서만 쓴다 (사용자 결정에서 나온 Claude 판단, 2026-11-10 명세 승인).** 안내문 SVG(`components/forms/Poster.tsx`)와 테마 그림(`public/poster/themes/` 23개) 안의 색(테마 강조색·글자색·흰색·그림자)은 앱 토큰 예외다. 글꼴은 그림 안에서만 `PosterPretendard`(Pretendard 1.3.9 Bold·Black subset, `public/poster/fonts/`) 700·900을 쓰고, 이 이름은 `components/forms` 밖에서 쓰지 않는다. 앱 화면(서식 화면의 칸·단추·목록 포함)은 그대로 토큰과 Pretendard 400·500·600이다. 규칙 시험은 지우지 않고 이 예외만 연다. 글꼴 이름이 서식 폴더 밖에 없는지와 서식 폴더가 환자 자료 구역·브라우저 저장소를 쓰지 않는지는 `src/lib/forms/rules.test.ts`가 본다
**이유**: 사용자가 "대충 적으면 AI가 양식에 맞게 정리"하기를 원했다(`docs/tab-frame/plan.md` 서식 줄). 질문에 "적은 글이 우리 사이트 서버를 거쳐 Claude로 가고, 전화·주민번호·메일 모양 글자가 있으면 보내지 않는다"고 설명하고 받은 답이다 **(사용자, 2026-11-10)**. 휴진 안내 글은 비트 환자 자료가 아니라 사람이 손으로 적는 글이다(환자 자료 구역 규칙은 그대로다). 안내문은 의원에 붙이고 카톡으로 보내는 인쇄물이라, 승인한 시안(`docs/mockups/forms/index.html`, 사용자 "좋아")의 굵은 글자와 날마다 다른 테마 색이 있어야 한다
**트레이드오프**: 환자 이름 모양은 걸러낼 수 없다 → 글 칸 아래 늘 보이는 안내("전화번호·주민번호·메일 주소는 적지 마세요. 적은 글은 정리할 때만 AI로 보내고 저장하지 않아요")로 막고, 적은 글은 저장·로그하지 않는다. 부를 때마다 비용이 든다(약 1~2센트, `ai_usage`에 더함). AI가 공휴일 날짜를 틀릴 수 있다 → 사용자가 카드 칸에서 고친다(요일은 앱이 계산한다). 안내문 그림 안의 색·굵기는 앱 규칙의 예외라, 그 범위를 `components/forms`와 테마 색 목록(`lib/forms/themes.ts`)으로 가둔다

**덧붙임 — 환자 안내문 (2026-11-15 사용자 결정, `specs/forms-guide`)**: 서식 탭에 환자 안내문(접수대·대기실에 붙이는 A4 한 장)을 더한다. 위 두 예외를 같은 틀로 쓰고 더 넓히지 않는다(대충 적은 글은 개인정보 모양이면 보내지 않고, 저장·로그하지 않는다. AI 그림의 '그릴 것'은 그림 이름으로 안내문과 함께 저장한다. 그림 안 글꼴은 700·900, 앱 화면은 그대로 토큰)
- **색은 병원 로고색 하나로 고정한다**(노랑·진회색·흰색, 테마 23개는 쓰지 않는다). 그림 안 색 값은 `components/forms/guideColors.ts` 한 곳에만 둔다(`src/app/theme.test.ts`가 막는다)
- **그림은 미리 그려 둔 그림 16개에서 AI가 고른다.** 맞는 것이 없으면 그림 없이 두고, 사람이 바꾸거나 뺄 수 있다. 그림은 파일이 아니라 코드로 그린 조각이다(`components/forms/guidePictures.tsx`)
- **AI 정리 경로는 `app/api/ai/forms/guide`다.** 보내는 것은 대충 적은 글(500자까지)뿐이고 생각 깊이는 휴진 안내와 같은 low다. AI가 사실을 지어내지 않게 시스템 글에 "메모에 없는 숫자·사실을 넣지 않는다"를 적고, 답에 메모에 없는 숫자가 하나라도 있으면 답 전체를 버린다(`E-AI-FAILED`, '43,850'과 '43850'은 같게 본다)
- **AI 그림은 도형·색 이름·숫자로만 받아 앱이 그린다** (2026-11-15 명세 승인 뒤 사용자 요청 "그림도 새로 생성할 수 있게 해"). 경로는 `app/api/ai/forms/guide/picture`이고, 보내는 것은 사람이 적은 '그릴 것'(20자까지, 개인정보 모양이면 안 보냄)뿐이다. 답을 SVG·HTML 글로 받으면 "답은 글자로만 그린다" 규칙을 깨고 스크립트·바깥 주소가 섞일 길이 생긴다. 그래서 정해 둔 도형 다섯 가지(원·타원·네모·선·길)·색 이름 네 가지(노랑·진회색·흰색·없음)·숫자만 받아 앱이 검사하고, 그림 요소는 앱이 만든다(도형 40개까지, `lib/forms/guideDrawing.ts`). 생각 깊이는 그림 품질 때문에 medium이다. 외부 그림 AI(사진 같은 그림)와 그림 파일 올리기는 하지 않는다
- **저장은 새 표 `form_guides`다**(RLS, 내 병원 줄만, 한 줄 16,000바이트까지). 안내문 칸과 고른 그림, AI로 그린 그림(도형과 '그릴 것' 이름)을 담는다. 대충 적은 글은 두지 않는다. 휴진 안내 표·경로(`form_notices`·`app/api/ai/forms`)는 고치지 않는다
**트레이드오프(덧붙임)**: 숫자 검사는 '4만 3850원'·'두 번'처럼 글로 쓴 수는 못 본다 → 시스템 글 규칙과 사람이 보고 고치는 것에 맡긴다. AI 그림은 아이콘 수준이라 엉성할 수 있다 → 다시 그리거나 16개에서 고른다. 그림 한 번에 약 2~5센트가 든다(`ai_usage`에 더함)

### ADR-029: 휴진 안내 AI 배경은 적은 말을 OpenAI 그림 AI로 보낸다
**맥락**: 서식 탭 휴진 안내는 테마 그림(ADR-028, `specs/forms-themes`에서 테마마다 그림 1·2)만 고를 수 있다. 2026-11-15 사용자 요청 "진료일정 배경디자인도 생성할 수 있게 해": 짧은 말을 적으면 생생한 배경 그림이 만들어지고, 마음에 드는 것은 다시 쓰고 싶다. Claude는 그림 파일을 만들지 않고, 도형만 받아 앱이 그리는 길(ADR-028 덧붙임의 AI 그림)은 아이콘 수준이다. 그림 AI를 쓰면 "AI에는 서버가 DB에서 읽은 집계만 보낸다"(ADR-007, `CLAUDE.md` 아키텍처 규칙)와 "AI는 Claude"에 부딪힌다. 그래서 이 경로 하나에만 예외를 연다
**결정** (2026-11-15 사용자 결정, `specs/forms-themes`): 휴진 안내 '배경' 칸의 [AI로 배경 만들기]는 사용자가 적은 짧은 말로 OpenAI 그림 AI가 배경 그림을 만든다. 경로는 `app/api/ai/forms/background` 하나다(`POST /api/ai/forms/background`, 서버 코드는 그대로 `app/api/ai/` 안, ADR-004). 모델은 `gpt-image-2.6-flare`(1584×2240 A4 비율, 품질 medium, JPEG 압축 88), SDK 없이 fetch로 부른다(`app/api/ai/openaiImage.ts`)
- **보내는 것**: 고정 프롬프트(가장자리만 장식, 가운데와 아래 가운데 로고 자리는 비움, 글자·숫자·로고·사람 얼굴 금지 — `lib/forms/background.ts`의 `backgroundPrompt`)와 사용자가 적은 말(앞뒤 공백을 뗀 1~30자)뿐이다. 승인 확인 뒤 서버가 다시 검사해, 제어 문자(줄바꿈·탭 포함)나 전화번호·주민번호·메일 주소 모양이면 OpenAI를 부르지 않고 하루 한도도 세지 않는다(`E-FORMS-PRIVATE`, 화면도 보내기 전에 같은 검사를 한다)
- **보내지 않는 것**: 병원(이름·id)·환자·안내문 카드(날짜·카드 이름)·사용자 정보(계정·메일, `user` 같은 식별 칸). 보내는 몸통 열쇠는 정해 둔 일곱 개(`model`·`prompt`·`size`·`quality`·`n`·`output_format`·`output_compression`)뿐이다
- **값과 한도**: 한 장 약 80원(약 7초)이다. 값은 토큰 단가(입력 5·출력 30, 백만분의 1달러)로 세고 답에 사용량이 없으면 한 장 60,000(백만분의 1달러)으로 센다. 지금 사용량 표 `ai_usage`에 `add_ai_usage`로 더한다(AI 리포트 화면의 사용량에 함께 보인다). 병원마다 하루 20장(한국 날짜)이고, 보내기 전에 DB 함수 `take_ai_image()`가 `ai_image_days`에 센다(OpenAI가 실패해도 한 장). OpenAI 계정의 달 한도는 사용자가 OpenAI 관리 화면에서 정한다(넘으면 `E-FORMS-BG-QUOTA`)
- **저장**: 서버는 그림을 저장하지 않고 답(`{ image }`, base64)으로만 돌려준다. 사용자가 [내 배경으로 저장]을 누른 그림만 브라우저가 RLS로 저장한다: 표 `form_backgrounds`(적은 말·강조색·작은 그림 120×170)와 Storage 버킷 `form-backgrounds`(큰 그림, 공개 아님, 병원 id 폴더, 표에 줄이 있는 이름만 올림). 내 배경은 30장까지다. 적은 말은 목록 이름으로 저장된다(개인정보 모양이면 저장하지도 않는다). 프롬프트 글·OpenAI 답의 다른 칸은 어디에도 두지 않는다. 안내문은 `form_notices.theme`에 `bg-<id>`로 고른 배경을 가리킨다
- **열쇠**: `OPENAI_API_KEY`는 서버 환경 변수(Vercel)와 `.env.local`에만 둔다. `NEXT_PUBLIC_*`에 넣지 않고, 커밋·로그·출력·채팅 붙여넣기를 하지 않는다(`CLAUDE.md` 비밀값 규칙과 같다). 열쇠가 없으면 부르지 않고 `E-FORMS-BG-FAILED`다
- **로그**: 오류 번호·경로만 남긴다(`console.error('[api/ai/forms/background]', code)` 한 줄). 적은 말·프롬프트·그림·열쇠·OpenAI 오류 글은 남기지 않는다(`plan.md` §8)
- **CSP는 바꾸지 않는다**: OpenAI는 서버만 부르고 브라우저는 OpenAI와 말하지 않으므로 `connect-src`에 `api.openai.com`을 더하지 않는다. 그림은 우리 서버 답(`connect-src 'self'`)과 Supabase Storage(이미 `connect-src`에 있는 Supabase origin)로 받아 `data:` 주소(이미 `img-src 'self' data: blob:`에 있음)로 그린다. Storage 서명 주소(https)를 `<img>`에 바로 걸면 `img-src`에 Supabase origin을 더해야 하고 그림 파일(PNG) 만들기에서 다시 읽어야 해서 쓰지 않는다
- **글자 색은 앱이**: 강조색은 AI에게 받지 않고 앱이 그림 가장자리에서 뽑아 흰 글자 4.5·'N월' 판 3 대비를 맞춘다(`lib/forms/accent.ts`). 글자 뒤에는 반투명 흰 판을 깐다. 안내문 그림 안의 색 예외(ADR-028)는 넓히지 않는다(새 색 글자 없음)
**이유**: 사용자가 도형이 아닌 생생한 그림을 원했고, Google이 아닌 OpenAI 그림 AI를 골랐다 **(사용자, 2026-11-15)**. 시험(2026-11-15)에서 한 장 약 7초·약 80원·A4 비율 그림이 나왔고, 앱이 강조색과 흰 판을 맞추면 어느 그림에서도 글자가 읽혔다(승인 시안 `docs/mockups/forms-themes/ai-backgrounds.html`). 배경의 말('봄 벚꽃' 같은)은 비트 환자 자료가 아니라 사람이 적는 짧은 말이다(환자 자료 구역 규칙은 그대로다)
**대안**: (1) Claude가 SVG 글로 그림 — "답은 글자로만 그린다" 규칙을 깨고 생생한 그림이 아니다. (2) 도형만 받아 앱이 그림(ADR-028 덧붙임) — 아이콘 수준이다. (3) Google 그림 AI — 사용자가 고르지 않았다. (4) 서버가 만든 그림을 바로 Storage에 둠 — 마음에 안 든 그림까지 쌓이고 service role 키가 필요하다. (5) 브라우저가 OpenAI를 바로 부름 — 열쇠가 브라우저로 가고 CSP를 넓혀야 한다
**트레이드오프**: 적은 말이 병원 밖(OpenAI 서버)으로 간다 → 30자·개인정보 모양 거부·늘 보이는 안내("적은 말만 OpenAI 그림 AI로 보내요. 전화번호·주민번호·메일 주소는 적지 마세요…")로 줄인다. 환자 이름 모양은 걸러낼 수 없다. 그림에 글자 비슷한 무늬가 섞일 수 있다 → 사람이 미리보기로 보고 [다시 만들기]. 하루 한도는 보내기 전에 세서 OpenAI가 실패해도 한 장이 줄어든다. 내 배경을 지워도 그것을 쓴 안내문의 `bg-<id>`는 DB가 알려 주지 않는다(외래 키 없음) → 화면이 알리고 저절로 고른 테마로 그린다. AI 공급자가 둘(Anthropic·OpenAI)이 되어 열쇠·한도는 두 관리 화면에서 본다

### ADR-030: 예약 탭은 환자 이름·차트번호를 서버에 저장한다 (구글 캘린더 대신)
**맥락**: 의원은 공용 구글 캘린더에 예약(이름·차트번호·담당·종류)을 적어 왔다. 2026-11-17 사용자: 웹앱 '예약' 탭이 구글 캘린더를 대신하고, 접수·치료실·진료실 PC와 폰(총괄·원장님)이 같은 예약표를 몇 초 안에 본다. 이것은 "환자 개인정보는 의원 PC 밖으로 나가지 않는다 · 서버에는 집계 숫자만"(`CLAUDE.md` 아키텍처 규칙, ADR-003·020·021)에 부딪힌다. 그래서 이 탭의 표에만 예외를 연다
**결정** (사용자, `specs/clinic-calendar`):
- **서버에 두는 것**: 예약 한 줄(`calendar_appts`: 날짜·시작·길이·환자 이름·차트번호(없어도 됨)·시행자·종류·메모 100자·도착 상태·처음 자리), 종일 줄(`calendar_allday`: 메모 20자·시행자 휴무), 설정(`calendar_settings`), 바뀜 숫자(`calendar_rev`)
- **두지 않는 것**: 전화번호·주민번호·주소·성별·나이·생일·마지막 내원·비트 접수 목록·비트 자체 예약(RsvInf). 비트 찾기 결과 중 사람이 고른 이름·차트번호 두 칸만 예약 칸에 들어간다. 이름·메모가 전화·주민번호·메일 모양이면 앱이 보내지 않는다
- **비트에서 서버로 가는 값은 도착 자동 표시(`auto`: 왔음·안 옴·없음) 하나다.** 비트 PC Worker가 그날 접수 차트번호와 예약 차트번호를 견주어 예약 id마다 셈하고, 화면은 그 id·값만 적는다. 접수 목록은 Worker 밖으로 나가지 않는다(ADR-020 길 그대로). 폰은 그 값을 읽기만 한다
- **읽기**: RLS로 승인된 내 병원 계정만. 기본 권한을 모두 거둔 뒤 필요한 칸 권한만 준다. anon 없음. AI로는 보내지 않는다
- **지우기**: 날짜가 한국 날짜 오늘−1년보다 이른 예약·종일 줄은 예약을 넣을 때마다 DB 트리거가 지운다(확장 기능·예약 작업 없음)
- **다른 PC**: 보이는 동안 5초마다 `calendar_rev` 숫자 하나만 읽고 바뀌었을 때만 다시 읽는다. 실시간 연결(Supabase Realtime)은 쓰지 않아 CSP `connect-src`는 그대로다
**이유**: 구글 캘린더를 대신하고 폰에서도 이름으로 예약을 봐야 한다 **(사용자, 2026-11-17)**. 신환은 차트번호가 없어 이름이 있어야 한다. 도착 표시를 폰에서도 보려면 비트 PC가 정한 값이 서버에 있어야 한다 **(사용자)**
**대안**: (1) 비트 예약만 쓰기 — 폰에서 못 보고 담당·종류 칸이 없다. (2) 차트번호만 — 신환·폰에서 누군지 모른다. (3) Realtime — CSP에 wss origin을 더하고 구독 권한을 따로 다뤄야 한다. (4) pg_cron으로 매일 지움 — 확장을 켜야 하고 PGlite 시험으로 증명하지 못한다
**트레이드오프**: 환자 이름·차트번호가 의원 밖(Supabase 서울)에 1년까지 남는다. 계정이 털리면 보인다 → 구글 로그인·관리자 승인·30분 자동 로그아웃 그대로. 메모의 개인정보는 모양 검사로만 막는다. 예약을 하나도 넣지 않는 동안은 지난 줄이 지워지지 않는다(매일 넣으므로 늦어도 하루). 5초 읽기로 요청이 는다(PC 셋이 하루 10시간이면 약 2만 번, 답은 숫자 하나)

### ADR-031: 데스크 계정 — 병원마다 '데스크' 역할 계정을 따로 둔다 (plan.md §10 "직원·원장 계정과 역할"을 다시 꺼냄)
**맥락**: plan.md §0-1·§10은 혼자 쓰는 MVP라 직원 계정·역할(구성원 표)을 2차로 미뤘다. 2026-11-18 시연(ERP 업체 부장님)에서 데스크 PC는 업무일지·수납일지·예약만 봐야 한다는 말이 나왔고, 사용자가 "데스크 계정 따로"(서버가 막음)를 골랐다. 원장 계정을 데스크 PC에 같이 쓰면 통계·매출·청구가 다 보인다
**결정** (사용자, `specs/desk-feedback`):
- 역할은 '데스크' 하나다. 원장(병원 계정 = `hospitals.owner_id`)이 설정에서 데스크 구글 메일을 5개까지 더하고 뺀다. 그 메일로 로그인하면 가입 승인 없이 그 병원의 데스크다. 표 `hospital_members`(병원·메일·역할 'desk'), 사용자 표 권한은 없고 정의자 함수(`add_desk_member`·`desk_members`·`remove_desk_member`·`my_desk`)로만 다룬다
- 데스크는 로그인 메일(JWT의 email)로 맞춘다. 사용자 id는 적지 않는다(로그인 콜백·문지기가 쓰지 않게)
- `my_hospital_id()`는 그대로 원장 전용이다. 데스크는 `my_desk_hospital_id()`와 '데스크 …' 정책이 연 표에서만 읽고 쓴다: `worklog_days`·`sunap_days`·`sunap_spends`·`sunap_settings`·`calendar_settings`·`calendar_appts`·`calendar_allday`(표 권한대로), `worklog_settings`·`stats_rx_groups`·`calendar_rev`(읽기). 이 표들의 `hospital_id` 기본값과 예약 트리거 둘은 `my_clinic_hospital_id()`(원장 먼저, 아니면 데스크)
- 이미 병원 가입 신청(승인·대기·거절)이 있는 메일은 데스크가 될 수 없고, 데스크 메일은 병원 가입 신청을 못 한다(restrictive 정책). 기존 계정을 데스크로 바꾸는 것은 미룸(사용자 결정 미룸, 2026-11-18)
- 화면: 탭 셋(업무일지·수납일지·예약), 첫 화면 수납일지, 다른 주소는 막힌 화면(`DeskGate`). 탭 셋 밖에서 여는 주소는 비트 PC 연결 화면(`/claim/setup`) 하나뿐이다 — 탭에는 없고 계정 메뉴·수납일지 안내 칸·업무일지 안내에서 간다(desk-setup, 2026-11-19). AI 경로는 원장만(그대로)
- ADR-004 덧붙임: 페이지 문지기(`readMe`)는 내 병원 줄이 없을 때 `my_desk()`로 내 데스크 줄을 읽는다. 쓰지 않는다
**이유**: 데스크 PC에서 원장 자료가 보이지 않아야 하고, 주소를 쳐도 서버가 주지 않아야 한다 **(사용자, 2026-11-18)**
**대안**: (1) `my_hospital_id()`에 데스크를 넣기 — 모든 표가 한꺼번에 데스크에 열린다. (2) 화면만 숨기기 — 주소·개발자 도구로 자료가 보인다. (3) 직원 PIN — 계정·세션 구조를 새로 만들어야 한다. (4) 첫 로그인 때 사용자 id 적기 — 콜백·문지기가 DB에 써야 한다
**트레이드오프**: 데스크 구글 메일이 서버(Supabase 서울)에 남는다(환자 정보 아님). 메일로 맞추므로 Supabase 인증의 메일 확인(Confirm email)을 끄지 않는다. 세 탭에 새 표가 생기면 그 표에도 데스크 정책을 따로 더해야 한다. 데스크도 비트 PC 연결 화면에서 설치 파일(보관함 `install-files`, 읽기 규칙 "설치 파일 읽기(승인된 사용자·데스크·관리자)", `20261119200000_desk_install_files.sql`)을 받아 확장·도우미를 깔고 연결한다(desk-setup, 2026-11-19). `20261117010000_calendar.sql`을 다시 붙여 넣으면 이 SQL도 다시 붙여 넣어야 한다
**바꾸는 것**: `plan.md` §0-1·§2-1·§5 DB 표·§10, `CLAUDE.md` 인증 예외 줄(내 병원·관리자·데스크 줄, ADR-004·ADR-031), `docs/ARCHITECTURE.md` DB 표·인증

### ADR-032: 신환 1명당 매출 — 환자·날 금액은 비트 PC Worker 메모리에만 둔다
**맥락**: 통계 매출 칸의 '신환 1명당'(`specs/stats-insights` REQ-6106)은 신환이 처음 온 날부터 90일 동안 낸 진료비를 센다. 지금까지 비트에서 오는 금액은 날·원장님 합계(`doctorDays`)뿐이라 환자마다의 금액이 없었다. 환자별 금액은 지금까지 웹이 다루지 않던 자료다
**결정** (2026-11-18 사용자 "이번에 같이 만들기", `specs/stats-insights`): 도우미 0.11.0의 `stats.rows` v5 답 맨 끝에 `pays`[[차트번호, 수납일, 총진료비]]를 더한다(원장님별 금액과 같은 기준 줄, 환자·날마다 합, 원 단위 정수, 환불이 더 큰 날은 음수, 0원 줄은 보내지 않음)
- **어디에 두나**: 통계 Worker가 검사한 뒤(`helperData.ts` — v5에서만 받고 없어도 된다, 줄 수 한도는 다른 줄과 같다, 모양이 틀리면 `E-BRIDGE-BAD-REPLY`) 차트번호를 메모리 번호로 바꿔 Worker 메모리(`BitMemory.pays`)에만 둔다. 다음 불러오기가 덮어쓰고 저장하지 않는다
- **밖으로 가는 것**: `patientValue`가 센 1명당 숫자(대상 수·1명당 평균·내원 횟수·한 번 올 때 평균)와 받은 치료별 줄(묶음 열쇠·인원·평균)뿐이다. 받은 치료 줄은 5명 이상인 조합만 따로 두고 나머지는 '그 밖'으로 합친다. 환자 번호·환자별 금액은 Worker 밖(화면·서버·AI)으로 가지 않는다
- **서버에 저장하지 않는다**: 이 숫자도 `stats_months`·`validate.ts`에 넣지 않는다(시안의 "서버에는 평균과 인원만"보다 좁다). 그래서 비트에서 불러온 PC에서만 보인다
- **옛 도우미**: v3·v4 답과 `pays`가 없는 v5 답도 그대로 받는다. 그때 탭은 '도우미를 0.11.0으로 올리면 볼 수 있어요'다
**이유**: 1명당 매출은 환자마다 첫 내원일과 90일 안 금액을 맞춰야 셀 수 있어 합계만으로는 안 된다. 환자 자료는 의원 PC Worker 안에서만 계산한다는 규칙(ADR-020) 안에서 끝낼 수 있다
**대안**: (1) 도우미가 1명당 숫자까지 셈 — 묶음(처방 칸 묶음·빼는 처방 규칙)과 신환 날 규칙을 C#에 한 벌 더 두어야 한다. (2) 1명당 숫자를 서버에 저장 — 다른 기기에서도 보이지만 저장 모양·AI 검사를 늘려야 하고 사용자가 고르지 않았다
**트레이드오프**: 환자별 금액이 비트 PC 브라우저 메모리에 불러온 기간만큼(많아야 약 26달) 머문다 → 탭을 닫거나 다시 불러오면 사라진다. 불러온 기간이 짧으면(90일이 다 지난 신환이 없으면) '아직 셀 환자가 없어요'다. 도우미 0.11.0을 깔기 전에는 안내 글만 보인다

### ADR-033: 병원 정보를 한 곳(clinic_profiles)에 두고, 페이지 guard가 그 이름을 읽는다
- 결정: 병원 이름·로고·전화·주소·호칭·요일별 진료시간·휴진일·원장님·직원을 `clinic_profiles` 한 줄(RLS 내 병원, 고치기는 원장만, 데스크는 읽기만)과 비공개 Storage `clinic-logos`에 둔다. 서식·문자·예약·통계·대시보드·AI가 이것을 읽는다. 예약 시행자 목록은 이것의 '예약에 보이기' 사람으로 합친다(옛 칸은 남겨 두고 읽지 않는다).

- 대가: 데스크가 예약 시행자를 더하지 못한다(원장이 병원 정보에서). 진료시간은 통계에서 보이는 칸만 바꾸고 저장 모양은 그대로다.

### ADR-034: 재고 탭은 거래명세서 사진과 엑셀 머리 줄을 Claude로 보낸다 (환자 정보 없음)
- 맥락: 2026-11-21 사용자: 입고는 거래명세서 사진을 올리면 AI가 날짜·거래처·물품·수량·단가를 읽고, 처음 목록은 가진 엑셀을 그대로 올리면 AI가 칸을 맞춘다. "Claude에는 서버가 DB에서 읽은 집계만 보낸다"(ADR-007, `CLAUDE.md` 아키텍처 규칙)에 부딪혀 이 두 경로에만 예외를 연다(`specs/inventory`).
- 결정: `app/api/ai/inventory/invoice`(`POST`)는 브라우저가 줄인 JPEG 한 장(긴 변 1,600px, base64 4,000,000자까지)과 서버가 DB에서 읽은 내 병원 물품 이름·단위 목록만 Claude로 보낸다. `app/api/ai/inventory/columns`(`POST`)는 엑셀 머리 줄(30칸)과 앞 줄 5개(칸마다 40자)만 보내고, 칸에 전화·주민번호·메일 모양이 있으면 보내지 않는다. 앱 양식 그대로인 엑셀은 AI를 부르지 않는다. 둘 다 승인된 원장만(데스크 아님), 병원·사용자 정보는 보내지 않고, 요청·답을 로그하지 않으며(오류 번호·경로만), 사용량은 `ai_usage`에 더한다. 답은 정해 둔 모양(JSON 스키마)만 받아 검사하고 사람이 확인 화면에서 고친 뒤 저장한다. 사진은 사용자가 [저장]한 입고만 비공개 Storage `inventory-photos`(내 병원 폴더, JPEG 3,000,000바이트까지)에 둔다. 서버는 사진을 저장하지 않는다.
- 덧붙임: `plan.md` §10 '재고 단위 변환·유효기간' 가운데 유효기간을 물품마다 가장 빠른 것 하나로 다시 꺼낸다(사용자, 2026-11-21). 단위 변환은 그대로 미룬다.
- 대안: (1) 사람이 다 적기 — 사용자가 사진 읽기를 원했다. (2) 브라우저 글자 인식(OCR) — 표 모양 명세서에서 물품·수량을 잇지 못한다. (3) 엑셀 칸을 사람이 고르기만 — 양식 그대로면 그렇게 하고, 사용자 엑셀일 때만 AI가 먼저 골라 준다(고를 칸은 그대로 있음).
- 트레이드오프: 명세서·주문 캡처에 환자 이름이 찍힐 수 있다(보조기 주문 등) → 늘 보이는 안내('환자 이름이 보이는 사진은 올리지 마세요'), Claude 규칙(사람 이름을 적지 않음), 답의 개인정보 모양 검사로 줄인다. 모양 없는 이름과 사진 속 글자는 막지 못하고 그 사진이 Storage에 남는다. 사진 한 장에 대략 30~80원이 든다.

### ADR-035: 주소록 — 사이트 비밀번호·계좌를 잠그지 않고 다른 칸처럼 서버에 둔다
**맥락**: 주소록(`specs/contacts`)에는 업체 사이트 아이디·비밀번호와 계좌가 들어간다. 2026-11-21 인터뷰에서 사용자는 잠금 번호(따로 정한 번호로 브라우저에서 잠그고 볼 때 풀기)를 고르다가 "그냥 잠그지 마"로 정했다. 의원 계정은 접수·치료실·진료실 PC에 로그인돼 있어 그 PC 앞에 앉은 누구나 [보기]로 볼 수 있다는 점을 듣고 정했다. 이 값들은 우리 서비스의 비밀값(Supabase 키·API 열쇠, `CLAUDE.md` 보안 규칙)이 아니라 사용자가 적는 업체 자료다
**결정** (사용자, `specs/contacts`):
- 사이트 비밀번호(`site_pw`)·계좌(`account`)는 `contacts_companies`의 다른 칸과 똑같이 글자로 저장한다. 앱이 따로 암호화하지 않는다(Supabase 저장소 자체 암호화만)
- 읽기·쓰기는 RLS로 승인된 내 병원 **원장 계정만**(`my_hospital_id()`). 데스크 계정(ADR-031)·다른 병원·anon은 0줄. AI 경로로 보내지 않고, 로그·오류 글에 담지 않는다
- 화면은 평소 `●●●●●●`로 가리고 [보기]를 누른 칸만 보인다(다른 업체로 옮기거나 화면을 떠나면 다시 가림). 엑셀 미리 보기는 칸 값을 보이지 않는다. 엑셀 양식 `쓰는 법`에 "다 올린 뒤에는 지우거나 잘 보관하세요"가 있다
**이유**: 사용자 결정(2026-11-21). 잠금 번호는 PC마다 다시 쳐야 하고 잊으면 되살릴 수 없다. 혼자 쓰는 MVP라 원장 계정 보호(구글 로그인·관리자 승인·30분 자동 로그아웃)로 충분하다고 봤다

### ADR-036: 고시·공지는 서버가 정해 둔 시각에 바깥 사이트를 읽고, 모으기 전용 계정으로 쓴다
**맥락**: 고시·공지 탭(specs/notices)은 로그인한 사람이 없는 아침에 사이트를 읽고 모든 병원이 볼 줄을 써야 한다. 서버 코드는 `app/api/ai/` 하나, service role 키 금지, 문지기는 로그인 안 한 요청을 `/login`으로 보낸다(CLAUDE.md·ADR-004).
**결정** (2026-11-21 사용자 인터뷰·시안 승인, 설계는 Claude 판단):
- 경로는 `GET /api/ai/notices/collect` 하나(`app/api/ai/` 안). Vercel Cron(무료판은 식마다 하루 한 번·그 시간 안 아무 때, 한 프로젝트 100개까지)으로 같은 경로를 아홉 식 건다: `0 22 * * *`(한국 07시대 아침)과 `0 0`·`0 2`·…·`0 14`(한국 09~23시대 두 시간마다). 실행은 모두 같고, 새 글 확인은 출처마다 하루 한 번(첫 실행 = 아침)이다. 나머지는 지난 글 채우기와 일괄 결과 거두기다 — 시안의 '하루쯤'을 지키려고. `Authorization: Bearer <CRON_SECRET>`만 받는다(같은 시간 비교, 비어 있으면 거부). 300초(무료판 최대) 안에서 시간 표대로 멈추고 다음 실행이 잇는다. 같은 실행이 두 번 와도 DB 잠금(`notice_start_run`)과 '있는 key는 넣지 않음'으로 한 번만 한다.
- 문지기 예외 한 칸: `lib/auth/gate.ts`의 공개 경로에 이 주소 하나를 더한다. 지키는 것은 경로의 `CRON_SECRET` 검사다.
- DB 쓰기는 **모으기 계정**: Supabase 인증 계정 하나(메일·비밀번호는 Vercel 환경 변수 `NOTICES_COLLECTOR_EMAIL`·`NOTICES_COLLECTOR_PASSWORD`에만)가 공개 열쇠로 비밀번호 로그인한다. 허용 목록 표 `notice_collectors`(admins처럼 SQL 편집기로만 넣음)에 있는 계정만 공용 표에 넣고 고친다(지우기 없음). 병원 줄이 없어 병원 자료는 RLS가 막는다. 시험용 우회 길이 아니라 권한이 좁은 진짜 계정이다.
- 사이트 규칙을 지킨다: 정해 둔 주소만 부르고(복지부는 RSS만), 브라우저 모양 UA, host마다 동시 2개·300ms 간격. 의사협회(서울 서버에서 막힘)·건보공단(robots 금지)·회원 전용 사이트는 뺀다. 한 출처가 막히면 그 출처만 '못 가져옴'이다.
**대안**: (1) service role 키 — 규칙 금지. (2) Supabase Edge Function·pg_cron — 서버 코드가 `app/api/ai` 밖으로 나가고 service role을 갖는다. (3) anon이 부르는 함수 + 비밀 글자 인자 — 권한이 RLS가 아니라 글자 하나에 달린다. (4) 하루 한 번만 — 처음 채우기가 1~2주라 시안 '하루쯤'과 어긋난다. (5) 실행이 자기를 다시 부르는 사슬 — 끝없이 돌 위험. (6) Vercel Schedules(베타) — 베타다.
**트레이드오프**: 모으기 비밀번호가 새면 가짜 글을 쓸 수 있다 → 주소 제약(두 사이트만)·글자로만 그림·지우기 없음, 비밀번호를 바꾸면 끝난다. 사이트 모양이 바뀌면 그 출처가 멈추고 코드를 고쳐야 한다. 시각이 그 시간 안에서 흔들린다. Vercel은 Cron Jobs를 Schedules로 옮길 예정이라 그때 설정을 옮긴다.

### ADR-037: 모든 병원이 같이 보는 공용 표 (plan.md §0 '모든 표에 hospital_id' 예외)
**결정**: 고시·공지 글·출처 글·출처 상태·주간 모음(`notices`·`notice_posts`·`notice_sources`·`notice_weeks`)은 병원과 상관없는 같은 자료라 `hospital_id` 없이 한 벌만 둔다(요약은 한 번만 만든다). 읽기는 승인된 원장(`my_hospital_id()`가 있음)과 모으기 계정만이고 데스크·승인 대기·anon은 못 본다. 실행 기록 `notice_runs`(토큰·비용·건수 숫자만)는 관리자·모으기 계정만 읽는다. 병원마다 다른 것(읽음·별표·메모·규칙 확인 `notice_marks`, 묻기 횟수 `notice_ask_days`·`notice_ask_holds`, 내 낱말 `notice_keywords`와 그 맞춤 `notice_keyword_hits`)은 `hospital_id` 표다. 맞춤 줄은 정의자 트리거만 쓴다(공용 글이 바뀌면 모든 병원 낱말로 다시 맞춤). 메모는 병원이 손으로 적는 500자 글이다: 앱이 환자 정보 모양(주민번호·전화·차트번호·긴 숫자)을 막고 AI로 보내지 않는다(업무일지 메모 ADR-025와 같은 남는 위험 — 환자 이름은 못 막음).
**이유**: 같은 글을 병원마다 따로 요약하면 비용이 병원 수만큼 든다. 판단 기준(정형외과 의원)이 모두 같다 **(사용자)**.
**트레이드오프**: 공용 줄은 모으기 계정만 쓴다. 지우는 길이 없어 잘못 들어간 글은 SQL 편집기로 지운다. 무료 DB 500MB 안에서 본문·붙임 글자를 각 20,000자로 묶는다.

### ADR-038: 바깥 공개 글을 Claude로 보내고, 묻기는 사용자가 적은 질문을 보낸다 (ADR-007 '서버가 DB에서 읽은 집계만' 예외)
**결정**:
- **요약**: 심평원·복지부 공개 글의 본문과 붙임을 `claude-opus-5-5`(effort medium)로 보낸다. PDF는 파일째(document 블록, 30쪽·18MB까지, 넘으면 서버가 뽑은 글자), HWPX는 서버가 뽑은 글자, 옛 HWP는 건너뛰고 '본문만 보고 요약'. 병원·사용자·환자 정보는 보내지 않는다. 바깥 글은 `<notice>`·`<attachment>`로 감싸 자료로만 다룬다. 답은 정해 둔 JSON 여섯 칸만 받아 칸마다 검사·자르기 한다. 붙임 파일은 저장하지 않고 찾기용 글자(20,000자)와 원래 링크만 둔다 **(사용자)**.
- **일괄 처리**: 올라온 지 3일이 지난 글(처음 채우기)은 Message Batches(반값)로 보내고 다음 실행에 거둔다. 일괄은 `fallbacks`를 못 써서 거절·실패는 다음 실행에 바로 부르기로 다시 한다.
- **묻기**: 사용자가 적은 질문(1~300자)을 그 글(서버가 DB에서 읽은 제목·요약·본문·붙임 글자)과 함께 보낸다. 화면과 서버가 같은 검사(`askCheck.ts`: 주민번호·전화·차트번호·6자리 넘는 숫자)로 막고 보내지 않는다. 병원마다 하루 20번을 보내기 전에 DB가 표로 세고(`take_notice_ask`), AI가 실패하면 표를 돌려줘 횟수가 줄지 않는다(시안). 질문·답은 저장·로그하지 않는다(로그는 오류 번호·경로 한 줄). 답은 글자로만 그린다. 칸 위에 늘 '환자 이름·주민번호·전화번호·차트번호는 쓰지 마세요.'
- **새 패키지**: `unpdf`(PDF 글자·쪽 수), `fflate`(HWPX zip) — 서버 `attachText.ts`만.
- **점검 규칙 연결**: 서버가 `lib/precheck/data/rules.json`을 읽기만 해 근거 고시 번호와 맞춘다(규칙 자동 수정 없음). 환자 자료 구역 울타리는 그대로다.
**이유**: 붙임까지 읽은 세 줄 요약과 자유 질문은 사용자가 골랐다 **(사용자, 2026-11-21)**. 보내는 것은 누구나 볼 수 있는 정부 공개 글이다. 질문은 서식 AI 정리(ADR-028)와 같은 틀로 막는다.
**대안**: (1) PDF를 늘 글자로만 — 싸지만 표·스캔 PDF를 놓친다. (2) Files API에 올려 두기 — 바깥에 파일이 남는다. (3) 정해 둔 질문만 — 사용자가 자유 질문을 골랐다.
**트레이드오프**: 환자 이름은 걸러낼 수 없다 → 안내 글과 저장·로그 안 함. 9자리 약품코드 같은 긴 숫자도 막힌다. 바깥 글 속 지시(프롬프트 주입)는 모양 고정 답·글자 그림으로 피해를 줄인다. 비용은 처음 8~17만 원·매달 약 1.5만 원 어림이고 `notice_runs`로 잰다.

### ADR-042: 입지 분석은 서버 경로가 바깥 공개 자료를 대신 부른다 (관리자만, Claude 아님)
**맥락**: 입지 분석(specs/location)은 공공데이터포털·카카오 로컬 자료가 필요하고 둘 다 열쇠가 있어야 한다. 열쇠를 브라우저에 두면 드러나고, 공공데이터포털은 브라우저 부르기(CORS)도 막는다. 서버 코드는 `app/api/ai/` 하나뿐이다(ADR-004).
**결정** (호출한 쪽 설계 결정 + Claude 판단, 2026-11-22):
- `POST /api/ai/location/query`·`GET /api/ai/location/keys` 두 경로를 `app/api/ai/location/` 아래 둔다. Claude는 부르지 않는다 — AI 폴더를 서버 코드 자리로 쓰는 예외다.
- 열쇠 `DATA_GO_KR_KEY`(디코딩 열쇠)·`KAKAO_REST_KEY`는 Vercel 환경 변수와 `.env.local`에만. 앱 화면에 열쇠 칸을 두지 않는다.
- 서버가 로그인·승인된 병원·`admins` 줄을 확인한다. 아니면 401·403이고 바깥에 부르지 않는다.
- 정해 둔 종류·칸만 받고 정해 둔 host만 부른다(redirect 없음, 8초, 2MB). 서버는 DB에 쓰지 않는다(저장은 브라우저가 RLS로). 카카오 답은 서버에도 담아 두지 않는다. 서버 메모리 보관도 없다(역·정류장 좌표는 정적 파일).
- 로그는 오류 번호·종류만. 좌표·주소·답은 남기지 않는다.
- 새 경쟁 의원 확인은 Vercel Cron이 아니라 관리자가 대시보드를 열 때 브라우저가 한다(후보마다 30일에 한 번).
**대안**: (1) 브라우저가 바로 부름 — 열쇠가 드러나고 CORS에 막힌다. (2) Cron — 세션이 없어 관리자 표를 못 읽는다 → 모으기 계정이 또 필요하다(ADR-036 같은 장치). (3) 카카오 JS SDK의 주소 찾기 — REST 열쇠를 서버에 두는 쪽으로 통일했다.
**트레이드오프**: 대시보드를 한 달 넘게 안 열면 알림이 늦다. 바깥 응답 모양이 바뀌면 그 종류만 '못 받음'이고 코드를 고친다. 무료 한도(카카오 로컬 하루 10만 건, 공공데이터포털 자료마다 개발 1만 건)를 넘기면 그날은 못 받는다.

### ADR-043: 카카오 지도 JavaScript 키는 `NEXT_PUBLIC_KAKAO_MAP_KEY`에 둔다 — 비밀값이 아니다. `/location`만 CSP·Referrer를 넓힌다
**맥락**: CLAUDE.md는 `NEXT_PUBLIC_*`에 비밀값을 넣지 않게 한다. 카카오 지도 SDK는 브라우저가 주소에 `appkey=`로 키를 실어 부른다. 앱은 `Referrer-Policy: no-referrer`인데 카카오는 요청이 등록한 사이트에서 왔는지 본다.
**결정**:
- JavaScript 키는 카카오가 웹 페이지에 드러나도록 만든 키이고, 카카오 개발자 화면에 등록한 사이트(`https://seoseungkwanapp.vercel.app`, 개발 `http://localhost:3000`)에서 온 요청만 받는다. 그래서 비밀값이 아니라 공개 이름표로 보고 `NEXT_PUBLIC_KAKAO_MAP_KEY`에 둔다. 사이트 잠금이 없는 REST 키는 비밀값이라 서버에만 둔다(ADR-042). '비밀값을 NEXT_PUBLIC에 넣지 않는다' 규칙과 부딪히지 않는다.
- `/location`·`/location/…`에만 카카오 origin을 정확한 이름으로 CSP에 더하고(와일드카드 없음) `Referrer-Policy: strict-origin-when-cross-origin`(사이트 이름만 보내고 주소 뒤쪽은 안 보냄). 다른 화면은 그대로다.
**대안**: (1) JS 키도 서버 뒤 — SDK가 브라우저에서 키를 쓰므로 안 된다. (2) 정적 지도 그림 — 로드뷰·하늘 사진·움직이는 지도가 없다. (3) 모든 경로에 넓힘 — 지도 없는 화면까지 바깥 스크립트를 허락한다.
**트레이드오프**: 우리 사이트 안에서는 키가 보인다(다른 사이트는 못 씀). 무료 한도는 카카오 계정의 첫 번째 앱에만 준다. `/location`에서만 카카오 스크립트가 돌고 Referrer를 사이트 이름만큼 연다. 키를 바꾸면 다시 배포해야 한다(빌드 때 들어감).

### ADR-044: 카카오 결과는 저장하지 않고, 공공 자료는 후보를 저장한 날의 값으로 굳힌다
**맥락**: 카카오 운영정책 제5조는 결과 묶어 두기·다시 팔기를 막고, 카카오 직원 답(데브톡 2026-10-29)은 받은 주소·좌표를 업무 자료로 오래 저장하면 안 되고 사용자가 직접 정한 위치 좌표는 된다고 했다. 사용자는 '볼 때 받고 저장 때 그날 값으로 굳힘 + 기준 날짜'를 골랐다.
**결정**: 저장하는 것은 `specs/location/design.md` 6절 '저장하는 것' 목록뿐이다(표 여섯·사진 바구니, `supabase/migrations/20261122000000_location.sql`). 카카오에서 받은 주소 글·좌표·장소 목록·거리·로드뷰·법정동 코드는 저장하지 않고 열 때마다 부른다. 점수는 공공 자료(역·정류장 포함)만 써서 굳힌다. 숫자마다 출처 id·기준 날짜를 달고, 출처·법 근거·없는 자료 목록은 `lib/location/sources.ts` 한 곳이다. 동 경계는 국가데이터처 SGIS 경계(이용 제한 없음)를 줄여 `public/location/dongs/`에 둔다(반기마다 사람이 바꿈). 역·정류장 좌표(국토교통부 버스정류장 위치 15067528·도시철도역사 15013205, 이용 제한 없음)도 `public/location/transit/`에 둔다(해마다 사람이 바꿈).
**대안**: (1) 둘레 시설도 저장 — 정책 위반. (2) 아무것도 굳히지 않음 — 견줄 때마다 값이 바뀐다. (3) 동 경계를 그때마다 바깥에서 — 공개 API가 없거나 따로 가입해야 한다.
**트레이드오프**: 둘레 시설·거리 사진은 카카오 열쇠가 없으면 안 보이고 열 때마다 바뀐다. 동 경계·소득·정류장·역 좌표 파일은 사람이 새로 넣기 전까지 옛 기준 날짜를 보인다.
