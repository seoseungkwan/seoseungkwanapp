# 개발 계획: `ai-report` — AI로 보고서·PPT를 내 양식 그대로 만들기

- 작업 사본(worktree): `/home/developer/seoseungkwan/wt-ai-report`
- 브랜치: `feat-ai-report` (main `e9777a0`에서 시작, main은 건드리지 않음)
- 상태: **계획 승인 대기**. 승인 전에는 코드를 고치지 않는다.

## 0. 무엇을 만드나

숫자 집계를 Claude(Anthropic API)가 글로 정리하고, 그 글을 **미리 고정해 둔 내 양식**에 채워서
① 화면 보고서(브라우저 인쇄 → PDF)와 ② PPT 파일(.pptx)로 받는다.

핵심 원칙: **모양은 코드가, 글은 AI가 맡는다.**
- 표지·색·글꼴·쪽 순서·표 모양·글투(개조식/존댓말, 길이)는 "양식 정의" 한 곳에 고정한다.
- Claude는 정해진 칸(제목, 핵심 요약 3줄, 근거 숫자, 추정 표시, 다음 할 일)만 채운 JSON을 돌려준다.
- 그래서 몇 번을 만들어도 같은 모양이 나온다. AI가 디자인을 바꿀 수 없다.

## 1. 지켜야 할 기존 규칙 (CLAUDE.md · plan.md · ADR)

| 규칙 | 이 기능에서 하는 것 |
|---|---|
| 서버 코드는 `app/api/ai/` 하나 (ADR-004) | AI 호출은 이 경로 안에만 둔다. PPT·PDF는 브라우저에서 만든다 |
| AI에는 집계 숫자만, 서버가 DB에서 읽어 `validate.ts`로 검사 (ADR-007) | 브라우저가 보낸 숫자는 쓰지 않는다. 환자 정보·직원 이름·개인별 급여는 보내지 않는다 |
| 답은 글자로만 그린다, HTML 금지 (§6-2) | AI 답 JSON의 각 칸을 글자로만 넣는다. 태그·마크다운은 글자 그대로 보인다 |
| 키는 서버 환경 변수 `ANTHROPIC_API_KEY`에만 | `.env.local`·Vercel 환경 변수에만. 로그에는 오류 번호·경로만 |
| 월간 PDF는 브라우저 인쇄, 보고서는 저장하지 않음 (ADR-011) | 그대로 따른다. 열 때마다 새로 만든다 |
| 화면은 목업 승인 뒤에만 구현 | 양식 미리보기 목업을 먼저 승인받는다 |
| `plan.md §10`(미룬 것)은 만들지 않음 | 사용자별 AI 호출 제한 등은 넣지 않는다 |

**새로 정해야 하는 것:** PPT는 plan.md에 없던 기능이다. 서버를 늘리지 않으려고 **브라우저에서 .pptx를 만든다**(예: `pptxgenjs` 패키지). 패키지 추가와 이 결정은 명세와 ADR-016에 적고 승인받는다.

## 2. 승인할 때 같이 답해 주실 것

1. ✅ **"내 스타일" 자료**: Claude Design의 "그래프 보고서 목업"(https://claude.ai/artifact/DYcLGZSHKfZkPn42eZg2UK)으로 정함(2026-10-29 사용자). 그 색·글꼴·그래프 모양·쪽 순서를 양식 정의로 옮긴다.
2. ✅ **첫 양식**: 월간보고 PPT (2026-10-29 사용자)
3. **숫자 출처**: main에는 아직 매출·급여·DB 표가 없다. 첫 버전은 **환자 통계 집계만** 쓰고, 매출·급여는 그 기능이 생기면 칸을 늘린다.
4. **로그인 의존**: AI 경로는 "승인된 사용자"인지 확인해야 하고, 보고서 화면은 로그인 뒤 앱 틀 안에 들어간다. 앱 화면 꾸미기 방식(Tailwind, ADR-015)도 로그인 작업과 함께 들어온다(main은 아직 CSS Modules). 그래서 로그인 작업(`feat-auth`)이 main에 합쳐진 뒤에 Phase 3-②(화면)·③(서버 연결)을 한다. 그 전에는 화면과 상관없는 로직을 먼저 만든다.
5. ✅ **PPT 글꼴**: 맑은 고딕으로 고정 (2026-10-29 사용자). PPT는 여는 PC에 깔린 글꼴을 쓰므로, 어느 PC에서 열어도 모양이 같게 한다. 화면 보고서는 목업 글꼴을 따른다.
6. **비용**: 모델은 구현할 때 값을 비교해 제안한다(ADR-007). 실제 API를 부르는 시험은 돈이 들어서 부르기 전에 묻는다. Anthropic 콘솔 월 한도는 사용자가 건다.

## 3. Phase별 계획 (SDD → TDD → 구현 → 테스트 → PR)

### Phase 0. 준비 — ✅ 끝남

- 한 일: 작업 사본·브랜치 만들기, 패키지 설치(`npm ci`), 검사 장치 확인
- 확인 결과:
  - 코드 규칙 검사(`npm run lint`)·빌드(`npm run build`) 통과
  - 안전장치: 명세 승인 전 `src/` 수정 차단(sdd-guard), main 직접 push 차단(guard-bash), 문서(.md)는 허용 — 모두 새 사본에서 작동
  - 브랜치 이름 `feat-ai-report` → 명세 `specs/ai-report/`가 생기면 자동으로 이 기능이 "현재 기능"이 된다
  - 시험(`npm test`) 965개 통과, **속도 시험 2개 실패**: 같은 컴퓨터(처리 장치 2개)에서 다른 창이 `feat-auth` 빌드·스크린샷을 돌리는 중이라 느려진 것. 따로 돌리면 통과한다. 이 기능과 무관하며, Phase 4 검사는 다른 작업이 없을 때 돌린다.
- 주의: 이 사본에서 작업할 때는 Claude를 **이 폴더에서** 새로 열어야 검사 장치가 이 사본을 기준으로 돈다.

### Phase 1. SDD — 명세와 목업

- 할 일
  1. `/sdd`로 `specs/ai-report/requirements.md`(REQ·AC), `design.md`, `tasks.md`(TASK마다 `- Files:` 범위)를 쓴다. `.harness/active`를 `ai-report`로 바꾼다.
  2. ADR-016(브라우저에서 PPT 만들기 + 패키지), `docs/UI_GUIDE.md`에 "보고서·PPT 양식" 절을 더한다.
  3. 양식 미리보기 목업(표지·요약·근거 숫자·표 쪽, 보고서 화면과 PPT 쪽)을 보여 드린다. 비용 드는 이미지 생성은 쓰지 않는다.
- 미리 잡아 둔 요구사항(명세에서 다듬음)
  - REQ-001 양식 정의: 색·글꼴·쪽 순서·칸 이름·글자 수 한도를 한 파일에 고정
  - REQ-002 AI 답 검사: 정해진 칸 밖의 내용·너무 긴 글·빈 칸은 거부하고 쉬운 오류 문구(`lib/errors.ts`)
  - REQ-003 보내는 자료: 집계 숫자만. 이름·차트번호·전화·주민번호·메일 모양이 섞이면 보내지 않음
  - REQ-004 보고서 화면: 글자로만 그림, 인쇄용 CSS로 A4 한 장씩
  - REQ-005 PPT 파일: 양식 순서·색·글꼴대로 슬라이드를 만들고 내려받기
  - REQ-006 서버 AI 경로: 승인된 사용자만, DB에서 읽은 집계만, 키는 서버에만
- 완료 조건
  - `sdd check` 통과: 모든 REQ에 AC가 있고, 모든 AC가 TASK에 이어지고, TASK마다 수정 범위가 있다
  - 목업을 사용자가 승인했다
  - 사용자가 입력창에 `/sdd approve ai-report`를 쳐서 승인 기록(`specs/ai-report/approval.json`)이 생겼다
- 검증 방법: `~/.claude/harness/bin/sdd check`, `~/.claude/harness/bin/sdd status`(요구사항→시험 연결표)
- 사용자에게 묻는 지점: 목업 승인, 명세 승인

### Phase 2. TDD — 실패하는 시험 먼저

- 할 일: TASK마다 시험부터 쓰고 돌려서 **실패(RED)를 확인**한다. 시험 이름에 AC 번호를 넣는다.
  - 양식 정의: 색·글꼴·쪽 순서가 정의대로인지
  - AI 답 검사기: 칸 밖 내용·태그·너무 긴 글을 거부하는지
  - 보내는 자료: 금지 자료 모양이 들어가면 막는지
  - PPT 만들기: 만든 .pptx를 열어(zip 속 XML) 슬라이드 수·순서·글꼴·색을 확인
  - 보고서 화면: 글자로만 그리는지, 인쇄용 CSS가 있는지
  - 서버 경로: 미승인 사용자 거절, 브라우저가 보낸 숫자 무시, Anthropic 호출은 가짜(mock)로
- 완료 조건: 모든 TASK의 시험이 "구현이 없어서" 실패한 기록이 `specs/ai-report/tdd-log.jsonl`에 있다(문법 오류로 실패한 것은 RED로 치지 않음)
- 검증 방법: `~/.claude/harness/bin/tdd-run`, `npx vitest run <시험 파일>`

## 4. 양식: "그래프 보고서 목업"에서 뽑은 것

자세한 값은 `docs/ai-report-style-notes.md`. 명세(Phase 1)에서 이 값을 양식 정의로 고정한다.

- **PPT 바탕**: 목업의 인쇄용(밝은) 색을 쓴다(추천, 승인 때 확인). 화면용 어두운 색은 쓰지 않는다.
  - 글자 #111827 · 보조 #374151 · 흐린 글자 #4B5563 · 선 #D5D9E2 · 바탕 #FFFFFF
  - 강조 보라 #5B4BC4 · 늘었음 파랑 #1D4ED8 · 줄었음 주황 #B45309 · 재방문 비율 청록 #0F766E · 잠정 금색 #A16207(줄 바탕 #FEF9C3)
  - 그래프: 이번 기간은 보라 실선, 비교 기간은 회색 점선 #9CA3AF. 처방군 색 순서 #C4B5FD · #3B82F6 · #FBBF24 · #DB2777
  - 그림자 없음, 선 1px, 모서리 둥글기 10px
- **글꼴**: 전부 맑은 고딕(사용자 결정). 목업의 고정폭 숫자 글꼴 대신 표 숫자는 오른쪽 정렬로 맞춘다.
- **월간보고 PPT 쪽 순서(16:9)**
  1. 표지: 작은 꼬리표("MONTHLY REPORT") · 제목("2026년 10월 월간보고") · 비교 기간(이번 달 vs 지난달·작년 같은 달) · 만든 시각 · "환자 이름·차트번호 없음"
  2. 한눈에: 발견 4개, 숫자를 앞에 둔 한 문장
  3. 핵심 숫자 카드 3~4개 + 늘고 준 폭(+11.5%, −9.0%, 0.6%p, ↑/↓)
  4. 그래프 한 쪽에 하나씩: 위에 한 줄 결론("선택 처방 건수 2,761건 · 작년 같은 기간 2,476건보다 11.5% ↑"), 눈금 3줄, 마지막 점에만 숫자, 범례 대신 선 끝에 이름
  5. 요약 표
  6. 계산 기준: "· "로 시작하는 개조식 메모
- **누가 무엇을 채우나**: 숫자·늘고 준 폭·그래프·표·그래프 결론 줄은 **코드가 계산**한다(AI가 숫자를 바꾸지 못함). AI는 "한눈에" 문장과 다음 할 일 문장만 쓴다.
- **글투**: "~늘었어요", "확인해 보세요" 같은 해요체 한 문장. 자료가 덜 모인 달은 "잠정". AI의 원인 짐작은 plan.md §2-3대로 "추정"이라고 쓴다.
- **명세에서 정리할 작은 것 (Claude 판단)**: 목업에서 주황이 "줄었음"과 "신환" 둘 다에 쓰인다. 그래서 신환 그래프 색을 처방군 색과 겹치지 않게 따로 정한다.
