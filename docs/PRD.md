# PRD: 병원 업무 도구 (서비스 이름 미정, 임시 이름 사용)

> 2026-10-28 grill-me 인터뷰에서 정한 내용. 자세한 계획과 MVP 단순화는 루트의 `plan.md`에 있다 — 부딪히면 plan.md가 이긴다.

## 목표
정형외과 의원 총괄의 반복 업무(환자 통계, 매출, 재고, 급여·인센티브, 일일마감·보고)를 웹사이트 하나에서 처리한다.

## 사용자
- 당분간은 나(관리자) 혼자 쓴다. 승인 가입 기능은 만들어 두고, 나중에 다른 병원도 유치할 수 있게 한다
- 모든 데이터에 병원 구분값을 둔다(나중에 병원별로 분리)
- 흐름: 랜딩 → 구글 로그인 → (처음만) 가입 신청 → 관리자 승인 → 대시보드

## 핵심 기능 (첫 버전)
1. **환자 통계**: 통계분석 파일럿(`seoseungkwan/tonggye-bunseok`)의 파일 읽기·계산 코드와 테스트를 옮긴다. 화면은 새 UI로 만든다
   - 비트 '환자별 소모 통계' 파일을 업로드하고, 계산은 브라우저 안에서만 한다
   - 일·주·월 신환·재진, 신환율·재진율(전체 중 비율), 신환 재방문율(7일·14일 이내)
   - 처방별 신환율·재진율 = 그 처방을 받은 환자 중 신환·재진 비율
   - **처방 골라 보기 칸의 신환율·재진율** = 건을 밑수로 쓴다(신환 ÷ 건수, 재진 ÷ 건수). 이 칸에만 해당하고, 처방별 신환·재진 칸은 명 그대로다. 2026-11-03 사용자가 시안을 승인했고 건수 기준을 안내받았으며 이의를 말하지 않았다
   - 처방코드 그룹(예: 도수치료 10·20·30분) + 즐겨찾기. 설정은 서버에 저장
   - 그래프·증감률
2. **AI 분석(Claude API)**: 버튼을 누르면 나오는 분석 리포트 + 이어서 묻는 채팅. 집계 숫자만 보낸다. Anthropic 콘솔에 월 한도를 걸고, 앱 설정 화면에 이번 달 사용량을 보여 준다
3. **매출**: 의원 PC의 비트 폴더에 있는 파일을 읽는다. 크롬·엣지에서 폴더를 한 번 연결해 두면 이후 최신 파일을 읽는다. 원본은 PC 밖으로 나가지 않는다
4. **재고**: 입고·사용·실사를 직접 입력한다. 최소 수량 아래로 떨어지면 발주 알림을 띄운다
5. **직원 급여·인센티브**
   - 직원별 기본급(세후)
   - 인센티브 항목을 직원별로 설정: 건당 정액 / 매출의 % / 고정 수당
   - 같은 치료라도 항목마다 금액·%가 다르다(예: 도수치료 급여·비급여·신장분사1·신장분사2)
   - 실적(건수·매출)은 매달 직접 입력한다
   - 세후 지급액까지 계산하고, 세무사에게 보낼 표를 만든다. 세전 역산·4대보험·원천세는 세무사가 처리한다
   - 저장 항목: 이름·직종·금액만
6. **일일마감·일일보고·월말보고**: 지금 쓰는 양식을 웹으로 옮긴다
7. **인건비율·치료사 생산성**: 매출 대비 인건비 %, 직원별 건수·매출·인센티브 추이
8. **원장님 보고용 월간 PDF**: 월말보고 + 통계 그래프 + AI 분석
9. **랜딩**: 다른 병원 유치용. 히글스필드로 히어로 배경 영상 1개 + 기능 소개 이미지를 만든다(생성 전 크레딧 견적). 스크롤 애니메이션은 코드로 만든다
   - 2026-10-30 사용자: 그림·영상을 빼고 제품 화면 미리보기로(ADR-018, specs/landing-v2)
10. **관리자 화면**: 가입 신청을 승인·거절한다

## 개인정보 원칙
- 환자 개인정보는 서버에도, Claude API에도 절대 보내지 않는다. 브라우저 안에서 계산하고 집계 숫자만 저장·전송한다
- 직원 주민번호·계좌번호는 저장하지 않는다

## 기술·인프라

- 새 사이트를 배포한 뒤, 사용자 확인을 받고 파일럿(tonggye-bunseok)의 Vercel·Supabase를 내린다
